# 第 84 章 · 对象数组与遍历

> [!abstract] 本章目标
> 掌握从"数组首地址 + 个数"遍历所有对象的完整流程，
> 以及每一步必须做的防御。

> [!note] 承上
> 上一章造好了 demo 引擎，里面有对象数组。
> 本章从"数组首地址 + 个数"出发，**把整个数组读出来并逐个解析**（含三层防御）。

## 先看本项目的遍历代码

```cpp
for (int i = 0; i < Count; ++i) {
    const uint64_t objectAddress = dr->Read<uint64_t>(
        static_cast<uintptr_t>(Arrayaddr) + 0x8ULL * i);
    if (!IsValidObject(objectAddress) ||
        objectAddress == static_cast<uint64_t>(MySelf)) {
        continue;
    }
    /* 处理每个对象 */
}
```

十行里包含了全部要点。逐个拆。

## 结构的获取链

```
模块基址 (libUE4)
    ↓ +0xB3EC650
UWorld 指针
    ↓ +0x30
ULevel 指针
    ↓ +0x98
Actor 数组首地址
    ↓ +0xA0
Actor 数量
```

对应代码：

```cpp
Uworld = dr->Read<uint64_t>(libUE4 + 0xB3EC650);
if (Uworld == 0) return;

Uleve = dr->Read<uint64_t>(Uworld + 0x30);
if (Uleve == 0) return;

Arrayaddr = dr->Read<uint64_t>(Uleve + 0x98);
Count = dr->Read<int>(Uleve + 0xA0);
```

**每一跳都要判空。** 为什么？

| 场景 | 会发生什么 |
|---|---|
| 游戏在加载界面 | `UWorld` 可能是 0 |
| 切换关卡中 | `ULevel` 可能正在重建 |
| 数组还没填充 | `Arrayaddr` 是 0，`Count` 是 0 |

不判空 → 用 0 当地址去读 → 段错误。

## 遍历的三个防御层

### 防御 1：数组本身的合法性

```cpp
if (Arrayaddr == 0 || Count <= 0 || Count > MAX_COUNT) return;
```

为什么要设上限？

```cpp
Count = dr->Read<int>(Uleve + 0xA0);
```

如果读出来的是垃圾（比如 `0x7FFFFFFF` = 21 亿），
循环 21 亿次 → 程序卡死。

**建议上限**：10000（实际游戏场景里的 Actor 通常几百个）。

### 防御 2：每个指针的合法性

```cpp
static bool IsValidObject(uint64_t address) {
    return address > 0x10000000ULL && address < 0x10000000000ULL &&
           (address % 4) == 0;
}
```

三条判据（第 17 章讲过）：

| 判据 | 拦截什么 |
|---|---|
| `> 0x10000000` | 读到 0 或极小值（失败 + 偏移） |
| `< 0x10000000000` | 超出用户空间上限的垃圾值 |
| `% 4 == 0` | 未对齐的指针（必定错误） |

### 防御 3：排除自身

```cpp
if (objectAddress == (uint64_t)MySelf) continue;
```

不排除的话，会在自己头上画方框。

## 优化：一次读完整个数组

逐个读 N 次 → 一次读 N×8 字节：

```cpp
// 分配本地缓冲
std::vector<uint64_t> objects(Count);

// 一次读完
int n = dr->Read(Arrayaddr, objects.data(), Count * 8);
if (n != Count * 8) {
    // 部分失败，可能数组正在变化
}

// 本地遍历（零 I/O）
for (int i = 0; i < Count; i++) {
    uint64_t obj = objects[i];
    if (!IsValidObject(obj)) continue;
    /* ... */
}
```

**N 次 I/O → 1 次**（第 81 章）。

## 遍历时的时间一致性问题

考虑这个场景：

```
1. 读完数组（50 个对象）
2. 处理对象 0：读它的位置
3. 此时游戏删除了对象 17
4. 处理对象 17：读到已释放的内存 → 垃圾或崩溃
```

**这是真实存在的竞态。** 外部程序无法加锁（除非用内核驱动暂停目标）。

缓解方法：

| 方法 | 说明 |
|---|---|
| 严格校验 | 每个读出来的值都做范围检查（第 89 章） |
| 失败跳过 | 读失败就 `continue`，不试图修复 |
| 重试 | 整帧重试一次（本项目没做，但是合理的改进） |
| 快照 | 一次读尽可能多的数据，减少时间窗口 |

## 完整的遍历模板

```cpp
struct ActorSnapshot {
    uint64_t address;
    uint32_t nameId;
    Vec3     position;
    bool     valid;
};

std::vector<ActorSnapshot> CollectActors(IDriver *dr,
                                          uint64_t arrayAddr,
                                          int32_t  count) {
    std::vector<ActorSnapshot> out;
    if (arrayAddr == 0 || count <= 0 || count > 10000) return out;

    // 1. 一次读整个指针数组
    std::vector<uint64_t> ptrs(count);
    if (dr->Read(arrayAddr, ptrs.data(), count * 8) != count * 8) {
        return out;      // 读失败，返回空
    }

    // 2. 过滤 + 收集需要读的字段
    std::vector<uint64_t> validPtrs;
    for (auto p : ptrs) {
        if (IsValidObject(p)) validPtrs.push_back(p);
    }
    if (validPtrs.empty()) return out;

    // 3. 批量读每个对象的名字 ID 和 root 指针
    struct RawData { uint32_t nameId; uint64_t root; };
    std::vector<RawData> raws(validPtrs.size());
    std::vector<ReadRequest> reqs;
    for (size_t i = 0; i < validPtrs.size(); i++) {
        reqs.push_back({validPtrs[i] + 0x18, &raws[i].nameId, 4});
        reqs.push_back({validPtrs[i] + 0x168, &raws[i].root, 8});
    }
    if (!ReadBatch(dr, reqs)) return out;

    // 4. 批量读世界坐标
    std::vector<Vec3> positions(validPtrs.size());
    reqs.clear();
    for (size_t i = 0; i < validPtrs.size(); i++) {
        if (!IsValidObject(raws[i].root)) continue;
        reqs.push_back({raws[i].root + 0x1F0, &positions[i], sizeof(Vec3)});
    }
    ReadBatch(dr, reqs);

    // 5. 组装结果（全部在本地，零 I/O）
    out.reserve(validPtrs.size());
    for (size_t i = 0; i < validPtrs.size(); i++) {
        ActorSnapshot s{};
        s.address  = validPtrs[i];
        s.nameId   = raws[i].nameId;
        s.position = positions[i];
        s.valid    = IsValidObject(raws[i].root) && IsFiniteVec3(positions[i]);
        out.push_back(s);
    }
    return out;
}
```

**I/O 次数：1（数组）+ 2（批量字段）≈ 3 次**，不管有多少个对象。

## 链表遍历（另一种组织方式）

有些引擎用链表而非数组：

```cpp
uint64_t cur = Read<uint64_t>(listHead);
int guard = 0;
while (cur != 0 && guard++ < 10000) {      // ★ 必须有上限
    /* 处理 cur */
    cur = Read<uint64_t>(cur + nextOffset);
}
```

> [!danger] 链表遍历必须设迭代上限
> 如果链表成环（数据损坏或故意构造），会无限循环。
> `guard < 10000` 是必须的防御。

## 本项目的"最近目标"选择

遍历时顺便找最近的目标：

```cpp
float 最近目标距离 = 1e30f;

for (...) {
    const float 目标dx = rootScreen.X - px;
    const float 目标dy = rootScreen.Y - py;
    const float 目标距离 = 目标dx*目标dx + 目标dy*目标dy;   // 平方，不开方

    if (目标距离 < 最近目标距离) {
        最近目标距离 = 目标距离;
        目标物体位置 = Vec3(rootWorld.X, rootWorld.Y, rootWorld.Z);
        有目标物体 = true;
    }
}
```

注意用的是**屏幕距离**（距屏幕中心的像素距离），不是世界距离——
因为"准星附近"才是玩家关心的。

### 坏味道重构推演：从"硬编码筛选"到"可插拔谓词"

> [!tip] 筛选条件为什么不该写死在循环里？
> 上面"找最近目标"的循环里塞了阈值判断。当筛选条件变多（距离/血量/名字/可见性），
> 写死在循环里就会变成"意大利面"。看两种写法的差别。

❌ **稚嫩写法：所有条件硬编码在循环里**

```cpp
// ❌ 坏味道：筛选规则散落在遍历循环中
ActorSnapshot 选择目标(ActorSnapshot* list, int n) {
    float 最近 = 1e30f;
    ActorSnapshot 结果{};
    for (int i = 0; i < n; i++) {
        auto& a = list[i];
        if (!a.visible) continue;                       // 规则1：可见
        if (a.dist > 500.0f) continue;                   // 规则2：距离（硬编码 500）
        if (a.hp <= 0) continue;                          // 规则3：活着
        if (strncmp(a.name, "BP_Character", 12) != 0) continue;  // 规则4：类名
        if (a.dist < 最近) { 最近 = a.dist; 结果 = a; }
    }
    return 结果;
}
```

| 坏味道 | 后果 |
|---|---|
| 阈值硬编码 | 改距离阈值要改函数体、重编 |
| 规则与遍历耦合 | 加规则就往循环里塞 `if` |
| 无法复用 | 想按血量排序选目标？只能重写一个函数 |
| 无法测试 | 规则逻辑埋在循环里，不好单独验证 |

✅ **优雅写法：谓词（谓词可插拔 + 组合器）**

```cpp
// ✅ 本项目真实做法：用 std::function 表达"过滤器"，规则可插拔
//（见本章"动手演练"的 Filter 定义）
struct ActorSnapshot { const char* name; float dist; float hp; bool visible; };
using Filter = std::function<bool(const ActorSnapshot&)>;

inline Filter NameFilter(const char* prefix) {
    return [prefix](const ActorSnapshot& a) {
        return std::strncmp(a.name, prefix, std::strlen(prefix)) == 0;
    };
}
inline Filter DistanceFilter(float maxDist) {
    return [maxDist](const ActorSnapshot& a) { return a.dist <= maxDist; };
}
inline Filter HpFilter(float minHp) {
    return [minHp](const ActorSnapshot& a) { return a.hp > minHp; };
}
inline Filter And(Filter a, Filter b) {
    return [a, b](const ActorSnapshot& s) { return a(s) && b(s); };
}

// 业务代码：组合规则，循环里不含任何具体阈值
auto f = And(NameFilter("BP_Character"), And(DistanceFilter(500), HpFilter(0)));
for (int i = 0; i < n; i++) if (f(list[i])) { /* 候选 */ }
```

### 核心指标对比

| 维度 | ❌ 硬编码筛选 | ✅ 谓词组合 |
|---|---|---|
| **可维护性** | 改阈值改函数体 | 改阈值改构造参数 |
| **可扩展性** | 加规则塞 `if` | 加规则加一个 Filter |
| **复用性** | 规则锁死在一个循环 | 规则可任意组合/复用 |
| **单元测试** | 难（埋循环里） | 每个 Filter 可独立断言 |

### 演进动因剖析

> [!note] 为什么本项目用 `std::function` 谓词？
> 1. **筛选规则是配置**：距离/血量阈值来自 `ConfigManager::Settings`，
>    不该硬编码进循环体。
> 2. **规则要能组合**：先按名字筛、再按距离筛、再按血量筛——组合子让规则自由拼装。
> 3. **每个规则要能单测**：`NameFilter`/`DistanceFilter` 各自可写断言（见本章习题）。
>
> **一句话**：当"筛选条件会变、会组合、要测试"时，把条件抽成**谓词**——
> 这就是本章 `Filter` + `And` 组合器的设计动因。

## 课后习题

### 习题 84.1 实现带防御层的对象数组遍历（★★）

**任务要求**：写 `forEachObject(arrayAddr, count, mem, size, callback)`，
遍历对象数组时对每个元素做合法性检查（跳过 0 指针）。

**核心骨架**：

```cpp
#include <cstdio>
#include <cstdint>
#include <cstring>
#include <vector>
#include <cassert>

// 从 mem 里读一个 8 字节指针
uint64_t readPtr(const uint8_t* mem, size_t size, uint64_t addr) {
    if (addr + 8 > size) return 0;
    uint64_t v; memcpy(&v, mem + addr, 8); return v;
}

// 遍历对象数组，跳过无效（0）元素
int forEachObject(uint64_t arrayAddr, int count,
                  const uint8_t* mem, size_t size,
                  std::vector<uint64_t>& out) {
    int valid = 0;
    for (int i = 0; i < count; i++) {
        uint64_t obj = readPtr(mem, size, arrayAddr + i * 8);   // ★ 每个元素 8 字节
        if (obj == 0) continue;                                 // ★ 跳过空指针
        out.push_back(obj);
        valid++;
    }
    return valid;
}
```

**验证断言**：

```cpp
int main() {
    uint8_t mem[64] = {0};
    uint64_t objs[4] = {0x1000, 0, 0x2000, 0x3000};   // 第 2 个是空指针
    memcpy(mem + 8, objs, sizeof(objs));

    std::vector<uint64_t> found;
    int n = forEachObject(8, 4, mem, sizeof(mem), found);
    printf("找到 %d 个有效对象\n", n);
    assert(n == 3);                       // 跳过 0
    assert(found[0] == 0x1000 && found[2] == 0x3000);
    printf("习题 84.1 全部通过\n");
    return 0;
}
```

**验证断言**：4 个元素中 1 个是空指针 → 返回 `3` 个有效对象。

## 性能考量与复杂度说明

**【时间复杂度】**

对象数组遍历是 `O(n)`（n = Actor 数量），每个对象内部读若干字段是 `O(1)`（固定偏移）：

```
遍历 1 次     O(n)      每个 Actor 读 ~5 个字段（名字/位置/骨骼根）
单对象处理    O(1)      偏移读取，与 n 无关
完整一帧      O(n)      本项目 n 通常 50~200
```

**最差场景**：`n` 很大（如 1000+ 对象）时，逐个读内存会累积成瓶颈——这正是第 81 章"批量读"要解决的问题（把 n 次系统调用压成常数次）。

**【空间开销】**

- 每帧临时存 `n` 个对象的快照（位置/名字），约 `n × 几十字节`。
- **潜在压力点**：`std::string name_` 每次遍历都构造（第 223 行 `GetNameById`），n 大时有内存分配开销。优化方向：字符串驻留（相同名字只存一份）。

**【并发与 I/O 瓶颈】**

- 遍历是**主线程串行**的——每个 `dr->Read` 都是一次真正的跨进程 I/O（几十微秒）。n=200 时约 10ms，**接近一帧预算的一半**。
- **锁竞争**：本项目三个后台线程（第 82 章）与主线程共享 `dr`，读写时靠驱动内部锁串行化。

> [!note] 工程权衡：为何不一次读完整个数组？
> 真实项目**部分做了**（第 81 章的批量读），但没有把所有字段都批量——因为：
> ① 过滤要**边读边判**（无效对象要跳过），批量读会读无用数据；
> ② 批量缓冲需要额外内存，且要处理"部分成功"；
> ③ 对象数量动态变化，预分配可能浪费。
> **折中**：先批量读"数组本身"，再按需读每个有效对象——平衡了 I/O 次数与内存开销。
