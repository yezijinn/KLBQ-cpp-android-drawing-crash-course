# 第 87 章 · 如何自己找偏移（方法论）

> [!abstract] 本章目标
> 掌握"从已知值反推地址"的通用方法：特征码扫描、指针扫描、字符串定位。
> 全部用自写的 demo 引擎演示，不依赖任何第三方程序。

> [!note] 承上
> 前面几章用的偏移都是"已知的"。
> 本章讲**怎么自己找到偏移**——特征码扫描、指针扫描、字符串定位。这是卷七最重要的能力。

## 先明确问题

我们已知：
- 目标进程里有个 `g_world` 变量，值是 `0x12345678`
- 但我们**不知道** `g_world` 在哪个地址

要找的是：`存放这个值`的地址。

```
地址            内容
0x7a1b3ec650   0x12345678    ← 想找到这里
```

> [!important] 六种方法不用都精通——先学两个
> 下面有六个方法，**不是并列的**。按这个顺序学：
>
> | 顺序 | 方法 | 为什么 | 何时用 |
> |---|---|---|---|
> | **1** | **方法四**（字符串定位） | 最实用、成功率最高 | **优先试这个** |
> | **2** | **方法三**（多次筛选） | 通用，不依赖字符串 | 方法四失效时 |
> | 3 | 方法二（内存扫描） | 方法三的前置技能 | 理解方法三用 |
> | 4 | 方法一（静态分析） | 需要反汇编基础 | 手上有 .so 文件时 |
> | 5 | 方法五（指针扫描） | 工具自动化程度高 | 找复杂指针链时 |
> | 6 | 方法六（反推验证） | 辅助手段 | 验证其它方法的结果 |
>
> **新手先用方法四**——它靠"代码里的字符串"定位，
> 比盲目扫描几百 MB 内存省事得多。学完方法四再回头看方法三。

## 方法一：静态分析（最简单）

如果能拿到可执行文件/库，直接反汇编：

```bash
aarch64-linux-android-objdump -d libUE4.so | grep -A5 '<某个函数>'
```

看到：

```asm
adrp    x0, 0x7a1b3e000
add     x0, x0, #0xc650      ; x0 = 0x7a1b3ec650
ldr     x1, [x0]             ; 读出 g_world
```

`adrp + add` 这对指令就是"取某个全局变量的地址"。
基址 + `0xc650` 就是偏移。

**前提**：能拿到文件，且它是可读的。

## 方法二：内存扫描（运行时）

原理：**已知值 → 搜内存 → 找到存放它的地址**。

### 场景：找 g_world

已知 demo 引擎打印了 `g_world = 0x55d3a1b2c000`。
扫描整个进程内存找这个值：

```cpp
std::vector<uint64_t> ScanValue(MemReader &mem,
                                 const std::vector<std::pair<uint64_t,uint64_t>> &regions,
                                 uint64_t value) {
    std::vector<uint64_t> hits;

    const size_t CHUNK = 1024 * 1024;      // 1MB 一块
    std::vector<uint64_t> buf(CHUNK / 8);

    for (auto [start, end] : regions) {
        for (uint64_t addr = start; addr < end; addr += CHUNK) {
            size_t len = std::min<size_t>(CHUNK, end - addr);
            int n = mem.Read(addr, buf.data(), len);
            if (n <= 0) continue;

            size_t count = n / 8;
            for (size_t i = 0; i < count; i++) {
                if (buf[i] == value)
                    hits.push_back(addr + i * 8);
            }
        }
    }
    return hits;
}
```

问题：**一个 8 字节值在几百 MB 内存里可能命中几百次**。

## 方法三：多次筛选（逐步缩小）

这是内存扫描的核心技巧——**改变目标值，看哪些地址跟着变**。

```
1. 第一次扫描 g_world = 0x55d3a1b2c000  →  命中 500 个地址
2. 让 demo 重新生成世界（值变成 0x55d3a1c34000）
3. 第二次扫描新值                        →  命中 480 个
4. 取交集                                →  可能只剩 1~5 个
5. 再变一次，再筛                         →  确定唯一
```

## 方法四：字符串定位（最实用）

思路：**代码里一定有引用全局变量的指令，而这些指令附近有可识别的字符串**。

### 实践：给 demo 引擎埋一个标记

```cpp
// demo_engine.cpp
static const char *kMarker = "DEMO_ENGINE_MARKER_v1";

void PrintWorld() {
    printf("[%s] g_world = %p\n", kMarker, (void*)g_world);
    // ...
}
```

编译后，字符串 `"DEMO_ENGINE_MARKER_v1"` 在 `.rodata` 段。
而 `PrintWorld` 函数里会引用 `g_world`。

步骤：

```
1. 扫描内存找字符串 "DEMO_ENGINE_MARKER_v1"  → 得到 strAddr
2. 扫描找"谁引用了 strAddr"                    → 得到 refAddr（在代码段）
3. 从 refAddr 往前后看汇编，找到 adrp+add 取 g_world 地址的指令
4. 从指令里解出偏移
```

第 2 步的实现：

```cpp
// 在可读写数据区里找"值等于 strAddr 的指针"
// （真实情况下引用在代码段，adrp+add 编码的地址，不是直接存指针）
```

> [!note] ARM64 的麻烦
> ARM64 用 `adrp`（取页基址）+ `add`（加页内偏移）两条指令构造地址，
> 不会直接存一个 64 位指针。所以第 2 步要**反汇编**代码段来找。
>
> 简化做法：扫描整个模块，找 `adrp xN, #imm` 后紧跟 `add xN, xN, #imm2`
> 且计算出的地址等于 `strAddr` 的位置。
> 这就是"指针扫描"工具做的事。

## 方法五：指针扫描（Pointer Scan）

最强大的通用方法：

```
1. 找到目标值的当前地址 A
2. 扫描整个内存，找出所有"值等于 A"的地址（谁指向 A）
3. 对每个结果递归往上找（谁指向它）
4. 得到一串"基址 + 偏移链"
5. 重启程序，验证哪条链仍然有效
```

```
[libUE4.so + 0xB3EC650] → 0x1b2c000 (UWorld)
                              ↓ +0x30
                          0x1b40000 (ULevel)
                              ↓ +0x98
                          0x1c00000 (Actor数组)
```

**有效的链在重启后仍然有效**（因为静态偏移不变，只有基址变）。

## 方法六：从已知结构反推

如果你已经知道一部分偏移，可以验证和推导其它：

```
已知：Actor + 0x18 = nameId
验证：读 Actor + 0x18，用 GetNameById 解析，看是不是合理的类名
     → 是 → 偏移对
     → 否 → 试试 0x1C、0x20...
```

**暴力试错 + 合理性验证**，在小范围搜索时很有效。

## 验证偏移是否正确的四个标准

| 标准 | 说明 |
|---|---|
| **值合理** | 指针落在有效范围（第 17 章） |
| **可跟随** | 沿链继续读，下一级也有效 |
| **稳定** | 多次读取结果一致（或按预期变化） |
| **语义正确** | 解析出来的名字/坐标符合预期 |

**只有四条全满足才算找到。**

## 实践：给 demo 引擎做一次完整定位

任务：不打印 `g_world` 地址，只用扫描找到它。

```cpp
// 1. demo 引擎：定期改变 g_world 指向的 World 里的数据
//    （比如 actorCount 每秒变化）
// 2. 外部扫描器：
//    a. 第一次扫描：找所有 8 字节对齐的、值在某个范围的指针
//    b. 打印命中数
//    c. 等 demo 改变数据
//    d. 第二次扫描：找指向"内容变化了"的地址

// 简化示例：已知 actorCount 从 6 变成 7
std::vector<uint64_t> FindWorldPointer(MemReader &mem,
                                        const auto &regions) {
    // 第一次：读所有内存，找值 == 6 的 4 字节位置
    auto hits1 = ScanValue32(mem, regions, 6);
    printf("第一次命中 %zu 个\n", hits1.size());

    printf("请让 demo 改变 actorCount，然后按回车\n");
    getchar();

    // 第二次：在这些位置里找值 == 7 的
    std::vector<uint64_t> hits2;
    for (uint64_t addr : hits1) {
        if (mem.Read<int32_t>(addr) == 7)
            hits2.push_back(addr);
    }
    printf("第二次命中 %zu 个\n", hits2.size());
    return hits2;
}
```

跑起来你会发现：**第一次几万个命中，第二次只剩几个。**
其中一个就是 `World.level.actorCount` 的地址，
往上推就能找到 `g_world`。

## 常见困难

| 困难 | 原因 | 应对 |
|---|---|---|
| 命中太多 | 值太常见（如 0、1） | 选一个罕见的值 |
| 命中为 0 | 值在寄存器里没写回内存 | 换个时机扫描 |
| 地址每次都变 | 堆分配，没有静态指针 | 必须找静态根（模块+偏移） |
| 找到但重启后失效 | 是动态地址 | 继续往上找指针链 |
| 代码段读不了 | 权限限制 | 用内核驱动或换方法 |

## 课后习题

### 习题 87.1 实现内存值扫描器（★★）

**要求**：在一段内存里扫描所有等于目标值的 4 字节位置——这是"找偏移"的第一步。

**核心骨架**（用本地数组模拟目标内存）：

```c
#include <stdio.h>
#include <stdint.h>
#include <string.h>
#include <assert.h>

// 扫描 mem 里所有值等于 target 的 4 字节位置，结果写入 out，返回个数
int scan_value(const uint8_t* mem, size_t size, uint32_t target, uint32_t* out, int maxOut) {
    int found = 0;
    for (size_t i = 0; i + 4 <= size; i += 4) {   // 4 字节对齐扫描
        uint32_t v;
        memcpy(&v, mem + i, 4);
        if (v == target) {
            if (found < maxOut) out[found] = (uint32_t)i;
            found++;
        }
    }
    return found;
}

int main(void) {
    uint32_t data[8] = {100, 200, 100, 300, 100, 400, 500, 100};
    uint32_t hits[16];
    int n = scan_value((uint8_t*)data, sizeof(data), 100, hits, 16);
    printf("找到 %d 处\n", n);
    assert(n == 4);                       // 4 个 100
    assert(hits[0] == 0);                 // 偏移 0
    assert(hits[1] == 8);                 // 偏移 8（第 3 个元素）
    printf("习题 87.1 全部通过\n");
    return 0;
}
```

**验证断言**：数组里 4 个 `100`，返回偏移 `0/8/16/28`（字节偏移）。

> [!tip] 这道题练什么
> ① **按字节偏移扫描**（`i += 4`，每个 int 4 字节）；② **`memcpy` 读值**避免对齐问题；
> ③ 这是本项目"内存扫描"的第一步——找出所有可能的位置，再**多次筛选**缩小范围（本章方法三）。

### 习题 87.2 多值筛选缩小范围（★★）

**要求**：先用值 A 扫描得候选，再在这些候选里筛出**值变成了 B** 的位置。

**参考实现**：

```c
#include <stdio.h>
#include <stdint.h>
#include <string.h>
#include <assert.h>

int main(void) {
    uint32_t before[6] = {50, 60, 50, 70, 50, 80};   // 变化前
    uint32_t after[6]  = {50, 60, 99, 70, 99, 80};   // 变化后：两个 50 变成 99

    // 第一次扫描：找 50
    int cand[16], nc = 0;
    for (int i = 0; i < 6; i++) if (before[i] == 50) cand[nc++] = i;
    assert(nc == 3);   // 3 个 50

    // 第二次筛选：在候选里找"变成了 99"的
    int result[16], nr = 0;
    for (int j = 0; j < nc; j++) {
        int idx = cand[j];
        if (after[idx] == 99) result[nr++] = idx;
    }
    printf("筛选后剩 %d 个候选\n", nr);
    assert(nr == 2);
    assert(result[0] == 2 && result[1] == 4);
    printf("习题 87.2 全部通过\n");
    return 0;
}
```

> [!note] 为什么要多次筛选
> 一个值 `50` 在内存里可能出现在成百上千个位置。**改变游戏里的值，再筛一次**，
> 候选会指数级减少——几次之后就能定位到唯一地址（本章方法三"多次筛选"）。
