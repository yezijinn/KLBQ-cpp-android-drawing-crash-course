# 第 92 章 · 数据结构文档化

> [!abstract] 本章目标
> 建立一套能长期维护的偏移文档。
> **卷七收官章**——本卷是"把字节还原成有意义的对象"。

> [!note] 承上
> 卷七从"造 demo 引擎"走到"相机数据"，全部偏移都摸清了。
> 本章收官：**把偏移文档化**（`offsets.h`），让项目能长期维护。

## 先看为什么必须写文档

三个月后，游戏更新了，你打开代码：

```cpp
uint64_t x = dr->Read<uint64_t>(obj + 0x370);
```

`0x370` 是什么？Mesh 组件？还是别的？
你是怎么找到它的？下次更新还能复现吗？

**没有文档，每次更新都要重新逆向一遍。**

## 文档应该记什么

| 项目 | 说明 |
|---|---|
| 偏移值 | 数字本身 |
| 类型 | 指针 / int / float / 结构体 |
| 含义 | 这个字段是什么 |
| 如何找到的 | 定位方法（便于下次复现） |
| 验证方法 | 怎么确认它是对的 |
| 版本 | 适用于哪个版本 |
| 发现日期 | 时间线 |

## 一份好的偏移文档模板

```markdown
## UWorld (引擎核心对象)

**获取**：`libUE4.so + 0xB3EC650`
**类型**：`uint64_t`（指针）
**验证**：读出来后 `+0x30` 应得到有效指针；`+0x98` 是数组、`+0xA0` 是数量

| 偏移 | 类型 | 字段 | 说明 |
|---|---|---|---|
| +0x30 | ptr | PersistentLevel | 当前关卡 ULevel |
| +0x188 | ptr | OwningGameInstance | 游戏实例 |
| +0x1xx | ... | ... | ... |

**定位方法**：
从 `UGameplayStatics::GetGameInstance` 相关字符串入手，
在引用处找到静态指针的 adrp+add 指令。

**更新记录**：
- 2026-09-14 初始记录，版本 1.0.0
```

## 本项目的偏移全景（汇总）

把前面章节散落的偏移汇总成一张表——**这就是你的速查手册**。

### 全局静态（相对 libUE4 基址）

| 偏移 | 内容 | 章节 |
|---|---|---|
| `+0xB236B00` | GName 池 | 85 |
| `+0xB3C5D00` → `+0x20` → `+0x270` | 投影矩阵指针 | 91 |
| `+0xB3EC650` | UWorld | 84 |
| `+0xB476F20` → `+0x8` | PhysX 场景数组 | 93 |
| `+0x25E8` | 刚体数组（相对场景） | 93 |

### UWorld

| 偏移 | 类型 | 字段 |
|---|---|---|
| `+0x30` | ptr | PersistentLevel |
| `+0x188` | ptr | OwningGameInstance |

### ULevel

| 偏移 | 类型 | 字段 |
|---|---|---|
| `+0x98` | ptr | Actors 数组首地址 |
| `+0xA0` | int32 | Actors 数量 |

### PlayerController

| 偏移 | 类型 | 字段 |
|---|---|---|
| `+0x378` | Rotator | ControlRotation（自瞄写入点） |
| `+0x390` | ptr | AcknowledgedPawn（自己的角色） |
| `+0x3A8` | ptr | PlayerCameraManager |
| `+0xB38` | ptr | CachedPMCharacter |

### PlayerCameraManager

| 偏移 | 类型 | 字段 |
|---|---|---|
| `+0x2300` | Vec3 | CameraCache.Location |
| `+0x230C` | Rotator | CameraCache.Rotation |
| `+0x2318` | float | CameraCache.FOV |

### Actor

| 偏移 | 类型 | 字段 |
|---|---|---|
| `+0x18` | uint32 | NameID（FName） |
| `+0x168` | ptr | RootComponent |
| `+0x370` | ptr | Mesh 组件 |
| `+0x380` → `+0x54C` | float | 胶囊体半径 |

### Mesh

| 偏移 | 类型 | 字段 |
|---|---|---|
| `+0x2A0` | BoneTransform | ComponentToWorld |
| `+0x578` | ptr | 骨骼数组 |

### RootComponent

| 偏移 | 类型 | 字段 |
|---|---|---|
| `+0x1F0` | Vec3 | 世界坐标 |

### 骨骼

| 常量 | 值 | 说明 |
|---|---|---|
| `BONE_STRIDE` | 48 | 每个骨骼项字节数 |
| `BONE_HEAD` | 7 | 头 |
| `BONE_CHEST` | 6 | 胸 |
| `BONE_PELVIS` | 1 | 骨盆 |

### 武器链

```
PC +0xB38 → +0x7B0 (InventoryComponent)
          → +0x15C0 (CurrentWeapon)
          → +0x848 (AttackComponent)
          → +0x280 (Projectiles 数组)
          → +0x288 (Projectiles 数量)
```

## 用代码表达文档

> [!warning] 真实项目的现状 vs 本章的建议
> 真实项目 KLBQ **没有** `offsets.h`——偏移目前**散落在 `draw_Gui.cpp`**（如 `libUE4 + 0xb236b00`、`+0x168`、`+0x370`）。
> 这样改一个版本要翻好几处，正是本章要解决的问题。
> **本章的 `offsets.h` 是"推荐的重构方案"**：把散落的偏移集中到一个头文件，注释即文档。
> 你可以在自己的练习项目里直接采用；重构真实项目时，把 `draw_Gui.cpp` 里的常量抽到这里即可。

把文档写成代码，比写在 Markdown 里更好维护：

```cpp
// offsets.h —— 集中所有偏移（本项目推荐的重构方案），注释即文档
#pragma once
#include <cstdint>

// 适用版本：游戏 1.0.0 / libUE4.so MD5: a1b2c3...
// 最后更新：2026-09-14
// 更新人：你自己

struct Offsets {
    // ===== 全局静态（相对模块基址）=====
    static constexpr uint64_t GNAME_POOL   = 0xB236B00;
    static constexpr uint64_t MATRIX_CHAIN = 0xB3C5D00;
    static constexpr uint64_t MATRIX_MID   = 0x20;
    static constexpr uint64_t MATRIX_FINAL = 0x270;
    static constexpr uint64_t UWORLD       = 0xB3EC650;
    static constexpr uint64_t PHYSX_PTR    = 0xB476F20;

    // ===== UWorld =====
    static constexpr uint64_t UWORLD_LEVEL            = 0x30;
    static constexpr uint64_t UWORLD_GAMEINSTANCE     = 0x188;

    // ===== ULevel =====
    static constexpr uint64_t ULEVEL_ACTORS           = 0x98;
    static constexpr uint64_t ULEVEL_ACTORCOUNT       = 0xA0;

    // ===== GameInstance → LocalPlayer → PC =====
    static constexpr uint64_t GI_LOCALPLAYERS         = 0x38;
    static constexpr uint64_t LP_PLAYERCONTROLLER     = 0x30;

    // ===== PlayerController =====
    static constexpr uint64_t PC_CONTROLROTATION      = 0x378;
    static constexpr uint64_t PC_ACKNOWLEDGEDPAWN     = 0x390;
    static constexpr uint64_t PC_CAMERAMANAGER        = 0x3A8;
    static constexpr uint64_t PC_CACHEDPMCHARACTER    = 0xB38;

    // ===== CameraManager =====
    static constexpr uint64_t CAM_CACHE_LOCATION      = 0x2300;
    static constexpr uint64_t CAM_CACHE_ROTATION      = 0x230C;
    static constexpr uint64_t CAM_CACHE_FOV           = 0x2318;

    // ===== Actor =====
    static constexpr uint64_t ACTOR_NAMEID            = 0x18;
    static constexpr uint64_t ACTOR_ROOTCOMPONENT     = 0x168;
    static constexpr uint64_t ACTOR_MESH              = 0x370;
    static constexpr uint64_t ACTOR_CAPSULE_COMP      = 0x380;
    static constexpr uint64_t CAPSULE_RADIUS          = 0x54C;

    // ===== Mesh =====
    static constexpr uint64_t MESH_COMPONENTTOWORLD   = 0x2A0;
    static constexpr uint64_t MESH_BONEARRAY          = 0x578;

    // ===== RootComponent =====
    static constexpr uint64_t ROOT_WORLDPOS           = 0x1F0;

    // ===== 武器链 =====
    static constexpr uint64_t CHAR_INVENTORY          = 0x7B0;
    static constexpr uint64_t INV_CURRENTWEAPON       = 0x15C0;
    static constexpr uint64_t WEAPON_ATTACKCOMP       = 0x848;
    static constexpr uint64_t ATTACK_PROJECTILES      = 0x280;
    static constexpr uint64_t ATTACK_PROJCOUNT        = 0x288;

    // ===== 骨骼 =====
    static constexpr uint32_t BONE_STRIDE             = 48;
    static constexpr int BONE_PELVIS     = 1;
    static constexpr int BONE_CHEST      = 6;
    static constexpr int BONE_HEAD       = 7;
    static constexpr int BONE_L_SHOULDER = 8;
    static constexpr int BONE_L_ELBOW    = 10;
    static constexpr int BONE_L_WRIST    = 11;
    static constexpr int BONE_R_SHOULDER = 30;
    static constexpr int BONE_R_ELBOW    = 31;
    static constexpr int BONE_R_WRIST    = 32;
    static constexpr int BONE_L_THIGH    = 49;
    static constexpr int BONE_L_KNEE     = 50;
    static constexpr int BONE_L_ANKLE    = 51;
    static constexpr int BONE_R_THIGH    = 53;
    static constexpr int BONE_R_KNEE     = 54;
    static constexpr int BONE_R_ANKLE    = 55;

    // ===== PhysX =====
    static constexpr uint64_t PHYSX_SCENEARRAY_OFFSET = 0x8;
    static constexpr uint64_t SCENE_RIGIDACTORS       = 0x25E8;
    static constexpr uint64_t SCENE_SQMANAGER         = 0x2430;
    static constexpr uint64_t SHAPE_MANAGER           = 0x28;

    // 元信息
    static constexpr const char *VERSION = "1.0.0";
    static constexpr const char *UPDATED = "2026-09-14";
};
```

**好处**：
- 改一处，全项目生效
- IDE 能跳转、能补全
- 编译器会检查拼写
- 版本信息随代码走

## 版本快照

保留历史版本，便于回退和对比：

```cpp
// offsets_v1.h
namespace v1 { struct Offsets { /* 2026-01 的偏移 */ }; }

// offsets_v2.h
namespace v2 { struct Offsets { /* 2026-09 的偏移 */ }; }

// offsets.h
#include "offsets_v1.h"
#include "offsets_v2.h"
using CurrentOffsets = v2::Offsets;      // 切换只需改这一行
```

## 自检：文档和代码同步

文档会过时，代码不会。所以让代码自己验证：

```cpp
// 启动时的偏移自检
bool SelfTest(IDriver *dr, uint64_t base) {
    using O = Offsets;

    // 1. GName 池：应该能解析出至少一个名字
    uint64_t gname = base + O::GNAME_POOL;
    if (GetNameById(gname, 1).empty()) {
        LOGE("自检失败：GName 池偏移可能失效");
        return false;
    }

    // 2. UWorld 链
    uint64_t world = dr->Read<uint64_t>(base + O::UWORLD);
    if (!IsValidPtr(world)) { LOGE("自检失败：UWorld"); return false; }

    uint64_t level = dr->Read<uint64_t>(world + O::UWORLD_LEVEL);
    if (!IsValidPtr(level)) { LOGE("自检失败：UWorld_Level"); return false; }

    int32_t count = dr->Read<int32_t>(level + O::ULEVEL_ACTORCOUNT);
    if (count < 0 || count > 10000) { LOGE("自检失败：Count=%d", count); return false; }

    // 3. 相机
    /* ... */

    LOGI("偏移自检通过，版本 %s", O::VERSION);
    return true;
}
```

**每次启动自动跑一遍**，有问题立刻知道。

## 常见坑排查表

| 症状 | 最可能的原因 | 解法 |
|---|---|---|
| 更新后**不知道改哪** | 偏移散落各处 | 集中到 `offsets.h` |
| 偏移失效**静默画错** | 没有启动自检 | 加自检，为 0 时报错退出 |
| 多版本**混用出错** | 没版本表 | 维护 `版本→偏移` 对照表 |
| 团队协作**对不上** | 偏移没文档 | 每个结构体标注字段偏移 |
