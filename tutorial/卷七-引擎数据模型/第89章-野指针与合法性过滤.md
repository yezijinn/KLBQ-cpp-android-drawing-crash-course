# 第 89 章 · 野指针与合法性过滤

> [!abstract] 本章目标
> 建立一套完整的防御体系，让程序在读错数据时**不崩溃**。
> 这是外部程序稳定运行的生命线。

> [!note] 承上
> 前几章能读出数据了，但读错就会崩。
> 本章建一套**完整的防御体系**（八层过滤），让程序读错数据时不崩溃。

> [!important] 前置条件
> - 本章的多级校验逻辑可用**本地内存模拟**验证（构造"合法区域"数组），无需设备。

## 先看"野指针"从哪来

```cpp
uint64_t obj = dr->Read<uint64_t>(arrayAddr + i * 8);
```

这个值可能是：

| 情况 | 值 |
|---|---|
| 正常 | 一个有效的 Actor 地址 |
| 读取失败 | 0 |
| 对象已释放 | 原地址，但内存已被回收/复用 |
| 偏移失效 | 完全随机的数 |
| 数组越界 | 相邻数据被当指针 |

**后面四种都是"野指针"，用它去读就可能崩溃。**

## 本项目原有的过滤

```cpp
static bool IsValidObject(uint64_t address) {
    return address > 0x10000000ULL && address < 0x10000000000ULL &&
           (address % 4) == 0;
}
```

三条判据。但**不够**——下面逐条分析并扩展。

## 第一层：地址范围

```cpp
bool InUserRange(uint64_t addr) {
    // Android arm64 用户空间典型范围
    return addr > 0x10000000ULL && addr < 0x10000000000ULL;
}
```

依据（第 17 章的布局）：
- 小于 0x10000000（256MB）：几乎不可能是堆/库地址
- 大于 0x10000000000（1TB）：超出用户空间

> [!note] 这些数字怎么来的
> Android arm64 的 `TASK_SIZE` 取决于 `VA_BITS`（通常 39 或 48）：
> - 39 位：用户空间上限 `0x0000007F_FFFFFFFF`（512GB）
> - 48 位：上限 `0x0000FFFF_FFFFFFFF`（256TB）
>
> 本项目的 `0x10000000000`（1TB）是个保守的经验值。
> **要精确就得查设备的 `VA_BITS`**，但经验值够用。

## 第二层：对齐

```cpp
bool IsAligned(uint64_t addr) {
    return (addr % 4) == 0;      // 至少 4 字节对齐
}
```

指针在 C++ 里至少按 4 字节对齐（多数是 8）。
奇数地址必然是错的。

更严格：

```cpp
bool IsAligned8(uint64_t addr) { return (addr % 8) == 0; }
```

## 第三层：读权限（maps 校验）

最靠谱但最慢：查这个地址是否真的映射了。

```cpp
class RegionCache {
public:
    void Refresh(pid_t pid) {
        regions_ = GetScannableRegions(ParseMaps(pid));
        // 排序以便二分查找
        std::sort(regions_.begin(), regions_.end());
    }

    bool Contains(uint64_t addr) const {
        // 二分查找
        auto it = std::upper_bound(regions_.begin(), regions_.end(), addr,
            [](uint64_t a, const auto &r) { return a < r.first; });
        if (it == regions_.begin()) return false;
        --it;
        return addr < it->second;
    }

private:
    std::vector<std::pair<uint64_t,uint64_t>> regions_;
};
```

**成本**：每次校验一次二分查找（~20 次比较，纳秒级）。
比读失败导致的异常处理便宜得多。

> [!tip] 缓存要定期刷新
> 进程会 mmap/munmap，缓存会过期。
> 建议每 1~2 秒刷新一次，或者读失败时立即刷新。

## 第四层：值合理性

读出来的**值**本身也要检查：

```cpp
// 坐标：必须是有限数，且在合理范围
bool IsValidPosition(const Vec3 &p) {
    if (!std::isfinite(p.x) || !std::isfinite(p.y) || !std::isfinite(p.z))
        return false;
    // UE4 世界坐标通常在 ±1e6 厘米（10 公里）内
    const float LIMIT = 1e7f;
    return std::fabs(p.x) < LIMIT && std::fabs(p.y) < LIMIT && std::fabs(p.z) < LIMIT;
}

// 数量：不能为负，不能巨大
bool IsValidCount(int32_t c) {
    return c >= 0 && c <= 10000;
}

// 名字 ID：不能为 0（0 是"无名字"）
bool IsValidNameId(uint32_t id) {
    return id != 0 && id < 0x1000000;
}

// 角度：在合理范围
bool IsValidAngle(float deg) {
    return std::isfinite(deg) && deg >= -360.0f && deg <= 360.0f;
}
```

**每个字段都该有对应的合理性判据。**

## 第五层：跨字段一致性

几个字段之间应该自洽：

```cpp
bool IsConsistent(const ActorSnapshot &s) {
    // 有名字 ID 就应该能解析出名字
    if (s.nameId != 0 && s.name.empty()) return false;

    // 有 root 组件就应该有坐标
    if (s.root != 0 && !IsValidPosition(s.position)) return false;

    // .screen 位置与 world 位置应该对应（投影可逆验证太贵，跳过）

    return true;
}
```

## 第六层：结果过滤（绘制前）

即使前面都过了，画之前还要再查：

```cpp
static bool IsFiniteScreenPoint(const Vector2A &point) {
    return std::isfinite(point.X) && std::isfinite(point.Y);
}

if (!IsFiniteScreenPoint(rootScreen) ||
    !IsFiniteScreenPoint(topScreen) ||
    !IsFiniteScreenPoint(bottomScreen)) {
    continue;
}
```

以及包围盒检查（第 52 章）：

```cpp
if (boxWidth <= 1.0f || boxWidth > abs_ScreenX ||
    boxRight < 0.0f || boxX > abs_ScreenX ||
    boxBottom < 0.0f || boxTop > abs_ScreenY) {
    continue;
}
```

## 完整的过滤流水线

```
读指针
  ↓ ① 范围检查
  ↓ ② 对齐检查
  ↓ ③ （可选）maps 校验
处理对象
  ↓ ④ 读字段
  ↓ ⑤ 每个字段的合理性
  ↓ ⑥ 跨字段一致性
投影
  ↓ ⑦ isfinite 检查
绘制
  ↓ ⑧ 屏幕包围盒检查
```

**八层防御，一层都不能省。**

## 一个通用的校验工具

```cpp
struct ValidationResult {
    bool ok;
    const char *reason;
};

class PtrValidator {
public:
    ValidationResult Check(uint64_t addr) const {
        if (addr == 0)
            return {false, "null"};
        if (!InUserRange(addr))
            return {false, "out-of-range"};
        if (!IsAligned(addr))
            return {false, "misaligned"};
        if (strict_ && !regions_.Contains(addr))
            return {false, "unmapped"};
        return {true, nullptr};
    }

    void SetStrict(bool s) { strict_ = s; }
    void Refresh(pid_t pid) { regions_.Refresh(pid); }

    // 统计各原因的拒绝次数（调试用）
    std::unordered_map<std::string, int> stats;

private:
    bool strict_ = false;
    RegionCache regions_;
};
```

统计各原因的拒绝次数——**调试时极其有用**：
如果 "out-of-range" 占 90%，说明偏移错了；
如果 "unmapped" 占多数，说明对象被释放了。

## 性能考虑

| 检查 | 成本 |
|---|---|
| 范围/对齐 | ~1 ns |
| isfinite | ~1 ns |
| 二分查找 maps | ~50 ns |
| 完整校验一个 Actor | ~200 ns |

对比一次内存读取（~3000 ns），**校验成本可忽略**。

**结论：宁可多校验，也不要崩溃。**

## 本项目的防御盘点

| 位置 | 防御 |
|---|---|
| `IsValidObject()` | 范围 + 对齐 |
| 每级指针链后 | `if (X == 0) return;` |
| `IsFiniteScreenPoint()` | isfinite |
| 包围盒检查 | 屏幕范围 |
| `camMakeMatrix` | FOV 范围、NaN 检查、0 值检查 |
| `w < 0.001f` | 近平面 |
| `len > 1024` 检查 | 名字长度上界 |
| `boxWidth > abs_ScreenX` | 异常尺寸 |

**还缺的**（可以做改进）：
- maps 校验（第三层）
- 跨字段一致性（第五层）
- 校验统计（便于诊断）

## 课后习题

### 习题 89.1 实现多级指针合法性校验（★★）

**任务要求**：写 `isValidPtr(addr, knownRegions)`，校验一个地址是否落在"已知可读区域"内，
再写 `followChain(base, offsets, regions)` 沿指针链逐跳校验（任一跳非法即返回 0）。

**核心骨架**（用本地数组模拟内存区域）：

```cpp
#include <cstdio>
#include <cstdint>
#include <cstring>
#include <vector>
#include <cassert>

struct Region { uint64_t start, end; };

bool inRegions(uint64_t addr, const std::vector<Region>& regions) {
    for (const auto& r : regions)
        if (addr >= r.start && addr + 8 <= r.end) return true;   // 留够 8 字节
    return false;
}

// 沿链跳：每跳读一个指针，任一跳不在合法区域就返回 0
uint64_t followChain(uint64_t base, const std::vector<uint64_t>& offsets,
                     const std::vector<Region>& regions,
                     const uint8_t* mem, size_t memSize) {
    uint64_t cur = base;
    for (uint64_t off : offsets) {
        uint64_t addr = cur + off;
        if (!inRegions(addr, regions)) return 0;   // ★ 每跳校验
        memcpy(&cur, mem + addr, 8);
    }
    return cur;
}
```

**验证断言**：

```cpp
int main() {
    uint8_t mem[64] = {0};
    uint64_t a = 0x10, b = 0x20, target = 0xDEAD;
    memcpy(mem + 0x00, &a, 8);       // [0] → 0x10
    memcpy(mem + 0x10, &b, 8);       // [0x10] → 0x20
    memcpy(mem + 0x20, &target, 8);  // [0x20] → 0xDEAD

    std::vector<Region> regions = { {0, 64} };   // 整块 [0,64) 合法

    uint64_t r = followChain(0, {0x00, 0x00, 0x00}, regions, mem, sizeof(mem));
    printf("链尾 = 0x%llX\n", (unsigned long long)r);
    assert(r == 0xDEAD);

    // 有一跳越界（off 太大）→ 返回 0
    uint64_t bad = followChain(0, {0x00, 0x1000}, regions, mem, sizeof(mem));
    assert(bad == 0);
    printf("习题 89.1 全部通过\n");
    return 0;
}
```

**验证断言**：合法链得 `0xDEAD`；某跳地址落在区域外时返回 `0`（不崩）。

> [!danger] 每跳都要校验
> 目标进程随时可能切换关卡、释放对象，指针链**任何一环都可能突然变成野指针**。
> 本项目每一级都判空 + 区域校验（`if (Uworld == 0) return;`），这是防崩溃的第一道防线。

### 习题 89.2 用 maps 校验地址可读（★，概念题）

**任务要求**：说出为什么"地址非 0"还不够，还要查 `/proc/pid/maps`。

> [!question]- 参考答案
> 因为**非 0 的地址未必可读**——它可能落在：
> - 未映射的空洞（访问直接 SIGSEGV）；
> - 只读段（写会崩）；
> - 已释放的对象内存（读到垃圾）。
> 查 maps 能确认"这个地址确实在一段 `r--`/`rw-` 的映射里"，
> 本项目 `GetScanRegions()` 就是给扫描器返回"可读区域列表"（第 76、89 章）。

## 性能考量与复杂度说明

**【时间复杂度】**

八层校验**逐层短路**，最坏 O(8)，平均远小于（大部分对象在前几层就被排除）：

| 层 | 检查 | 成本 |
|---|---|---|
| 1 | 地址非 0 | ~1ns |
| 2 | 对齐检查 | ~1ns |
| 3 | 区域校验（二分）| ~10ns |
| ... | ... | ... |
| 8 | 真值复读 | ~µs |

**关键**：**便宜的检查放前面**，贵的放后面——把成本从 O(8µs) 降到平均 O(几十 ns)。

**【空间开销】**
- 每层只存临时变量，无额外分配。
- 区域列表缓存：`区域数 × 16 字节`，可忽略。

**【并发与 I/O 瓶颈】**
- 校验本身是 CPU 计算（快）；但第 8 层"真值复读"是 **I/O**（慢）。
- **锁竞争**：区域列表若被多线程读写，需保护。

> [!note] 工程权衡：为何八层而非一层大检查？
> 一层大检查要么太严（误杀合法对象）要么太松（放行野指针）。
> **分层短路**：既保证安全（不崩），又尽量不误杀——且每层可**独立统计拒绝原因**，便于调试。
