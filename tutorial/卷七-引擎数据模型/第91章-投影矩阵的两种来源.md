# 第 91 章 · 投影矩阵的两种来源

> [!abstract] 本章目标
> 理解"读引擎矩阵"和"自己算矩阵"的取舍，
> 以及本项目为什么两个都保留。

> [!note] 承上
> 上一章拿到了相机三要素。
> 本章讲 W2S 的两种做法——**读引擎矩阵 vs 自己算矩阵**，本项目两个都保留（互为备份）。

## 先看代码的分支

```cpp
inline bool WorldToScreen(const Vector3A& obj, Vector2A& screen) {
    // 分支 A：用引擎矩阵
    if (ConfigManager::Settings.矩阵W2S && MatrixPtr != 0) {
        const float* m = &MatrixData.M[0][0];
        const float w = m[3]*obj.X + m[7]*obj.Y + m[11]*obj.Z + m[15];
        if (w < 0.001f) return false;
        const float cx = m[0]*obj.X + m[4]*obj.Y + m[8] *obj.Z + m[12];
        const float cy = m[1]*obj.X + m[5]*obj.Y + m[9] *obj.Z + m[13];
        screen.X = (cx / w + 1.0f) * px;
        screen.Y = (1.0f - cy / w) * py;
        return std::isfinite(screen.X) && std::isfinite(screen.Y);
    }

    // 分支 B：自算矩阵
    float w = matrix[3]*obj.X + matrix[7]*obj.Y + matrix[11]*obj.Z + matrix[15];
    if (w < 0.001f) return false;
    /* ... */
}
```

一个开关 `矩阵W2S` 切换两种方案。

## 方案 A：读引擎矩阵

### 获取方式

```cpp
MatrixPtr = dr->Read<uint64_t>(dr->Read<uint64_t>(libUE4 + 0xB3C5D00) + 0x20) + 0x270;

MatrixData = Matrix{};
if (MatrixPtr != 0) {
    dr->Read(MatrixPtr, &MatrixData, sizeof(MatrixData));
}
```

三级链：`libUE4 + 0xB3C5D00` → `+0x20` → `+0x270`。

结果是一个 4×4 矩阵（16 个 float，64 字节）。

### 优点

| 优点 | 说明 |
|---|---|
| **最准确** | 引擎自己用的就是这个，不可能不一致 |
| 自动跟随 | 开镜、过场、特殊状态都自动正确 |
| 无需校准 | 不用调焦距系数 |

### 缺点

| 缺点 | 说明 |
|---|---|
| 依赖偏移 | 三级链任一环失效就全废 |
| 可能读到旧值 | 引擎可能有多份矩阵（上一帧/当前帧） |
| 无法微调 | 读什么就是什么 |

### UI 上的状态提示

```cpp
ImGui::Checkbox("矩阵投影W2S", &ConfigManager::Settings.矩阵W2S);
ImGui::SameLine();
ImGui::TextColored(MatrixPtr != 0 ? ImVec4(0.0f, 0.8f, 0.0f, 1.0f)
                                  : ImVec4(0.8f, 0.0f, 0.0f, 1.0f),
                   "矩阵:%s", MatrixPtr != 0 ? "有效" : "无效");
```

**绿色=有效，红色=无效**——一眼知道该不该用。

## 方案 B：自算矩阵

### 构造方式

第 49、50 章讲过：用相机的 Location/Rotation/FOV 构建。

```cpp
MinimalViewInfo camViewInfo;
camViewInfo.Location = AppBase.Location;
camViewInfo.Rotation = AppBase.Rotation;
camViewInfo.FOV = AppBase.Fov;
camMakeMatrix(camViewInfo);
```

### 优点

| 优点 | 说明 |
|---|---|
| 不依赖矩阵偏移 | 只要有相机三要素就行 |
| 可微调 | 焦距系数滑块（第 50 章） |
| 便于调试 | 每个中间量都能看到 |

### 缺点

| 缺点 | 说明 |
|---|---|
| 可能不准 | 坐标系约定、FOV 定义可能与引擎不同 |
| 需要校准 | 靠焦距系数调 |
| 特殊情况会错 | 过场动画、后处理效果 |

### 焦距微调

```cpp
ImGui::SliderFloat("垂直焦距系数", &ConfigManager::Settings.垂直焦距系数, 0.2f, 2.5f, "%.3f");
ImGui::SliderFloat("水平焦距系数", &ConfigManager::Settings.水平焦距系数, 0.2f, 2.5f, "%.3f");
```

## 两种方案的对比表

| | 引擎矩阵 | 自算矩阵 |
|---|---|---|
| 准确度 | ★★★★★ | ★★★☆☆（需校准） |
| 抗偏移失效 | ★☆☆☆☆（三级链） | ★★★★☆（只需相机） |
| 可调试性 | ★★☆☆☆ | ★★★★★ |
| 特殊场景 | ★★★★★ | ★★☆☆☆ |
| 性能 | 相同（都是一次矩阵乘） | 相同 |

## 为什么两个都留

**互为备份**：

- 引擎矩阵失效（偏移变了）→ 切自算，虽然可能略有偏差但能用
- 自算不准（特殊场景）→ 切引擎矩阵

这就是第 88 章说的"降级设计"。

> [!tip] 好的工程设计：关键路径要有备份
> 类似的还有：
> - 骨骼读不到 → 用根节点 + 高度偏移
> - 无内核驱动 → 用 process_vm_readv
> - 高精度失败 → 低精度兜底

## 验证矩阵是否正确

### 方法 1：正前方投影到屏幕中心

```cpp
Vec3 front = camPos + GetForward(camRot) * 1000.0f;   // 正前方 10 米
Vec2 s;
if (WorldToScreen(front, s)) {
    // s 应该 ≈ (px, py)，即屏幕中心
    float dx = fabsf(s.x - px);
    float dy = fabsf(s.y - py);
    if (dx > 1.0f || dy > 1.0f)
        printf("矩阵可能有问题，偏移 (%.1f, %.1f)\n", dx, dy);
}
```

**这是最灵敏的检验**——正前方的点必须投到正中心。

### 方法 2：两种方案互相验证

```cpp
Vec2 s1, s2;
WorldToScreenWithEngineMatrix(p, s1);
WorldToScreenWithOwnMatrix(p, s2);

float diff = sqrtf((s1.x-s2.x)*(s1.x-s2.x) + (s1.y-s2.y)*(s1.y-s2.y));
printf("两种方案差异: %.2f 像素\n", diff);
```

如果差异很小（<5 像素），说明两者都对。
如果差异很大，说明**至少有一个错了**。

### 方法 3：已知物体对照

在游戏里找一个位置已知的物体（比如你自己角色的脚），
看画出来的方框是否贴合。

**这是最终的实用检验。**

## 矩阵的内存布局

引擎矩阵和自算矩阵的访问方式一致：

```cpp
// 引擎矩阵：Matrix M[4][4]
m[3]*obj.X + m[7]*obj.Y + m[11]*obj.Z + m[15]

// 自算矩阵：float matrix[16]
matrix[3]*obj.X + matrix[7]*obj.Y + matrix[11]*obj.Z + matrix[15]
```

都是 `M[row + col*4]` 的列主序访问，
所以第 3 行（深度行）的四个元素是下标 3、7、11、15。

**这就是为什么两套代码长得一模一样**——
只要布局约定一致，切换只是换个数据源。

## 本项目的另一处矩阵

`GameTools::WorldMatrix`：

```cpp
GameTools::WorldMatrix = GameTools::rotatorToMatrix(AppBase.Rotation);
```

这是**旋转矩阵**（不含投影），用于把局部方向转世界方向。

用途示例：判断目标在不在视野内时，需要世界空间的朝向向量。

## 动手：矩阵对比工具

1. 在 demo 引擎里同时维护：
   - 一份"引擎矩阵"（模拟 UE4 内部算好的）
   - 相机三要素（供外部自算）
2. 外部程序读两种，各投影一批点
3. 输出对比表：

```
点           引擎矩阵        自算矩阵      差异
(100,0,0)   (1080,1200)   (1080,1200)   0.0 px
(100,50,0)  (1620,1200)   (1619,1201)   1.4 px
(200,0,50)  (1080,1350)   (1080,1350)   0.0 px
```

如果全部接近 0，说明你的自算公式和引擎一致。

**这是一个能反复用的验证工具**——
以后改任何投影相关的代码都跑一遍。
