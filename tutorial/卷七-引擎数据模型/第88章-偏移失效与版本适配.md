# 第 88 章 · 偏移失效与版本适配

> [!abstract] 本章目标
> 理解偏移为什么会失效，以及如何设计**抗更新**的结构。

> [!note] 承上
> 上一章会自己找偏移了。
> 但游戏一更新，偏移就失效——本章讲**怎么让程序抗更新**（自检 + 优雅降级）。

## 先看一个真实的失效场景

游戏更新了，你的程序还在用旧偏移：

```cpp
uint64_t Uworld = dr->Read<uint64_t>(libUE4 + 0xB3EC650);
// 读到 0x7FFE12345678（垃圾值）

uint64_t Uleve = dr->Read<uint64_t>(Uworld + 0x30);
// 段错误，或者读到随机数据
```

症状：

| 症状 | 原因 |
|---|---|
| 程序崩溃 | 用垃圾地址去读 |
| 画面全是乱线 | 读到的坐标是随机数 |
| 什么都没有 | 数组地址错，Count 是 0 |
| 方框位置全错 | 部分偏移变了 |

## 偏移为什么会变

每次游戏重新编译，编译器都会重新安排内存布局：

| 原因 | 影响 |
|---|---|
| 增删成员变量 | **后面的所有字段偏移都变** |
| 改基类 | 整条继承链的布局变 |
| 编译器版本/选项变化 | 对齐、内联、优化都可能变 |
| 引擎版本升级 | 大规模重构，几乎全变 |

**只要源码动一行，偏移就可能变。**

## 哪些偏移相对稳

| 偏移 | 稳定性 | 原因 |
|---|---|---|
| 模块基址 | **每次运行都变**（ASLR） | 靠动态查找解决 |
| `GName` 池（静态全局） | 较稳（版本内） | 全局变量位置固定 |
| `UWorld` 静态指针 | 较稳 | 同上 |
| `ULevel` 内部字段 | 中等 | 结构体可能微调 |
| `Actor` 成员偏移 | **易变** | 游戏类频繁改动 |
| 骨骼索引 | 较稳 | 骨架不变则索引不变 |

**规律：离引擎核心越近越稳，离游戏逻辑越近越易变。**

## 抗更新的设计策略

### 策略一：减少硬编码，多用"运行时发现"

| 硬编码（易失效） | 运行时发现（抗更新） |
|---|---|
| `libUE4 + 0xB3EC650` | 扫描特征码找到引用 |
| 固定骨骼索引 | 按名字匹配骨骼 |
| 假设某个字段在 0x370 | 遍历组件链表找 Mesh |

**但**：运行时发现代码复杂、慢、也可能失败。
所以实际是**混合**：主路径用硬编码（快），失败时降级到运行时发现。

### 策略二：集中管理偏移

**不要**把偏移散落在代码各处：

```cpp
// 差：几十处硬编码
uint64_t a = dr->Read<uint64_t>(obj + 0x370);
uint64_t b = dr->Read<uint64_t>(mesh + 0x578);
```

**要**集中到一个结构：

```cpp
// offsets.h
struct GameOffsets {
    // 全局
    uint64_t GName      = 0xB236B00;
    uint64_t UWorld     = 0xB3EC650;
    uint64_t MatrixPtr  = 0xB3C5D00;

    // UWorld
    uint64_t UWorld_Level      = 0x30;
    uint64_t UWorld_OwningGameInstance = 0x188;

    // ULevel
    uint64_t ULevel_Actors     = 0x98;
    uint64_t ULevel_ActorCount = 0xA0;

    // PlayerController
    uint64_t PC_ControlRotation = 0x378;
    uint64_t PC_AcknowledgedPawn = 0x390;
    uint64_t PC_PlayerCameraManager = 0x3A8;

    // Actor
    uint64_t Actor_NameId      = 0x18;
    uint64_t Actor_RootComponent = 0x168;
    uint64_t Actor_Mesh        = 0x370;

    // Mesh
    uint64_t Mesh_BoneArray    = 0x578;
    uint64_t Mesh_ComponentToWorld = 0x2A0;

    // Camera
    uint64_t Cam_CacheLocation = 0x2300;
    uint64_t Cam_CacheRotation = 0x230C;
    uint64_t Cam_CacheFOV      = 0x2318;

    // 版本标识
    const char *version = "1.0.0";
};

extern GameOffsets g_offsets;
```

更新时只改这一个文件——第 92 章会展开。

### 策略三：版本检测与多套偏移

```cpp
struct OffsetSet {
    const char *versionPattern;      // 如何识别这个版本
    GameOffsets offsets;
};

static const OffsetSet kSets[] = {
    { "1.0.0", { /* 偏移集 A */ } },
    { "1.1.0", { /* 偏移集 B */ } },
    { "1.2.0", { /* 偏移集 C */ } },
};

GameOffsets DetectVersion(IDriver *dr) {
    // 读版本字符串，或者用某个偏移处的值做指纹
    for (auto &s : kSets) {
        if (MatchVersion(dr, s.versionPattern))
            return s.offsets;
    }
    return kSets[0].offsets;      // 默认用最新的
}
```

**指纹识别**：找一个在版本间有差异的稳定值作为特征。

```cpp
bool CheckFingerprint(IDriver *dr, uint64_t base) {
    // 比如：某处的魔数
    uint32_t magic = dr->Read<uint32_t>(base + 0x1234);
    return magic == 0xDEADBEEF;
}
```

### 策略四：自检与优雅降级

启动时验证关键偏移：

```cpp
bool ValidateOffsets(IDriver *dr, const GameOffsets &o, uint64_t base) {
    uint64_t world = dr->Read<uint64_t>(base + o.UWorld);
    if (!IsValidPtr(world)) {
        LOGE("UWorld 偏移失效");
        return false;
    }

    uint64_t level = dr->Read<uint64_t>(world + o.UWorld_Level);
    if (!IsValidPtr(level)) {
        LOGE("UWorld_Level 偏移失效");
        return false;
    }

    int32_t count = dr->Read<int32_t>(level + o.ULevel_ActorCount);
    if (count < 0 || count > 10000) {
        LOGE("ActorCount 异常: %d", count);
        return false;
    }

    return true;
}
```

**失败就在 UI 上提示，而不是继续跑出乱码**：

```cpp
if (!ValidateOffsets(dr, g_offsets, libUE4)) {
    ImGui::TextColored(ImVec4(1,0,0,1), "偏移已失效，请更新");
    return;      // 不绘制 ESP
}
```

## 本项目的做法

坦白说，本项目**没有**做完善的版本适配——它用的是单套硬编码偏移。
原因：面向特定版本，维护者会随游戏更新手动修偏移。

但项目里有两处"降级设计"值得学：

### 1. 矩阵双来源

```cpp
if (ConfigManager::Settings.矩阵W2S && MatrixPtr != 0) {
    // 用引擎矩阵（更准）
} else {
    // 用自算矩阵（更稳）
}
```

一个失效时切另一个（第 91 章）。

### 2. 骨骼降级

```cpp
Vec3 瞄准点(rootWorld.X, rootWorld.Y, rootWorld.Z + Cfg.高度偏移);

if (Cfg.骨骼部位 != 0) {
    // 尝试用骨骼
    // 读不到就保持根节点的瞄准点
}
```

骨骼偏移失效 → 自动回退到"根节点 + 高度偏移"。

## 更新偏移的流程

游戏更新后：

```
1. 确认症状：是崩溃？还是数据不对？
2. 定位哪个偏移失效（从崩溃地址或错误的中间值反推）
3. 用第 87 章的方法重新定位
4. 更新 offsets 表
5. 回归测试：所有功能都要过一遍
6. 记录到文档（第 92 章）
```

> [!tip] 保留一份"已知好版本"的记录
> 包括：游戏版本号、二进制大小、MD5、当时可用的偏移集。
> 这样能快速判断"是不是游戏更新了"。

## 减少依赖偏移的技巧

| 技巧 | 说明 |
|---|---|
| 用名字而非类型 | 名字字符串比 UClass 指针稳定 |
| 用链表遍历而非固定索引 | 组件按类型找，不按下标 |
| 用相对关系 | 比如"从 Actor 找 RootComponent"比硬编码绝对便宜稳 |
| 多用引擎矩阵 | 引擎算的比自己推的准 |

## 动手：给 demo 引擎做一次"版本更新"

1. 在 demo 引擎的 `Actor` 结构里**插入一个新字段**：

```cpp
struct Actor {
    uint64_t vtable;
    uint32_t objectId;
    uint32_t nameId;
    uint32_t newField;        // ← 新增！
    uint64_t components;      // 偏移从 0x10 变成 0x18
    uint64_t next;            // 从 0x18 变成 0x20
};
```

2. 重新编译运行
3. 用你的读取程序去读 → **会发现组件读不到了**
4. 用第 87 章的方法重新定位
5. 更新偏移表，验证修好

**亲手经历一次"偏移失效 → 重新定位"的完整流程**，比读十页书有用。

## 课后习题

### 习题 88.1 用集中式偏移表 + 版本检测（★★）

**要求**：把偏移集中到一个结构体，提供"按版本返回对应偏移"的函数，
并写启动自检（偏移全 0 时报错）。

**核心骨架**：

```cpp
#include <cstdio>
#include <cstdint>
#include <cassert>

struct GameOffsets {
    const char* version;
    uint64_t actorMesh;       // Mesh 组件偏移
    uint64_t meshBoneArray;   // 骨骼数组偏移
};

// 集中管理多套偏移（本项目 offsets.h 的做法）
GameOffsets g_offsetsV1 = { "1.0.0", 0x370, 0x578 };
GameOffsets g_offsetsV2 = { "1.1.0", 0x378, 0x580 };   // 版本更新后变了

const GameOffsets* SelectOffsets(const char* version) {
    // "1.0.0" 和 "1.1.0" 的第 3 个字符（下标 2）分别是 '0' 和 '1'
    if (version[2] == '1') return &g_offsetsV2;
    return &g_offsetsV1;
}

// 启动自检：关键偏移不能为 0
bool SelfTest(const GameOffsets* o) {
    return o && o->actorMesh != 0 && o->meshBoneArray != 0;
}

int main() {
    const GameOffsets* o = SelectOffsets("1.1.0");
    printf("版本 %s: actorMesh=0x%llX\n", o->version, (unsigned long long)o->actorMesh);
    assert(o->actorMesh == 0x378);
    assert(SelfTest(o));

    // 模拟自检失败
    GameOffsets bad = { "x", 0, 0 };
    assert(!SelfTest(&bad));
    printf("习题 88.1 全部通过\n");
    return 0;
}
```

**验证断言**：版本 1.1.0 返回新偏移 `0x378`；偏移全 0 时自检失败。

> [!note] 为什么要集中管理
> 偏移散落各处时，游戏一更新要改几十处。集中到 `offsets.h` 后，
> **只需改一个文件**。启动自检能在偏移失效时"明确报错"而不是画错或崩溃（第 88、92 章）。
