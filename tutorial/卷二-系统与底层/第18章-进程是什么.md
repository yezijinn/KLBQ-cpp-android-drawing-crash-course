# 第 18 章 · 进程是什么

> [!abstract] 本章目标
> 理解进程在内核里到底是一个什么对象，能自己写出"按包名找 PID"的代码。
> 本项目 `Driver::GetPid()` 就是这段代码。

## 先看一句话的答案

**进程 = 一个独立的虚拟地址空间 + 一组内核维护的元数据 + 至少一个执行流（线程）。**

内核里每个进程/线程是一个 `task_struct`（Linux 内核的结构体），里面有：
PID、页表基址、打开的文件、信号处理器、CPU 上下文、内存映射链表……

你不需要记住这个结构，但要知道：**它存在，且内核知道每个进程的一切。**

## PID 与 TGID

| 概念 | 含义 | 在哪看 |
|---|---|---|
| PID | 内核里每个执行流（线程）的唯一 ID | `/proc/<pid>` |
| TGID | 线程组 ID = 主线程的 PID | `/proc/<pid>/status` 里的 `Tgid` |
| 我们常说的"进程 PID" | 其实是 TGID | |

一个 Android App 通常有几十个线程，它们**PID 不同、TGID 相同**：

```bash
ls /proc/1234/task/        # 列出该进程的所有线程
cat /proc/1234/status | grep -E 'Pid|Tgid|Threads'
```

> [!note] 为什么本项目用 tgid
> ```cpp
> req->tgid = global_pid;   // driver.h
> ```
> 内核按线程组操作，意味着"作用于整个进程"，读写内存时不需要区分具体线程
> （所有线程共享同一个地址空间）。

## /proc：内核开的一扇窗

`/proc` 不是真实磁盘目录，是内核**动态生成**的虚拟文件系统。
每一个数字目录，就是一个活着的进程。

| 路径 | 内容 |
|---|---|
| `/proc/<pid>/cmdline` | 启动命令行（Android 上就是包名！） |
| `/proc/<pid>/status` | 状态：Name/State/Pid/PPid/Uid |
| `/proc/<pid>/maps` | 内存映射（第 17 章） |
| `/proc/<pid>/mem` | 内存本体（需 ptrace 权限，本项目不用） |
| `/proc/<pid>/task/` | 该进程的所有线程 |
| `/proc/<pid>/fd/` | 打开的文件描述符 |
| `/proc/<pid>/exe` | 指向可执行文件的符号链接 |
| `/proc/self` | 指向"当前进程"的快捷方式 |

## 找 PID：按包名

Android 上每个 App 进程的 `cmdline` 就是它的包名：

```bash
adb shell cat /proc/1234/cmdline
# 输出：com.idreamsky.klbqm
```

> [!note] 这里的 `xxd` 和 `|` 管道
> `xxd` 是**十六进制查看器**（第 19 章会讲），`|` 是**管道**——把左边命令的输出，作为右边命令的输入。
> `cat ... | xxd | head -2` 读作："读文件 → 转成十六进制 → 只看前 2 行"。

注意：`cmdline` 里参数之间用 `\0` 分隔，**不是空格**。

```bash
cat /proc/1234/cmdline | xxd | head -2
# 00000000: 636f 6d2e 6964 7265 616d 736b 792e 6b6c  com.idreamsky.kl
# 00000010: 6271 6d00                              bqm.
```

结尾那个 `00` 就是分隔符。

> [!note] 下面代码用到的新东西（第 22 章系统讲）
> 这段 `find_pid_by_name` 用到了一批 POSIX API，**第 22 章会完整讲**，这里先给"够读懂"的最小说明：
>
> 涉及的类型：`DIR`（目录句柄）、`struct dirent`（一个目录项，含 `d_name` 文件名）、`pid_t`（进程 ID 的整数类型）。
>
> | 用到的 | 是什么 |
> |---|---|
> | `opendir` / `readdir` / `closedir` | 打开目录 / 读一个目录项 / 关闭目录 |
> | `open` / `read` / `close` | 打开文件 / 读内容 / 关闭（POSIX 层，非 C 标准库） |
> | `O_RDONLY` | `open` 的标志："只读" |
> | `ssize_t` | 有符号的"大小"类型（`read` 的返回值，可能是 -1） |
> | `snprintf(buf, n, fmt, ...)` | 格式化并写进缓冲区（比 `sprintf` 安全，指定了大小） |
> | `strcmp` | 比较字符串（第 06 章讲过，相等返回 0） |
> | `atoi` | 字符串转整数 |
>
> **你只需要先看懂"流程"**：遍历 `/proc` 里的每个数字目录 → 读它的 `cmdline` → 和包名比较。
> 这些函数的具体用法第 22 章会讲透。

> [!note] `fork` / `exec` / `wait` 也是新东西
> 本章后面"进程的生老病死"一节出现的 `fork()` / `execl()` / `waitpid()`：
> - `fork()`：复制当前进程，产生一个子进程（返回 0 表示"我是子进程"，返回 >0 表示"我是父进程"）
> - `exec()`：用另一个程序**替换**当前进程
> - `wait()`：等子进程结束并回收它
> 这三个函数本章会解释作用，**你不需要会写多进程程序**，只要理解"进程可以被复制、可以被替换、需要被回收"。

### 自己实现一遍

本项目 `Driver::GetPid()` 的逻辑（简化版）。**别一上来就看完整代码**——先看骨架，再一步步填。

#### 第一步：骨架

先只看"要做什么"，不看细节：

```c
int find_pid_by_name(const char *target) {
    // ① 打开 /proc 目录
    // ② 遍历里面的每一项
    //     - 跳过不是数字的项
    //     - 读这一项对应的 cmdline
    //     - 和 target 比较，相等就返回它的 PID
    // ③ 关闭目录，返回 -1（没找到）
}
```

**四句话就是整个算法。** 下面逐步把注释换成真代码。

#### 第二步：打开 /proc

```c
#include <dirent.h>

int find_pid_by_name(const char *target) {
    DIR *dir = opendir("/proc");       // 打开目录，返回"目录句柄"
    if (!dir) return -1;               // 打不开（权限？）直接失败

    // ...（下面填）
    closedir(dir);                     // 关目录
    return -1;
}
```

`opendir` 类似 `fopen`，只不过打开的是**目录**；`DIR*` 是"目录句柄"。

#### 第三步：遍历 + 跳过非数字项

```c
    struct dirent *entry;
    while ((entry = readdir(dir)) != NULL) {   // 每轮取一个目录项
        const char *name = entry->d_name;      // 项的名字
        if (name[0] < '0' || name[0] > '9')    // 首字符不是数字
            continue;                          // → 跳过（cpuinfo、meminfo 等）
        // ...（下面填）
    }
```

`readdir` 一次返回一个目录项（`struct dirent`），返回 `NULL` 表示到头了。
`/proc` 里只有**数字命名的目录**才是进程，所以首字符不是数字就跳过。

#### 第四步：读 cmdline

```c
        char path[64], cmdline[256];
        snprintf(path, sizeof(path), "/proc/%s/cmdline", name);   // 拼出路径
        int fd = open(path, O_RDONLY);       // 打开这个文件
        if (fd < 0) continue;                // 打不开（进程刚好退出了）→ 跳过
        ssize_t n = read(fd, cmdline, sizeof(cmdline) - 1);       // 读内容
        close(fd);                           // 关文件
        if (n <= 0) continue;                // 没读到 → 跳过
        cmdline[n] = 0;                      // 手动补 '\0'，让它成为合法字符串
        // ...（下面填）
```

#### 第五步：比较 + 返回

```c
        if (strcmp(cmdline, target) == 0) {  // 一样？
            closedir(dir);                   // 先关目录
            return atoi(name);               // 目录名就是 PID，转成整数返回
        }
```

#### 合起来：完整代码

```c
#include <dirent.h>
#include <fcntl.h>
#include <unistd.h>
#include <string.h>
#include <stdio.h>
#include <stdlib.h>

int find_pid_by_name(const char *target) {
    DIR *dir = opendir("/proc");
    if (!dir) return -1;

    struct dirent *entry;
    char path[64], cmdline[256];

    while ((entry = readdir(dir)) != NULL) {
        const char *name = entry->d_name;
        if (name[0] < '0' || name[0] > '9') continue;

        snprintf(path, sizeof(path), "/proc/%s/cmdline", name);
        int fd = open(path, O_RDONLY);
        if (fd < 0) continue;
        ssize_t n = read(fd, cmdline, sizeof(cmdline) - 1);
        close(fd);
        if (n <= 0) continue;
        cmdline[n] = 0;

        if (strcmp(cmdline, target) == 0) {
            closedir(dir);
            return atoi(name);
        }
    }
    closedir(dir);
    return -1;
}
```

**回头对照**：现在再看开头那四句骨架，是不是每一句都对应了上面的代码？

四个要点：
1. `readdir` 扫 `/proc`，跳过非数字目录（还有 `cpuinfo`、`meminfo` 等）
2. 读 `cmdline`，直接 `strcmp` 比较（因为 `\0` 已经帮我们切好了第一段）
3. 找到就立即 `closedir` 返回（**不要忘了关目录句柄，否则泄漏**）
4. 找不到返回 `-1`

> [!danger] 忘记 closedir 会泄漏文件描述符
> 每个进程能打开的 fd 数量有上限（通常 1024）。
> 如果在循环里反复扫 `/proc` 而不关，几百次之后所有 `open` 都会失败，
> 报 `Too many open files`。本项目用 `std::scoped_lock` 保证的是锁，
> 但 `DIR*` 的关闭仍靠每个 return 分支手动 `closedir(dir)`——注意看代码里每个 return 前都有。

## 进程状态

`cat /proc/<pid>/status`：

```
Name:   klbqm
State:  S (sleeping)
Tgid:   12345
Pid:    12345
PPid:   800
Uid:    10123  10123  10123  10123
```

| State | 含义 |
|---|---|
| R | 运行中 |
| S | 可中断睡眠（等事件，最常见） |
| D | 不可中断睡眠（等 IO，**kill -9 都杀不掉**） |
| T | 被停止（调试器暂停） |
| Z | 僵尸（已退出但父进程没回收） |

## 进程的生老病死

```c
#include <unistd.h>
#include <sys/wait.h>

pid_t pid = fork();          // 复制出一个子进程
if (pid == 0) {
    // 子进程：代码从这里继续
    execl("/bin/ls", "ls", "-l", NULL);   // 换成另一个程序
} else {
    // 父进程
    int status;
    waitpid(pid, &status, 0);   // 等子进程结束并回收
}
```

| 调用 | 作用 |
|---|---|
| `fork()` | 复制当前进程（写时复制，不是真拷贝内存） |
| `exec()` | 用新程序**覆盖**当前进程的地址空间 |
| `wait()` | 等子进程结束，回收资源 |
| `exit()` | 终止自己 |

`fork` + `exec` 是 Unix 启动程序的标准两步。
Android 的 zygote 就是靠 `fork` 快速孵化 App 进程的。

## 孤儿与僵尸

- **僵尸**：子进程死了，父进程没 `wait()` → 内核保留它的 `task_struct`，占一个 PID
- **孤儿**：父进程先死 → 子进程被 `init`（PID 1）收养，`init` 会定期回收

判断僵尸：

```bash
ps aux | grep defunct
# 或
cat /proc/<pid>/status | grep State   # Z
```

## 权限：谁能动谁

Linux 规则：

| 条件 | 能否操作目标进程 |
|---|---|
| 同一 UID（同一用户） | 可以（受其它安全模块约束） |
| 不同 UID | 不可以 |
| root（UID 0） | 基本可以 |

Android 上更复杂：**每个 App 是一个独立 UID**（如 `u0_a123`），
所以普通 App 之间完全隔离。要读别的进程，通常需要 root。

```bash
adb shell id          # 默认 shell 用户，uid=2000
adb shell su -c id    # root，uid=0
```

> [!warning] root 不等于万能
> Android 还有 SELinux。root 只是绕过了 UID 检查，
> SELinux 策略仍然可能拒绝你的操作（第 37 章详述）。
> 典型症状：`Permission denied` 但 `id` 显示已是 root。

> [!note] 这段代码用到的两个新函数
> - `sscanf(buf, fmt, ...)`：从**字符串**里按格式提取数据（`scanf` 是从键盘读，`sscanf` 是从内存字符串读）。
>   这里 `sscanf(buf + 5, "%255s", name)` 意思是"从 `Name:` 后面的部分提取一个词，最多 255 字符"。
> - `strncmp(a, b, n)`：比较字符串的**前 n 个字符**（`strcmp` 比全串，`strncmp` 只比前 n 个）。
>   这里 `strncmp(buf, "Name:", 5) == 0` 就是"判断这行是不是以 `Name:` 开头"。
> 两个函数都和 `printf`/`strcmp` 一个家族，第 22 章讲文件 IO 时会一起见到。

## 动手：写一个 mini ps

> [!tip] Windows 用户怎么办
> 本练习用了 `opendir`/`readdir`、`open`/`read`，**Windows 上没有 `/proc`**。可用 WSL，或在 Android 设备上跑（`adb shell`）。

```c
#include <stdio.h>
#include <dirent.h>
#include <string.h>
#include <stdlib.h>

int main(void) {
    DIR *dir = opendir("/proc");
    if (!dir) return 1;
    struct dirent *e;

    printf("%-8s %s\n", "PID", "NAME");
    while ((e = readdir(dir))) {
        if (e->d_name[0] < '0' || e->d_name[0] > '9') continue;

        char path[64], buf[512];
        snprintf(path, sizeof(path), "/proc/%s/status", e->d_name);
        FILE *fp = fopen(path, "r");
        if (!fp) continue;

        char name[256] = "";
        while (fgets(buf, sizeof(buf), fp)) {
            if (strncmp(buf, "Name:", 5) == 0) {
                sscanf(buf + 5, "%255s", name);
                break;
            }
        }
        fclose(fp);
        printf("%-8s %s\n", e->d_name, name);
    }
    closedir(dir);
    return 0;
}
```

改一改：再读出 `State:` 和 `VmRSS:`（物理内存占用），做成 `ps` 的简版。
