# 第 17 章 · 虚拟地址空间

> [!abstract] 本章目标
> 理解"每个进程都以为自己独占整个内存"这件事是怎么做到的，
> 并能看懂 `/proc/pid/maps` 的每一行。
> 这是全部跨进程读取技术的第一块基石。

## 先看一个反直觉的实验

> [!note] 下面 `(void*)main` 的写法
> **函数名本身就是函数的地址**（第 05 章"函数指针"提过）。`(void*)main` 就是"取 main 的地址，转成通用指针 `void*`"，好给 `%p` 打印。
> 另外 `malloc(sizeof(int))` 是第 04 章讲过的堆分配。**这两处不影响本章主题（看地址分布），照抄即可。**

```c
#include <stdio.h>
#include <stdlib.h>

int global_var = 42;

int main(void) {
    int  stack_var = 7;
    int *heap_var  = malloc(sizeof(int));

    printf("代码 main   : %p\n", (void*)main);
    printf("global_var  : %p\n", (void*)&global_var);
    printf("heap_var    : %p\n", (void*)heap_var);
    printf("stack_var   : %p\n", (void*)&stack_var);
    return 0;
}
```

一次典型输出（64 位 Linux）：

```
代码 main   : 0x0000000000401136
global_var  : 0x0000000000404010
heap_var    : 0x0000000001c4a2a0
stack_var   : 0x00007ffd8e3c4a1c
```

四个地址，四个**数量级完全不同**的区域。而且：再运行一次，堆和栈的地址又变了（ASLR），
但 `main` 和 `global_var` 的地址基本不变。

## 虚拟地址：一张只属于本进程的地图

你的程序里看到的每一个地址，都不是物理内存的真实地址。
CPU 访问内存时，会经过一个叫 **MMU（内存管理单元）** 的硬件，查一张表，把虚拟地址翻译成物理地址。

```
进程 A                          进程 B
虚拟 0x400000 ─┐                虚拟 0x400000 ─┐
               │  MMU 查表                     │  MMU 查表
               ↓                               ↓
          物理 0x1A300000                 物理 0x2B700000
```

**关键结论：进程 A 的 `0x400000` 和进程 B 的 `0x400000` 是两块完全不同的物理内存。**
所以在 A 里 `*(int*)0x400000 = 1`，改不到 B 的任何东西。这就是进程隔离。

> [!note] 这就是为什么"作弊要读内存"变复杂了
> 你不能直接在自己程序里解引用游戏进程的地址——那是另一张地图。
> 必须借助内核提供的接口（第 74 章的 `process_vm_readv`，或内核驱动），
> 由内核拿着**对方**的页表去翻译。

## 页与页表

MMU 不是一字节一字节翻译的，那样太慢。它按**页（page）**管理：

- 典型页大小：**4096 字节（4KB）**
- 虚拟地址 `0x7ffd8e3c4a1c`：低 12 位（`a1c`）是页内偏移，高位是页号
- 页表：页号 → 物理页框号 的映射表

64 位系统用 4 级页表（PGD → PUD → PMD → PTE），每级 512 项，覆盖 48 位虚拟地址。

```
虚拟地址（48 位有效）：
┌────────┬────────┬────────┬────────┬────────────┐
│ PGD 9b │ PUD 9b │ PMD 9b │ PTE 9b │ 页内偏移 12b│
└────────┴────────┴────────┴────────┴────────────┘
```

页表由内核维护，每个进程一套（切换进程时换页表基址寄存器）。

## 一个进程的典型内存布局

```
高地址
0xFFFF_FFFF_FFFF_FFFF ┌──────────────────┐
                      │   内核空间        │  所有进程共享，用户态不可访问
0xFFFF_0000_0000_0000 ├──────────────────┤
                      │   栈 (stack)      │  ↓ 向下生长，局部变量、返回地址
                      ├──────────────────┤
                      │   ↕ 未映射空洞    │  （防止栈溢出踩到别处）
                      ├──────────────────┤
                      │   mmap 区         │  动态库、大块 malloc、共享内存
                      │   ↓ 向下生长      │
                      ├──────────────────┤
                      │      ...          │
                      ├──────────────────┤
                      │   堆 (heap)       │  ↑ 向上生长，malloc
                      ├──────────────────┤
                      │   .bss            │  未初始化的全局/静态变量
                      ├──────────────────┤
                      │   .data           │  已初始化的全局/静态变量
                      ├──────────────────┤
                      │   .rodata         │  只读数据、字符串常量
                      ├──────────────────┤
                      │   .text           │  代码（机器指令）
低地址                │                   │
0x0000_0000_0000_0000 └──────────────────┘  0 地址不可访问（NULL）
```

各段对照（第 08 章讲过栈，这里补全）：

| 段 | 放什么 | 权限 | 例子 |
|---|---|---|---|
| `.text` | 函数机器码 | r-x | `main`、`Read` |
| `.rodata` | 只读数据 | r-- | `"libUE4.so"` 字面量 |
| `.data` | 已初始化全局 | rw- | `int g = 42;` |
| `.bss` | 未初始化全局 | rw- | `int g;`（启动时清零） |
| heap | `malloc` | rw- | 动态分配 |
| mmap | 动态库、共享内存 | 依设置 | `libUE4.so` |
| stack | 局部变量 | rw- | 函数内变量 |

## 权限位：r / w / x

每一页都有权限标记：

| 位 | 含义 | 违反后果 |
|---|---|---|
| r | 可读 | SIGSEGV |
| w | 可写 | SIGSEGV |
| x | 可执行 | SIGSEGV |

**代码段是 `r-x`（不可写），数据段是 `rw-`（不可执行）。**

> [!tip] 一句话记住
> **代码只读、数据不执行**——这就是 W^X（Write XOR Execute）规则。
> 它是现代系统的基本安全机制：防止你把数据当代码执行（缓冲区溢出攻击的核心防线）。

所以：

```c
// 想改代码段 → 崩（main 在代码段，不可写）
*(char*)main = 0x90;      // SIGSEGV

// 想执行栈上的数据 → 崩（stack_buf 是栈上数组，栈页不可执行）
void (*f)() = (void(*)())stack_buf;
f();                       // SIGSEGV（除非该页允许执行）
```

> [!note] 这两行是"示意"，跑不起来
> `main` 是函数、`stack_buf` 只是个假设的栈数组——**它们只是用来说明"违反权限会崩"**，不是可运行的代码。
> 真正想验证，看上面的权限表和 `/proc/self/maps` 输出即可。

## 用 /proc 亲眼看见布局

每个进程在 `/proc/<pid>/maps` 里暴露自己的完整内存映射：

```bash
cat /proc/self/maps
```

输出（节选，已简化）：

```
556b8a2000-556b8a3000 r--p 00000000 fc:00 1234  /usr/bin/cat
556b8a3000-556b8a9000 r-xp 00001000 fc:00 1234  /usr/bin/cat     ← 代码段
556b8aa000-556b8ab000 r--p 00007000 fc:00 1234  /usr/bin/cat     ← rodata
556b8ac000-556b8ad000 rw-p 00008000 fc:00 1234  /usr/bin/cat     ← data/bss
556b9c4000-556b9e5000 rw-p 00000000 00:00 0     [heap]            ← 堆
7f8c4a0000-7f8c4b2000 r-xp 00000000 fc:00 5678  /lib/libc.so.6   ← 动态库代码
7f8c4b2000-7f8c4b3000 rw-p 00111000 fc:00 5678  /lib/libc.so.6   ← 动态库数据
7ffd3e1000-7ffd402000 rw-p 00000000 00:00 0     [stack]           ← 栈
```

每行格式：

```
起始地址-结束地址  权限  文件偏移  设备   inode   路径
```

| 字段 | 含义 |
|---|---|
| `556b8a3000-556b8a9000` | 虚拟地址区间（半开区间，结束地址不含） |
| `r-xp` | 权限；最后一位 `p`=私有、`s`=共享 |
| `00001000` | 该段在文件里的偏移 |
| `fc:00` | 设备号 |
| `1234` | inode（0 表示匿名内存） |
| `/usr/bin/cat` | 映射的文件；`[heap]`/`[stack]` 为匿名 |

> [!tip] 本项目就靠解析这个文件
> `SysHal::get_module_base()` 读 `/proc/pid/maps`，找到包含模块名的那一行，
> 取起始地址作为模块基址。第 76 章你会亲手实现它。
> 同理，`MemDriver::GetScanRegions()` 在系统调用模式下也是解析 maps 得到可扫描区间。

## 模块基址与偏移

动态库被加载时，起始地址（基址）每次可能不同（ASLR），但**库内部的相对偏移是固定的**。

```
libUE4.so 基址 = 0x7a10000000（每次可能不同）
某个全局变量在库内的偏移 = 0xB3EC650（编译期就定死了）

实际地址 = 基址 + 偏移 = 0x7a1B3EC650
```

这就是本项目所有 `libUE4 + 0xB3EC650` 的由来。**偏移是静态的，基址是动态的。**

```cpp
uint64_t moduleBase = 0;
dr->GetModuleAddress("libUE4.so", 0, &moduleBase, true);   // 先拿基址
uint64_t Uworld = dr->Read<uint64_t>(moduleBase + 0xB3EC650);  // 再加偏移
```

## 为什么有的地址"看着就不对"

第 89 章会讲合法性过滤，这里先给直觉：

```cpp
static bool IsValidObject(uint64_t address) {
    return address > 0x10000000ULL && address < 0x10000000000ULL &&
           (address % 4) == 0;
}
```

三条判据的根据：

| 判据 | 依据 |
|---|---|
| `> 0x10000000`（256MB） | 合法堆/库地址远高于此；极小的地址通常是"读取失败返回的 0 + 偏移" |
| `< 0x10000000000`（1TB） | Android 用户空间上限在这个量级（VA_BITS 通常 39~48） |
| `% 4 == 0` | 指针至少 4 字节对齐；奇数地址必然是错的 |

这些不是随便写的数字，是从"地址空间布局的合理范围"推出来的。

> [!note] 这段代码用到的文件函数，第 22 章会详讲
> 下面的练习用到了 `fopen` / `fgets` / `fclose`——**C 标准库的按行读文件函数**。
> 卷一只讲过 `fopen` 打开文件（第 11 章"文件读写基础"），这里补上"按行读"：
> ```c
> FILE *fp = fopen("/proc/self/maps", "r");   // 打开文件
> char line[1024];
> while (fgets(line, sizeof(line), fp)) {     // 每次读一行
>     printf("%s", line);
> }
> fclose(fp);                                  // 关闭
> ```
> **`fgets(buf, size, fp)` 一次读一行**（最多 `size-1` 个字符），读到文件末尾返回 `NULL`，循环自然退出。
> 这是"按行读文本文件"的标准写法，第 22 章会系统讲解文件 IO。**这里先照抄即可。**
