# 第 23 章 · 进程间通信概览

> [!abstract] 本章目标
> 知道 6 种主流 IPC 各自的代价和适用场合，
> 并理解本项目为什么选"共享内存 + 轮询标志"而不是别的。

## 先看问题

两个进程，各自的虚拟地址空间完全隔离。要传数据，必须**借助内核**——
因为只有内核同时看得到两边的内存。

```
进程 A  ──┐
          ├──→  内核（中转）  ──→  进程 B
进程 B  ──┘
```

所有 IPC 机制的区别，就是"内核怎么中转"。

## 六种方式对比

| 方式 | 数据拷贝次数 | 需要内核配合 | 典型延迟 | 适合传什么 |
|---|---|---|---|---|
| 管道 pipe | 2 | 是 | ~µs | 字节流 |
| 信号 signal | 0 | 是 | ~µs | 一个编号 |
| 消息队列 | 2 | 是 | ~µs | 小消息 |
| 共享内存 shm | **0** | 建立时需要 | **~ns** | 大数据 |
| socket | 2~4 | 是 | ~10µs | 跨机器 |
| ptrace | 2 | 是 | ~µs | 调试/读写 |

**关键指标是"拷贝次数"：每次拷贝都要 CPU 搬运字节，数据量大时代价极高。**

## 管道

```c
int fd[2];
pipe(fd);            // fd[0]=读端  fd[1]=写端

write(fd[1], "hi", 2);
char buf[8];
read(fd[0], buf, 2);
```

单向。双向要开两个管道。
适合父子进程之间的简单通信。

## 信号

```c
kill(pid, SIGUSR1);     // 发一个编号
```

只能传"编号"，不能带数据（实时信号 `SIGRTMIN+n` 可附带一个 int）。
用途有限：通知、中断、退出。

> [!warning] 信号不能传结构体
> 想传复杂数据？用信号只是"敲门"，真正的数据走别的通道（如共享内存）。

## 共享内存：最快

原理：内核让**同一块物理内存**同时映射到两个进程的虚拟地址空间。

```
进程 A 虚拟 0x7000_0000 ─┐
                         ├──→ 物理页 0x1A300000
进程 B 虚拟 0x5000_0000 ─┘
```

两个进程访问各自的虚拟地址，实际上访问的是同一块物理内存。
**零拷贝，延迟就是一次内存访问（~100ns）。**

### POSIX 共享内存

```c
#include <sys/mman.h>
#include <fcntl.h>

// 创建/打开
int fd = shm_open("/my_shm", O_CREAT | O_RDWR, 0666);
ftruncate(fd, 4096);

// 映射进自己的地址空间
void *addr = mmap(NULL, 4096, PROT_READ | PROT_WRITE, MAP_SHARED, fd, 0);

// 直接用
struct MyData *data = (struct MyData*)addr;
data->count = 42;

// 清理
munmap(addr, 4096);
shm_unlink("/my_shm");
```

### 匿名共享内存（本项目用的）

不需要名字，直接要一块：

```c
void *req = mmap((void*)0x2025827000, sizeof(request_obj),
                 PROT_READ | PROT_WRITE,
                 MAP_SHARED | MAP_ANONYMOUS | MAP_FIXED_NOREPLACE,
                 -1, 0);
```

参数拆解：

| 参数 | 值 | 含义 |
|---|---|---|
| addr | `0x2025827000` | 指定映射地址（内核侧约定同一地址） |
| length | `sizeof(request_obj)` | 大小 |
| prot | `PROT_READ\|PROT_WRITE` | 可读写 |
| flags | `MAP_SHARED` | **改动对其他映射者可见**（关键） |
| flags | `MAP_ANONYMOUS` | 不关联文件，内容清零 |
| flags | `MAP_FIXED_NOREPLACE` | 必须映射到指定地址，被占则失败（不覆盖已有映射） |
| fd | `-1` | 匿名映射时填 -1 |

> [!danger] `MAP_FIXED` vs `MAP_FIXED_NOREPLACE`
> `MAP_FIXED`：如果该地址已有映射，**直接覆盖**（可能踩坏堆/栈）。
> `MAP_FIXED_NOREPLACE`：如果已占用，返回 `MAP_FAILED` 而不是覆盖。
> **永远用后者**，本项目就是这么做的。

## 为什么本项目用固定地址

```c
mmap((void *)0x2025827000, ...)
```

内核驱动和用户程序**事先约定好同一个虚拟地址**。
内核在自己的页表里也把这块物理内存映射到 `0x2025827000`。
这样双方用同一个地址值访问同一块内存，连"地址是多少"都不用传。

> [!note] 这是内核驱动的常见技巧
> 因为内核驱动是"外挂"的，不走标准 `shm_open` 流程，
> 约定固定地址是最简单的双方对齐方式。
> 缺点：如果地址被别的映射占用，整个方案失效（所以用 `NOREPLACE` 检测）。

## 有了共享内存，还需要通知对方

共享内存解决了"数据放哪"，但没解决"什么时候来看"。

三种通知方式：

| 方式 | 做法 | 代价 |
|---|---|---|
| 轮询 | 死循环检查标志位 | 占 CPU，但延迟最低 |
| futex | 内核协助的休眠/唤醒 | 不占 CPU，切换有开销 |
| 信号/eventfd | 内核发通知 | 有系统调用开销 |

**本项目选轮询**：

```c
inline void IoCommitAndWait() {
    req->kernel = true;                  // 告诉内核：有新请求
    while (!req->user) {                 // 等内核处理完
        asm volatile("yield");           // 提示 CPU：我在自旋，可以让出
    }
    req->user = false;                   // 消费掉完成标志
}
```

`asm volatile("yield")` 是 ARM64 的提示指令：
告诉 CPU"这是自旋等待"，让它降低功耗、避免流水线惩罚。
比空转 `while(1);` 文明得多。

> [!question] 为什么不用 futex 或信号？
> 因为驱动的请求-响应是**同步的、高频的、极短的**：
> 一次内存读请求可能只要几微秒。
> 用 futex 的话，光"休眠+唤醒"的开销就比处理本身还大。
> 轮询在"等待时间极短"时是最优解。

## volatile：必须的修饰符

```c
volatile bool kernel;   // 由用户模式设置
volatile bool user;     // 由内核模式设置
```

`volatile` 告诉编译器："这个变量可能被别人改，**不要把它缓存到寄存器里**"。

不加会怎样？

```c
// 编译器看到循环里没改 flag，可能优化成：
if (req->user) { ... }        // 只读一次！
while (1);                    // 死循环
```

这是多线程/共享内存编程的经典陷阱。本项目 `request_obj` 里的
`kernel`、`user`、`op`、`status` 四个字段全是 `volatile`。

> [!warning] volatile 不保证原子性
> 它只保证"每次都从内存读"，不保证"读-改-写"不可分割。
> 真正的原子操作要用 `__atomic_*` 或 `std::atomic`（第 82 章）。
> 本项目用 `SpinLock` 保护整个请求结构，`volatile` 只用于标志位。

## socket：跨进程也跨机器

```c
// Unix domain socket（本机）
int s = socket(AF_UNIX, SOCK_STREAM, 0);
```

Android 上 Binder 是主流（App 间通信），但原生层用 socket 更简单。
延迟比共享内存高一个数量级，胜在通用。

## ptrace：调试用的读写

```c
ptrace(PTRACE_ATTACH, pid, 0, 0);
long data = ptrace(PTRACE_PEEKDATA, pid, addr, 0);
ptrace(PTRACE_DETACH, pid, 0, 0);
```

能读写目标进程内存，但：
- 一次只能读一个字（4/8 字节），读 1KB 要 128~256 次调用
- 会**暂停目标进程**（有明显卡顿）
- 目标进程能检测到被 ptrace

**所以本项目不用 ptrace，用 `process_vm_readv`**（不停进程、可批量）。

## 选型决策树

```
需要传大量数据？
├─ 是 → 共享内存
│        └─ 需要通知？
│           ├─ 等待极短（µs级）→ 轮询 + yield
│           └─ 等待较长 → futex / eventfd
└─ 否 → 传少量控制信息
         ├─ 父子进程 → pipe
         ├─ 只是通知 → signal
         └─ 通用/跨机器 → socket

需要读写别的进程内存？
├─ 批量、不停进程 → process_vm_readv
├─ 需要硬件断点等高级功能 → 内核驱动 + 共享内存
└─ 调试场景 → ptrace
```

## 本项目的最终选择

```
用户态程序  ←──共享内存 @0x2025827000──→  内核驱动
              （请求-响应，volatile 标志 + yield 轮询）

或者（无内核时）：
用户态程序  ──process_vm_readv 系统调用──→  内核  ──→  目标进程内存
```

两条路都被 `IDriver` 接口包住（第 80 章），业务代码不用关心走哪条。

## 动手：双进程共享内存

写两个程序：writer 创建共享内存并写一个结构体，reader 读出来。

```c
// common.h
#include <stdint.h>
typedef struct {
    volatile int  ready;
    int32_t       count;
    float         values[4];
} SharedData;
#define SHM_PATH "/klbq_test_shm"
#define SHM_SIZE sizeof(SharedData)
```

```c
// writer.c
#include <stdio.h>
#include <fcntl.h>
#include <sys/mman.h>
#include <unistd.h>
#include <string.h>
#include "common.h"

int main(void) {
    int fd = shm_open(SHM_PATH, O_CREAT | O_RDWR, 0666);
    ftruncate(fd, SHM_SIZE);
    SharedData *d = mmap(NULL, SHM_SIZE, PROT_READ|PROT_WRITE, MAP_SHARED, fd, 0);

    d->ready = 0;
    d->count = 4;
    for (int i = 0; i < 4; i++) d->values[i] = i * 1.5f;
    d->ready = 1;                    // 最后置位（发布语义）

    printf("写完了，ready=%d，等 reader...\n", d->ready);
    getchar();
    munmap(d, SHM_SIZE);
    shm_unlink(SHM_PATH);
    return 0;
}
```

```c
// reader.c
#include <stdio.h>
#include <fcntl.h>
#include <sys/mman.h>
#include "common.h"

int main(void) {
    int fd = shm_open(SHM_PATH, O_RDWR, 0666);
    SharedData *d = mmap(NULL, SHM_SIZE, PROT_READ|PROT_WRITE, MAP_SHARED, fd, 0);

    while (!d->ready) { __builtin_ia32_pause(); }   // x86；ARM64 用 asm("yield")

    printf("count=%d\n", d->count);
    for (int i = 0; i < d->count; i++)
        printf("  values[%d] = %.2f\n", i, d->values[i]);
    munmap(d, SHM_SIZE);
    return 0;
}
```

编译（Linux/WSL 需要 `-lrt`）：

```bash
gcc writer.c -o writer -lrt
gcc reader.c -o reader -lrt
./writer &      # 后台运行
./reader        # 应读出数据
```

**注意 `d->ready = 1` 写在最后**——这叫"发布（publish）"：
先填好所有数据，最后才置标志位。反过来会读到半截数据。
