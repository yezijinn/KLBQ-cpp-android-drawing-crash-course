# 第 25 章 · ARM64 寄存器与调用约定

> [!abstract] 本章目标
> 能读懂简单的 ARM64 汇编，知道参数怎么传、返回值放哪、栈怎么用。
> 这是第 30 章（反汇编）、第 87 章（找特征码）的必要基础。
>
> [!important] 别怕，你只需要看懂 5 条指令
> 汇编看着吓人，但**本章不要求你会写汇编**，只要求"看到能认出"。核心就 5 条：
>
> | 指令 | 一眼认出它是 | 出现在 |
> |---|---|---|
> | `stp x29, x30, [sp, #-N]!` | **函数开头**（保存寄存器、开栈帧） | 每个函数序言 |
> | `ldp x29, x30, [sp], #N` | **函数结尾**（恢复、关栈帧） | 每个函数尾声 |
> | `bl xxx` | **调用一个函数** | 任何函数调用处 |
> | `ret` | **返回** | 函数末尾 |
> | `ldr x0, [x1, x2, lsl #3]` | **访问指针数组**（`arr[i]`，×8 因为 64 位） | 遍历数组处 |
>
> 其余的寄存器表、寻址模式、调用约定，**当字典查**，不用背。

## 先看一段真实的 ARM64 汇编

写一个简单的 C 函数：

```c
int add3(int a, int b, int c) {
    return a + b + c;
}
```

编译成汇编（`aarch64-linux-android-gcc -S`，或本地 `gcc -S`）：

```bash
aarch64-linux-android21-clang -S -O1 add.c -o add.s
```

输出：

```asm
add3:
        add     w0, w0, w1      // w0 = a + b
        add     w0, w0, w2      // w0 = w0 + c
        ret                     // 返回，结果在 w0
```

三行。参数 `a,b,c` 分别在 `w0,w1,w2`，结果直接写回 `w0`。

## ARM64 寄存器表

| 寄存器 | 位宽写法 | 用途 |
|---|---|---|
| `x0` ~ `x7` | `x`=64位, `w`=32位 | **第 1~8 个参数** / 返回值 |
| `x0` | | **返回值**（也用于 x0 返回） |
| `x8` | | 间接结果位置 / 系统调用号 |
| `x9` ~ `x15` | | 临时寄存器（调用者无需保存） |
| `x16`, `x17` | | 内部过程调用暂存（PLT 用） |
| `x18` | | 平台寄存器（保留） |
| `x19` ~ `x28` | | **被调用者保存**（用了要恢复） |
| `x29` (FP) | | 帧指针 |
| `x30` (LR) | | **链接寄存器：存返回地址** |
| `sp` | | 栈指针 |
| `xzr` / `wzr` | | 恒零寄存器（读恒为 0） |
| `pc` | | 程序计数器 |

浮点：

| 寄存器 | 用途 |
|---|---|
| `v0` ~ `v7` | 浮点参数 / 返回值 |
| `v8` ~ `v15` | 被调用者保存（低 64 位） |
| `v0`~`v31` | 128 位，可作 `s`(32)/`d`(64)/`q`(128) |

> [!note] `w0` 和 `x0` 是同一个寄存器的不同视图
> ```
> x0: 64 位  [================]
> w0: 低 32 位[========]        写 w0 会把 x0 高 32 位清零
> ```

## AArch64 调用约定（AAPCS64）

**1. 参数传递**
- 前 8 个整数/指针参数 → `x0` ~ `x7`
- 前 8 个浮点参数 → `v0` ~ `v7`
- 超过 8 个 → 用栈传

```c
void f(int a, int b, int c, int d, int e, int g, int h, int i, int j);
//     x0   x1   x2   x3   x4   x5   x6   x7   →j 走栈
```

**2. 返回值**
- 整数/指针 → `x0`（128 位用 `x0:x1`）
- 浮点 → `v0`

**3. 寄存器保存责任**

| 寄存器 | 谁负责保存 |
|---|---|
| `x0`~`x7`, `x9`~`x15` | **调用者**（caller-saved）：调用前自己备份 |
| `x19`~`x28`, `x29`, `x30` | **被调用者**（callee-saved）：函数用了就要恢复 |

看一个用到 `x19` 的函数：

```asm
myfunc:
        stp     x19, x30, [sp, #-32]!    // 把 x19 和 x30(LR) 压栈
        mov     x19, x0                  // 用 x19 存第一个参数
        /* ... 使用 x19 ... */
        ldp     x19, x30, [sp], #32      // 恢复
        ret
```

`stp` = store pair，`ldp` = load pair。`[sp, #-32]!` 是"先减 sp 再存"（预索引）。

**这是识别函数开头/结尾的标志**：看到 `stp x29, x30, [sp, #-N]!` 就是函数序言。

## 常用指令速查

| 指令 | 含义 | 例子 |
|---|---|---|
| `mov` | 传送 | `mov x0, #42` |
| `movz/movk` | 构造大立即数 | `movz x0, #0x1234` |
| `add/sub` | 加减 | `add x0, x0, #8` |
| `ldr` | 从内存加载 | `ldr x0, [x1, #0x10]` |
| `str` | 存到内存 | `str x0, [sp, #8]` |
| `ldp/stp` | 加载/存储一对 | `stp x29, x30, [sp, #-16]!` |
| `b` | 无条件跳转 | `b label` |
| `bl` | 跳转并链接（**调用函数**） | `bl printf` |
| `blr` | 跳转到寄存器地址 | `blr x8` |
| `ret` | 返回（跳到 x30） | `ret` |
| `cbz/cbnz` | 比较为0/非0则跳 | `cbz x0, label` |
| `cmp` + `b.eq` | 比较后条件跳 | `cmp x0, #0` / `b.eq label` |
| `svc #0` | **系统调用** | `svc #0` |
| `yield` | 自旋提示 | `yield` |

## 寻址模式

```asm
ldr x0, [x1]              // x0 = *(x1)
ldr x0, [x1, #8]          // x0 = *(x1 + 8)        立即数偏移
ldr x0, [x1, x2]          // x0 = *(x1 + x2)       寄存器偏移
ldr x0, [x1, x2, lsl #3]  // x0 = *(x1 + x2*8)     带移位的偏移 ← 数组访问！
ldr x0, [x1, #8]!         // x1 += 8; x0 = *x1     前索引
ldr x0, [x1], #8          // x0 = *x1; x1 += 8     后索引
```

**`lsl #3`（左移 3 位 = ×8）就是数组下标计算**——看到它基本就是在访问指针数组：

```c
uint64_t elem = arr[i];      // arr 是 uint64_t*
```
```asm
ldr x0, [x1, x2, lsl #3]
```

本项目遍历 Actor 数组的代码，编译后就是这样。

## 读一个完整的函数

```c
int clamp_to(int v, int max) {
    if (v > max) return max;
    return v;
}
```

```asm
clamp_to:
        cmp     w0, w1              // 比较 v 和 max
        csel    w0, w1, w0, gt      // 条件选择：v > max ? max : v
        ret
```

`csel`（conditional select）是 ARM 的特色指令：避免分支跳转，比 `if` 高效。

再一个带循环的：

```c
int sum(int *arr, int n) {
    int s = 0;
    for (int i = 0; i < n; i++) s += arr[i];
    return s;
}
```

```asm
sum:
        mov     w2, 0               // s = 0
        mov     w3, 0               // i = 0
        b       .Lcheck
.Lloop:
        ldr     w4, [x0, w3, sxtw #2]   // w4 = arr[i]  (×4 因为 int)
        add     w2, w2, w4              // s += arr[i]
        add     w3, w3, 1               // i++
.Lcheck:
        cmp     w3, w1                  // i < n ?
        b.lt    .Lloop                  // 是则继续循环
        mov     w0, w2                  // 返回值放 w0
        ret
```

## 系统调用的汇编

```c
syscall(270, pid, local, 1, remote, 1, 0);
```

```asm
mov     x8, #270            // 调用号放 x8
mov     x0, pid             // 第1参数
mov     x1, local           // 第2参数
mov     x2, #1
mov     x3, remote
mov     x4, #1
mov     x5, #0
svc     #0                  // 触发系统调用
// 返回值在 x0
```

**系统调用号放 `x8`，不是 `x0`。** 这是 ARM64 的约定（x86-64 是放 `rax`）。

本项目用 C 的 `syscall()` 函数，编译后就是这段。

## 栈帧结构

```asm
myfunc:
        stp     x29, x30, [sp, #-48]!   // 保存 FP 和 LR，开 48 字节栈帧
        mov     x29, sp                  // 新 FP = 当前 SP
        stp     x19, x20, [sp, #16]      // 保存 callee-saved 寄存器
        /* 函数体 */
        ldp     x19, x20, [sp, #16]      // 恢复
        ldp     x29, x30, [sp], #48      // 恢复 FP/LR 并释放栈帧
        ret
```

栈帧图：

```
高地址
        ┌──────────────┐
 x29→   │  上一个 x29   │
        │  返回地址 x30 │
        ├──────────────┤
        │   x19        │
        │   x20        │
        ├──────────────┤
        │  局部变量     │
 sp→    └──────────────┘
低地址
```

**每个栈帧都记着上一个 x29**——这就是调用栈（backtrace）能还原出来的原因（第 08 章）。

## 帧指针省略（-fomit-frame-pointer）

优化编译时，编译器可能不维护 `x29`，导致无法回溯调用栈。

| 选项 | 影响 |
|---|---|
| 默认（-O2） | 常省略 FP，栈回溯困难 |
| `-fno-omit-frame-pointer` | 保留 FP，便于调试和性能剖析 |

本项目 `Application.mk` 里有 `-funwind-tables`——它生成独立的 unwind 表，
即使没有 FP 也能回溯栈。**这是崩溃分析的关键选项。**

> [!note] `objdump -d` 是反汇编工具（第 20 章提过，第 30 章详讲）
> `objdump -d <文件>` 会把二进制里的机器码**翻译回汇编指令**。
> ```bash
> objdump -d add | head -40    # 反汇编 add 可执行文件，只看前 40 行
> ```
> 输出左边是地址、中间是机器码字节、右边是汇编指令。**本章看汇编全靠它。**

## 常见混淆点

| 混淆 | 真相 |
|---|---|
| `x30` 和 `lr` | 同一个寄存器，两种叫法 |
| `w0` 和 `x0` | 同一寄存器，32位视图 vs 64位视图 |
| `mov` vs `ldr` | `mov` 传立即数/寄存器，`ldr` 从内存加载 |
| `b` vs `bl` | `b` 纯跳转，`bl` 会把返回地址写入 `x30` |
| `ret` | 等价于 `mov pc, x30`（但不完全等价） |
