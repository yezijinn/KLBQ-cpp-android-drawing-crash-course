# 第 49 章 · 相机与视图矩阵

> [!abstract] 本章目标
> 理解"把世界变成以相机为中心"的变换，
> 并读懂本项目 `camMakeMatrix` 里那 12 个矩阵元素的来历。

## 先看问题

世界里有 1000 个物体，每个都有自己的世界坐标。
要画到屏幕上，需要知道**从相机的视角看，它们在哪**。

这就是视图矩阵（View Matrix）的工作：

```
世界坐标  ──[视图矩阵]──→  相机空间坐标
                          （相机在原点，朝 +X 看）
```

## 先搞清：左手系 vs 右手系

> [!note] 左手系 vs 右手系
> 3D 坐标系有两种约定，最直观的区别是 **Z 轴朝哪**（假设 X 向右、Y 向上）：
> - **右手系**：Z **朝屏幕外**（朝向你）。OpenGL、数学教材常用。
> - **左手系**：Z **朝屏幕里**（远离你）。**DirectX、UE4、本项目**用这个。
>
> 怎么记：右手系伸出右手，拇指 X、食指 Y，中指自然指向 Z（朝你）；左手系同理用左手。
>
> **注意：上面只是"手系"的通用定义，UE4 的具体轴是另一套**——
> UE4 用 **X 前、Y 右、Z 上**（第 47 章讲过），不是"X 右、Y 上、Z 里"。
> 手系决定了"哪个方向是正"，UE4 的具体轴决定"哪个轴叫什么名字"，
> 两者叠加才是本项目实际用的坐标系：**左手系 + (X 前, Y 右, Z 上)**。
>
> **为什么会影响公式**：叉积结果的朝向、旋转正方向、视图矩阵的符号都随手系变。
> **本项目所有公式都是 UE4 这套下的，别照抄 OpenGL 教程（那是右手系）。**

## 相机的三个属性

```cpp
struct MinimalViewInfo {
    Vec3    Location;    // 相机在哪
    Rotator Rotation;    // 朝哪看
    float   FOV;         // 视野角度
};
```

本项目每帧从内存读这三项：

```cpp
dr->Read(玩家相机 + 0x2300, &相机位置, sizeof(相机位置));
dr->Read(玩家相机 + 0x230C, &相机旋转, sizeof(相机旋转));
相机FOV = dr->Read<float>(玩家相机 + 0x2318);
```

## 相机空间（View Space）

约定（UE4 / 本项目）：

```
相机在原点 (0,0,0)
朝 +X 看（前）
+Y 是右
+Z 是上
```

把一个世界点转到相机空间，做两件事：

1. **平移**：把相机移到原点 → 减去相机位置
2. **旋转**：把相机朝向摆正 → 乘以相机旋转的逆

```
v_view = R⁻¹ × (v_world - C)
         ↑        ↑
      旋转的逆   平移
```

因为旋转矩阵是正交的，**逆 = 转置**（第 46 章）。

## 从旋转矩阵构造相机基向量

第 47 章讲过，`rotatorToMatrix` 的三行是：

```
第 0 行 = 前 (Forward)   = (CP*CY,     CP*SY,     SP   )
第 1 行 = 右 (Right)     = (SR*SP*CY - CR*SY, ...)
第 2 行 = 上 (Up)        = (...)
```

本项目为了简化，**只用 Pitch 和 Yaw**（忽略 Roll），
于是三个基向量可以手写：

```cpp
float sp = sinf(pitch), cp = cosf(pitch);
float sy = sinf(yaw),   cy = cosf(yaw);

// 前方向
forward = (cy*cp, sy*cp, sp);

// 右方向（前方向绕 Z 转 90 度）
right   = (-sy, cy, 0);

// 上方向（垂直于前、右，可由叉积得到，详见下方说明）
up      = (-sp*cy, -sp*sy, cp);
```

本项目**不直接算 up**，而是利用一个几何事实：**up 一定垂直于 right 和 forward**，
所以它可以用 cross 求出来（谁叉乘谁见下方说明）。

先看本项目实际写进矩阵的值（代码里直接给出结果）：

```cpp
matrix[1]  = (-sp * cy) / t;
matrix[5]  = (-sp * sy) / t;
matrix[9]  = (cp)       / t;
```

即 `up = (-sp*cy, -sp*sy, cp)`。用它验证两个极端情况：

| 情况 | 代入 | 结果 | 是否符合直觉 |
|---|---|---|---|
| pitch=0（平视） | up=(-0, -0, 1) | (0,0,1) | ✓ 正上方 |
| pitch=90°（抬头看天） | up=(-cy, -sy, 0) | 水平向后 | ✓ 抬头时"上"变成水平向后 |

> [!note] 怎么自己记住 up 公式
> up 同时垂直于 right 和 forward，所以它等于这两者的**叉积**。
> 用第 45 章给的叉积公式（`a.y*b.z - a.z*b.y` 那套），
> 把 `a = forward = (cy*cp, sy*cp, sp)`、`b = right = (-sy, cy, 0)` 代进去，逐分量算：
> ```
> up.x = forward.y*right.z - forward.z*right.y
> up.y = forward.z*right.x - forward.x*right.z
> up.z = forward.x*right.y - forward.y*right.x
> ```
> 化简后正好是 `(-sp*cy, -sp*sy, cp)`，和代码写的一致。
> 记住结论 `up = (-sp*cy, -sp*sy, cp)` 即可；
> 不确定符号时，用两个极端情况（pitch=0 得 (0,0,1)、pitch=90° 得水平向后）代入验证。

## 视图矩阵的三个行向量

把旋转的逆（= 转置）写出来，视图矩阵的旋转部分是：

```
┌                    ┐
│ forward.x  forward.y  forward.z │   ← 第 0 行 = 前
│ right.x    right.y    right.z   │   ← 第 1 行 = 右（本项目的 y 行）
│ up.x       up.y       up.z      │   ← 第 2 行 = 上
└                    ┘
```

为什么是转置？因为：

```
v_view.x = dot(forward, v_world - C)
v_view.y = dot(right,   v_world - C)
v_view.z = dot(up,      v_world - C)
```

**投影到基向量上 = 点积 = 矩阵的行乘以向量。**

> [!note] 这是"数学理想版"，本项目源码把行的顺序换了
> 上面把前/右/上放在第 0/1/2 行，是**数学上最标准的排列**，
> 好处是 `v_view = (前向, 右向, 上向)` 一眼对应。
>
> 但本项目源码**把三行的顺序重新排了**（见下文"矩阵元素的排布"）：
> 右、上放在第 0/1 行，**前向被放到第 3 行（最底）**。
> 为什么这么排？因为 W2S 里**先要算深度 `w`**（= 前向点积），
> 把前向放在最后一行、用一个独立的 `w = matrix[3]*x + ...` 就能取出深度，代码更简洁。
>
> **两处说的其实是同一件事**——都是"把世界点投到前/右/上三个基向量上"，
> 只是行号摆放不同。读源码时以第 3 行为前向即可。

## 平移项

```
v_view.x = dot(forward, v_world) - dot(forward, C)
                                   ↑ 这个常数就是平移项
```

这个平移项落到数组里，就是深度行最后那个元素 `matrix[15]`：

```cpp
matrix[3]  = cy * cp;                                    // forward.x
matrix[7]  = sy * cp;                                    // forward.y
matrix[11] = sp;                                         // forward.z
matrix[15] = -(camX * matrix[3] + camY * matrix[7] + camZ * matrix[11]);
//            ↑ -dot(forward, C)
```

**`matrix[15]` 就是 `-dot(forward, 相机位置)`**。

### 横向、纵向也有各自的平移项

同样的道理，right 行和 up 行也各有自己的平移项。因为视图矩阵的三行分别是
"把世界点投影到 forward / right / up 三个基向量上"，所以每一行都要**减去相机在这一基向量上的投影**：

```
v_view.x（深度）= forward·v - forward·C   → 平移项 -forward·C 落在 matrix[15]
v_view.y（横向）= right·v   - right·C     → 平移项 -right·C   落在 matrix[12]
v_view.z（纵向）= up·v      - up·C        → 平移项 -up·C      落在 matrix[13]
```

注意：源码里横向、纵向的**整行**都除以了 `t`（投影缩放），所以它们的平移项也带着 `/ t`：

```cpp
// right 行 = (-sy, cy, 0)，整行 / t
matrix[12] = -(camX*(-sy) + camY*cy) / t;              // = -right·C / t
// up 行 = (-sp*cy, -sp*sy, cp)，整行 / t
matrix[13] = -(camX*(-sp*cy) + camY*(-sp*sy) + camZ*cp) / t;  // = -up·C / t
```

而深度行（forward）**不除 t**（深度不需要投影缩放），所以它的平移项 `matrix[15]` 是干净的 `-forward·C`。
这解释了为什么三行的平移项一个带 `/ t`、一个不带——**跟着各自的行走**。

## 本项目的 camMakeMatrix（逐行）

> [!note] 源码摘录
> 下面这段用了项目里的全局 `matrix[16]`、`MinimalViewInfo`、`PI`，**不能单独编译**。
> 本章"动手"那块才是自包含、可运行的版本。

```cpp
static inline void camMakeMatrix(const MinimalViewInfo& camViewInfo) {
    if (camViewInfo.FOV < 1.0f || camViewInfo.FOV > 179.0f) return;   // ①
    float camX = camViewInfo.Location.x;
    float camY = camViewInfo.Location.y;
    float camZ = camViewInfo.Location.z;
    if (camX == 0.0f && camY == 0.0f && camZ == 0.0f) return;         // ②
    if (camX != camX || camY != camY || camZ != camZ) return;          // ③

    float pitch = camViewInfo.Rotation.Pitch * PI / 180.0f;
    float yaw   = camViewInfo.Rotation.Yaw   * PI / 180.0f;
    float sp = sinf(pitch), cp = cosf(pitch);
    float sy = sinf(yaw),   cy = cosf(yaw);

    float t = tanf(camViewInfo.FOV * 0.5f * PI / 180.0f);              // ④
    if (t == 0.0f) t = 0.0001f;

    // 深度行（forward）
    matrix[3]  = cy * cp;
    matrix[7]  = sy * cp;
    matrix[11] = sp;
    matrix[15] = -(camX*matrix[3] + camY*matrix[7] + camZ*matrix[11]);

    // x 行（right）÷ t
    matrix[0]  = -sy / t;
    matrix[4]  =  cy / t;
    matrix[8]  =  0.0f;
    matrix[12] = -(camX*(-sy) + camY*cy) / t;

    // y 行（up）÷ t
    matrix[1]  = (-sp*cy) / t;
    matrix[5]  = (-sp*sy) / t;
    matrix[9]  = (cp)     / t;
    matrix[13] = -(camX*(-sp*cy) + camY*(-sp*sy) + camZ*cp) / t;

    // 未用
    matrix[2] = matrix[6] = matrix[10] = matrix[14] = 0.0f;
}
```

四处防御性检查：

| # | 检查 | 防什么 |
|---|---|---|
| ① | FOV 在 1~179 度 | FOV=0 会导致除零 |
| ② | 相机位置不全为 0 | 读到空数据（刚进游戏/切场景） |
| ③ | `x != x` 判断 NaN | NaN 是唯一不等于自己的值（第 26 章） |
| ④ | `t == 0` 兜底 | tan(极小角) 可能下溢为 0 |

> [!tip] `x != x` 判断 NaN 是标准技巧
> IEEE754 规定 NaN 与任何值（包括自己）比较都为 false。
> 也可以用 `std::isnan(x)`，更清晰。本项目用了前者。

### 矩阵元素的排布

本项目用**一维数组 `matrix[16]`**，采用"列主序存储、行主序数学"。
注意这里**把前向放到了最后一行**（和上面"数学理想版"的顺序不同，原因见上）：

```
matrix[0], matrix[4], matrix[8],  matrix[12]   ← right 行（行下标 0）
matrix[1], matrix[5], matrix[9],  matrix[13]   ← up 行  （行下标 1）
matrix[2], matrix[6], matrix[10], matrix[14]   ← 未用  （行下标 2）
matrix[3], matrix[7], matrix[11], matrix[15]   ← forward / 深度行（行下标 3）
```

即 `matrix[row + col*4]`——**同一行的元素在数组里相隔 4**。

> [!note] "行下标 3"和前面说的"第 4 行"是同一个东西
> 本章用**行下标（从 0 数）**：0、1、2、3。
> 第 46~48 章说"平移在**第 4 行**"用的是**从 1 数**的日常说法。
> 两者指的是**同一行**（数组下标 `3,7,11,15`），只是数法不同，不要以为是两行。

使用时（第 50 章会看到）：

```cpp
float w = matrix[3]*obj.X + matrix[7]*obj.Y + matrix[11]*obj.Z + matrix[15];
```

用的正是这一"深度行"（行下标 3）。

> [!warning] 这段代码的注释与实现容易混淆
> 源码注释写的是"行布局(列主序存储)"，
> 实际访问方式是 `matrix[i + j*4]`（j 是列），即**列主序存储**。
> 读代码时记住：`matrix[3]`、`matrix[7]`、`matrix[11]`、`matrix[15]`
> 共同构成数学意义上的深度行（行下标 3，即上面说的"第 4 行"）。

### 除以 t 是什么意思？

```cpp
matrix[0] = -sy / t;
```

`t = tan(FOV/2)` 是投影缩放因子。
**这里把投影矩阵合并进了视图矩阵**——一步到位得到"视图×投影"矩阵。

第 50 章会解释 `t` 的几何意义。

## 为什么本项目忽略 Roll

Roll（翻滚）在 FPS 游戏里几乎不用（画面不会歪）。
忽略它能：
- 简化计算（少一次三角函数）
- 避免万向节死锁的边界情况

代价：如果游戏有载具翻滚等场景，投影会略有偏差。

## 动手：手算一个视图矩阵

```cpp
#include <cstdio>
#include <cmath>
#include <cassert>

constexpr float PI = 3.14159265358979323846f;
float matrix[16] = {};

void camMakeMatrix(float camX, float camY, float camZ,
                   float pitchDeg, float yawDeg, float fovDeg) {
    float pitch = pitchDeg * PI / 180.0f;
    float yaw   = yawDeg   * PI / 180.0f;
    float sp = sinf(pitch), cp = cosf(pitch);
    float sy = sinf(yaw),   cy = cosf(yaw);
    float t  = tanf(fovDeg * 0.5f * PI / 180.0f);
    if (t == 0.0f) t = 0.0001f;

    matrix[3]  = cy*cp;  matrix[7]  = sy*cp;  matrix[11] = sp;
    matrix[15] = -(camX*matrix[3] + camY*matrix[7] + camZ*matrix[11]);

    matrix[0]  = -sy/t;  matrix[4]  = cy/t;   matrix[8]  = 0.0f;
    matrix[12] = -(camX*(-sy) + camY*cy) / t;

    matrix[1]  = (-sp*cy)/t; matrix[5] = (-sp*sy)/t; matrix[9] = cp/t;
    matrix[13] = -(camX*(-sp*cy) + camY*(-sp*sy) + camZ*cp) / t;

    matrix[2] = matrix[6] = matrix[10] = matrix[14] = 0.0f;
}

// 返回相机空间深度（>0 表示在相机前方）
float depth(float x, float y, float z) {
    return matrix[3]*x + matrix[7]*y + matrix[11]*z + matrix[15];
}

int main(void) {
    // 相机在原点，朝 +X（pitch=0, yaw=0），FOV=90
    camMakeMatrix(0, 0, 0, 0, 0, 90);

    printf("正前方 10 米处深度 = %.2f\n", depth(10, 0, 0));    // 期望 10
    printf("正右方 10 米处深度 = %.2f\n", depth(0, 10, 0));    // 期望 0
    printf("正后方 10 米处深度 = %.2f\n", depth(-10, 0, 0));   // 期望 -10

    assert(fabsf(depth(10,0,0) - 10.0f) < 1e-4f);
    assert(fabsf(depth(0,10,0)) < 1e-4f);          // 侧面深度为 0
    assert(fabsf(depth(-10,0,0) + 10.0f) < 1e-4f); // 后方为负

    // 相机移到 (100,0,0)，同一点的相对深度应变小
    camMakeMatrix(100, 0, 0, 0, 0, 90);
    printf("相机移到(100,0,0)后，(110,0,0) 深度 = %.2f\n", depth(110,0,0));
    // 期望 10（相对距离没变）
    assert(fabsf(depth(110,0,0) - 10.0f) < 1e-4f);

    // yaw=90：相机朝 +Y
    camMakeMatrix(0, 0, 0, 0, 90, 90);
    printf("yaw=90 时，(0,10,0) 深度 = %.2f\n", depth(0,10,0));   // 期望 10
    assert(fabsf(depth(0,10,0) - 10.0f) < 1e-4f);

    printf("全部通过\n");
    return 0;
}
```

三个关键验证：
1. 正前方深度 = 距离；侧面 = 0；后方 = 负数
2. 相机移动后，相对深度正确
3. 旋转后，深度跟着转
