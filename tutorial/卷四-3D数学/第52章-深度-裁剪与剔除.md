# 第 52 章 · 深度、裁剪与剔除

> [!abstract] 本章目标
> 掌握 5 种剔除手段，知道本项目每一处 `continue` 背后的原因。
> 这直接决定了 ESP 的性能。

## 先看为什么要剔除

假设场景里有 500 个 Actor，每个要读 10 次内存、算 15 根骨骼、画几十条线。
一帧下来几千次操作，60fps 只有 16.6ms——**不做剔除根本跑不动**。

剔除的本质：**用便宜的判断，提前丢掉大量无用工作**。

> [!note] 下面流程里的"视锥剔除"，视锥就是"相机能看到的那块梯形区域"——本节第 3 小节会详解，先看流程图。

```
500 个 Actor
  ↓ 距离剔除（1 次减法比较）
200 个
  ↓ 视锥剔除（1 次投影）
 40 个
  ↓ 屏幕外剔除（4 次比较）
 12 个
  ↓ 遮挡剔除（1 次射线，贵）
  5 个        ← 真正绘制
```

**越便宜的判断放越前面。**

## 1. 深度剔除（近平面）

最简单的一条：

```cpp
float w = matrix[3]*obj.X + matrix[7]*obj.Y + matrix[11]*obj.Z + matrix[15];
if (w < 0.001f) return false;
```

`w` 是点在相机前方的距离。**小于 0 表示在相机背后**。

```
        相机
         │
    w>0  │  w<0
   前方   │  后方
   可见   │  丢弃
```

为什么阈值是 0.001 而不是 0？
- 防止 `w` 极小时除出巨大坐标（inf）
- 相当于一个"近裁剪面"

## 2. 距离剔除

太远的物体看不清，也不用画：

```cpp
// 本项目自瞄里的距离过滤
if (世界距离 <= 1.0f || 世界距离 > Cfg.最大距离) return;
```

`最大距离` 默认 50000（UE4 单位是厘米，即 500 米）。

**用距离平方比较，省开方**（第 45 章）：

```cpp
float dx = a.x - b.x, dy = a.y - b.y, dz = a.z - b.z;
if (dx*dx + dy*dy + dz*dz > maxDist * maxDist) continue;
```

> [!note] 单位问题
> UE4 的世界单位是**厘米**。
> 角色高度约 165（不是 1.65），50000 = 500 米。
> 本项目代码里那些 `+165.0f`、`+100.0f` 都是厘米。
> 混淆单位是最容易犯的错——**始终记住 UE4 用厘米**。

## 3. 视锥剔除（Frustum Culling）

视锥是相机能看到的那块"梯形区域"：

> [!tip] 想象手电筒
> 想象手电筒照出去的光：从灯泡出发、越远越宽的一个**锥体**。
> 相机看到的范围就是这么一个锥体，叫"视锥"。落在锥体外的东西，画都不用画。

```
       远平面
    ┌─────────┐
   /           \
  /             \
 /               \
└─────────────────┘
      相机（近平面）
```

判断方法：投影后看 NDC 是否在 [-1, 1]：

```cpp
float ndc_x = clip_x / w;
float ndc_y = clip_y / w;
if (ndc_x < -1 || ndc_x > 1 || ndc_y < -1 || ndc_y > 1) {
    // 在视野外
}
```

**注意**：本项目的 W2S **没有**做这一步判断！
它只判断了 `w < 0.001`，然后照样返回屏幕坐标（可能在屏幕外）。

剔除放在调用方：

```cpp
if (!IsFiniteScreenPoint(rootScreen) || ...) continue;
...
if (boxRight < 0.0f || boxX > abs_ScreenX ||
    boxBottom < 0.0f || boxTop > abs_ScreenY) continue;
```

这是**屏幕空间剔除**，效果等价于视锥剔除。

## 4. 屏幕外剔除（包围盒）

画方框前，检查方框的包围盒是否完全在屏幕外：

```cpp
const float boxRight = boxX + boxWidth;
if (boxWidth <= 1.0f ||                              // 太小（异常）
    boxWidth > abs_ScreenX ||                        // 太大（异常）
    boxRight < 0.0f || boxX > abs_ScreenX ||         // 完全在左右外
    boxBottom < 0.0f || boxTop > abs_ScreenY) {      // 完全在上下外
    continue;
}
```

注意：这是**保守**判断。包围盒与屏幕有交集就保留，
所以屏幕上边缘的半个方框也会画——这是对的。

## 5. 遮挡剔除（Occlusion）

最贵也最有用：判断物体是否被墙挡住。

本项目用 Embree 光线投射（第 95~99 章）：

```cpp
static bool 射线被遮挡(const Vector3A &from, const Vector3A &to) {
    if (DynamicLoadScene == nullptr || HeightFieldScene == nullptr) return false;
    physx::PxVec3 origin(from.X, from.Y, from.Z);
    physx::PxVec3 target(to.X, to.Y, to.Z);
    if (DynamicLoadScene->Raycast(origin, target).hit.geomID != RTC_INVALID_GEOMETRY_ID) return true;
    if (HeightFieldScene->Raycast(origin, target).hit.geomID != RTC_INVALID_GEOMETRY_ID) return true;
    return false;
}
```

一次射线查询约几微秒。所以**只在必要时做**：

```cpp
const bool 被遮挡 = (physx已初始化 &&
                    (ConfigManager::Settings.方框 || ConfigManager::Settings.射线)) &&
                    射线被遮挡(...);
//  ↑ 只有开了方框或射线显示，且 PhysX 已初始化，才做
```

**三个条件缺一不可**——这就是"能省则省"的工程判断。

## 6. 背面剔除（扩展）

画三角形时，背对相机的面不用画：

```cpp
// 用叉积判断：法线朝向相机吗
Vec3 normal = Cross(v1 - v0, v2 - v0);
Vec3 toCam  = camPos - v0;
if (Dot(normal, toCam) < 0) {
    // 背面，跳过
}
```

本项目画 PhysX 线框时**没有**做背面剔除（线框模式下意义不大），
但这是标准优化，值得知道。

## 剔除顺序的最优解

按"单次成本"从低到高排：

| 顺序 | 手段 | 单次成本 | 剔除能力 |
|---|---|---|---|
| 1 | 指针合法性检查 | ~ns | 过滤垃圾数据 |
| 2 | 深度（w<0） | ~ns | 过滤背后 |
| 3 | 距离平方 | ~10ns | 过滤过远 |
| 4 | 屏幕外包围盒 | ~10ns | 过滤视野外 |
| 5 | 遮挡射线 | ~µs | 过滤被挡住的 |

**本项目正是这个顺序**。看 `DrawPlayer` 的代码结构：

```cpp
for (int i = 0; i < Count; ++i) {
    // 1. 指针合法性
    if (!IsValidObject(objectAddress) || objectAddress == MySelf) continue;

    // 2. 读名字、读位置（不可避免的 I/O）

    // 3. 投影（内含深度剔除）
    if (!WorldToScreen(rootWorld, rootScreen)) continue;

    // 4. 有限性检查
    if (!IsFiniteScreenPoint(rootScreen) || ...) continue;

    // 5. 屏幕外包围盒
    if (boxRight < 0 || boxX > abs_ScreenX || ...) continue;

    // 6. 遮挡（贵）
    const bool 被遮挡 = ... && 射线被遮挡(...);

    // 7. 绘制
}
```

> [!tip] 唯一可以再优化的地方
> 距离剔除（第 3 项）本可以在投影之前做，但本项目没做。
> 加一句能省掉远处的投影计算：
> ```cpp
> float dx = rootWorld.X - 相机位置.X;
> float dy = rootWorld.Y - 相机位置.Y;
> float dz = rootWorld.Z - 相机位置.Z;
> if (dx*dx + dy*dy + dz*dz > maxDistSq) continue;   // 加在读位置之后
> ```

## 深度缓冲（Z-Buffer）

上面说的都是"CPU 端剔除"。GPU 端还有一层：

**深度缓冲**：每个像素记录当前最近物体的深度，
新来的片元如果更远就丢弃。

```
渲染前：深度缓冲全为"无穷远"
渲染 A（深度 10）：写入 10
渲染 B（深度 20）：20 > 10，丢弃  ← B 被 A 挡住
渲染 C（深度 5）：5 < 10，写入 5  ← C 更近，覆盖
```

这解决了"谁挡住谁"的绘制顺序问题。

**但本项目的覆盖层没有深度信息**——它是在 2D 平面上画线，
先后画的会覆盖先画的。所以**绘制顺序就是"深度顺序"**：

```cpp
// 本项目按屏幕距离从远到近... 实际没排序
// 所以近处和远处的方框可能叠错
```

这是可以改进的点（第 100 章的综合练习会提到）。

## 动手：给 w2s_demo 加剔除统计

在第 51 章的 demo 基础上：

```c
typedef struct {
    int total;
    int culled_depth;      // w < 0.001
    int culled_distance;   // 超过最大距离
    int culled_offscreen;  // 屏幕外
    int visible;
} CullStats;

CullStats stats = {0};

void process_point(Vec3 p, float maxDist) {
    stats.total++;

    float w = g_matrix[3]*p.x + g_matrix[7]*p.y + g_matrix[11]*p.z + g_matrix[15];
    if (w < 0.001f) { stats.culled_depth++; return; }

    float dx = p.x - g_cam.x, dy = p.y - g_cam.y, dz = p.z - g_cam.z;
    if (dx*dx + dy*dy + dz*dz > maxDist*maxDist) { stats.culled_distance++; return; }

    float sx, sy;
    world_to_screen(p, &sx, &sy);
    if (sx < 0 || sx > 2*g_px || sy < 0 || sy > 2*g_py) { stats.culled_offscreen++; return; }

    stats.visible++;
}
```

然后生成 10000 个随机点（相机周围 ±1000 米），统计各阶段剔除了多少。
调 `maxDist` 观察曲线——这就是"剔除效率"的直观感受。
