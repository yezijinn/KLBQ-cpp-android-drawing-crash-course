# 第 52 章 · 深度、裁剪与剔除

> [!abstract] 本章目标
> 掌握 **5 种核心剔除手段**（深度 / 距离 / 视锥 / 屏幕外 / 遮挡）+ **1 种扩展手段**（背面剔除），
> 知道本项目每一处 `continue` 背后的原因。
> 这直接决定了 ESP 的性能。

> [!note] 承上
> 上一章能算出"每个点投到屏幕哪里"了。
> 但场景里几百个物体全算一遍太慢——本章讲**剔除**：怎么用便宜的判断提前丢掉无用工作。

## 先看为什么要剔除

假设场景里有 500 个 Actor，每个要读 10 次内存、算 15 根骨骼、画几十条线。
一帧下来几千次操作，60fps 只有 16.6ms——**不做剔除根本跑不动**。

剔除的本质：**用便宜的判断，提前丢掉大量无用工作**。

> [!note] 下面流程里的"视锥剔除"，视锥就是"相机能看到的那块梯形区域"——本节第 3 小节会详解，先看流程图。
> 注意：**本项目的"视锥剔除"和"屏幕外剔除"是同一件事的两种说法**（投影后判断点是否落在屏幕范围内），
> 所以流程里把它俩放在一起，你只要理解成"投影后丢掉屏幕外的点"即可。

```
500 个 Actor
  ↓ 距离剔除（1 次减法比较）
200 个
  ↓ 投影 + 视锥/屏幕外剔除（1 次投影 + 4 次比较）
 40 个
  ↓ 遮挡剔除（1 次射线，贵）
  5 个        ← 真正绘制
```

**越便宜的判断放越前面。**

## 1. 深度剔除（近平面）

最简单的一条：

```cpp
float w = matrix[3]*obj.X + matrix[7]*obj.Y + matrix[11]*obj.Z + matrix[15];
if (w < 0.001f) return false;
```

`w` 是点在相机前方的距离。**小于 0 表示在相机背后**。

```
        相机
         │
    w>0  │  w<0
   前方   │  后方
   可见   │  丢弃
```

为什么阈值是 0.001 而不是 0？
- 防止 `w` 极小时除出巨大坐标（inf）
- 相当于一个"近裁剪面"

## 2. 距离剔除

太远的物体看不清，也不用画：

```cpp
// 本项目自瞄里的距离过滤
if (世界距离 <= 1.0f || 世界距离 > Cfg.最大距离) return;
```

`最大距离` 默认 50000（UE4 单位是厘米，即 500 米）。

**用距离平方比较，省开方**（第 45 章）：

```cpp
float dx = a.x - b.x, dy = a.y - b.y, dz = a.z - b.z;
if (dx*dx + dy*dy + dz*dz > maxDist * maxDist) continue;
```

> [!note] 单位问题
> UE4 的世界单位是**厘米**。
> 角色高度约 165（不是 1.65），50000 = 500 米。
> 本项目代码里那些 `+165.0f`、`+100.0f` 都是厘米。
> 混淆单位是最容易犯的错——**始终记住 UE4 用厘米**。

## 3. 视锥剔除（Frustum Culling）

视锥是相机能看到的那块"梯形区域"：

> [!tip] 想象手电筒
> 想象手电筒照出去的光：从灯泡出发、越远越宽的一个**锥体**。
> 相机看到的范围就是这么一个锥体，叫"视锥"。落在锥体外的东西，画都不用画。

```
       远平面
    ┌─────────┐
   /           \
  /             \
 /               \
└─────────────────┘
      相机（近平面）
```

判断方法：投影后看 NDC 是否在 [-1, 1]：

```cpp
float ndc_x = clip_x / w;
float ndc_y = clip_y / w;
if (ndc_x < -1 || ndc_x > 1 || ndc_y < -1 || ndc_y > 1) {
    // 在视野外
}
```

**注意**：本项目的 W2S **没有**做这一步判断！
它只判断了 `w < 0.001`，然后照样返回屏幕坐标（可能在屏幕外）。

剔除放在调用方：

```cpp
if (!IsFiniteScreenPoint(rootScreen) || ...) continue;
...
if (boxRight < 0.0f || boxX > abs_ScreenX ||
    boxBottom < 0.0f || boxTop > abs_ScreenY) continue;
```

这是**屏幕空间剔除**，效果等价于视锥剔除。

## 4. 屏幕外剔除（包围盒）

画方框前，检查方框的包围盒是否完全在屏幕外：

```cpp
const float boxRight = boxX + boxWidth;
if (boxWidth <= 1.0f ||                              // 太小（异常）
    boxWidth > abs_ScreenX ||                        // 太大（异常）
    boxRight < 0.0f || boxX > abs_ScreenX ||         // 完全在左右外
    boxBottom < 0.0f || boxTop > abs_ScreenY) {      // 完全在上下外
    continue;
}
```

注意：这是**保守**判断。包围盒与屏幕有交集就保留，
所以屏幕上边缘的半个方框也会画——这是对的。

## 5. 遮挡剔除（Occlusion）

最贵也最有用：判断物体是否被墙挡住。

本项目用 Embree 光线投射（第 95~99 章）。

> [!note] 以下是**源码摘录**，用了 `physx::`、`Vector3A`、`DynamicLoadScene` 等外部类型，**不能单独编译**：

> [!note] `physx::` 是什么（现在只需知道这么多）
> `physx::` 是 **PhysX 物理引擎的命名空间**——UE4 游戏用 PhysX 存碰撞体数据。
> 本项目读游戏内存时，读出来的数据是 PhysX 格式，所以代码里到处都是 `physx::PxXxx`。
>
> **你现在（卷四）不用深入**——只要知道：
> - `physx::PxVec3` = PhysX 的三维向量（等价于我们用的 `Vec3`）
> - 上面的代码在"把 `Vector3A` 转成 PhysX 能接受的格式"
>
> 第 93 章（卷八）会系统讲 PhysX。**这里的代码是"预告"**——
> 你不需要理解 PhysX 就能读懂第 52 章的剔除逻辑，把 `PxVec3` 当成"另一个 Vec3"即可。

```cpp
static bool 射线被遮挡(const Vector3A &from, const Vector3A &to) {
    if (DynamicLoadScene == nullptr || HeightFieldScene == nullptr) return false;
    physx::PxVec3 origin(from.X, from.Y, from.Z);
    physx::PxVec3 target(to.X, to.Y, to.Z);
    if (DynamicLoadScene->Raycast(origin, target).hit.geomID != RTC_INVALID_GEOMETRY_ID) return true;
    if (HeightFieldScene->Raycast(origin, target).hit.geomID != RTC_INVALID_GEOMETRY_ID) return true;
    return false;
}
```

一次射线查询约几微秒。所以**只在必要时做**：

```cpp
const bool 被遮挡 = (physx已初始化 &&
                    (ConfigManager::Settings.方框 || ConfigManager::Settings.射线)) &&
                    射线被遮挡(...);
//  ↑ 只有开了方框或射线显示，且 PhysX 已初始化，才做
```

**三个条件缺一不可**——这就是"能省则省"的工程判断。

## 6. 背面剔除（扩展手段，非核心 5 种之一）

画三角形时，背对相机的面不用画：

```cpp
// 用叉积判断：法线朝向相机吗
Vec3 normal = Cross(v1 - v0, v2 - v0);   // 面的法线
Vec3 toCam  = camPos - v0;                // 从面指向相机
if (Dot(normal, toCam) < 0) {
    // 法线背对相机 → 这是背面，跳过
}
```

> [!note] 符号依赖两个前提
> 上面 `Dot < 0 判背面` 成立的前提是：
> ① 三角形顶点顺序（v0→v1→v2）是**逆时针**（从正面看）；
> ② `Cross` 的方向与坐标系手系匹配。
> 这两者任一相反，"正/背面"就会整个颠倒。所以实际引擎里，背面剔除的开关
> 常做成可配置（有些模型顶点顺序就是反的）。**别死记符号，用已知朝向的三角形测一次为准。**

本项目画 PhysX 线框时**没有**做背面剔除（线框模式下意义不大），
但这是标准优化，值得知道。

## 剔除顺序的最优解

按"单次成本"从低到高排：

| 顺序 | 手段 | 单次成本 | 剔除能力 |
|---|---|---|---|
| 1 | 指针合法性检查 | ~ns | 过滤垃圾数据 |
| 2 | 深度（w<0） | ~ns | 过滤背后 |
| 3 | 距离平方 | ~10ns | 过滤过远 |
| 4 | 屏幕外包围盒 | ~10ns | 过滤视野外 |
| 5 | 遮挡射线 | ~µs | 过滤被挡住的 |

**本项目正是这个顺序**。看 `DrawPlayer` 的代码结构：

```cpp
for (int i = 0; i < Count; ++i) {
    // 1. 指针合法性
    if (!IsValidObject(objectAddress) || objectAddress == MySelf) continue;

    // 2. 读名字、读位置（不可避免的 I/O）

    // 3. 投影（内含深度剔除）
    if (!WorldToScreen(rootWorld, rootScreen)) continue;

    // 4. 有限性检查
    if (!IsFiniteScreenPoint(rootScreen) || ...) continue;

    // 5. 屏幕外包围盒
    if (boxRight < 0 || boxX > abs_ScreenX || ...) continue;

    // 6. 遮挡（贵）
    const bool 被遮挡 = ... && 射线被遮挡(...);

    // 7. 绘制
}
```

> [!tip] 唯一可以再优化的地方
> 距离剔除（第 3 项）本可以在投影之前做，但本项目没做。
> 加一句能省掉远处的投影计算：
> ```cpp
> float dx = rootWorld.X - 相机位置.X;
> float dy = rootWorld.Y - 相机位置.Y;
> float dz = rootWorld.Z - 相机位置.Z;
> if (dx*dx + dy*dy + dz*dz > maxDistSq) continue;   // 加在读位置之后
> ```

## 深度缓冲（Z-Buffer）

上面说的都是"CPU 端剔除"。GPU 端还有一层：

**深度缓冲**：每个像素记录当前最近物体的深度，
新来的片元如果更远就丢弃。

```
渲染前：深度缓冲全为"无穷远"
渲染 A（深度 10）：写入 10
渲染 B（深度 20）：20 > 10，丢弃  ← B 被 A 挡住
渲染 C（深度 5）：5 < 10，写入 5  ← C 更近，覆盖
```

这解决了"谁挡住谁"的绘制顺序问题。

**但本项目的覆盖层没有深度信息**——它是在 2D 平面上画线，
先后画的会覆盖先画的。所以**绘制顺序就是"深度顺序"**：

```cpp
// 本项目按屏幕距离从远到近... 实际没排序
// 所以近处和远处的方框可能叠错
```

这是可以改进的点（第 100 章的综合练习会提到）。

## 动手：给 w2s_demo 加剔除统计

在第 51 章的 demo 基础上。**注意**：第 51 章的相机位置是 `main` 里的局部变量 `cam`，
下面的 `process_point` 要用到它，所以先把它提成全局变量——在第 51 章 demo 的全局区加一行：

```c
// 在第 51 章 demo 的 "static float g_matrix[16];" 附近加上：
static Vec3 g_cam = {0, 0, 50};   // 相机位置提成全局，供 process_point 使用
```

然后把 `main` 里原来的 `Vec3 cam = {0, 0, 50};` 改成使用这个全局变量即可。

```c
typedef struct {
    int total;
    int culled_depth;      // w < 0.001
    int culled_distance;   // 超过最大距离
    int culled_offscreen;  // 屏幕外
    int visible;
} CullStats;

CullStats stats = {0};

void process_point(Vec3 p, float maxDist) {
    stats.total++;

    float w = g_matrix[3]*p.x + g_matrix[7]*p.y + g_matrix[11]*p.z + g_matrix[15];
    if (w < 0.001f) { stats.culled_depth++; return; }

    float dx = p.x - g_cam.x, dy = p.y - g_cam.y, dz = p.z - g_cam.z;
    if (dx*dx + dy*dy + dz*dz > maxDist*maxDist) { stats.culled_distance++; return; }

    float sx, sy;
    world_to_screen(p, &sx, &sy);
    if (sx < 0 || sx > 2*g_px || sy < 0 || sy > 2*g_py) { stats.culled_offscreen++; return; }

    stats.visible++;
}
```

然后生成 10000 个随机点（相机周围 ±1000 米），统计各阶段剔除了多少。
调 `maxDist` 观察曲线——这就是"剔除效率"的直观感受。

## 课后习题

### 习题 52.1 实现深度剔除 + 包围盒屏幕外剔除（★★）

**任务要求**：写 `shouldDraw(camX, boxX, boxW, screenW)`，
依次做深度剔除（camX < 0.001 丢弃）和包围盒屏幕外剔除。

**参考实现**：

```cpp
#include <cstdio>
#include <cassert>

// 返回 true 表示需要绘制
bool shouldDraw(float camDepth, float boxX, float boxW, float screenW) {
    if (camDepth < 0.001f) return false;              // 1. 深度剔除（相机后方）
    if (boxW <= 1.0f) return false;                   // 2. 太小（异常）
    if (boxW > screenW) return false;                 // 3. 太宽（异常）
    float right = boxX + boxW;
    if (right < 0.0f || boxX > screenW) return false; // 4. 完全在左右外
    return true;
}

int main() {
    float sw = 1080;
    assert(shouldDraw(100, 500, 100, sw));       // 正常：画
    assert(!shouldDraw(-10, 500, 100, sw));      // 相机后方：不画
    assert(!shouldDraw(100, 1200, 100, sw));     // 完全在右侧外：不画
    assert(!shouldDraw(100, -200, 100, sw));     // 完全在左侧外：不画
    assert(shouldDraw(100, -50, 100, sw));       // 部分在屏内：画
    printf("习题 52.1 全部通过\n");
    return 0;
}
```

**验证断言**：后方/完全屏外不画；部分在屏内要画。

> [!tip] 越便宜的判断放越前面
> 深度剔除（1 次比较）最便宜，放最前；包围盒剔除（几次比较）次之；
> 遮挡剔除（射线，几微秒）最贵，放最后。**顺序错了性能就差**（第 52 章核心）。

### 习题 52.2 用距离平方省开方（★★）

**任务要求**：比较两点距离是否超过 `maxDist`，用**距离平方**避免 `sqrt`。

**参考实现**：

```cpp
#include <cstdio>
#include <cassert>

struct V3 { float x, y, z; };

bool tooFar(V3 a, V3 b, float maxDist) {
    float dx = a.x - b.x, dy = a.y - b.y, dz = a.z - b.z;
    return dx*dx + dy*dy + dz*dz > maxDist * maxDist;   // ★ 用平方，不开方
}

int main() {
    V3 a{0, 0, 0}, b{3, 4, 0};
    assert(!tooFar(a, b, 10.0f));   // 距离 5 < 10
    assert(tooFar(a, b, 4.0f));     // 距离 5 > 4
    printf("习题 52.2 全部通过\n");
    return 0;
}
```

> [!note] 为什么省开方
> `sqrt` 是几十个周期的操作，而在剔除里距离判断**每帧要做几千次**。
> 比较 `dist² < r²` 和 `dist < r` 结果一样，但前者不用开方。本项目 500 个 Actor 全靠这招提速。
