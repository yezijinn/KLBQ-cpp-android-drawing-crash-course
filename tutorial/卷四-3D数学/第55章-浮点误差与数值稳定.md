# 第 55 章 · 浮点误差与数值稳定

> [!abstract] 本章目标
> 知道误差从哪来、怎么累积、怎么防。
> 本项目每一处 `isfinite` 和 `clamp` 都是本章的实践。

> [!note] 承上
> 上一章给数学库写了测试。
> 本章讲数学库最隐蔽的敌人——**浮点误差**：从哪来、怎么累积、怎么防。

## 先看三个真实会发生的场景

```cpp
// 场景 1：大坐标 + 小偏移
float worldX = 10000000.0f;      // UE4 大地图坐标
float boneOffset = 0.05f;
worldX += boneOffset;            // 没效果！

// 场景 2：累积漂移
float angle = 0;
for (int i = 0; i < 1000000; i++) angle += 0.1f;
// angle ≈ 100000，但精确值应该是 100000.0，实际差了几百

// 场景 3：除零
float w = 极小值;
float x = clip / w;              // inf 或 nan
```

三个场景只是"引子"，背后的成因有 **四类**（下面逐个拆解：有效位数、抵消误差、累积误差、除零/下溢）。
之所以先看三个场景，是因为它们最直观；第四类（除零）到"原因四"才展开。

## 原因一：有效位数不够（大数吃小数）

float 有 24 位二进制有效位，约 **7 位十进制**。

```
10000000.0f  需要表示到个位 → 8 位有效数字 → 超出 7 位
```

实际的 float 在 1e7 附近的间距是：

```cpp
float a = 10000000.0f;
float b = std::nextafter(a, 20000000.0f);   // a 的下一个可表示值
printf("%.1f\n", b - a);      // 输出 1.0
```

**在 1e7 这个量级，float 的最小间隔是 1.0。**
所以加 0.05 完全没效果。

| 数量级 | float 最小间隔 |
|---|---|
| 1 | ~1.2e-7 |
| 100 | ~7.6e-6 |
| 10000 | ~9.8e-4 |
| 1e6 | ~0.0625 |
| 1e7 | ~1.0 |
| 1e8 | ~8.0 |

> [!warning] 对项目的影响
> UE4 大地图坐标可能到 1e6~1e7 量级。
> 在这个量级下：
> - 骨骼偏移小于 1 厘米的调整**不会生效**
> - 位置微小抖动会被"量化"
> - 两点相减（相近的大数）会严重损失精度 ← **抵消误差**
>
> **解法**：先相减再运算。
> ```cpp
> // 不好：两个大数直接减，有效位损失
> float dist = (b - a).Length();
> 
> // 其实这已经是正确写法了。错误的是：
> // 用大数做中间运算后才相减
> ```

## 原因二：抵消误差（Catastrophic Cancellation）

两个相近的数相减，有效位数急剧减少：

```cpp
float a = 1.2345678f;      // 8 位有效
float b = 1.2345677f;
float d = a - b;           // 结果只有 1~2 位有效数字
```

本项目里 `matrix[15] = -(camX*f.x + camY*f.y + camZ*f.z)`
然后 `w = dot(forward, obj) + matrix[15]`——
这就是"两个相近大数相减"的标准模式。

如果相机在 (1e7, 0, 0)，物体也在 (1e7+10, 0, 0)：

```
w = forward·obj - forward·cam
  = 1e7+10 - 1e7
  = 10      ← 但 1e7 的两个表示都要 8 位精度，float 只有 7 位
```

**结果误差可能有几米。**

> [!tip] 这是引擎用 double 存世界坐标的原因之一
> UE4 的 `FVector` 默认是 `double`（UE5 起），UE4 老版本是 float。
> 本项目读的是 float（`Vector3A`），所以在大地图上会有这个误差。
> 实际观察到的现象：**远处目标的方框会抖**。

## 原因三：累积误差

每次运算引入一点误差，累加起来：

```cpp
float sum = 0;
for (int i = 0; i < 1000000; i++) sum += 0.1f;
printf("%f\n", sum);     // 约 100958.34，不是 100000.0
```

误差约 0.1%。

本项目的累积发生在自瞄平滑：

```cpp
累积角度.Pitch += sp;      // 每帧加一点
```

**解法（本项目用的）**：到位后直接赋值，重置累积：

```cpp
if (std::fabs(dp) <= 0.05f && std::fabs(dy) <= 0.05f) {
    累积角度 = 目标角;      // ★ 直接赋值，清零累积误差
    写入角度(累积角度);
    return true;
}
```

## 原因四：除零与下溢

```cpp
float w = tiny;
float result = clip / w;     // inf
```

本项目三处防御：

```cpp
// 1. 近平面
if (w < 0.001f) return false;

// 2. tan 下溢
float t = tanf(FOV * 0.5f * PI / 180.0f);
if (t == 0.0f) t = 0.0001f;

// 3. 归一化
float len = Length();
return len < 1e-6f ? Vec3{} : (*this) / len;
```

## NaN 的传播

NaN 一旦产生，会污染所有后续运算：

```cpp
float a = 0.0f / 0.0f;      // nan
float b = a + 1;            // nan
float c = b * 0;            // nan
bool  d = (c == c);         // false！
```

**NaN 不会崩溃，只会静默地给出错误结果。**

本项目的三道防线：

```cpp
// 防线 1：源头检查
if (camX != camX || camY != camY || camZ != camZ) return;   // NaN 检查

// 防线 2：投影结果检查
return std::isfinite(screen.X) && std::isfinite(screen.Y);

// 防线 3：使用前检查
static bool IsFiniteScreenPoint(const Vector2A &point) {
    return std::isfinite(point.X) && std::isfinite(point.Y);
}
if (!IsFiniteScreenPoint(rootScreen) || ...) continue;
```

> [!note] 三道防线不是冗余
> 源头拦不住全部（比如读到的数据本身是 NaN），
> 中间检查拦不住全部（比如除法产生的 inf），
> 所以终点必须再查一次。**防御是分层的。**

## inf 的处理

```cpp
float inf = 1.0f / 0.0f;
inf - inf        // nan（不是 0！）
inf * 0          // nan
inf / inf        // nan
```

所以 `isfinite`（同时检查 nan 和 inf）比 `isnan` 更合适。

## 比较浮点数的正确方式

```cpp
// 错误
if (a == b)

// 绝对误差（适合同量级、接近 0 的值）
if (fabsf(a - b) < 1e-6f)

// 相对误差（通用，推荐）
bool NearlyEqual(float a, float b, float eps = 1e-5f) {
    float diff = fabsf(a - b);
    float scale = fmaxf(1.0f, fmaxf(fabsf(a), fabsf(b)));
    return diff < eps * scale;
}
```

本项目用的是绝对阈值（角度 0.05 度、距离 0.001），
因为量级固定，够用。

## 数值稳定的五个习惯

### 1. 先减后加

```cpp
// 不好
float result = (a + c) - (b + c);     // 中间值被放大

// 好
float result = a - b;                 // 直接相减
```

### 2. 用 double 做中间计算

```cpp
// 累加用 double，最后转 float
double sum = 0;
for (...) sum += values[i];
float result = (float)sum;
```

### 3. 避免除小数

```cpp
// 不好
float x = a / 0.0001f;      // 等价于 a * 10000，但精度差

// 好
float x = a * 10000.0f;
```

### 4. 用 clamp 限制范围

```cpp
const int targetFps = std::clamp(Config.gui_frame_rate, 60, 185);
```

防止异常值进入后续计算。

### 5. 定期重置累积量

```cpp
if (到位) 累积角度 = 目标角;      // 清零误差
```

## 一个实战：验证 float 精度边界

```cpp
#include <cstdio>
#include <cmath>
#include <cstdint>
#include <initializer_list>   // for (float b : {…}) 需要它

void show_spacing(float base) {
    float next = std::nextafter(base, base * 2 + 100);
    printf("在 %.0f 附近，float 最小间隔 = %.6f\n", base, next - base);
}

int main(void) {
    for (float b : {1.0f, 100.0f, 10000.0f, 1e6f, 1e7f, 1e8f})
        show_spacing(b);

    // 大数吃小数
    float big = 1e7f;
    float before = big;
    big += 0.05f;
    printf("\n1e7 + 0.05 结果变化: %s\n",
           (big == before) ? "无变化（被吃掉）" : "有变化");

    // 抵消误差
    float a = 1.2345678f, b = 1.2345677f;
    printf("1.2345678 - 1.2345677 = %.10f (真值 0.0000001)\n", a - b);

    // 累积误差
    float sum = 0;
    for (int i = 0; i < 1000000; i++) sum += 0.1f;
    printf("100万次 += 0.1f: %.2f (真值 100000.00)\n", sum);

    double dsum = 0;
    for (int i = 0; i < 1000000; i++) dsum += 0.1;
    printf("用 double 累加: %.2f\n", dsum);

    // NaN/inf
    float nan_ = 0.0f / 0.0f;
    float inf  = 1.0f / 0.0f;
    printf("\nnan == nan ? %d\n", nan_ == nan_);
    printf("inf - inf = %f\n", inf - inf);
    printf("isfinite(nan)=%d isfinite(inf)=%d isfinite(1.0)=%d\n",
           std::isfinite(nan_), std::isfinite(inf), std::isfinite(1.0f));
    return 0;
}
```

跑一遍，观察：
- 1e7 附近间隔是 1.0，加 0.05 无变化
- 相减结果只有 1~2 位有效
- float 累加误差 0.1%，double 几乎精确
- NaN 不等于自己，inf-inf 得到 nan

## 课后习题

### 习题 55.1 相对误差比较函数（★★）

**任务要求**：实现 `nearly_equal_rel(a, b, eps)`，用相对误差比较两个浮点数（本项目自瞄判断"已对准"用的思路）。

**参考实现**：

```cpp
#include <cmath>
#include <cstdio>
#include <cassert>

bool nearly_equal_rel(float a, float b, float eps) {
    float diff  = fabsf(a - b);
    float scale = fmaxf(1.0f, fmaxf(fabsf(a), fabsf(b)));
    return diff < eps * scale;
}

int main() {
    // 数值在 0 附近：用绝对差
    assert(nearly_equal_rel(0.0f, 1e-5f, 1e-4f));
    // 大数比较：相对误差
    assert(nearly_equal_rel(1000000.0f, 1000000.5f, 1e-4f));
    // 明显不同：不等
    assert(!nearly_equal_rel(1.0f, 2.0f, 1e-4f));
    // 经典的 0.1+0.2 != 0.3，但 nearly_equal 判为"接近"
    float s = 0.1f + 0.2f;
    assert(nearly_equal_rel(s, 0.3f, 1e-4f));
    printf("0.1+0.2=%.7f, 判为接近 0.3\n", s);
    printf("习题 55.1 全部通过\n");
    return 0;
}
```

**验证断言**：`0.1f + 0.2f` 虽不等于 `0.3f`，但相对误差判定为"接近"。

> [!warning] 绝不直接用 == 比较浮点
> `if (a == b)` 对浮点数几乎总是错的。正确做法是比差值是否足够小——
> 绝对阈值（数值在 0 附近）或相对阈值（大数比较）。

### 习题 55.2 观察累积误差与补偿（★★）

**要求**：累加 `0.1f` 一百万次，观察与精确值的偏差；再用"Kahan 求和"减少误差。

**参考实现**：

```cpp
#include <cstdio>
#include <cassert>

int main() {
    // 朴素累加：误差累积
    float sum1 = 0.0f;
    for (int i = 0; i < 1000000; i++) sum1 += 0.1f;

    // Kahan 补偿求和：误差更小
    float sum2 = 0.0f, c = 0.0f;
    for (int i = 0; i < 1000000; i++) {
        float y = 0.1f - c;
        float t = sum2 + y;
        c = (t - sum2) - y;
        sum2 = t;
    }

    printf("朴素累加 = %.1f\n", sum1);
    printf("Kahan求和 = %.1f\n", sum2);
    printf("精确值   = 100000.0\n");
    // Kahan 结果离精确值更近
    assert(fabsf(sum2 - 100000.0f) <= fabsf(sum1 - 100000.0f));
    printf("习题 55.2 全部通过\n");
    return 0;
}
```

> [!note] 累积误差的应对
> 一百万次 `+= 0.1f`，每次舍入一点点，累积起来偏几百。
> 本项目自瞄的应对是**到位后直接赋值**（`累积角度 = 目标角`），而不是无限逼近——
> 避免持续累积误差。
