# 第 68 章 · 多屏与镜像

> [!abstract] 本章目标
> 理解 Android 的多显示设备模型，学会用 `dumpsys display` 解析屏幕信息，
> 并知道投屏时覆盖层怎么跟着显示。

> [!note] 承上
> 前几章都在**一块屏**上工作。
> 本章处理**多屏**：投屏时覆盖层怎么跟着显示（镜像）。

## 先看有哪些"屏幕"

Android 上不止一个显示设备：

| 类型 | layerStack | 说明 |
|---|---|---|
| 内置屏幕 | 0 | 手机本身的屏 |
| 外接（HDMI/DP） | 1+ | 有线投屏 |
| 虚拟屏（scrcpy/Vysor） | 2+ | 软件创建的 |
| 无线投屏 | 1+ | Miracast / Chromecast |

```bash
adb shell dumpsys display
```

输出（简化）：

```
DisplayDeviceInfo{"内置屏幕", displayId 0, ...}:
  uniqueId="local:0"
  type BUILT_IN, tzoffset ...
  mCurrentLayerStack=0
  mCurrentLayerStackRect=(0, 0 - 1080, 2400)
  mCurrentOrientation=0
  ...

DisplayDeviceInfo{"HDMI 屏幕", displayId 2, ...}:
  uniqueId="local:1"
  type HDMI, ...
  mCurrentLayerStack=1
  mCurrentLayerStackRect=(0, 0 - 1920, 1080)
  mCurrentOrientation=0
```

> [!note] 字段名以项目实际解析的为准
> 真实项目 `ParseDumpDisplayInfo`（`ANativeWindowCreator.h`）抓的是这几个 key：
> `uniqueId="…"`、`type …,`、`mCurrentLayerStack=`、`mCurrentLayerStackRect=`、`mCurrentOrientation=`。
> 不同 Android 版本的 `dumpsys` 输出格式略有差异，所以项目用的是**字符串查找**而非固定列解析。

关键字段：

| 字段 | 含义 |
|---|---|
| `uniqueId` | 唯一标识（如 `local:0`） |
| `mCurrentLayerStack` | **图层栈 ID**（决定图层显示在哪个屏） |
| `mCurrentLayerStackRect` | 该屏在 layerStack 空间的矩形 `(l, t - r, b)` |
| `mCurrentOrientation` | 旋转（0/1/2/3） |
| `type` | BUILT_IN / HDMI / WIFI / VIRTUAL / OVERLAY |

## 图层的 layerStack

默认创建的图层 `layerStack = 0`，只在内置屏幕显示。

要让它显示到第二个屏幕：

```cpp
t.setLayerStack(sc, 1);
```

或者创建镜像（见下）。

## 三种多屏方案

| 方案 | 做法 | 适用场景 |
|---|---|---|
| **多图层** | 每个屏幕创建一个图层 | 各屏内容不同 |
| **镜像图层** | `SurfaceComposerClient::mirrorSurface` | 各屏内容相同 ★ |
| **虚拟显示** | `createVirtualDisplay` | 录屏、scrcpy |

本项目的"多屏镜像"用第二种。

## SurfaceComposerClient::mirrorSurface

真实项目用的 API 是 **`SurfaceComposerClient::mirrorSurface`**
（不是 `SurfaceControl::createMirrorSurface`）。它随版本有**多个重载**，
项目用"逐个试"的方式适配（**照抄 `ANativeWindowCreator.h`**）：

```cpp
// 不同版本的 mirrorSurface 符号（项目 ResolveMethod 逐个尝试）
"_ZN7android21SurfaceComposerClient13mirrorSurfaceEPNS_14SurfaceControlE"              // 1 参
"_ZN7android21SurfaceComposerClient13mirrorSurfaceEPNS_14SurfaceControlES2_"           // 2 参
"_ZN7android21SurfaceComposerClient13mirrorSurfaceERKNS_2spINS_14SurfaceControlEEE"    // sp 版
"_ZN7android21SurfaceComposerClient13mirrorSurfaceEPNS_14SurfaceControlES2_S2_"        // 3 参
```

项目 `MirrorSurface(surface, layerStack)` 里按"新 API 优先、失败回退"调用：

```cpp
if (MirrorSurface_v3)      mirrorSurface = MirrorSurface_v3(data, surface.data, nullptr, nullptr);
if (!mirrorSurface && MirrorSurface_sp)  mirrorSurface = MirrorSurface_sp(data, surfacePtr);
if (!mirrorSurface && MirrorSurface_v2)  mirrorSurface = MirrorSurface_v2(data, surface.data, nullptr);
if (!mirrorSurface && MirrorSurface)     mirrorSurface = MirrorSurface(data, surface.data);
```

> [!note] 镜像的完整流程
> 项目不是一次调用就能镜像，而是：
> 1. `CreateSurface("MirrorRoot@<layerStack>", w, h)` 建一个容器图层；
> 2. `mirrorSurface(...)` 把源图层镜像出来；
> 3. `SetLayerStack(mirror, layerStack)` 指定显示到哪个屏；
> 4. `ZoomSurface(...)` 设缩放/旋转（见下文）。
>
> 镜像 API 在不同版本差异很大，这是"用私有 API"的又一处代价（第 66 章的方法）。

## 本项目的实现思路

`ANativeWindowCreator::ProcessMirrorDisplay()`：

```
1. 节流：距上次超过一定间隔才执行（避免频繁 fork/popen）
2. popen("dumpsys display") 抓输出
3. ParseDumpDisplayInfo 解析出所有非 -1 的 layerStack 及矩形
4. 对每个非 0 的 layerStack：
   a. 若还没镜像，CreateSurface("MirrorRoot@<layerStack>") 建容器
   b. mirrorSurface(...) 镜像出源图层
   c. SetLayerStack(mirror, layerStack) 指定显示到哪个屏
   d. ZoomSurface(...) 设缩放/旋转（SetMatrix 4 分量）
5. 屏幕变化/旋转时清缓存重建；消失的镜像销毁
```

## 解析 dumpsys 输出

真实项目 `ParseDumpDisplayInfo`（**照抄 `ANativeWindowCreator.h`**）：
它不用"逐行解析"，而是**在整段文本里按 key 找值**（因为不同版本换行位置不定）：

```cpp
struct DumpDisplayInfo {
    std::string uniqueId;
    uint32_t    currentLayerStack;
    int32_t     orientation = 0;
    std::string type;
    struct { int32_t left, top, right, bottom; } currentLayerStackRect;
};

// 从文本里截取 "start 和 end 之间的子串"
static std::string_view SubStringView(const std::string_view &str,
                                      std::string_view start, std::string_view end,
                                      int startOffset = 0) {
    auto s = str.find(start, startOffset);
    if (s == std::string::npos) return {};
    auto e = str.find(end, s + start.size());
    if (e == std::string::npos) return {};
    return str.substr(s + start.size(), e - s - start.size());
}

std::vector<DumpDisplayInfo> ParseDumpDisplayInfo(const std::string_view &text) {
    std::vector<DumpDisplayInfo> out;
    size_t it = std::string_view::npos;
    while ((it = text.find("DisplayDeviceInfo", it + 1)) != std::string_view::npos) {
        auto type   = SubStringView(text, "type ", ",", it);
        auto uid    = SubStringView(text, "uniqueId=\"", "\"", it);
        auto ls     = SubStringView(text, "mCurrentLayerStack=", "\n", it);
        auto rect   = SubStringView(text, "mCurrentLayerStackRect=", "\n", it);
        auto orient = SubStringView(text, "mCurrentOrientation=", "\n", it);

        if (ls == "-1") continue;              // layerStack=-1 跳过
        if (uid.empty() || ls.empty()) continue;

        DumpDisplayInfo d;
        d.uniqueId = std::string(uid);
        d.currentLayerStack = std::stoul(std::string(ls));
        d.orientation = orient.empty() ? 0 : std::stoi(std::string(orient));
        d.type = std::string(type);
        // 解析 "(l, t - r, b)" 形式的矩形
        // …（用 find("(")、find(", ")、find(" - ") 逐段取整数，见项目源码）
        out.push_back(d);
    }
    return out;
}
```

> [!note] 为什么用"查找"而不是"逐行"
> `dumpsys display` 的换行位置随版本变，逐行解析很容易失效。
> 项目用 `find(key)` + `find(结束符)` 的方式，**只要 key 还在就能抓到值**，更抗版本差异。

**要点**：
- `DisplayDeviceInfo{` 是块的开始
- 每个字段用 `find` + `atoi` 提取
- 遇到下一个块时保存上一个

## 缩放与位置计算

镜像时要把源分辨率适配到目标屏。真实项目用的不是 3×3 矩阵，而是
**`Transaction::SetMatrix(surface, dsdx, dtdx, dtdy, dsdy)`**（4 个缩放/旋转分量），
并按 orientation 分四种情况（**照抄 `ANativeWindowCreator.h` 的 `ZoomSurface`**）：

```cpp
void ZoomSurface(SurfaceControl &surface, float scaleX, float scaleY,
                 uint32_t orientation, std::string type) {
    if (nullptr == surface.data) return;

    static SurfaceComposerClientTransaction transaction;
    StrongPointer<void> surfacePtr{surface.data};

    if (14 <= systemVersion && type == "VIRTUAL") {
        float dsdx, dtdx, dtdy, dsdy;
        switch (orientation) {
        case 0: dsdx = scaleX;  dtdx = 0.0f;    dtdy = 0.0f;    dsdy = scaleY;  break;
        case 1: dsdx = 0.0f;    dtdx = scaleY;  dtdy = -scaleX; dsdy = 0.0f;    break;
        case 2: dsdx = -scaleX; dtdx = 0.0f;    dtdy = 0.0f;    dsdy = -scaleY; break;
        case 3: dsdx = 0.0f;    dtdx = -scaleY; dtdy = scaleX;  dsdy = 0.0f;    break;
        }
        transaction.SetMatrix(surfacePtr, dsdx, dtdx, dtdy, dsdy);
    } else {
        // 老版本：只做缩放，不处理旋转
        transaction.SetMatrix(surfacePtr, scaleX, 0, 0, scaleY);
    }
    transaction.Apply(false, true);
}
```

缩放比例怎么算（项目 `ProcessMirrorDisplay` 里）：
```cpp
float scaleX = (float)surfaceDisplayWidth  / builtinDisplayWidth;
float scaleY = (float)surfaceDisplayHeight / builtinDisplayHeight;
uint32_t relativeOrientation = (builtinDisplayOrientation - displayInfo.orientation + 4) % 4;
// 若两屏相对旋转 90°，则交换 scaleX/scaleY
```

> [!note] 这里是"缩放 + 旋转"，不是"缩放 + 居中平移"
> 网上常见的镜像示例用 3×3 矩阵带平移，但**本项目用的是 4 分量 `SetMatrix`**，
> 只做缩放与旋转，不做居中平移（位置由另一处 `setPosition` 处理）。
> 以项目源码为准。

## 为什么本项目要管多屏

场景：用户用 scrcpy 投屏到电脑上操作。

```
电脑屏幕 (scrcpy 窗口)
    ↑ 虚拟屏 layerStack=2
    ↑ 如果覆盖层只在 layerStack=0，投屏画面里就看不到它
```

**做了镜像之后，投屏画面里也能看到覆盖层。** 这是实用的功能。

## 性能考虑

解析 `dumpsys display` 是**启动一个进程**，很慢（几十毫秒）。

本项目：

```cpp
void screen_config() {
    static std::chrono::steady_clock::time_point lastTime{};
    const auto now = std::chrono::steady_clock::now();
    if (now - lastTime < std::chrono::milliseconds(250)) return;   // ★ 节流
    ...
    lastTime = now;
}
```

**250ms 节流一次**——即使每帧调用 `screen_config()`，
实际每秒最多执行 4 次。

> [!tip] 更好的做法
> 用 `DisplayManager` 的回调监听屏幕变化，而不是轮询。
> 但原生层没有公开回调，只能轮询或者用 Binder 监听（复杂）。
> 本项目选择了节流轮询——简单且够用。

## 动手：屏幕信息解析器

> [!important] 前置条件
> 需要 **Android 设备**（`dumpsys display` 读设备显示信息）。
> 多屏/镜像行为需对应硬件；单屏设备也能跑通基础部分。

把上面的 `ParseDisplays` 补全，加上输出：

> [!note] 这段 main 用到 `ParseDisplays()`（前面定义），且需补 `#include <cstdio>`、`<string>`。
> **不能单独编译**，要配合前面的实现。

```cpp
int main(void) {
    FILE *fp = popen("dumpsys display", "r");
    if (!fp) { printf("popen 失败\n"); return 1; }

    std::string text;
    char buf[4096];
    while (fgets(buf, sizeof(buf), fp)) text += buf;
    pclose(fp);

    auto displays = ParseDisplays(text);
    printf("发现 %zu 个显示设备:\n", displays.size());
    for (auto &d : displays) {
        printf("  [%d] %-16s layerStack=%d  %dx%d  rot=%d  type=%s\n",
               d.displayId, d.uniqueId.c_str(), d.layerStack,
               d.width, d.height, d.rotation, d.type.c_str());
    }
    return 0;
}
```

在手机上跑，观察：
1. 内置屏的 layerStack 是不是 0？
2. 连接投屏后，列表里多了什么？
3. 旋转屏幕后 `rotation` 怎么变？

## 常见问题

| 问题 | 原因 | 解法 |
|---|---|---|
| `dumpsys` 输出格式对不上 | 厂商定制 ROM 改了输出 | 做容错解析，找不到就跳过 |
| 镜像创建了但没内容 | 源 layerStack 不对 | 核对 `layerStack` 字段 |
| 镜像变形 | 没处理宽高比/旋转 | 用 min(scaleX,scaleY) + 旋转矩阵 |
| 投屏画面卡顿 | 每秒重建镜像 | 缓存，只在变化时重建 |
| 屏幕消失后残留 | 没销毁 | 对比列表，销毁消失的 |

> [!note] 多屏/镜像场景
> 投屏、折叠屏、车载屏都可能出现多 display。本项目针对"主屏 + 可能镜像"简化处理，
> 遇到镜像时图层可能不在镜像里（取决于系统策略）。

## 常见坑排查表

| 症状 | 最可能的原因 | 解法 |
|---|---|---|
| 投屏时**自己图层不显示** | 图层没进镜像 | 查系统镜像策略 |
| 旋转后**画面错位** | 没更新 orientation | 监听 `displayInfo.orientation` 变化重建 |
| 多屏时**尺寸不对** | 用了错误的 display | 选主 display 的尺寸 |

### 习题 68.2 分析"投屏时 overlay 怎么跟随"（★★★，分析）

**任务要求**：分析：

1. 投屏（如 HDMI）时，新建的是什么？（新 display？新 layerStack？）
2. 覆盖层要显示在投屏上，需要做什么？
3. 如果只想要"手机和投屏显示不同内容"，怎么实现？

**参考答案要点**：
1. 新增一个 **display device**，对应一个新的 **layerStack**；
2. 把 overlay 图层的 layerStack 设为该外接屏的值（或用 mirror 关联）；
3. 用**独立的 layerStack**——不同 display 消费不同 layerStack 的图层。

> [!tip] 评价层要点
> 核心概念：**display ↔ layerStack 是多对一/一对多关系**。
> 理解这层映射，就能推理出"同一图层能否同时上两块屏"。
