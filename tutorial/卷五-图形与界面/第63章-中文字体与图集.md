# 第 63 章 · 中文字体与图集

> [!abstract] 本章目标
> 搞懂字体图集原理，解决中文显示方块问题，
> 并理解本项目为什么把字体内嵌成 `.cpp` 数组。

> [!note] 承上
> 前两章让 ImGui 能画出来，但只有英文。
> 本章解决**中文显示**（字体图集 + 内嵌字体）。

## 先看"豆腐块"

中文显示成 `□□□` 的原因只有一个：**字体里没有这些字形**。

ImGui 默认只加载 ASCII 范围（0x0020~0x00FF）。
要显示中文，必须：
1. 加载一个中文字体文件
2. 告诉 ImGui 要覆盖哪些字符范围

## 字体图集（Font Atlas）

ImGui 不会为每个字准备一张纹理——那样有几万个纹理。
它把所有需要的字形**渲染到一张大纹理**上：

```
┌────────────────────────────────┐
│ A B C D E F G ...              │
│ 中 文 字 形 显 示 ...           │
│ ！ 。 ， 、 ？ ...              │
│                                │
└────────────────────────────────┘
       一张 1024×1024 或更大的纹理
```

每个字形记录：

```cpp
struct ImFontGlyph {
    ImU32     Codepoint;   // 字符编码
    float     AdvanceX;    // 前进宽度
    float     X0, Y0, X1, Y1;   // 在图集里的包围盒
    float     U0, V0, U1, V1;   // 对应的纹理坐标 ★
};
```

绘制文字时，每个字符生成两个三角形（一个四边形），
UV 坐标指向图集里对应区域。

**这就是"文字 = 贴图四边形"的全部秘密。**

## 加载字体的三种方式

### 1. 从文件加载

```cpp
ImGuiIO &io = ImGui::GetIO();
io.Fonts->AddFontFromFileTTF("/sdcard/DroidSansFallback.ttf", 24.0f,
                             nullptr, io.Fonts->GetGlyphRangesChineseFull());
```

缺点：依赖外部文件，路径可能不存在。

### 2. 从内存加载（本项目做法）

```cpp
ImFontConfig config;
config.FontDataOwnedByAtlas = false;
config.SizePixels = SizePixels;
config.OversampleH = 2;
config.OversampleV = 1;

zh_font = io.Fonts->AddFontFromMemoryTTF(
    const_cast<unsigned char *>(g_heiti_ttf_data),
    static_cast<int>(EmbeddedAssets::HeitiSize()),
    SizePixels,
    &config,
    io.Fonts->GetGlyphRangesChineseFull());

io.FontDefault = zh_font;
```

> [!danger] `FontDataOwnedByAtlas = false` 是必须的
> 默认是 `true`，意味着 ImGui 在图集构建完成后会 `free()` 这块内存。
> 而我们的数据在 `.rodata` 段（静态数组），**free 静态内存 = 崩溃**。
>
> 这是本项目 `M_Android_LoadFont` 里最容易忽略的一行。

### 3. 内嵌为 C++ 数组

把 TTF 文件转成字节数组：

```bash
# 用 xxd（Git Bash / Linux 自带）
xxd -i heiti.ttf > heiti_ttf.cpp
```

> [!warning] `xxd -i` 生成的变量名由**文件名**决定
> 上面这条命令对 `heiti.ttf` 会生成两个变量：
> - `heiti_ttf[]`（字节数组）
> - `heiti_ttf_len`（长度）
>
> **注意**：它**不会**生成 `g_heiti_ttf_data` 这种名字。本项目里的名字是**手工改过**的
> （把 `heiti_ttf` 改成 `g_heiti_ttf_data`、`heiti_ttf_len` 改成 `g_heiti_ttf_size`）。
> **你跟着本项目走，就要照抄项目里的名字**；用自己 `xxd -i` 生成的原始名也行——
> 只要**数组名和加载代码里的名字一致**即可。

生成（名字**对齐本项目**后的样子）：

```cpp
extern "C" {
extern const unsigned char g_heiti_ttf_data[] = {
  0x00, 0x01, 0x00, 0x00, 0x00, 0xff, 0xff, 0xff, ...
  // 几百万字节
};
extern const unsigned int g_heiti_ttf_size = sizeof(g_heiti_ttf_data);
}
```

> [!tip] 长度用 `sizeof` 而不是写死数字
> 本项目写的是 `sizeof(g_heiti_ttf_data)`——**换了字体文件也不用改这一行**。
> 若用 `xxd -i` 自带的 `heiti_ttf_len`，它也是个编译期常量，效果一样。

本项目 `heiti_ttf.cpp` 就是这么来的（本项目实际约 **2.9 MB**，即 **3,033,180 字节**——文件头注释 `size = 3033180` 写明了）。

**注意**：这个 `.cpp` 编译很慢，且产物会大几 MB（第 41 章提过）。

> [!tip] 减小字体体积
> 用 `pyftsubset` 裁剪出项目实际用到的字：
> ```bash
> pip install fonttools
> pyftsubset heiti.ttf --text="方框射线骨骼人数自瞄启用平滑视野距离" \
>     --output-file=heiti_small.ttf
> ```
> 本项目内嵌黑体约 2.9 MB；若还想更小，用 `pyftsubset` 裁出项目实际用到的字，
> 常用几百字可压到 50KB 级。

## Glyph Range（字符范围）

```cpp
io.Fonts->GetGlyphRangesDefault();      // 仅 ASCII
io.Fonts->GetGlyphRangesChineseFull();  // 全部常用中文 ★ 本项目
io.Fonts->GetGlyphRangesJapanese();
io.Fonts->GetGlyphRangesKorean();
io.Fonts->GetGlyphRangesCyrillic();
```

自定义范围（更省）：

```cpp
static const ImWchar ranges[] = {
    0x0020, 0x00FF,      // ASCII + 拉丁
    0x2000, 0x206F,      // 通用标点
    0x3000, 0x303F,      // 中文标点
    0x4E00, 0x9FFF,      // CJK 统一汉字（常用）
    0xFF00, 0xFFEF,      // 全角字符
    0,                   // 结束标记
};
io.Fonts->AddFontFromMemoryTTF(..., ranges);
```

常用 Unicode 区间：

| 范围 | 内容 |
|---|---|
| `0x0020-0x007F` | 基本 ASCII |
| `0x4E00-0x9FFF` | CJK 统一汉字（2 万多字） |
| `0x3000-0x303F` | 中文标点（，。、） |
| `0xFF00-0xFFEF` | 全角字符（ＡＢＣ１２３） |

> [!note] `GetGlyphRangesChineseFull` 不等于"全部汉字"
> 它包含 GB2312 级别的常用字（约 7000 字）。
> 生僻字可能仍然显示为方块——本项目 UI 用的都是常用字，没问题。

## 图集尺寸问题

字多 + 字号大 = 图集放不下：

```
Assertion failed: (TexWidth <= 4096), ...
```

解决：

| 方法 | 做法 |
|---|---|
| 减小字号 | `SizePixels` 从 25 降到 18 |
| 减少字符 | 用自定义 range 代替 Full |
| 提高上限 | `io.Fonts->TexDesiredWidth = 4096;` |
| 多图集 | ImGui 1.92+ 支持自动分页 |

本项目：字号 25，中文全量，图集约 4096×4096 或更大。

## 缩放：Style.ScaleAllSizes

```cpp
ImGui::GetStyle().ScaleAllSizes(3.0f);
```

手机上 DPI 高，控件默认尺寸小得没法点。
这行把所有间距、圆角、滚动条尺寸**统一放大 3 倍**。

**只影响尺寸，不影响字号**——字号由 `SizePixels` 单独控制。

本项目的组合：

```cpp
void init_My_drawdata() {
    ImGui::StyleColorsLight();
    M_Android_LoadFont(25.0f);          // 字号 25
    ImGui::GetStyle().ScaleAllSizes(3.0f);   // 控件放大 3 倍
}
```

## Oversample（过采样）

```cpp
config.OversampleH = 2;
config.OversampleV = 1;
```

把字形渲染到图集时放大 2 倍再缩小，抗锯齿更好。

代价：图集面积 ×2（或 ×4）。

## 字体图集的构建时机

```cpp
// 添加完所有字体后，构建图集
unsigned char *pixels;
int width, height;
io.Fonts->GetTexDataAsRGBA32(&pixels, &width, &height);

// 上传到 GPU（Vulkan 后端做）
ImGui_ImplVulkan_CreateFontsTexture(cmd);
```

**只需要构建一次**，之后每帧复用这张纹理。

> [!warning] 添加字体后必须重建纹理
> 如果运行时换字体（比如用户切换字号），要：
> ```cpp
> io.Fonts->Clear();
> // 重新 AddFont...
> ImGui_ImplVulkan_DestroyFontsTexture();
> ImGui_ImplVulkan_CreateFontsTexture(cmd);
> ```

## 绘制中文文本

```cpp
// 窗口内
ImGui::Text("人数: %d", count);

// DrawList 直绘
draw->AddText(ImVec2(x, y), IM_COL32(255,255,0,255), "真人");

// 指定字号
draw->AddText(ImGui::GetFont(), 50.0f, pos, color, countBuf);
```

本项目的用法：

```cpp
ImVec2 textPos = ImVec2(boxX, boxTop);
draw->AddText(textPos, ImColor(255, 255, 0, 255), name_.c_str());
```

**必须传 UTF-8 编码的字符串。** 源码文件是 UTF-8，字符串字面量自然就是 UTF-8。

> [!danger] 源文件编码必须是 UTF-8 无 BOM
> 否则中文字符串在编译后是乱码（第 44 章）。

## 字体渲染的开销

每个字符 = 2 个三角形 = 6 个顶点。
一句 20 字的话 = 120 个顶点。

本项目一帧画几十条标签，约几千顶点——可忽略。

## 动手：验证中文显示

```cpp
#include "imgui.h"
#include <cstdio>

int main(void) {
    IMGUI_CHECKVERSION();
    ImGui::CreateContext();
    ImGuiIO &io = ImGui::GetIO();
    io.DisplaySize = ImVec2(800, 600);

    // 用默认字体（只有 ASCII）
    io.Fonts->AddFontDefault();
    io.Fonts->Build();

    // 检查某个中文字符是否有字形
    ImFont *font = io.Fonts->Fonts[0];
    printf("默认字体包含 'A' 吗? %s\n",
           font->FindGlyph('A') ? "是" : "否");
    printf("默认字体包含 '中'(0x4E2D) 吗? %s\n",
           font->FindGlyph(0x4E2D) ? "是" : "否");   // 应该是"否"

    ImGui::NewFrame();
    ImGui::Begin("测试");
    ImGui::Text("ASCII: Hello");
    ImGui::Text("中文: 方框 射线 骨骼");      // 会显示方块
    ImGui::End();
    ImGui::Render();

    // 统计：有多少字形
    printf("图集尺寸: %dx%d\n", io.Fonts->TexWidth, io.Fonts->TexHeight);
    printf("字形数量: %d\n", font->Glyphs.Size);

    ImGui::DestroyContext();
    return 0;
}
```

然后加入中文字体（用系统里的字体文件），重跑：

```cpp
io.Fonts->AddFontFromFileTTF("C:/Windows/Fonts/msyh.ttc", 24.0f,
                             nullptr, io.Fonts->GetGlyphRangesChineseFull());
```

对比两次输出：`FindGlyph(0x4E2D)` 从"否"变"是"，
图集尺寸和字形数量大幅增加。

## 课后习题

### 习题 63.1 用 hexdump 估算内嵌字体大小（★）

**任务要求**：把 `heiti_ttf.cpp` 里的 `g_heiti_ttf_size` 常量打印出来，换算成 MB，
验证它确实约 2.9 MB（提示：真实项目头注释写 `size = 3033180`）。

**参考实现**：

```c
#include <stdio.h>
#include <assert.h>

int main(void) {
    // 真实项目 heiti_ttf.cpp 头注释：size = 3033180
    const unsigned int g_heiti_ttf_size = 3033180;
    double mb = g_heiti_ttf_size / 1024.0 / 1024.0;
    printf("字体大小 = %u 字节 = %.2f MB\n", g_heiti_ttf_size, mb);
    assert(mb > 2.8 && mb < 3.0);   // 约 2.9 MB
    printf("习题 63.1 全部通过\n");
    return 0;
}
```

**验证断言**：`3033180` 字节 ≈ `2.89 MB`，在 `[2.8, 3.0]` 区间内。

> [!note] 为什么关心字体体积
> 内嵌字体是产物体积的大头（约 2.9 MB）。本项目用 `pyftsubset` 裁剪常用字，
> 几百字可压到 50KB 级——这是第 41 章"体积裁剪"的重点对象之一。

### 习题 63.2 内存中的字符范围（概念题）

**任务要求**：说出 `GetGlyphRangesChineseFull()` 和 `GetGlyphRangesDefault()` 的区别。

> [!question]- 参考答案
> - `GetGlyphRangesDefault()`：只有 ASCII（0x20~0xFF），**中文会显示成方块**。
> - `GetGlyphRangesChineseFull()`：包含全部常用汉字，**中文正常显示**，但图集会更大。
> 本项目用后者（`io.Fonts->GetGlyphRangesChineseFull()`），代价是字体数组和纹理图集都更大。
