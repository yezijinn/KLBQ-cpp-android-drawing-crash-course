# 第 66 章 · 跨版本符号适配

> [!abstract] 本章目标
> 学会"一套代码适配 Android 5~17"的方法。
> **本章产出 `overlay` 成品**（总纲承诺的第 3 个成果）。

> [!important] 这是全书最难的一章，别想一次吃下
> 本章是全教程**环境复杂度最高**的一章（要真机 + root + SurfaceFlinger 私有符号）。建议分两步走：
>
> **第一步：先在你手头这一台设备上跑通**
> - 用本章的"按版本探测"代码，只针对**你这台设备的 Android 版本**做适配
> - 目标：看到屏幕上出现一个透明图层（哪怕只有一个版本能用）
> - **跑通一台，就已经成功了 80%**
>
> **第二步：再扩展适配其它版本**
> - 手头没有的设备不用管，等有设备/用户反馈时再补
> - 维护一张"设备型号 → Android 版本 → 用哪个符号"的兼容表
>
> **不要追求"一次写对 5 个版本"**——那会让你卡很久。**先跑通一个，再逐步扩展。**
>
> 本章难度主要在"环境"（设备、root、符号），不在"代码逻辑"。卡住时先确认：
> 设备 root 了吗？`dumpsys SurfaceFlinger` 能看到图层吗？符号侦察器找到目标符号了吗？

## 先看问题有多严重

同一个函数 `createSurface`，在不同 Android 版本：

| Android | API | 签名 |
|---|---|---|
| 5.0 | 21 | `(name, w, h, format, flags)` |
| 8.0 | 26 | `(name, w, h, format, flags, parentHandle)` |
| 10 | 29 | `(name, w, h, format, flags, parentHandle, windowType, ownerUid)` |
| 11 | 30 | `(name, w, h, format, flags, parentHandle, LayerMetadata)` |
| 12 | 31 | `(..., LayerMetadata)` 参数位置又变了 |

**符号名完全不同，参数个数也不同。**

## 解法：运行时探测 + 备选列表

```cpp
struct SymbolEntry {
    const char *mangled;      // 符号名
    int minApi, maxApi;       // 适用版本范围
};
```

初始化时按当前 API 选择：

```cpp
int GetApiLevel() {
    char buf[PROP_VALUE_MAX];
    __system_property_get("ro.build.version.sdk", buf);
    return atoi(buf);
}
```

然后：

```cpp
static const SymbolEntry kCreateSurfaceSymbols[] = {
    // Android 11+ (LayerMetadata 版本)
    {"_ZN7android21SurfaceComposerClient13createSurfaceERKNS_7String8EjjijPNS_2spINS_7IBinderEEENS_13LayerMetadataE", 30, 99},
    // Android 8-9 (windowType/ownerUid 版本)
    {"_ZN7android21SurfaceComposerClient13createSurfaceERKNS_7String8EjjijPNS_2spINS_7IBinderEEEii", 26, 29},
    // Android 5-7 (老版本)
    {"_ZN7android21SurfaceComposerClient13createSurfaceERKNS_7String8Ejjij", 21, 25},
};

void* FindSymbol(void *lib, const SymbolEntry *table, size_t n, int api) {
    // 先按版本找
    for (size_t i = 0; i < n; i++) {
        if (api >= table[i].minApi && api <= table[i].maxApi) {
            void *p = dlsym(lib, table[i].mangled);
            if (p) return p;
        }
    }
    // 版本判断失败就全试一遍
    for (size_t i = 0; i < n; i++) {
        void *p = dlsym(lib, table[i].mangled);
        if (p) return p;
    }
    return nullptr;
}
```

**"按版本找 → 找不到就全试"** 是双保险。

> [!note] 为什么不能只靠版本判断
> 因为：
> - 厂商可能修改系统（MIUI、ColorOS 等）
> - Android 版本的 API 号与实际符号不一定严格对应
> - 某些版本有多个重载，`dlsym` 返回哪个不确定
>
> 所以**以 `dlsym` 是否成功为准**，版本只用来排序优先级。

## 需要适配的东西不止符号

| 项目 | 版本差异 |
|---|---|
| **符号名** | 上面说的 |
| **结构体布局** | `String8`、`LayerMetadata`、`sp<T>` |
| **创建标志** | `eFXSurfaceBufferState` / `eFXSurfaceBufferQueue` |
| **窗口类型值** | `441731` 只在特定版本有效 |
| **跳过截图的设置方式** | flag / windowType / LayerMetadata（第 67 章） |

## 结构体布局适配

`String8` 是个典型：

```cpp
// Android 9 之前：内部是 const char*
struct String8_old {
    const char *mString;
};

// Android 10+：内部是 std::string（有 SSO 优化）
struct String8_new {
    char  data[16];      // 短字符串优化缓冲
    size_t size;
    // ... 联合体
};
```

**大小从 8 字节变成 32 字节。** 栈上分配时必须区分：

```cpp
union String8Storage {
    uint8_t  raw[40];          // 取最大值
    uint64_t align;            // 保证对齐
};

String8Storage nameBuf;
memset(&nameBuf, 0, sizeof(nameBuf));

if (api >= 29) {
    // 用新版本的构造函数
    pfnString8_ctor_new(&nameBuf, name);
} else {
    pfnString8_ctor_old(&nameBuf, name);
}
```

> [!danger] 用 `union` + 最大尺寸是权宜之计
> 更稳妥的做法是**完全避免构造 `String8`**：
> 用 `dlsym` 找到的构造函数，或者直接传一个预先构造好的空对象。
>
> 本项目用一个技巧：**只传一个字符很短的名字**（如系统层名），
> 这样即使布局是 SSO 版本也不会出错。

## 创建标志的差异

```cpp
// 老版本
ISurfaceComposerClient::eFXSurfaceNormal = 0x00000000

// 新版本（Android 11+）
ISurfaceComposerClient::eFXSurfaceBufferState = 0x00000080
ISurfaceComposerClient::eFXSurfaceBufferQueue = 0x00000100
```

本项目：

```cpp
uint32_t flags = 0;
if (api >= 30) {
    flags = 0x100;      // eFXSurfaceBufferQueue
} else {
    flags = 0;
}
```

## 完整的 overlay 程序

```cpp
// overlay.cpp —— 一个能跑的透明覆盖层
#include <android/log.h>
#include <android/native_window.h>
#include <sys/system_properties.h>
#include <dlfcn.h>
#include <cstdio>
#include <cstring>
#include <cstdlib>

#define LOGI(...) __android_log_print(ANDROID_LOG_INFO,  "Overlay", __VA_ARGS__)
#define LOGE(...) __android_log_print(ANDROID_LOG_ERROR, "Overlay", __VA_ARGS__)

static int g_api = 0;
static void *g_libgui = nullptr;

// 函数指针
typedef void* (*FN_SCC_new)(void);
typedef int   (*FN_SCC_initCheck)(void*);
typedef void* (*FN_SCC_createSurface)(void*, void*, uint32_t, uint32_t,
                                      int32_t, uint32_t, void*, void*);
typedef void* (*FN_SC_getSurface)(void*);

static FN_SCC_new           pfnSCC_new = nullptr;
static FN_SCC_initCheck     pfnSCC_initCheck = nullptr;
static FN_SCC_createSurface pfnSCC_create = nullptr;
static FN_SC_getSurface     pfnSC_getSurface = nullptr;

static void* TrySym(const char *name) {
    void *p = dlsym(g_libgui, name);
    if (p) LOGI("  找到符号: %s", name);
    return p;
}

bool InitLibGui() {
    char buf[PROP_VALUE_MAX];
    __system_property_get("ro.build.version.sdk", buf);
    g_api = atoi(buf);
    LOGI("Android API = %d", g_api);

    g_libgui = dlopen("libgui.so", RTLD_NOW);
    if (!g_libgui) { LOGE("dlopen libgui: %s", dlerror()); return false; }

    // 构造函数：几个版本都试
    pfnSCC_new = (FN_SCC_new)TrySym("_ZN7android21SurfaceComposerClientC1Ev");
    if (!pfnSCC_new)
        pfnSCC_new = (FN_SCC_new)TrySym("_ZN7android21SurfaceComposerClientC1ENS_2spINS_7ISurfaceComposerEEE");

    pfnSCC_initCheck = (FN_SCC_initCheck)TrySym("_ZNK7android21SurfaceComposerClient9initCheckEv");
    pfnSC_getSurface = (FN_SC_getSurface)TrySym("_ZNK7android14SurfaceControl10getSurfaceEv");

    // createSurface：按版本优先，失败则全试
    const char *cands[] = {
        "_ZN7android21SurfaceComposerClient13createSurfaceERKNS_7String8EjjijPNS_2spINS_7IBinderEEENS_13LayerMetadataE",
        "_ZN7android21SurfaceComposerClient13createSurfaceERKNS_7String8EjjijPNS_2spINS_7IBinderEEEii",
        "_ZN7android21SurfaceComposerClient13createSurfaceERKNS_7String8EjjijPNS_2spINS_7IBinderEEE",
        "_ZN7android21SurfaceComposerClient13createSurfaceERKNS_7String8Ejjij",
    };
    for (auto n : cands) {
        pfnSCC_create = (FN_SCC_createSurface)TrySym(n);
        if (pfnSCC_create) break;
    }

    return pfnSCC_new && pfnSCC_initCheck && pfnSCC_create && pfnSC_getSurface;
}

ANativeWindow* CreateOverlayWindow(const char *name, int w, int h) {
    // 分配足够大的缓冲（覆盖所有版本的对象大小差异）
    void *client = calloc(1, 128);
    pfnSCC_new(client);

    int err = pfnSCC_initCheck(client);
    if (err != 0) { LOGE("SurfaceComposerClient 初始化失败: %d", err); return nullptr; }
    LOGI("SurfaceComposerClient 就绪");

    // String8 名字（用最大尺寸缓冲）
    uint8_t nameBuf[64] = {};
    // 简化：直接用短名字且按当前 API 选构造函数
    // （真实工程要 dlsym 对应版本的 String8 构造函数）

    void *sc = calloc(1, 64);
    uint32_t flags = (g_api >= 30) ? 0x100 : 0;

    // 注意：这里的调用签名是简化的，
    // 真实代码要按 g_api 选择对应参数个数的函数指针类型
    void *surface = nullptr;

    LOGI("（此处省略与版本相关的参数组装）");
    // 实际调用 pfnSCC_create(...)

    if (surface) {
        ANativeWindow *win = (ANativeWindow*)pfnSC_getSurface(sc);
        LOGI("窗口创建成功: %p", win);
        return win;
    }
    return nullptr;
}

int main(void) {
    if (!InitLibGui()) { LOGE("初始化失败"); return 1; }

    ANativeWindow *win = CreateOverlayWindow("MyOverlay", 1080, 2400);
    if (!win) return 1;

    int w = ANativeWindow_getWidth(win);
    int h = ANativeWindow_getHeight(win);
    LOGI("窗口尺寸: %dx%d", w, h);

    // 到这里窗口已创建，接下来交给 Vulkan/ImGui 渲染（第 59 章）

    LOGI("按 Ctrl+C 结束");
    while (true) { usleep(1000000); }
    return 0;
}
```

> [!warning] 上面的 createSurface 调用是**示意**
> 因为不同版本参数个数不同，真实代码必须：
> ```cpp
> if (g_api >= 30) {
>     typedef void* (*FN11)(void*, void*, uint32_t, uint32_t, int32_t,
>                           uint32_t, void*, void*, void*);
>     ((FN11)pfnSCC_create)(client, nameBuf, w, h, fmt, flags,
>                           nullptr, sc, metadata);
> } else if (g_api >= 26) {
>     typedef void* (*FN8)(void*, void*, uint32_t, uint32_t, int32_t,
>                          uint32_t, void*, void*);
>     ((FN8)pfnSCC_create)(client, nameBuf, w, h, fmt, flags, nullptr, sc);
> }
> ```
> **用不同的函数指针类型来对应不同参数个数。**

## 验证清单（每台设备都要跑）

```bash
# 1. 设备信息
adb shell getprop ro.build.version.sdk
adb shell getprop ro.build.version.release

# 2. 符号是否存在
adb pull /system/lib64/libgui.so
aarch64-linux-android-nm -D -C libgui.so | grep createSurface

# 3. 运行 overlay
adb push overlay /data/local/tmp/
adb shell chmod 755 /data/local/tmp/overlay
adb shell su -c /data/local/tmp/overlay &

# 4. 看日志
adb logcat -s Overlay

# 5. 确认图层创建成功
adb shell dumpsys SurfaceFlinger | grep -i overlay
```

**第 5 步能看到你的图层，就成功了。**

## 维护多版本支持表

本项目 `ANativeWindowCreator.h` 里维护了一张表（简化）：

| 项目 | Android 5-7 | 8-9 | 10 | 11-12 | 13+ |
|---|---|---|---|---|---|
| createSurface 参数 | 5 | 7 | 8 | 8 | 8 |
| String8 构造 | 老 | 老 | 新 | 新 | 新 |
| 跳过截图 | flag | windowType | windowType | LayerMetadata | LayerMetadata |
| 镜像显示 | 不支持 | 支持 | 支持 | 支持 | 支持 |

**这张表是"用私有 API"必须付出的维护成本。**

## 动手：建你自己的设备档案

为你的设备（或模拟器）建一份档案：

```markdown
## 设备: XXX
- Android 版本: 13, API 33
- ABI: arm64-v8a

### libgui 符号
- createSurface: _ZN7android21SurfaceComposerClient13createSurfaceE...（找到）
- getSurface: 找到
- initCheck: 找到

### 结果
- 图层创建: 成功
- 层级: INT_MAX-1
- 透明: 正常
```

每换一台设备就更新一次。这是长期维护的关键文档。
