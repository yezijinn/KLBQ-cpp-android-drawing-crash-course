# 第 69 章 · 触摸事件链路

> [!abstract] 本章目标
> 理解一次触摸从手指到应用的完整旅程，
> 并知道 `/dev/input` 和 `uinput` 在其中的位置。

> [!note] 承上
> 覆盖层能显示、能调层级了，但它还"不吃触摸"。
> 本章讲**触摸事件的完整链路**——从手指到应用经过哪些环节。

> [!important] 前置条件
> - **读 `/dev/input/eventN`** 需要 **root 设备**（普通 shell 读不到）。
> - 无 root 设备：本章链路**读懂即可**，动手留到有 root 设备时再做。

## 先看完整链路

```
手指按到屏幕
    ↓
触摸屏硬件（I2C/SPI 控制器）
    ↓
内核触摸屏驱动（如 ft5x06_ts）
    ↓ 生成 input_event，写入 /dev/input/eventX
InputReader（system_server 的线程）
    ↓ 读取 /dev/input/eventX
    ↓ 解析成 MotionEvent
InputDispatcher
    ↓ 决定发给哪个窗口
App 的 ViewRootImpl
    ↓
onTouchEvent()
```

**关键点**：所有触摸最终都变成 `/dev/input/eventX` 里的结构体。
谁有权限读这个文件，谁就能看到所有触摸；
谁有权限写 `/dev/uinput`，谁就能**伪造**触摸。

## input_event 结构

```c
#include <linux/input.h>

struct input_event {
    struct timeval time;    // 时间戳（16 字节）
    __u16 type;             // 事件类型
    __u16 code;             // 事件代码
    __s32 value;            // 值
};                          // 共 24 字节
```

| type | 含义 | 常见 code |
|---|---|---|
| `EV_SYN` (0) | 同步信号 | `SYN_REPORT`(0) 表示一组事件结束 |
| `EV_KEY` (1) | 按键 | `BTN_TOUCH`(0x14a) 触摸按下/抬起 |
| `EV_ABS` (3) | 绝对坐标 | `ABS_MT_POSITION_X`(0x35) `ABS_MT_POSITION_Y`(0x36) |
| `EV_ABS` | | `ABS_MT_TRACKING_ID`(0x39) 触点 ID |
| `EV_ABS` | | `ABS_MT_SLOT`(0x2f) 槽位（多点触控） |

多点触控协议（Protocol B）：

```
EV_ABS  ABS_MT_SLOT        0          ← 第 0 个手指
EV_ABS  ABS_MT_TRACKING_ID 1234       ← 新触点（负值表示抬起）
EV_ABS  ABS_MT_POSITION_X  540        ← X 坐标
EV_ABS  ABS_MT_POSITION_Y  1200       ← Y 坐标
EV_SYN  SYN_REPORT         0          ← 同步：这一组生效
```

## 补一课：设备文件与 ioctl

> [!warning] 这一节是后面的基础，别跳过
> 本章和第 70、71 章会大量出现 `ioctl`（全卷出现 40+ 次），但它**在前面几卷从没讲过**。
> 这里补上，够用即可。

**① 设备文件（device file）**

Linux 有个设计："**把硬件也当成文件**"。触摸屏、键盘、GPU……在 `/dev` 下都有一个对应的文件：

```bash
ls -l /dev/input/
# crw-rw---- 1 root input 13, 64 event0    ← 一个输入设备
```

开头的 `c` 表示"字符设备"，对它做 `open / read / write / close`，就相当于在操作这个硬件。
（这和第 22 章讲的"文件 IO"是**同一套接口**，只不过对象从磁盘文件换成了硬件。）

**② 普通 read/write 不够用时，用 ioctl**

设备往往需要"除了读写数据之外的控制操作"，比如：
- 查询触摸屏的坐标范围（`EVIOCGABS`）
- 独占这个设备，不让别的程序读（`EVIOCGRAB`）
- 告诉虚拟设备"我要创建了"（`UI_DEV_CREATE`）

这些**既不是读也不是写**，而是"给设备发一条命令"。Linux 为此提供了 `ioctl`：

```c
#include <sys/ioctl.h>

// ioctl(设备 fd, 命令码, 参数指针)
int ret = ioctl(fd, EVIOCGABS(ABS_MT_POSITION_X), &absinfo);
//                ↑ 命令（宏，定义在头文件里）   ↑ 结果写到这里
```

> [!note] ioctl 的三个参数
> | 参数 | 含义 |
> |---|---|
> | `fd` | 设备文件描述符（`open` 得到的） |
> | 命令码 | 一个宏（如 `EVIOCGRAB`、`UI_SET_EVBIT`），**告诉设备"要干什么"** |
> | 参数 | 输入/输出数据。有的命令不需要参数（传 0），有的传指针 |
>
> 不同设备的命令码完全不同——触摸屏用 `EVIOC*`，uinput 用 `UI_*`。**命令码都定义在对应的头文件里**
> （`<linux/input.h>`、`<linux/uinput.h>`），所以要用哪个设备，就得 `#include` 那个头。

**③ 为什么用 ioctl 而不是 read/write**

一句话：**read/write 负责"数据流"，ioctl 负责"控制"**。
你要读触摸坐标 → 用 `read`；你要问触摸屏"你的量程多大" → 用 `ioctl`。

记住这个区分，后面的代码就看得懂了。

## 读取触摸

现在可以看懂这段代码了：

```c
#include <linux/input.h>
#include <fcntl.h>
#include <unistd.h>

// 1. 打开触摸屏设备文件（第 22 章的文件 IO）
int fd = open("/dev/input/event2", O_RDONLY);
struct input_event ev;

// 2. 循环读取事件（每次 read 拿到一个 input_event 结构体）
while (read(fd, &ev, sizeof(ev)) == sizeof(ev)) {
    switch (ev.type) {
    case EV_ABS:
        if (ev.code == ABS_MT_POSITION_X) printf("X = %d\n", ev.value);
        if (ev.code == ABS_MT_POSITION_Y) printf("Y = %d\n", ev.value);
        if (ev.code == ABS_MT_TRACKING_ID) {
            if (ev.value >= 0) printf("按下 id=%d\n", ev.value);
            else               printf("抬起\n");
        }
        break;
    case EV_SYN:
        if (ev.code == SYN_REPORT) printf("--- 同步 ---\n");
        break;
    }
}
```

**必须先找到哪个 eventX 是触摸屏**（下一节）。

## 识别触摸屏设备

扫描 `/dev/input/`：

```c
int fd = open(path, O_RDWR);
unsigned long bits[64] = {};
// 查询支持的绝对轴
ioctl(fd, EVIOCGBIT(EV_ABS, sizeof(bits)), bits);

// 检查是否有 ABS_MT_POSITION_X 和 Y
bool hasX = bits[ABS_MT_POSITION_X / (8*sizeof(long))] &
            (1UL << (ABS_MT_POSITION_X % (8*sizeof(long))));
bool hasY = ...;

if (hasX && hasY) { /* 这是触摸屏 */ }
```

本项目 `TouchHelperA.cpp` 分两步：

**第一步 `checkDeviceIsTouch(fd)`**——用 `EVIOCGBIT` 查这个设备支持哪些绝对轴，
**必须同时有 `ABS_MT_SLOT`、`ABS_MT_POSITION_X`、`ABS_MT_POSITION_Y` 三个**才判定是触摸屏：

```cpp
// TouchHelperA.cpp：checkDeviceIsTouch（简化）
res = ioctl(fd, EVIOCGBIT(EV_ABS, bits_size), bits);   // 读出支持的 EV_ABS 位图
for (每个置位的轴) {
    if (轴 == ABS_MT_SLOT)        itmp  = true;   // 支持多点触控槽位
    if (轴 == ABS_MT_POSITION_X)  itmp2 = true;
    if (轴 == ABS_MT_POSITION_Y)  itmp3 = true;
}
return itmp && itmp2 && itmp3;                     // 三者齐全才是触摸屏
```

**第二步**——对通过判定的设备，用 `EVIOCGABS` 读出 X/Y 轴的取值范围，算出缩放系数：

```cpp
// TouchHelperA.cpp：Init（简化）
DIR *dir = opendir("/dev/input/");
for (每个 /dev/input/eventN) {
    int fd = open(temp, readOnly ? O_RDONLY : O_RDWR);
    if (fd < 0) continue;
    if (!checkDeviceIsTouch(fd)) { close(fd); continue; }

    ioctl(fd, EVIOCGABS(ABS_MT_POSITION_X), &device.absX);   // 读触摸轴量程(0~absX.maximum)
    ioctl(fd, EVIOCGABS(ABS_MT_POSITION_Y), &device.absY);
    device.S2TX = (float)screenW / device.absX.maximum;   // 触摸值 × S2TX = 屏幕 X
    device.S2TY = (float)screenH / device.absY.maximum;   // 触摸值 × S2TY = 屏幕 Y
    devices.push_back(device);
}
```

## 坐标转换

触摸屏的坐标系和屏幕分辨率**不一定相同**：

```
触摸屏硬件范围: 0 ~ 32767 (或 0 ~ 1080)
屏幕分辨率:     0 ~ 1080
```

需要缩放：

```c
struct input_absinfo absX;
ioctl(fd, EVIOCGABS(ABS_MT_POSITION_X), &absX);
// absX.minimum, absX.maximum, absX.value

float S2TX = (float)absX.maximum / (float)screenWidth;
int touchX = (int)(screenX * S2TX);
```

本项目：

> [!note] 先认识 `My_Vector2` —— 项目里的"第三套向量"
> 到目前为止你见过两套向量（第 45 章）：
> - `Vec2`/`Vec3`（`VectorTools.h`，数学层，小写字段）
> - `Vector2A`/`Vector3A`（`draw.h`，绘制层，大写字段）
>
> 项目里**还有第三套**：`My_Vector2`/`My_Vector3`/`My_Vector4`（`VectorStruct.h`，触摸层）。
> 触摸代码用它，因为它**运算符重载最完整**（支持 `+=`、一元负号等链式写法）。
>
> ```cpp
> struct My_Vector2 {
>     float x, y;
>     My_Vector2 operator+(const My_Vector2 &o) const { /* ... */ }
>     My_Vector2 &operator+=(const My_Vector2 &o) { /* ... */ }   // 返回引用，可链式
>     My_Vector2 operator-() const { /* ... */ }                  // 一元负号
> };
> ```
>
> **为什么有三套**：历史包袱。新代码该用哪套，看它属于哪一层——
> 数学计算用 `Vec3`，绘制用 `Vector3A`，**触摸用 `My_Vector2`**。

```cpp
My_Vector2 Touch::Touch2Screen(const My_Vector2 &coord) {
    // 触摸坐标 → 屏幕坐标
}
My_Vector2 Touch::GetScale() {
    // 返回 S2TX / S2TY
}
```

## 独占：EVIOCGRAB

读取触摸时，可以选择"独占"——
这样系统其它组件就收不到触摸了：

```c
ioctl(fd, EVIOCGRAB, 1);      // 独占
/* ... */
ioctl(fd, EVIOCGRAB, 0);      // 释放（UNGRAB）
```

本项目用于"转发"模式：

```
独占读取真实触摸 → 处理后 → 用 uinput 重新注入
```

这样可以在中间插入自己的处理（比如给 ImGui 用）。

> [!danger] 忘了 UNGRAB 会导致触摸失灵
> 程序崩溃时如果没释放，设备会**完全无法触摸**。
> 本项目在析构和错误处理里都做了 `UNGRAB`：
> ```cpp
> ioctl(device.fd, EVIOCGRAB, UNGRAB);
> ```
> 调试时如果触摸失灵，`adb shell input` 还能救急。

## 触摸与 ImGui 的对接

ImGui 只需要三个信息：

```cpp
struct ImGuiIO {
    ImVec2 MousePos;           // 当前位置
    bool   MouseDown[5];       // 按键状态
    float  MouseWheel;         // 滚轮
};
```

所以转发逻辑：

```cpp
void Touch::UpdateImGuiInput() {
    ImGuiIO &io = ImGui::GetIO();

    // 用第一个按下的手指作为"鼠标"
    bool anyDown = false;
    float x = 0, y = 0;
    for (auto &dev : devices) {
        for (auto &f : dev.Finger) {
            if (f.isDown) {
                if (!anyDown) { x = f.pos.x; y = f.pos.y; anyDown = true; }
            }
        }
    }

    if (anyDown) {
        io.MousePos = ImVec2(x, y);
        io.MouseDown[0] = true;
    } else {
        io.MouseDown[0] = false;
    }
}
```

本项目 `main.cpp` 每帧调用它：

```cpp
Touch::UpdateImGuiInput();
```

## 屏幕旋转

横竖屏切换时坐标要变换：

```cpp
void Touch::setOrientation(int orientation) {
    // orientation: 0=竖 1=横(90°) 2=倒竖(180°) 3=横(270°)
}
```

变换规则（对应真实源码 `TouchHelperA.cpp` 的 `Touch2Screen`，
默认 `otherTouch = false` 分支）：

| orientation | 触摸 (tx,ty) → 屏幕 (sx,sy) |
|---|---|
| 0 | `(xt, yt)` |
| 1 | `(yt, screenSize.y - xt)` |
| 2 | `(screenSize.y - xt, screenSize.x - yt)` |
| 3 | `(screenSize.x - yt, xt)` |

> [!note] 项目里的 `screenSize` 是"排序后"的尺寸
> 项目在 `UpdateDisplayMetricsUnlocked` 里做了排序：
> `screenSize = size.x > size.y ? size : {size.y, size.x}`，
> 即 **`screenSize.x` 恒为较大值（高）、`screenSize.y` 恒为较小值（宽）**。
> 所以上面表里的 `screenSize.y` 相当于"宽 W"，`screenSize.x` 相当于"高 H"。
> 项目还维护 `otherTouch` 开关（另一套分支），用于特殊触摸模式。

```cpp
static int32_t orientation = -1;
if (orientation != displayInfo.orientation) {
    orientation = displayInfo.orientation;
    Touch::setOrientation(displayInfo.orientation);
}
```

## 动手：触摸监视器

```c
#include <stdio.h>
#include <fcntl.h>
#include <unistd.h>
#include <linux/input.h>
#include <dirent.h>
#include <string.h>
#include <sys/ioctl.h>

int main(void) {
    // 找一个有 ABS_MT_POSITION_X 的设备
    char path[64];
    int found = -1;
    for (int i = 0; i < 32; i++) {
        snprintf(path, sizeof(path), "/dev/input/event%d", i);
        int fd = open(path, O_RDONLY);
        if (fd < 0) continue;
        struct input_absinfo info;
        if (ioctl(fd, EVIOCGABS(ABS_MT_POSITION_X), &info) == 0) {
            printf("找到触摸屏: %s (范围 %d~%d)\n", path, info.minimum, info.maximum);
            found = fd;
            break;
        }
        close(fd);
    }
    if (found < 0) { printf("没找到触摸屏（需要 root）\n"); return 1; }

    printf("监视中，触摸屏幕试试...\n");
    struct input_event ev;
    int touchX = 0, touchY = 0, down = 0;
    while (read(found, &ev, sizeof(ev)) == sizeof(ev)) {
        if (ev.type == EV_ABS) {
            if (ev.code == ABS_MT_POSITION_X) touchX = ev.value;
            if (ev.code == ABS_MT_POSITION_Y) touchY = ev.value;
            if (ev.code == ABS_MT_TRACKING_ID) down = (ev.value >= 0);
        } else if (ev.type == EV_SYN && ev.code == SYN_REPORT) {
            printf("%s (%d, %d)\n", down ? "按下" : "抬起", touchX, touchY);
        }
    }
    close(found);
    return 0;
}
```

以 root 运行，触摸屏幕，观察输出。

再用 `adb shell getevent -l` 对比一下，确认你读的设备是对的。
