# 第 57 章 · 图形管线概览

> [!abstract] 本章目标
> 建立"从三角形数据到屏幕像素"的完整心智模型。
> 后面 Vulkan 的几十个 API 调用，都是这条管线上的零件。

> [!note] 承上
> 卷四把"三维世界"算成了"屏幕坐标"。从卷五起**真的画到屏幕上**。
> 本章先建立图形管线的完整心智模型——后面 Vulkan 的几十个 API 都是这条线上的零件。

## 先看一个 ImGui 按钮是怎么变成像素的

你在代码里写：

```cpp
if (ImGui::Button("确定")) { ... }
```

到屏幕出现一个按钮，中间发生了这些事：

```
① 顶点生成    ImGui 算出按钮四个角的坐标 + UV + 颜色
② 顶点着色器  把 2D 坐标变换到裁剪空间
③ 图元装配    四个顶点组装成两个三角形
④ 光栅化      三角形覆盖哪些像素？逐像素插值 UV 和颜色
⑤ 片元着色器  每个像素查字体图集，得到最终颜色
⑥ 混合测试    透明度混合、深度测试
⑦ 输出到帧缓冲 → 交换链 → 屏幕
```

**七个阶段，就是图形管线。**

> [!note] 上面第 ⑤ 步提到的"字体图集"是什么
> 字体图集（font atlas）= 把所有字符的图形**预先烘焙到一张大图**上。
> 渲染文字时，按字符查表找到它在图集里的位置，取那一小块（UV）贴上去。
> 这样一次纹理绑定就能画所有字，不用每字一张图。第 63 章会详讲。

## 逐阶段拆解

### ① 顶点数据（Vertex Data）

一个顶点不只有位置：

```cpp
struct ImDrawVert {
    ImVec2 pos;      // 位置（这里是 2D 屏幕坐标）
    ImVec2 uv;       // 纹理坐标
    ImU32  col;      // 颜色（RGBA 打包成 32 位）
};
```

ImGui 每帧生成成千上万个这样的结构体，存进**顶点缓冲**。

索引缓冲存的是"哪些顶点组成三角形"：

```cpp
// 一个矩形 = 两个三角形 = 6 个索引
ImDrawIdx idx[] = {0, 1, 2,  0, 2, 3};
```

> [!note] 为什么用索引
> 矩形 4 个顶点，如果不用索引要存 6 个（每个三角形 3 个）。
> 复杂网格共享顶点更多，索引能省大量空间。

### ② 顶点着色器（Vertex Shader）

> [!note] 先补一课：着色器（Shader）是什么
> 前面的管线步骤都在"搬运数据"，而**真正做计算的是着色器**。
> **着色器 = 一段跑在 GPU 上的小程序**。它用一种专门的语言写，叫 **GLSL**
> （OpenGL Shading Language，OpenGL 着色语言，语法很像 C）。
> 它和你写的 C/C++ 关系是：
> - 你用 C/C++ 把着色器源码**编译成 GPU 能执行的字节码**（SPIR-V），存进程序；
> - 渲染时 GPU 对**每个顶点/每个像素**并行跑一遍这段小程序。
>
> 本卷只涉及两个着色器：
>
> | 着色器 | 跑几次 | 干什么 |
> |---|---|---|
> | **顶点着色器**（Vertex Shader） | 每个顶点一次 | 算这个顶点最终在屏幕的哪个位置 |
> | **片元着色器**（Fragment Shader） | 每个像素一次 | 算这个像素最终是什么颜色 |

**GLSL 代码长什么样**——这是本项目真实的顶点着色器（`imgui_impl_vulkan.cpp`）：

```glsl
#version 450
layout(location = 0) in vec2 aPos;        // 输入：顶点位置
layout(location = 1) in vec2 aUV;         // 输入：纹理坐标
layout(location = 2) in vec4 aColor;      // 输入：顶点颜色

layout(push_constant) uniform uPushConstant {
    vec2 uScale;        // 缩放（由 CPU 传进来）
    vec2 uTranslate;    // 平移（由 CPU 传进来）
} pc;

void main() {
    gl_Position = vec4(aPos * pc.uScale + pc.uTranslate, 0, 1);
}
```

几个关键点（**看到就认识即可，不必会写**）：

| 写法 | 含义 |
|---|---|
| `in` / `out` | 输入 / 输出变量。顶点着色器的输出会传给片元着色器 |
| `layout(location = N)` | 给这个输入/输出**编号**，C++ 那边靠编号把数据送进来 |
| `uniform` | **所有顶点共享、由 CPU 每次绘制传进来的值**（缩放、平移等） |
| `gl_Position` | **顶点着色器唯一必须输出的东西**——这个顶点在"裁剪空间"里的位置 |
| `vec2` / `vec4` | 2 个 / 4 个 float 的向量，如 `vec4(x,y,z,w)` |

一句话：**着色器 = GPU 上的小程序，GLSL 是它的语言，`gl_Position` 是它算出来的屏幕位置。**

顶点着色器对每个顶点执行一次，主要做坐标变换。最简形式就是"4×4 矩阵乘顶点"：

```glsl
void main() {
    gl_Position = MVP * vec4(position, 1.0);   // 4×4 矩阵乘顶点
}
```

对 ImGui 来说，这一步就是把 2D 像素坐标映射到 `[-1,1]` 的正交投影。

本项目（真实源码 `imgui_impl_vulkan.cpp`）**没有用 4×4 矩阵**，
而是把正交投影压缩成 **4 个 float（scale + translate）**，通过 push constant 传给顶点着色器。

> [!note] push constant 是什么
> 着色器里的 `uniform`（共享值）需要 CPU 传进去。传的方式有几种，**push constant** 是最轻量的一种：
> **把一小段数据（本项目是 4 个 float）直接"塞"进命令缓冲，随绘制命令一起发给 GPU**，
> 不需要额外的内存缓冲、不需要描述符，快且简单。代价是**容量很小**（Vulkan 保证至少 128 字节），
> 但对"只传一个缩放+平移"来说绰绰有余。
>
> 本项目那 4 个 float，就对应顶点着色器里的 `vec2 uScale; vec2 uTranslate;`（见上面 GLSL 里的 `push_constant` 块）。

```cpp
// 真实源码 imgui_impl_vulkan.cpp：Setup scale and translation
float constants[4];
constants[0] = 2.0f / draw_data->DisplaySize.x; // Scale X
constants[1] = 2.0f / draw_data->DisplaySize.y; // Scale Y
constants[2] = -1.0f - draw_data->DisplayPos.x * constants[0]; // Translate X
constants[3] = -1.0f - draw_data->DisplayPos.y * constants[1]; // Translate Y
vkCmdPushConstants(command_buffer, bd->PipelineLayout,
                   VK_SHADER_STAGE_VERTEX_BIT, 0, sizeof(float) * 4, constants);
```

顶点着色器里就一步：

```glsl
gl_Position = vec4(aPos * pc.uScale + pc.uTranslate, 0, 1);
```

**为什么可以这么省**：ImGui 只需要正交投影，横向和纵向各是一个"缩放 + 平移"，
没有旋转、没有透视，所以 4×4 矩阵的其余元素全是 0，直接用两个 `vec2`（共 4 个 float）表达即可。
`2/DisplaySize` 把 `[0, 屏幕宽]` 映射到 `[-1,1]`；`-1` 是把它平移到 `[-1,1]` 区间。

### ③ 图元装配（Primitive Assembly）

把顶点按索引组装成三角形：

```cpp
VkPrimitiveTopology topology = VK_PRIMITIVE_TOPOLOGY_TRIANGLE_LIST;
```

常见拓扑：

| 拓扑 | 含义 | 用途 |
|---|---|---|
| `TRIANGLE_LIST` | 每 3 个顶点一个三角形 | 通用（ImGui 用） |
| `TRIANGLE_STRIP` | 复用前两个顶点 | 省索引 |
| `LINE_LIST` | 每 2 个顶点一条线 | **画骨骼线框** |
| `POINT_LIST` | 每个顶点一个点 | 点云 |

本项目画骨骼用的是 `AddLine`（最终变成退化三角形或线列表），
画 PhysX 网格用的是 `AddTriangle`。

### ④ 光栅化（Rasterization）

**把三角形变成一堆像素。**

```
   顶点A
    /\
   /  \      三角形覆盖的像素：
  /____\     ■■■■■
 B      C    ■■■■■■
             ■■■■■■■
```

对每个被覆盖的像素，**插值**出它的 UV 和颜色。

> [!note] 什么是"插值"，为什么需要它，以及"重心坐标"
> 顶点上带的数据（UV、颜色）是**在三角形三个角上**的。但我们要给三角形**内部的每个像素**都算出一个 UV/颜色，
> 这个"从三个角推算内部任意一点的值"的过程就叫**插值**。
>
> 怎么插？用**重心坐标（barycentric coordinates）**。可以这样理解：
> 三角形内任意一点 P，都能写成三个顶点的"加权平均"：
> ```
> P = w0 × A + w1 × B + w2 × C      且 w0 + w1 + w2 = 1
> ```
> 这三个权重 `(w0, w1, w2)` 就是 P 的重心坐标：
> - 点在顶点 A 上 → `(1, 0, 0)`；在中心 → `(1/3, 1/3, 1/3)`；在三角形外 → 会出现负数。
> - **判断"点是否在三角形内"就看：三个权重是否都 ≥ 0**。
>
> 拿到权重后，任何顶点属性都能插值——比如颜色 `P.color = w0×A.color + w1×B.color + w2×C.color`。
> 第 62 章的 CPU 后端会用这个公式，到时候对照着看就懂了。

### ⑤ 片元着色器（Fragment Shader）

对每个像素执行一次：

```glsl
void main() {
    outColor = texture(fontAtlas, uv) * color;
}
```

ImGui 的字体是**一张大图集**（所有字形拼在一张纹理上），
片元着色器按 UV 取对应区域，乘上顶点颜色。

> [!note] 上面 GLSL 里的 `texture(fontAtlas, uv)` 是什么
> - **纹理（texture）** = 一张"贴图"（这里就是字体图集那张大图）。
> - `texture(纹理, uv)` 是 GLSL 内置函数：**按坐标 `uv` 从纹理里取一个颜色**。
>   `uv` 是 0~1 的比例坐标（`(0,0)` 是左上、`(1,1)` 是右下），
>   所以每个顶点带的 UV，决定了它对应图集里的哪一小块。
> - `outColor` 是片元着色器的输出——这个像素最终的颜色。

### ⑥ 混合与测试

**Alpha 混合**：半透明怎么叠加

```cpp
// 标准 alpha 混合
finalColor = srcColor * srcAlpha + dstColor * (1 - srcAlpha);
```

Vulkan 配置：

```cpp
VkPipelineColorBlendAttachmentState blend = {};
blend.blendEnable = VK_TRUE;
blend.srcColorBlendFactor = VK_BLEND_FACTOR_SRC_ALPHA;
blend.dstColorBlendFactor = VK_BLEND_FACTOR_ONE_MINUS_SRC_ALPHA;
blend.colorWriteMask = VK_COLOR_COMPONENT_R_BIT | ... ;
```

**深度测试**：远的像素丢弃（第 52 章）

ImGui 通常**关闭**深度测试（2D UI 按绘制顺序叠加）。

### ⑦ 帧缓冲与输出

> [!note] 帧缓冲（Framebuffer）是什么
> **帧缓冲** = "这次渲染要往哪张图像写"的绑定。它把若干张**图像**（颜色附件、深度附件等）
> 打包起来，作为渲染的目标。你往帧缓冲里画，就是往它绑定的图像上画。
> 第 59 章会看到，交换链里的每张图像都配一个帧缓冲；渲染时选一个帧缓冲，画完再呈现。

渲染结果写入 `VkFramebuffer` 关联的图像，
然后通过**交换链**呈现到窗口。

## 管线的两种：图形 vs 计算

| | 图形管线 | 计算管线 |
|---|---|---|
| 输入 | 顶点数据 | 任意数据 |
| 着色器 | 顶点 + 片元（+几何/曲面） | 只有 compute |
| 输出 | 帧缓冲 | 缓冲/图像 |
| 用途 | 画图 | GPGPU（如 Embree 的某些加速） |

本项目只用图形管线。

## Vulkan 里的"管线状态对象"

OpenGL 是"状态机"，随时改状态：

```cpp
glEnable(GL_BLEND);
glBlendFunc(...);
glUseProgram(shader);
```

Vulkan 要求**提前把所有状态打包成一个对象**：

```cpp
VkGraphicsPipelineCreateInfo info = {};
info.stageCount = 2;
info.pStages = shaderStages;          // 顶点 + 片元着色器
info.pVertexInputState = &vertexInput;
info.pInputAssemblyState = &inputAssembly;
info.pRasterizationState = &rasterizer;
info.pColorBlendState = &blending;
info.layout = pipelineLayout;
info.renderPass = renderPass;

vkCreateGraphicsPipelines(device, cache, 1, &info, nullptr, &pipeline);
```

**好处**：驱动可以提前优化整条管线，运行时切换极快。
**代价**：初始化代码极长（本项目 `VulkanGraphics.cpp` 有几百行）。

> [!tip] 这是 Vulkan "啰嗦"的根源
> 一个三角形要写 1000 行初始化代码，不是 Vulkan 故意为难你，
> 而是它把 OpenGL 驱动在运行时偷偷做的事，全部交给你显式声明。
> 换来的是可预测的性能。

## 坐标系统回顾

```
局部空间 (Local)
    ↓ model 矩阵
世界空间 (World)
    ↓ view 矩阵
相机空间 (View)
    ↓ projection 矩阵
裁剪空间 (Clip)          ← 顶点着色器输出 gl_Position
    ↓ 透视除法 /w
NDC 空间 (-1..1)
    ↓ 视口变换
屏幕空间 (像素)
```

第 50、51 章手算的就是最后三步。
**渲染管线做的和我们手算的完全一致**——
区别只是它由 GPU 并行执行几百万次。

## 本项目处在管线的哪一步

本项目的覆盖层**不走完整管线**：

```
本项目：
  读内存 → CPU 算 W2S → ImGui 生成 2D 屏幕坐标 → 交给 ImGui 后端 → GPU 画出来
                            ↑
                    已经是我们手算好的像素坐标

游戏自己：
  3D 模型 → GPU 顶点着色器 → 光栅化 → 屏幕
```

**关键区别**：游戏是从 3D 顶点开始，本项目是从 **2D 屏幕坐标**开始。
所以本项目的"顶点着色器"只是一个简单的正交变换——
所有 3D→2D 的活儿都在 CPU 上用第 51 章的 W2S 做完了。

> [!note] 这也解释了为什么覆盖层性能好
> 不用传 3D 模型、不用做复杂的顶点变换，
> 每帧只有几万个 2D 三角形，GPU 负担极小。
> 真正的开销在 CPU 侧的内存读取（第 81 章会优化它）。

## 动手：用 CPU 模拟一次光栅化

不用 GPU，纯 C 代码画一个三角形，理解第 ④ 步：

```c
#include <stdio.h>
#include <string.h>

#define W 40
#define H 20
static char canvas[H][W];

// 判断点 p 是否在三角形 abc 内（重心坐标法）
static float sign(float ax, float ay, float bx, float by, float px, float py) {
    return (bx - ax) * (py - ay) - (by - ay) * (px - ax);
}

static int in_triangle(float ax, float ay, float bx, float by,
                       float cx, float cy, float px, float py) {
    float d1 = sign(ax,ay, bx,by, px,py);
    float d2 = sign(bx,by, cx,cy, px,py);
    float d3 = sign(cx,cy, ax,ay, px,py);
    int has_neg = (d1 < 0) || (d2 < 0) || (d3 < 0);
    int has_pos = (d1 > 0) || (d2 > 0) || (d3 > 0);
    return !(has_neg && has_pos);
}

int main(void) {
    memset(canvas, ' ', sizeof(canvas));

    // 三角形（屏幕坐标，y 向下）
    float ax = 5,  ay = 2;
    float bx = 35, by = 8;
    float cx = 15, cy = 18;

    // 遍历每个像素中心
    for (int y = 0; y < H; y++) {
        for (int x = 0; x < W; x++) {
            float px = x + 0.5f, py = y + 0.5f;
            if (in_triangle(ax,ay, bx,by, cx,cy, px,py))
                canvas[y][x] = '*';
        }
    }

    for (int y = 0; y < H; y++) {
        canvas[y][W-1] = 0;
        printf("%s\n", canvas[y]);
    }
    return 0;
}
```

跑起来你会看到一个 ASCII 三角形。**这就是光栅化**——
GPU 做的本质上就是这件事，只不过并行处理 200 万个像素。

## 综合练习：从三角形数据到屏幕像素（跨章）

这道题串起**卷五 57~66 章 + 卷四数学 + 卷八几何**，是整个 overlay 的缩影。
建议学完卷五后做。

### 任务要求

用你写过的组件，把一个世界坐标的三角形**画到 Android 屏幕上**：

1. **数学**（卷四）：用 `mathlib` 的 `Camera::WorldToScreen` 把三角形 3 个顶点的世界坐标投影成屏幕坐标
2. **组装图元**（第 57、61 章）：把 3 个屏幕坐标 + 颜色塞进一个 `ImDrawList`，用 `AddTriangleFilled` 画一个实心三角形
3. **提交渲染**（第 62 章）：把 `ImDrawData` 交给 Vulkan 后端（`ImGui_ImplVulkan_RenderDrawData`）
4. **显示**（第 59、64 章）：交换链提交 → SurfaceFlinger 合成 → 屏幕

### 核心代码骨架

```cpp
// 假设 overlay 已初始化好（卷五第 58-66 章的成果）
void DrawWorldTriangle(ImDrawList* draw, const Camera& cam,
                       Vec3 w0, Vec3 w1, Vec3 w2, ImU32 color) {
    // ① 世界坐标 → 屏幕坐标（卷四）
    Vec2 s0, s1, s2;
    if (!cam.WorldToScreen(w0, &s0) ||
        !cam.WorldToScreen(w1, &s1) ||
        !cam.WorldToScreen(w2, &s2)) {
        return;   // 任一点在相机后方或无效，整条跳过
    }

    // ② 组装成三角形图元（第 57、61 章）
    draw->AddTriangleFilled(
        ImVec2(s0.x, s0.y),
        ImVec2(s1.x, s1.y),
        ImVec2(s2.x, s2.y),
        color);
}
```

### 验证清单（逐层确认）

- [ ] **数学层**：写 `main` 用固定相机 + 固定三角形，调用 `DrawWorldTriangle` 的投影部分，打印 3 个屏幕坐标（不依赖 Android）
- [ ] **投影正确性**：三角形在相机正前方时，3 点应大致在屏幕中心附近；相机后方时 `WorldToScreen` 返回 `false`
- [ ] **图元层**：用第 62 章的 CPU 渲染后端，把 `ImDrawList` 的顶点数打印出来（一个三角形 = 3 顶点 / 3 索引）
- [ ] **数据流层**：打印 `ImDrawData` 的 `TotalVtxCount` / `TotalIdxCount`，确认三角形被算进去了
- [ ] **显示层**（需设备）：在 overlay 上看到一个实心三角形，颜色正确，随相机转动而移动

### 参考实现（离线验证部分，可在电脑上跑）

```cpp
#include <cstdio>
#include <cmath>
#include <cassert>

constexpr float PI = 3.14159265358979323846f;
struct V3 { float x, y, z; };
struct V2 { float x, y; };

bool W2S(V3 p, float hw, float hh, V2* out) {
    if (p.x < 0.001f) return false;
    float t = tanf(90.0f * 0.5f * PI / 180.0f);
    out->x = ((p.y / t) / p.x + 1.0f) * hw;
    out->y = (1.0f - (p.z / t) / p.x) * hh;
    return true;
}

int main() {
    float hw = 1080, hh = 1200;
    V3 tri[3] = { {100, -50, -50}, {100, 50, -50}, {100, 0, 50} };
    V2 scr[3];
    int drawn = 0;
    for (int i = 0; i < 3; i++)
        if (W2S(tri[i], hw, hh, &scr[i])) drawn++;
    assert(drawn == 3);                          // 3 点都在前方
    printf("三角形 3 顶点屏幕坐标:\n");
    for (int i = 0; i < 3; i++)
        printf("  (%.1f, %.1f)\n", scr[i].x, scr[i].y);
    // 1 个三角形 = 3 顶点（ImDrawList 内部会拆成 1 个三角形，3 索引）
    printf("图元统计: 顶点=%d 索引=%d\n", 3, 3);
    printf("综合练习（离线部分）通过\n");
    return 0;
}
```

> [!tip] 这道综合题的意义
> 它把"世界坐标 → 屏幕像素"这条 7 步链路（第 01 章那张图）缩成一个小三角形：
> **卷四算坐标 → 卷五画像素**。做完你就能理解 overlay 里每个方框是怎么来的。
> 毕业项目（第 100 章）只是把 1 个三角形扩展成几百个箱子和骨骼连线。
