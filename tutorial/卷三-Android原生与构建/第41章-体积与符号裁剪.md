# 第 41 章 · 体积与符号裁剪

> [!abstract] 本章目标
> 掌握 `-ffunction-sections` / `--gc-sections` / `-flto` / `strip` 四件套，
> 并知道调试时该关掉哪个。本项目 `APP_LDFLAGS` 就是这四件套。

## 先看效果

同一个程序，不同配置：

| 配置 | 大小 |
|---|---|
| 默认 `-O2` | 12.4 MB |
| + `-ffunction-sections -fdata-sections -Wl,--gc-sections` | 10.1 MB |
| + `-flto` | 8.7 MB |
| + `-s`（strip） | 6.2 MB |

四个选项，体积减半。

## 原理：节（section）是裁剪的最小单位

编译器默认把**一个源文件**的所有函数放进一个 `.text` 节。
链接器只能按"整个 `.o`"决定要不要（第 28 章）。

```
默认：
main.o  ──→  .text 包含 [main, unused_func1, unused_func2, ...]
             ↑ 只要用了 main，整个 .text 都进来

加 -ffunction-sections：
main.o  ──→  .text.main
             .text.unused_func1
             .text.unused_func2
             ↑ 每个函数独立成节，可以单独丢弃
```

| 选项 | 作用 |
|---|---|
| `-ffunction-sections` | 每个函数单独一节 |
| `-fdata-sections` | 每个全局变量单独一节 |
| `-Wl,--gc-sections` | 链接时丢弃"从任何根都不可达"的节 |

三者必须**配合**使用：前两个负责切分，第三个负责丢弃。

## 本项目里的配置

```makefile
# Application.mk
APP_CPPFLAGS := ... -fdata-sections -ffunction-sections ...
APP_LDFLAGS := -flto -Wl,--gc-sections -s
```

注意分工：
- 编译选项（`-f*-sections`）放 `APP_CPPFLAGS`
- 链接选项（`--gc-sections`）放 `APP_LDFLAGS`，且要 `-Wl,` 前缀

> [!note] `-Wl,` 是什么
> 编译器（clang）不认识 `--gc-sections` 这种链接器选项，
> `-Wl,` 表示"把这个原样传给链接器 ld"。
> 多个选项：`-Wl,--gc-sections,--as-needed`

## LTO：链接时优化

常规编译：每个 `.cpp` 独立编译成 `.o`，编译时看不到别的文件。

LTO：`.o` 里存的是**中间表示（LLVM IR）**而不是机器码，
链接时统一优化，能跨文件内联、删除死代码。

```
普通：  a.cpp → a.o(机器码) ┐
        b.cpp → b.o(机器码) ┴→ 链接 → app

LTO：   a.cpp → a.o(IR)     ┐
        b.cpp → b.o(IR)     ┴→ 链接时统一优化 → app
```

收益：
- 跨文件内联（小函数不再有调用开销）
- 更彻底的死代码消除
- 体积通常减少 10~30%

代价：
- 编译**慢很多**（内存占用也高）
- 调试信息可能不准

> [!tip] 调试时关掉 LTO
> ```makefile
> # APP_LDFLAGS := -flto -Wl,--gc-sections -s
> APP_LDFLAGS := -Wl,--gc-sections
> ```
> 定位崩溃时，LTO 会让 `addr2line` 给出的行号偏差较大。

## strip：删掉符号表

```bash
# 链接时直接 strip
APP_LDFLAGS += -s

# 或事后 strip
aarch64-linux-android-strip app

# 或保留调试信息到单独文件（推荐）
aarch64-linux-android-objcopy --only-keep-debug app app.debug
aarch64-linux-android-strip --strip-debug app
# 之后用 app.debug 来 addr2line
```

strip 删掉什么：

| 保留 | 删除 |
|---|---|
| `.text`（代码） | `.symtab`（符号表） |
| `.rodata` | `.debug_*`（调试信息） |
| `.dynamic` | `.strtab` |
| `.dynsym`（动态链接必需） | 注释节 |

> [!danger] strip 后 addr2line 失效
> 第 30 章讲过。正确做法：
> 1. 先备份未 strip 的版本
> 2. 或 `objcopy --only-keep-debug` 分离
> 3. 或调试期直接去掉 `-s`

## 推荐的双配置方案

```makefile
# Application.mk
ifeq ($(NDK_DEBUG),1)
    APP_OPTIM := debug
    APP_CPPFLAGS += -g
    APP_LDFLAGS :=              # 不加 -flto（编译快、定位准）
else
    APP_OPTIM := release
    APP_LDFLAGS := -flto -Wl,--gc-sections -s
endif
```

用法：

```bash
ndk-build NDK_DEBUG=1      # 调试版
ndk-build                  # 发布版
```

## 分析体积构成

**1. 按节看**

```bash
aarch64-linux-android-size -A app
# section              size      addr
# .text              1234568         0
# .rodata             456789         0
# .data                 1234         0
# .bss                 56789         0
```

**2. 按符号看**

```bash
aarch64-linux-android-nm --size-sort -S -C app | tail -30
```

找出最大的函数和最大的数据。

**3. 找重复/无用**

```bash
# 有没有链接进来的大库
aarch64-linux-android-nm -C app | grep -o 'std::__ndk1::[a-z_]*' | sort | uniq -c | sort -rn | head
```

## 本项目里最大的东西

按经验排序：

> [!note] 表里的两个缩写
> - **BVH = Bounding Volume Hierarchy**（包围体层次结构）：一种把一堆三角形组织成树、加速"射线求交"的数据结构。Embree 的核心就是它（第 96、97 章会讲）。
> - **SIMD = Single Instruction Multiple Data**（单指令多数据）：一条指令同时算多个数，常用于向量/矩阵加速（如一次算 4 个 float）。
>
> 两者都是"用空间或并行换速度"的技术，实现代码体积不小。

| 内容 | 大约 |
|---|---|
| Embree（BVH 构建 + 遍历 + SIMD） | 3~8 MB |
| libc++ 静态部分 | 1~2 MB |
| ImGui 核心（imgui/draw/tables/widgets 4 个） | 500 KB ~ 1 MB |
| **黑体字体数组 `heiti_ttf.cpp`** | **3~10 MB** ★ |
| Vulkan 后端 + 自有代码 | 几百 KB |

**字体往往是最大的单项。**

> [!tip] 字体的裁剪方法
> 完整中文字体 5~10 MB。可以只保留常用字：
> 1. 用 `fonttools` 的 `pyftsubset` 按字符集裁剪
> 2. ImGui 的 `AddFontFromMemoryTTF` 只加载指定 GlyphRange
> 3. 或者只保留项目 UI 里实际用到的几百个字
>
> 本项目用的是 `GetGlyphRangesChineseFull`（全量），
> 所以字体文件很大。这是可以优化的点。

## 其它减小体积的手段

| 手段 | 效果 | 代价 |
|---|---|---|
| `-Os`（优化体积） | 5~15% | 性能略降 |
| `--icf=all`（合并相同函数） | 5~10% | 需要 LTO |
| `-fno-exceptions -fno-rtti` | 10~20% | 语言特性受限 |
| 裁剪字体 | 几 MB | — |
| 去掉未用的第三方功能 | 视情况 | — |
| 压缩（UPX 等） | 50%+ | 启动慢、易被误报 |

```makefile
# 体积优先
LOCAL_CPPFLAGS += -Os
LOCAL_LDFLAGS  += -Wl,--icf=all
```

## 检查是否真的裁剪了

```bash
# 看有没有明显不该在的函数
aarch64-linux-android-nm -C app | grep -i 'imgui.*demo\|ShowDemo' 
# 如果启用了 IMGUI_DISABLE_DEMO_WINDOWS 应该没有

# 看节的数量（开了 function-sections 会很多）
aarch64-linux-android-readelf -S app | grep -c '\.text\.'
```
