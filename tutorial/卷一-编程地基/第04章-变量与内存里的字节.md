# 第 04 章 · 变量与内存里的字节

> [!abstract] 本章目标
> 建立"变量 = 一块有地址的内存"这个直觉，并亲手把内存里的字节打印出来。
> 这是理解本项目全部数据解析的基础。

## 先看一段能"看见内存"的代码

```c
#include <stdio.h>

int main(void) {
    int hp = 1000;
    unsigned char *p = (unsigned char *)&hp;

    printf("变量 hp 的地址：%p\n", (void *)&hp);
    printf("它占 %zu 字节，每个字节是：\n", sizeof(hp));
    for (int i = 0; i < sizeof(hp); i++) {
        printf("  [%d] 0x%02X  (%u)\n", i, p[i], p[i]);
    }
    return 0;
}
```

在你的机器上输出类似这样：

```
变量 hp 的地址：0x5FFE3C
它占 4 字节，每个字节是：
  [0] 0xE8  (232)
  [1] 0x03  (3)
  [2] 0x00  (0)
  [3] 0x00  (0)
```

1000 的十六进制是 `0x000003E8`。内存里存的是 `E8 03 00 00`——**低字节在前**。
这个现象叫"小端序"（第 24 章会展开讲，**现在不用深究**，只要记住这个画面）：
**内存是一排带编号的格子，每格 1 字节。**

## 类型 = 一次读几格 + 怎么解释

| 类型 | 字节数 | 值的范围 | 用途 |
|---|---|---|---|
| `char` / `int8_t` | 1 | -128 ~ 127 | 单字节、字符串 |
| `unsigned char` / `uint8_t` | 1 | 0 ~ 255 | **读内存时用这个** |
| `short` / `int16_t` | 2 | -32768 ~ 32767 | |
| `int` / `int32_t` | 4 | ±21 亿 | 通用整数 |
| `long long` / `int64_t` | 8 | 很大 | **地址、指针** |
| `float` | 4 | 6~7 位有效数字 | 坐标、角度 |
| `double` | 8 | 15~16 位 | 高精度计算 |

> [!warning] 别用 `int` 存地址
> 在 64 位系统上地址是 8 字节，`int` 通常只有 4 字节，会截断。
> 本项目里所有地址都用 `uintptr_t` 或 `uint64_t`（见 `driver.h`）。
> 这是一个会导致"莫名其妙读错数据"的经典 bug。

## 固定宽度类型：用 `stdint.h`

`int` 在 Windows 是 4 字节，在某些嵌入式平台是 2 字节。写跨进程程序时这不可接受。

```c
#include <stdint.h>

int32_t  hp;      // 一定是 4 字节
uint64_t address; // 一定是 8 字节
uint8_t  byte;    // 一定是 1 字节
```

本项目全部使用固定宽度类型，因为读出来的每个字段的字节数必须**精确**匹配：

```c
// 真实代码：从目标进程读一个 4 字节的 FOV
相机FOV = dr->Read<float>(static_cast<uintptr_t>(玩家相机) + 0x2318);
//        只差一个偏移或类型，读出来的就是垃圾
```

## sizeof 是你的朋友

```c
printf("char=%zu short=%zu int=%zu long=%zu ptr=%zu float=%zu double=%zu\n",
       sizeof(char), sizeof(short), sizeof(int), sizeof(long),
       sizeof(void*), sizeof(float), sizeof(double));
```

在 64 位环境典型输出：

```
char=1 short=2 int=4 long=4 ptr=8 float=4 double=8
```

注意 `long` 在 Windows 是 4 字节、Linux 64 位是 8 字节。**所以别用 `long` 存地址**——本项目里那些 `long int libUE4` 是历史写法，在 64 位 Linux/Android 上恰好是 8 字节才没出事。

## 打印各类值的正确格式符

| 类型 | 格式符 | 错误后果 |
|---|---|---|
| `int` | `%d` | |
| `unsigned` | `%u` | |
| `long long` | `%lld` | 用 `%d` 会输出错值 |
| 地址/指针 | `%p`（转成 `void*`） | 用 `%d` 在 64 位会截断 |
| `size_t` | `%zu` | |
| 十六进制 | `%X` / `%llX`（配 `unsigned long long`） | |
| `float` | `%f` | `printf` 会把 float 提升成 double |

打印地址的标准写法：

```c
printf("Uworld: 0x%llx\n", (unsigned long long)Uworld);
```

本项目 GUI 里全是这种写法（`ImGui::Text("Uworld: 0x%llx", ...)`），因为 `%llx` 在所有平台都稳定。

## 有符号 vs 无符号的陷阱

```c
uint8_t a = 200;
int8_t  b = (int8_t)a;   // b 变成 -56，不是 200
```

同样一个字节 `0xC8`，解释方式不同，值就不同。读内存时你**必须知道**目标字段是有符号还是无符号。

另一个经典坑：

```c
if (strlen(s) - 10 < 0)   // 永远不成立！
```
`strlen` 返回 `size_t`（无符号），减 10 后下溢成巨大正数。

## 变量的存储期

```c
int global_hp = 100;        // 全局：程序启动时分配，结束时释放

void func(void) {
    int local_hp = 50;      // 局部（栈）：进入函数分配，返回时销毁
    static int once = 0;    // 静态局部：只初始化一次，一直存在
    int *heap = malloc(sizeof(int));  // 堆：手动分配手动释放
}
```

| 存储期 | 位置 | 生命周期 | 谁负责释放 |
|---|---|---|---|
| 全局/静态 | 数据段 | 整个程序 | 系统 |
| 局部 | 栈 | 函数执行期 | 自动 |
| malloc | 堆 | 直到 free | **你** |

## 动手：写一个内存转储函数

这个函数你以后会一直用——把任意地址开始的 N 个字节打成十六进制：

```c
#include <stdio.h>
#include <stdint.h>

void hexdump(const void *addr, size_t len) {
    const uint8_t *p = (const uint8_t *)addr;
    for (size_t i = 0; i < len; i++) {
        if (i % 16 == 0) printf("\n%04zX  ", i);
        printf("%02X ", p[i]);
    }
    printf("\n");
}

int main(void) {
    int hp = 1000;
    hexdump(&hp, sizeof(hp));
    return 0;
}
```

输出：

```
0000  E8 03 00 00
```

把 `int` 换成 `float f = 3.14f` 再跑一次，你会看到 `C3 F5 48 40`——这就是 3.14 的 IEEE754 编码（第 26 章拆解它）。
