# 第 04 章 · 变量与内存里的字节

> [!abstract] 本章目标
> 建立"变量 = 一块有地址的内存"这个直觉，并亲手把内存里的字节打印出来。
> 这是理解本项目全部数据解析的基础。

> [!note] 承上
> 上一章你看到 `.c` 文件怎么变成可执行文件。
> 本章换个视角——**程序跑起来后，变量住在内存的哪里、长什么样**。

## 变量：给数据起个名字

第 03 章的 `demo.c` 里已经出现过 `int a = 5;`。这一节把它拆开讲透。

### 声明：创建一个"装数据的盒子"

```c
int a;         // 创建一个盒子，名字叫 a，里面装整数
```

这一行的三个部分：

```text
int  a  ;
│    │  └─ 分号：语句结束（第 02 章讲过，必须有）
│    └──── 变量名：你给这个盒子起的名字
└───────── 类型：告诉编译器"这个盒子装什么"
```

| 部分 | 作用 |
|---|---|
| 类型（`int`） | 决定这个盒子**能装什么**、**占多少字节**（后面"类型"一节详解） |
| 变量名（`a`） | 你起的名字，以后用这个名字访问盒子里的内容 |
| 分号（`;`） | 声明是一条语句，必须以 `;` 结束 |

**变量名（identifier，标识符）的规则**：

- 只能用**字母、数字、下划线** `_`
- **不能用数字开头**（`2a` 非法，`a2` 合法）
- 区分大小写（`a` 和 `A` 是两个不同的变量）
- 不能用 C 语言的**关键字**（如 `int`、`return`、`if`、`for`，这些词有特殊含义）

合法：`hp`、`player_x`、`_tmp`、`a2`、`世界坐标`（C++ 里允许中文，第 15 章讲）
非法：`2a`（数字开头）、`my-var`（有短横线）、`int`（关键字）

### 赋值：把值放进盒子

```c
a = 5;         // 把 5 放进 a 这个盒子
```

> [!danger] `=` 不是"等于"，是"把右边放进左边"
> 数学课上 `a = 5` 表示"a 和 5 相等"。
> 在 C 里，`a = 5;` 是一条**动作指令**："**把 5 存进 a 这个盒子**"。
> 执行完之后，`a` 里就是 5。
> 这个区别是新手最容易绕不过来的弯，务必想清楚。

看这段代码理解"赋值是一个动作"：

```c
int a;          // 建一个盒子，此刻里面是垃圾值（不确定）
a = 5;          // 把 5 放进去
printf("%d\n", a);   // 打印 a → 输出 5

a = 10;         // 再把 10 放进去，原来那个 5 被覆盖了
printf("%d\n", a);   // 打印 a → 输出 10
```

**同一个盒子可以被反复赋值，后写的覆盖先写的。**

> [!warning] 声明后不赋值，盒子里是"垃圾"
> `int a;` 之后，`a` 里不是 0，而是一个**不确定的值**（内存里那一格原来的内容）。
> 直接 `printf("%d\n", a)` 会打印出随机数。这叫"未初始化变量"。
> **规则：声明时就给初值。**

### 初始化：声明和赋值一起写

```c
int a = 5;      // 声明 + 初始化：建盒子的同时放进 5
```

这是最常用的写法。**推荐所有变量都这么写**，避免垃圾值。

### 声明多个变量

```c
int a = 5;
int b = 3;
int c = a + b;   // 右边可以用已经声明过的变量
```

也可以在一行里声明多个（**但本项目不推荐，可读性差**）：

```c
int a = 5, b = 3;      // 合法，但不推荐
```

### 动手：理解"盒子"模型

```c
#include <stdio.h>

int main(void) {
    int hp = 100;
    printf("初始 hp = %d\n", hp);

    hp = 80;
    printf("改成 80 后 hp = %d\n", hp);

    hp = hp - 20;   // 右边先算 hp - 20 = 60，再放回 hp
    printf("再减 20 后 hp = %d\n", hp);

    return 0;
}
```

输出：

```text
初始 hp = 100
改成 80 后 hp = 80
再减 20 后 hp = 60
```

特别看 `hp = hp - 20;` 这一行：它**不是**说"hp 等于 hp 减 20"，而是"**算出 hp - 20 的值，再存回 hp**"。
这是赋值与数学等式的根本区别。

## 类型：盒子装什么、有多大

C 里每个变量都必须有**明确的类型**。类型决定两件事：

1. **能装什么值**（整数？小数？字符？）
2. **在内存里占多少字节**（决定"这个盒子多大"）

### 四种最基本类型

| 类型 | 装什么 | 常见大小 | 例子 |
|---|---|---|---|
| `int` | 整数 | 4 字节 | `int hp = 100;` |
| `float` | 小数（单精度） | 4 字节 | `float x = 3.14f;` |
| `double` | 小数（双精度，更精确） | 8 字节 | `double pi = 3.14159265;` |
| `char` | 单个字符 | 1 字节 | `char c = 'A';` |

> [!note] `float` 后面的 `f` 是什么意思
> `float x = 3.14f;` 末尾那个 `f` 是告诉编译器"**这是 float 类型的字面量**"。
> 不写 `f`，编译器默认把小数字面量当 `double`，赋值给 `float` 时会有一个隐式转换（编译器可能警告）。
> **规矩**：写 `float` 变量时，小数末尾加 `f`。本项目全程遵守。

### `char` 与字符

`char` 装的是**一个字符**，用**单引号**包起来：

```c
char grade = 'A';      // 单引号：一个字符
char newline = '\n';   // 转义序列也可以（第 02 章讲过）
```

> [!danger] 单引号 vs 双引号，天差地别
> - `'A'` 是**字符**（`char` 类型，1 字节）
> - `"A"` 是**字符串**（一串字符，至少 2 字节：'A' 加一个"结束符"）
> 把 `char c = "A";` 写出来编译会警告——这是新手常见困惑。第 06 章会讲字符串。

> [!important] 字符本质上是数字（ASCII 编码）
> `char` 里存的其实是**一个 0~255 的整数**——只是我们约定某个数字代表某个字符。这个"数字↔字符"的对照表叫 **ASCII 码**。
> ```c
> char a = 'A';      // 实际上存的是 65
> char z = '0';      // 实际上存的是 48（字符零，不是数字 0！）
> ```
> 因为字符就是数字，所以**字符可以直接比较大小、做算术**：
> ```c
> char c = 'C';
> if (c >= 'A' && c <= 'Z') { /* 是大写字母 */ }
> ```
> 第 15 章判断"字符串是否全是数字"就用了这个：`ch >= '0' && ch <= '9'`。
> **记住**：字符 `'0'`（数字 48）和整数 `0` **不是一回事**。

### 常见整数类型

| 类型 | 大小 | 范围 | 备注 |
|---|---|---|---|
| `char` / `int8_t` | 1 字节 | -128 ~ 127 | 也常用来装小整数 |
| `short` / `int16_t` | 2 字节 | -32768 ~ 32767 | 少用 |
| `int` / `int32_t` | 4 字节 | 约 ±21 亿 | 最常用 |
| `long long` / `int64_t` | 8 字节 | 极大 | 装地址、时间戳 |

**具体范围**和**为什么有正负**，本章后面「有符号 vs 无符号的陷阱」一节会讲。
现在只要记住：**普通计数用 `int`，地址和大数用 `int64_t`/`uint64_t`。**

### 类型决定了什么

这三点在后面所有章节都会反复出现，先建立直觉：

| 类型决定 | 例子 |
|---|---|
| **一次读几个字节** | `int` 读 4 字节、`int64_t` 读 8 字节 |
| **怎么解释这些字节** | 同一串字节，按 `int` 读是整数，按 `float` 读是小数 |
| **能表示多大的数** | `int8_t` 最大 127，`int64_t` 能表示 900 亿亿 |

**这是第 04 章后面的核心，也是本项目"按偏移读内存"这件事的根基。**

### 更多常用类型：`bool`、`size_t`、`uintptr_t`

除了上面四种基础类型和整数类型，你还会经常遇到这三个：

#### `bool`：只有"真"和"假"

前面讲 `if` 时说过：**C 里没有专门的"布尔值"，用整数表示**（0 假，非 0 真）。

**C++ 补上了这个类型**，叫 `bool`：

```cpp
#include <cstdbool>   // C 里是 <stdbool.h>；C++ 里其实不用包含

bool alive = true;      // 真
bool dead  = false;     // 假

if (alive) { /* ... */ }
```

| 值 | 含义 | 等价整数 |
|---|---|---|
| `true` | 真 | `1` |
| `false` | 假 | `0` |

**`bool` 变量占 1 字节**。它和整数可以互相转换：

```cpp
bool b = 5;         // b 变成 true（非 0 都算真）
int  i = true;      // i 变成 1
int  j = false;     // j 变成 0
```

**函数返回"是/否"时常用 `bool`**：

```cpp
bool is_alive(int hp) {
    return hp > 0;      // 返回 true 或 false
}

if (is_alive(50)) { /* ... */ }
```

> [!tip] C 里用 `bool` 要 `#include <stdbool.h>`
> C99 起，C 语言也有 `bool` 了，但需要包含 `<stdbool.h>`。
> ```c
> #include <stdbool.h>
> bool ok = true;
> ```
> 老代码不用 `bool`，直接 `int` 存 0/1。**本项目两种都有**——新代码多用 `bool`。

#### `size_t`：装"大小/个数"的无符号整数

你在第 06 章会看到 `sizeof` 的结果类型，在字符串函数里会看到 `strlen` 的返回类型——它们都是 `size_t`。

```c
size_t n = sizeof(int);       // n = 4
size_t len = strlen("hello"); // len = 5
```

**`size_t` 是什么**：一个**无符号整数**，专门用来表示"大小、长度、个数、下标"。

| 特性 | 说明 |
|---|---|
| 无符号 | 不会为负，最小 0 |
| 大小 | 在 64 位系统是 8 字节，32 位系统是 4 字节 |
| 来源 | `#include <stddef.h>`（很多头文件间接包含了） |
| 打印 | 用 `%zu`（**不能**用 `%d`） |

**为什么需要它**：数组长度、字符串长度、内存大小这些都是"非负的数量"，用无符号整数最合适。而且它的大小会"跟着平台走"——在 64 位系统上能表示比 `int` 更大的数。

> [!danger] `size_t` 的减法陷阱
> `size_t` 无符号，**减法下溢不会变负，会变成一个巨大的正数**：
> ```c
> size_t a = 3;
> size_t b = 5;
> size_t c = a - b;    // 不是 -2，而是 18446744073709551614（2^64 - 2）！
> ```
> 所以 `if (strlen(s) - 10 < 0)` **永远不成立**（无符号数不可能 < 0）。
> 本章后面「有符号 vs 无符号的陷阱」会详解。

#### `uintptr_t` / `intptr_t`：装"地址"的整数

第 05 章你要学指针，会看到 `uintptr_t` 这个类型。**它是"能装下一个指针的整数"**。

```c
uintptr_t addr = (uintptr_t)&some_variable;   // 把地址当成整数存
```

| 类型 | 含义 |
|---|---|
| `uintptr_t` | **无符号**的"能装指针的整数" |
| `intptr_t` | **有符号**版本 |

> [!note] `void *` 是什么
> 上面出现了 `void *p`——**`void *` 叫"通用指针"**，表示"一个地址，但不知道它指向什么类型"。
> 任何类型的指针都能赋给它、它也能转成任何类型的指针。
> ```c
> int x = 5;
> void *p = &x;          // 任何指针都能存进 void*
> int *q = (int *)p;     // 再转回来
> ```
> **本项目中 `void *` 常用于"读写任意类型的内存"**——比如第 06 章的 `Read(addr, void *buffer, size_t size)`，用 `void *` 接收任意类型的缓冲区。
> 现在只要知道：**`void *` = "通用指针 / 未知类型的地址"**。

**为什么不用 `int`**：`int` 在 64 位系统只有 4 字节，装不下 8 字节的地址，会**截断**。

```c
void *p = /* 某个指针 */;         // （示意：p 指向一个真实对象）
int  wrong = (int)p;              // 错！64 位地址被截断成 32 位
uintptr_t right = (uintptr_t)p;   // 对！完整的 8 字节
```

> [!note] 上面的 `/* 某个指针 */` 是占位写法
> 真实代码里 `p` 是从某个变量取的地址（如 `void *p = &x;`）。
> 这里只演示"截断"这件事，**别把 `/* ... */` 当代码抄**。

**本项目里所有地址都用 `uint64_t` 或 `uintptr_t` 存**，绝不用 `int`。

> [!note] `uintptr_t` 和 `uint64_t` 有什么区别
> 在 64 位系统上它们**通常都是 8 字节**，可以互换。区别是"语义"：
> - `uint64_t` 强调"64 位整数"
> - `uintptr_t` 强调"专门用来装指针的整数"
> 本项目混用，读的时候当成"8 字节整数"就对了。

## 用 `printf` 打印各种类型的值

前面一直用 `printf("%d\n", a);`。那个 `%d` 叫**格式占位符**（format specifier）——它告诉 `printf`"**这里要填一个值，按 `d` 的方式打印**"。

### 常用占位符

| 占位符 | 对应类型 | 例子 | 输出 |
|---|---|---|---|
| `%d` | `int` | `printf("%d", 42);` | `42` |
| `%f` | `float` / `double` | `printf("%f", 3.14);` | `3.140000`（默认 6 位小数） |
| `%c` | `char` | `printf("%c", 'A');` | `A` |
| `%s` | 字符串 | `printf("%s", "hi");` | `hi` |
| `%p` | 地址/指针 | `printf("%p", &a);` | `0x7ffd...` |
| `%zu` | `sizeof` 的返回值 | `printf("%zu", sizeof(int));` | `4` |
| `%x` | 整数的十六进制 | `printf("%x", 255);` | `ff` |
| `%%` | 一个真正的 `%` | `printf("100%%");` | `100%` |

### 多个值的写法

```c
int hp = 100;
float speed = 3.5f;
char grade = 'A';

printf("hp=%d speed=%.1f grade=%c\n", hp, speed, grade);
// 输出：hp=100 speed=3.5 grade=A
```

规则：**占位符按顺序对应后面的参数**。第一个 `%d` 对应第一个参数 `hp`，第二个 `%.1f` 对应第二个参数 `speed`，以此类推。

**个数必须对得上**：占位符多了会打印垃圾，少了则后面的参数被忽略。

> [!tip] `%.1f` 是什么意思
> 小数点后的数字表示"**保留几位小数**"。
> `%f` = 默认 6 位（`3.140000`），`%.1f` = 1 位（`3.1`），`%.2f` = 2 位（`3.14`）。
> 本项目 `printf` 里到处是 `%.1f`、`%.2f`，就是为了控制输出精度。

### 动手：打印你自己的数据

```c
#include <stdio.h>

int main(void) {
    int age = 25;
    float height = 1.75f;
    char grade = 'A';

    printf("年龄: %d\n", age);
    printf("身高: %.2f 米\n", height);
    printf("评级: %c\n", grade);
    printf("全部: age=%d height=%.2f grade=%c\n", age, height, grade);
    return 0;
}
```

## 先看一段能"看见内存"的代码

先看这段代码：

```c
#include <stdio.h>

int main(void) {
    int hp = 1000;
    unsigned char *p = (unsigned char *)&hp;

    printf("变量 hp 的地址：%p\n", (void *)&hp);
    printf("它占 %zu 字节，每个字节是：\n", sizeof(hp));
    for (int i = 0; i < sizeof(hp); i++) {
        printf("  [%d] 0x%02X  (%u)\n", i, p[i], p[i]);
    }
    return 0;
}
```

逐行翻译成中文：

1. `int hp = 1000;` —— 建一个 `int` 变量 `hp`，放 1000
2. `unsigned char *p = ...` —— **本章主角**，一个指向 hp 内存的指针，本章随后讲
3. `printf("变量 hp 的地址：%p\n", (void *)&hp);` —— 打印 `hp` 的地址
4. `printf("它占 %zu 字节...", sizeof(hp));` —— 打印 `hp` 占几字节
5. `for (int i = 0; i < sizeof(hp); i++) { ... }` —— 循环 4 次，每次打印一个字节
6. `p[i]` —— 用指针 `p` 加下标 `i`，取得第 `i` 个字节

**看到没**：这段代码用到的语法——变量、`printf`、`%zu`/`%p`、`for`、下标——全部都在前面几节讲过。
接下来本章要讲的，是**第 2 行那个指针**到底怎么回事，以及"内存里存放的字节"是什么样的。
那才是本项目全部数据解析的基础。

在你的机器上输出类似这样：

```
变量 hp 的地址：0x5FFE3C
它占 4 字节，每个字节是：
  [0] 0xE8  (232)
  [1] 0x03  (3)
  [2] 0x00  (0)
  [3] 0x00  (0)
```

1000 的十六进制是 `0x000003E8`。内存里存的是 `E8 03 00 00`——**低字节在前**。
这个现象叫"小端序"（第 24 章会展开讲，**现在不用深究**，只要记住这个画面）：
**内存是一排带编号的格子，每格 1 字节。**

> 全书按由浅入深排列，不会让你看不懂前面的内容。

## 类型 = 一次读几格 + 怎么解释

| 类型 | 字节数 | 值的范围 | 用途 |
|---|---|---|---|
| `char` / `int8_t` | 1 | -128 ~ 127 | 单字节、字符串 |
| `unsigned char` / `uint8_t` | 1 | 0 ~ 255 | **读内存时用这个** |
| `short` / `int16_t` | 2 | -32768 ~ 32767 | |
| `int` / `int32_t` | 4 | ±21 亿 | 通用整数 |
| `long long` / `int64_t` | 8 | 很大 | **地址、指针** |
| `float` | 4 | 6~7 位有效数字 | 坐标、角度 |
| `double` | 8 | 15~16 位 | 高精度计算 |

> [!warning] 别用 `int` 存地址
> 在 64 位系统上地址是 8 字节，`int` 通常只有 4 字节，会截断。
> 本项目里所有地址都用 `uintptr_t` 或 `uint64_t`（见 `driver.h`）。
> 这是一个会导致"莫名其妙读错数据"的经典 bug。

## 固定宽度类型：用 `stdint.h`

`int` 在 Windows 是 4 字节，在某些嵌入式平台是 2 字节。写跨进程程序时这不可接受。

```c
#include <stdint.h>

int32_t  hp;      // 一定是 4 字节
uint64_t address; // 一定是 8 字节
uint8_t  byte;    // 一定是 1 字节
```

本项目全部使用固定宽度类型，因为读出来的每个字段的字节数必须**精确**匹配：

```c
// 真实代码：从目标进程读一个 4 字节的 FOV
相机FOV = dr->Read<float>(static_cast<uintptr_t>(玩家相机) + 0x2318);
//        只差一个偏移或类型，读出来的就是垃圾
```

> [!note] 这行代码里的新东西，现在先"看个形状"
> 这行是项目里的真实代码，包含几个你还没学的语法。**现在不用看懂，只要感受一下"按偏移读内存"长什么样**：
> - `dr->Read<...>` ：调用驱动对象的读取函数（`->` 第 07 章讲，模板 `<>` 第 13 章讲）
> - `static_cast<uintptr_t>(玩家相机)` ：类型转换（第 12 章讲）
> - `+ 0x2318` ：在地址上加偏移（第 05 章讲）
> - `dr->Read<float>(...)` ：读 4 字节、按 `float` 解释（本章前面刚讲过"类型决定读几字节"）
>
> **本章你只需要吸收一件事**：读一个字段，必须知道它"占几字节、是什么类型"——差一点读出来就是垃圾。

## sizeof 是你的朋友

```c
printf("char=%zu short=%zu int=%zu long=%zu ptr=%zu float=%zu double=%zu\n",
       sizeof(char), sizeof(short), sizeof(int), sizeof(long),
       sizeof(void*), sizeof(float), sizeof(double));
```

在 64 位环境典型输出：

```
char=1 short=2 int=4 long=4 ptr=8 float=4 double=8
```

注意 `long` 在 Windows 是 4 字节、Linux 64 位是 8 字节。**所以别用 `long` 存地址**——本项目里那些 `long int libUE4` 是历史写法，在 64 位 Linux/Android 上恰好是 8 字节才没出事。

## 打印各类值的正确格式符

| 类型 | 格式符 | 错误后果 |
|---|---|---|
| `int` | `%d` | |
| `unsigned` | `%u` | |
| `long long` | `%lld` | 用 `%d` 会输出错值 |
| 地址/指针 | `%p`（转成 `void*`） | 用 `%d` 在 64 位会截断 |
| `size_t` | `%zu` | |
| 十六进制 | `%X` / `%llX`（配 `unsigned long long`） | |
| `float` | `%f` | `printf` 会把 float 提升成 double |

打印地址的标准写法：

```c
printf("Uworld: 0x%llx\n", (unsigned long long)Uworld);
```

本项目 GUI 里全是这种写法（`ImGui::Text("Uworld: 0x%llx", ...)`），因为 `%llx` 在所有平台都稳定。

### 控制宽度与补零：`%02X` 这类写法

格式符里可以在 `%` 和字母之间加**数字**，控制"占几个字符宽、不够补什么"：

```c
printf("%X\n", 255);      // FF（最少几位就几位）
printf("%2X\n", 255);     // FF（宽度至少 2，够了就不补）
printf("%4X\n", 255);     // "  FF"（宽度 4，左边补空格）
printf("%04X\n", 255);    // 00FF（宽度 4，左边补 0）
```

| 写法 | 含义 |
|---|---|
| `%02X` | 至少 2 位，不够补 0（"2 位十六进制"） |
| `%04zX` | 至少 4 位，不够补 0（`z` 表示 size_t 参数） |
| `%.2f` | 小数点后保留 2 位 |

**为什么读内存时老用 `%02X`**：因为一个字节正好是"2 位十六进制"。**打印每个字节时补齐 2 位，看起来才整齐**：

```c
printf("%02X ", p[i]);   // 例如 E8 03 00 00，而不是 E8 3 0 0
```

第 04 章后面的 `hexdump`、本项目所有打印地址/字节的地方，都用这套宽度控制。

## 有符号 vs 无符号的陷阱

### 先说"为什么有正负"

一个字节是 8 个二进制位，能表示 2⁸ = 256 种状态。问题是：**这 256 种状态怎么分给正数和负数？**

C 语言有两种约定：

| 类型 | 约定 | 1 字节的范围 |
|---|---|---|
| **无符号**（`unsigned`） | 全部 256 种都算正数 | 0 ~ 255 |
| **有符号**（默认） | 拿出最高位当"**符号位**" | -128 ~ 127 |

**关键在最高位（第 8 位）**：

```text
无符号 200：  1 1 0 0 1 0 0 0      ← 8 位全用来表示数值 = 200
有符号 同样8位：1 1 0 0 1 0 0 0      ← 最高位是 1，表示"这是负数" = -56
```

**同一个字节（`0xC8`），当无符号解释是 200，当有符号解释是 -56。** 这就是"为什么有正负"。

> [!note] 负数的内部表示：补码
> 有符号数用"**补码**"表示：负数 = "对应的正数取反再加 1"。
> 你不用手算，只要知道：**有符号数的范围是"一半给负数，一半给正数"**——
> `int8_t` 是 -128~127，`int32_t` 是约 ±21 亿。

### 陷阱：同样一个字节，解释方式不同，值就不同

```c
uint8_t a = 200;
int8_t  b = (int8_t)a;   // b 变成 -56，不是 200
```

**读内存时你"必须知道"目标字段是有符号还是无符号**——猜错，读出来的数就全错。

### 为什么默认是"有符号"

C 语言的整数类型（`char`、`int`）**默认是有符号的**。想要无符号，要显式加 `unsigned`：

```c
int           a;   // 有符号，可能为负
unsigned int  b;   // 无符号，只可能 ≥ 0
```

**本项目读内存时特别小心这点**——因为游戏数据里既有"血量"（可能为负表示临时扣血）也有"数量"（一定是非负），类型不能猜。

另一个经典坑：

```c
if (strlen(s) - 10 < 0)   // 永远不成立！
```
`strlen` 返回 `size_t`（无符号），减 10 后下溢成巨大正数。

## 变量的存储期：变量能"活"多久

同一个 `int` 变量，写在**不同位置**，它的"生命周期"完全不同。这件事叫**存储期（storage duration）**。

**四种存储期**，用一段代码集中展示：

```c
int global_hp = 100;        // ① 全局变量

void func(void) {
    int local_hp = 50;      // ② 局部变量（栈）
    static int once = 0;    // ③ 静态局部变量
    int *heap = malloc(sizeof(int));   // ④ 堆变量
    // ... 用完要 free(heap);
}
```

| 存储期 | 声明位置 | 位置 | 生命周期 | 谁负责释放 |
|---|---|---|---|---|
| **全局** | 函数外 | 数据段 | 整个程序 | 系统 |
| **局部** | 函数内 | 栈 | 函数执行期 | 自动 |
| **静态局部** | 函数内 + `static` | 数据段 | 整个程序 | 系统 |
| **堆** | 任意 + `malloc` | 堆 | 直到 `free` | **你** |

### ① 全局变量：程序一开始就存在

```c
int global_hp = 100;      // 写在所有函数外面

int main(void) {
    printf("%d\n", global_hp);   // 任何函数里都能访问
    return 0;
}
```

**特点**：程序启动时分配，程序结束时销毁。**所有函数都能访问它**。

**缺点**：谁都能改，出了 bug 难追踪。**本项目尽量少用全局变量**，只在真正"全局唯一"的东西上用（如 `graphics` 渲染器）。

### ② 局部变量：函数一返回就没了

```c
void func(void) {
    int local_hp = 50;    // 进入 func 时创建
    // ...
}                          // 离开 func 时销毁
```

**这就是第 05 章讲的"不要返回局部变量地址"的原因**——函数返回后，`local_hp` 那块内存立刻作废。

### ③ 静态局部变量：只初始化一次，活到程序结束

```c
void counter(void) {
    static int count = 0;    // 只初始化一次（第一次调用时）
    count++;
    printf("调用了 %d 次\n", count);
}

int main(void) {
    counter();   // 调用了 1 次
    counter();   // 调用了 2 次
    counter();   // 调用了 3 次
    return 0;
}
```

**关键**：`count` 看起来是"局部的"，但它**只在第一次调用时初始化**，之后调用一直保留上次的值。

| 特性 | 普通局部变量 | 静态局部变量 |
|---|---|---|
| 初始化 | 每次进函数都重新初始化 | **只在第一次进函数时初始化一次** |
| 生命周期 | 函数执行期 | **整个程序运行期** |
| 作用域 | 函数内 | 函数内（外部访问不到） |
| 存放位置 | 栈 | 数据段 |

**`static` 的两种用法**：

| 写法 | 含义 |
|---|---|
| `static` 加在**局部变量**前 | 让它"活到程序结束"，但作用域还在函数内 |
| `static` 加在**全局变量**前 | 让这个全局变量只在本文件可见，别的文件看不到 |
| `static` 加在**函数**前 | 同上，函数只在本文件可见 |

**本项目里 `static` 用得不少**（函数内的"只初始化一次"缓存、只在本文件用的辅助函数）。碰到时知道是这个意思就行。

### ④ 堆变量：手动申请，手动释放

前三种都是"自动分配、自动销毁"。**堆不一样——它完全由你控制。**

**申请内存：`malloc`**

```c
#include <stdlib.h>

// 申请能装 1 个 int 的内存（4 字节）
int *p = malloc(sizeof(int));

if (p == NULL) {
    // 申请失败（内存不够）——一定要判！
    return;
}

*p = 100;              // 像普通指针一样用
printf("%d\n", *p);   // 100

free(p);               // 用完必须释放！
```

**`malloc` 做了什么**：向操作系统要一块内存，返回**这块内存的首地址**。

| 细节 | 说明 |
|---|---|
| 参数 | 要多少**字节**（`sizeof(类型)` 通常作为参数） |
| 返回 | `void *`（通用指针），赋给具体类型时会自动转换 |
| 失败 | 返回 `NULL`（**必须判**，否则空指针解引用崩） |
| 内容 | **未初始化**（里面有垃圾值），想清零用 `calloc`（分配并清零）或 `memset`（把已有内存清零） |

**释放内存：`free`**

```c
free(p);        // 释放 p 指向的那块内存
p = NULL;       // 好习惯：释放后置空，防止"悬空指针"
```

> [!danger] `malloc` 和 `free` 必须配对
> - **忘了 `free`** → 内存泄漏（内存一直占着）
> - **释放后再用** → 悬空指针，可能崩
> - **释放两次** → 崩
> - **释放非 `malloc` 来的指针** → 崩
> 这就是为什么第 14 章要讲**智能指针**——让释放自动发生，避免这些坑。

**申请数组**：

```c
int *arr = malloc(10 * sizeof(int));   // 10 个 int
if (arr == NULL) return;

for (int i = 0; i < 10; i++) arr[i] = i;   // 当数组用

free(arr);
```

**本项目里 `malloc`/`free` 出现不多**——大部分用 `new`/`delete`（第 14 章）或 `std::vector`（第 13 章）。但读老代码（比如 C 库的源码）时会碰到。

### 一张图记住四块内存

```text
高地址  ┌──────────────┐
        │    栈 (stack) │  ← 局部变量（自动、向下生长）
        ├──────────────┤
        │              │
        │    （空闲）   │
        │              │
        ├──────────────┤
        │    堆 (heap) │  ← malloc / new（手动、向上生长）
        ├──────────────┤
        │  数据段 (data)│  ← 全局变量、static 变量
        ├──────────────┤
        │  代码段 (text)│  ← 你的程序的指令
低地址  └──────────────┘
```

**第 17 章会把这张图讲透**（配合进程内存布局）。**现在只要记住四种变量的区别，以及"栈自动、堆手动"。**

### 顺带一提：常用字符串函数

读别人的内存时，经常要处理字符串。C 标准库提供了一组函数（都要 `#include <string.h>`）：

| 函数 | 作用 | 例子 |
|---|---|---|
| `strlen(s)` | 求字符串长度（不含 `\0`） | `strlen("hello")` → `5` |
| `strcpy(dst, src)` | 复制字符串 | `strcpy(dst, "hi")` |
| `strncpy(dst, src, n)` | 复制最多 n 个字符（更安全） | `strncpy(dst, src, 15)` |
| `strcmp(a, b)` | 比较（相等返回 0） | `if (strcmp(a, b) == 0)` |
| `strcat(dst, src)` | 拼接 | `strcat(dst, "!")` |
| `memset(p, v, n)` | 把 n 字节全设为 v | `memset(buf, 0, 100)` |
| `memcpy(dst, src, n)` | 复制 n 字节 | `memcpy(dst, src, 16)` |

**几个要点**：

- **`strlen` 返回 `size_t`**（本章前面讲过的无符号类型），所以 `strlen(s) - 10 < 0` 永远不成立
- **`strcpy` 不安全**（不知道目标够不够大），优先用 `strncpy`
- **`strcmp` 相等返回 0**，容易搞反（记住"0 表示相等"）
- **`memcpy`/`memset` 操作的是"字节"，不是"字符"**——常用于初始化结构体或复制二进制数据

**第 06 章讲字符串时还会细看这些**。这里先列出来，遇到时知道是什么。

## 动手：写一个内存转储函数

这个函数你以后会一直用——把任意地址开始的 N 个字节打成十六进制：

> [!note] 代码里的 `const` 先忽略
> 下面的函数签名里有 `const void *addr`、`const uint8_t *p`——**`const` 表示"这个指针指向的内容不会被修改"**。
> 它是个"承诺标记"，**第 12 章会专门讲**。现在看到 `const` 就当它是"只读"的意思，不影响理解函数在干什么。

```c
#include <stdio.h>
#include <stdint.h>

void hexdump(const void *addr, size_t len) {
    const uint8_t *p = (const uint8_t *)addr;
    for (size_t i = 0; i < len; i++) {
        if (i % 16 == 0) printf("\n%04zX  ", i);
        printf("%02X ", p[i]);
    }
    printf("\n");
}

int main(void) {
    int hp = 1000;
    hexdump(&hp, sizeof(hp));
    return 0;
}
```

输出：

```
0000  E8 03 00 00
```

把 `int` 换成 `float f = 3.14f` 再跑一次，你会看到 `C3 F5 48 40`——这就是 3.14 的 IEEE754 编码（第 26 章拆解它）。

## 课后习题

### 习题 04.1 亲手“看见”内存里的字节（★★）

**任务要求**：用 `unsigned char*` 把一个 `int` 的 4 个字节打印出来，
验证小端序（`1000` = `0x000003E8` → `E8 03 00 00`）。

**参考实现**：

```c
#include <stdio.h>
#include <assert.h>

int main(void) {
    int hp = 1000;                       // 0x000003E8
    unsigned char* p = (unsigned char*)&hp;
    printf("字节: %02X %02X %02X %02X\n", p[0], p[1], p[2], p[3]);

    // 小端序：低位字节在低地址
    assert(p[0] == 0xE8 && p[1] == 0x03 && p[2] == 0x00 && p[3] == 0x00);
    printf("习题 04.1 全部通过\n");
    return 0;
}
```

**验证断言**：`p[0..3]` 应为 `E8 03 00 00`（小端）。

> [!tip] 这道题练什么
> ① **变量 = 一块有地址的内存**；② **同一串字节，按不同方式解释得到不同值**；
> ③ **小端序**：低位字节在低地址。这是本项目读内存的基础（第 24 章展开）。

### 习题 04.2 类型决定“读几字节、怎么解释”（★★）

**任务要求**：同一个 4 字节，按 `int` 和 `float` 各读一次，观察结果完全不同。

**参考实现**：

```c
#include <stdio.h>
#include <string.h>
#include <assert.h>

int main(void) {
    // 0x4048F5C3 是 3.14f 的位模式
    unsigned char raw[4] = {0xC3, 0xF5, 0x48, 0x40};   // 小端存 3.14f

    float f;
    int   i;
    memcpy(&f, raw, 4);   // 按 float 解释
    memcpy(&i, raw, 4);   // 按 int 解释

    printf("按 float 读 = %.2f\n", f);
    printf("按 int   读 = %d\n", i);
    assert(f > 3.13f && f < 3.15f);      // 是 3.14
    assert(i == 0x4048F5C3);             // 是一大串整数
    printf("习题 04.2 全部通过\n");
    return 0;
}
```

> [!note] 同样的字节，不同的类型
> 这 4 个字节既是 `3.14f`，又是整数 `1078523331`——**取决于你用什么类型去解释它**。
> 本项目读内存时**必须知道每个字段的确切类型**，猜错读出的就是垃圾。
