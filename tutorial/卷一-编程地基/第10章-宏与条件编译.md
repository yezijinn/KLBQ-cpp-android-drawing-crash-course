# 第 10 章 · 宏与条件编译

> [!abstract] 本章目标
> 会读、会写宏与条件编译，能看懂本项目 `Android.mk` 和头文件里那些 `#define` 在干什么。
> 并知道宏的三个致命陷阱。

> [!note] 承上
> 上一章讲 `#include`——预处理的第一条指令。
> 本章讲**另外几条 `#` 开头的指令**：`#define`、`#ifdef`，它们也在预处理阶段处理。

## 先分清：# 开头的行都是"预处理指令"

你在前面章节已经见过好几行以 `#` 开头的代码：

```c
#include <stdio.h>       // 第 02 章见过：把文件粘过来
#include "calc.h"        // 第 09 章见过：同上
#define BONE_STRIDE 48   // 本章主角
#ifdef __aarch64__       // 本章后半部分要讲
#endif
#pragma once             // 第 09 章见过：头文件保护
```

**这些行不是 C 代码，是"预处理指令"。**

### 什么是预处理

复习一下第 03 章的编译四步：

```text
hello.c ──[预处理器]──> hello.i ──[编译器]──> hello.s ──[汇编器]──> hello.o ──[链接器]──> hello.exe
           处理 #           翻译成汇编        汇编→机器码       合并 .o 与库
```

**第一步"预处理"就是专门处理 `#` 开头的行的。** 它是一条"纯文本处理流水线"：

| 指令 | 作用 | 出现章节 |
|---|---|---|
| `#include` | 把指定文件的**内容粘过来** | 第 02、09 章 |
| `#define` | **定义一个宏**（文本替换规则） | 本章 |
| `#undef` | **取消**一个宏的定义 | 本章 |
| `#if` / `#ifdef` / `#ifndef` | **条件编译**：决定某段代码留不留 | 本章 |
| `#else` / `#elif` / `#endif` | 配合上面的条件 | 本章 |
| `#pragma` | 编译器特定指令（如 `#pragma once`） | 第 09 章 |
| `#error` | **主动报错**，停止编译 | 本章 |

**关键理解**：预处理器**不懂 C 语言**，它只懂"文本替换"和"条件判断"。它把 `#` 开头的行处理完之后，交给编译器的是一份**纯 C 代码**（可能变肥或变瘦）。

### 亲眼看看预处理前后

```c
// demo.c
#define MAX 100

int main(void) {
    int x = MAX;
    return 0;
}
```

跑 `gcc -E demo.c -o demo.i`，打开 `demo.i` 找到 `main`：

```c
int main(void) {
    int x = 100;    // ← MAX 被替换成了 100
    return 0;
}
```

**看到没**：`MAX` 不见了，全变成了 `100`。**这就是宏的工作方式——纯文本替换。**

## 宏：给一段文本起个名字

**宏（macro）= 一个"文本替换规则"**：你给一段文本起个名字，预处理器见到这个名字就用那段文本替换掉。

### `#define` 的两种形式

**形式一：对象式宏**（`#define 名字 值`）

```c
#define MAX 100
#define PI 3.14159
#define GREETING "Hello, world"
```

**这是一个"起名字"的动作**：以后代码里所有 `MAX` 都会被替换成 `100`，所有 `PI` 替换成 `3.14159`，等等。

**形式二：函数式宏**（`#define 名字(参数) 替换文本`）

```c
#define SQUARE(x) ((x) * (x))
#define MAX2(a, b) ((a) > (b) ? (a) : (b))
```

看起来像函数，但**它不是函数**——它是"带参数的文本替换"。`SQUARE(5)` 会被替换成 `((5) * (5))`。

### 为什么要有宏

为什么不用普通变量或 `const`？历史原因，也有现实原因：

| 场景 | 用宏的原因 |
|---|---|
| 数组大小 | C 语言早期不允许"变长数组"，只能用宏 |
| `#if` 条件里比较 | **预处理器阶段就要知道值**，不能用变量 |
| 头文件中的常量 | 项目老代码习惯（本项目就是这样） |
| 跨平台分支 | `#ifdef` 里的宏是平台信息 |
| 编译时替换成小段代码 | 避免函数调用开销（现在编译器会内联，这种用途减少） |

> [!tip] 现代 C++ 里更推荐 `constexpr`
> ```cpp
> constexpr int MAX = 100;      // 比 #define 好
> ```
> （`constexpr` 是"编译期常量"，**第 12 章会专门讲**。现在只要知道它比 `#define` 更安全即可。）
> 优点：**有类型、有作用域、调试器能看见、编译器会检查**。
> `#define` 是纯文本，没有任何这些特性。
> 本项目是历史工程，很多 `#define` 是老代码习惯。**新代码写 `constexpr`。**

### `#undef`：取消一个宏

```c
#define MAX 100
int a = MAX;      // 100
#undef MAX
// int b = MAX;   // 错：MAX 已经没有定义了
```

**用途**：防止宏污染后续代码。比如某个库定义了 `max`，你不想用它的版本，就 `#undef max` 再用自己的。

### 宏的"作用范围"

宏**一旦定义，从那一行开始，到 `#undef` 或文件末尾**，一直有效。**它不受 `{}` 作用域限制**（这是宏最大的坑之一，本章后半部分详讲）。

```c
#define MAX 100

void f(void) {
    int a = MAX;   // 100
}

int main(void) {
    int b = MAX;   // 100（依然有效）
    return 0;
}
```

**函数内部定义的宏，出了函数依然有效**——这一点和普通变量完全不同。

### 宏 vs 函数：什么时候用哪个

你可能会问：既然函数式宏看起来像函数，为什么不直接用函数？

| 特性 | 宏 | 函数 |
|---|---|---|
| 处理时机 | **预处理阶段**（编译前） | 运行时 |
| 参数类型 | **不检查**（任何类型都能传） | 严格检查 |
| 性能 | **无函数调用开销**（直接展开） | 有调用开销（可能被内联优化） |
| 调试 | **难**（看不到宏名，只有展开后的代码） | 容易 |
| 副作用 | **参数会被求值多次**（陷阱二详讲） | 参数只求值一次 |
| 命名空间 | **没有** | 有 |

**现代建议**：能用 `constexpr` 或 `inline` 函数，就不用宏。**宏只在"预处理器阶段需要"的场合用**——比如 `#if` 里的条件、头文件保护、平台分支。

### 动手：亲眼看看宏替换

```c
// macro_demo.c
#include <stdio.h>

#define MAX 100
#define SQUARE(x) ((x) * (x))

int main(void) {
    int a = MAX;
    int b = SQUARE(5);
    printf("%d %d\n", a, b);   // 100 25
    return 0;
}
```

1. 编译运行，确认输出 `100 25`
2. 跑 `gcc -E macro_demo.c -o macro_demo.i`，打开 `macro_demo.i` 找 `main`，你会看到 `MAX` 和 `SQUARE(5)` 都被替换了
3. **试着把 `MAX` 改成 `50` 再编译**——宏的值改了，所有用到它的地方都跟着变

**这个"看展开结果"的练习，是理解宏的唯一有效方式。** 后面讲陷阱时你会反复用到 `gcc -E`。


## 先看一个宏干了什么

```c
#define DEG_TO_RAD(d) ((d) * 3.1415926f / 180.0f)

float r = DEG_TO_RAD(90.0f);    // 展开成 ((90.0f) * 3.1415926f / 180.0f)
```

宏不是函数。**它在预处理阶段做纯文本替换**，编译器看到的是替换后的结果。

用 `gcc -E` 可以亲眼看到：

```bash
gcc -E test.c -o test.i && tail -5 test.i
```

## 宏的四种常见用法

### 1. 常量

```c
#define PAGE_SIZE 4096
#define MAX_SCAN_REGIONS 16534
#define BONE_STRIDE 48
#define MOD_NAME_LEN 256
```

（后三个都来自本项目 `driver.h` 和 `variable.h`。）

> [!note] 为什么不用 `const int`？
> 因为数组大小、case 标签等场合需要编译期常量，老式 C 里 `const` 不算。
> C++ 里推荐 `constexpr int PAGE_SIZE = 4096;`——有类型、有作用域、调试器能看见。
> 本项目的宏是历史写法与 C 风格残留。

### 2. 函数式宏

```c
#define BP_GET_MASK(record, reg) \
    (((record)->mask[(reg) >> 2] >> (((reg) & 0x3) << 1)) & 0x3)
```

注意两个细节：
- 每个参数都**加了括号**——这是必须的（见下面陷阱一）
- 行尾的 `\` 表示续行

### 3. 字符串化与拼接

```c
#define STR(x) #x              // 把参数变成字符串
#define CAT(a, b) a##b         // 把两段拼成标识符

STR(hello)        // "hello"
CAT(var, 123)     // var123
```

### 4. 日志包装

```c
#ifndef LS_LOGI_TAG
#define LS_LOGI_TAG(tag, fmt, ...) \
    __android_log_print(ANDROID_LOG_INFO, tag, fmt, ##__VA_ARGS__)
#endif
```

- `...` 和 `__VA_ARGS__`：可变参数宏
- `##__VA_ARGS__`：参数是空时，把前面多余的逗号删掉（GCC 扩展）
- 外面套 `#ifndef`：允许用户在外部先定义，覆盖默认实现

用法：

```c
LS_LOGI_TAG("Driver", "模块索引=%d 名称=%s", i, mod.name);
```

## 陷阱一：不加括号

```c
#define SQUARE(x) x * x

int a = SQUARE(1 + 2);     // 展开成 1 + 2 * 1 + 2 = 5，不是 9！
```

正确写法：

```c
#define SQUARE(x) ((x) * (x))
```

**规则：宏里每个参数都加括号，整个表达式再加一层括号。**

## 陷阱二：参数有副作用

```c
#define MAX(a, b) ((a) > (b) ? (a) : (b))

int x = 5;
int y = MAX(x++, 10);    // 展开：((x++) > (10) ? (x++) : (10))
                          // x 被加了两次！
```

**规则：不要把带 `++`、`--` 的表达式传给宏。**
C++ 里用 `std::max` 或模板函数替代。

## 陷阱三：宏没有作用域

```c
#define PI 3.14
// ... 之后所有代码里的 PI 都会被替换，包括你不想替换的地方
```

宏不受命名空间、结构体、函数限制。定义后一直生效到 `#undef` 或文件末尾。

> [!danger] 经典冲突：Windows 的 max/min 宏
> `windows.h` 定义了 `max` 和 `min` 宏，会破坏 `std::max`。
> 解法：在包含 `windows.h` 前 `#define NOMINMAX`。

## 条件编译：#if / #ifdef

### 平台分支

```c
#if defined(__arm__)
    int process_vm_readv_syscall = 376;
#elif defined(__aarch64__)
    int process_vm_readv_syscall = 270;      // ← Android 手机走这条
#elif defined(__i386__)
    int process_vm_readv_syscall = 347;
#else
    int process_vm_readv_syscall = 310;
#endif
```

这是本项目 `SysHal.h` 里的真实代码。同一个系统调用，在不同 CPU 架构上**调用号不同**。
条件编译让一份源码适配多架构。

常用预定义宏：

| 宏 | 含义 |
|---|---|
| `__aarch64__` | 64 位 ARM |
| `__arm__` | 32 位 ARM |
| `__x86_64__` | 64 位 x86 |
| `_WIN32` | Windows |
| `__linux__` | Linux |
| `__ANDROID__` | Android |

### 开关式功能裁剪

> [!note] 这是真实项目 `ANativeWindowCreator.h` 的模式（简化示意）
> 真实项目里宏带 tag/format/参数（如 `SURFACE_LOG_INFO(tag, fmt, ...)`），
> 这里简化为 `LOG(...)` 只为讲清"开关式裁剪"这个模式。

```c
#ifndef SURFACE_LOG_ENABLE
#define SURFACE_LOG_ENABLE 1
#endif

#if SURFACE_LOG_ENABLE
    #define LOG(fmt, ...) __android_log_print(ANDROID_LOG_INFO, "TAG", fmt, ##__VA_ARGS__)
#else
    #define LOG(fmt, ...)     // 空宏：调用被完全移除
#endif
```

关掉开关后，所有 `LOG(...)` 在预处理阶段就消失了，**零运行时开销**。

### 防止重复包含

```c
#ifndef NATIVESURFACE_DRAW_H
#define NATIVESURFACE_DRAW_H
/* ... */
#endif
```

（第 09 章讲过。）

## 编译器定义的宏（-D）

`Android.mk` 里：

```makefile
LOCAL_CPPFLAGS += -DVK_USE_PLATFORM_ANDROID_KHR
LOCAL_CPPFLAGS += -DIMGUI_IMPL_VULKAN_NO_PROTOTYPES
LOCAL_CPPFLAGS += -DIMGUI_DISABLE_DEBUG_TOOLS
```

`-DXXX` 等价于在源码开头写 `#define XXX`。

三个宏的作用：

| 宏 | 效果 |
|---|---|
| `VK_USE_PLATFORM_ANDROID_KHR` | 让 Vulkan 头文件包含 Android 窗口相关的声明 |
| `IMGUI_IMPL_VULKAN_NO_PROTOTYPES` | ImGui 不直接调用 Vulkan 函数，改用函数指针（配合动态加载） |
| `IMGUI_DISABLE_DEBUG_TOOLS` | 去掉调试工具，减小体积 |

## 日志里的实用宏

```c
printf("%s:%d %s\n", __FILE__, __LINE__, __func__);   // 文件名、行号、函数名
```

调试时很有用。本项目在排错阶段大量使用（第 16 章）。

一个好用的调试宏：

```c
#ifdef DEBUG
#define DBG(fmt, ...) \
    printf("[%s:%d] " fmt "\n", __func__, __LINE__, ##__VA_ARGS__)
#else
#define DBG(fmt, ...)
#endif
```

发布时不开 `DEBUG`，所有调试输出自动消失。

## 断言：assert

```c
#include <assert.h>

void process(uint8_t *buf, size_t len) {
    assert(buf != NULL);
    assert(len > 0);
    /* ... */
}
```

`assert` 失败会打印信息并终止程序。它在 `NDEBUG` 定义时**完全失效**：

```makefile
# release 构建
LOCAL_CPPFLAGS += -DNDEBUG
```

> [!warning] assert 里不要写有副作用的代码
> ```c
> assert(load_data() == 0);   // release 下这行整体消失，load_data 不会被调用！
> ```

## 一个完整的条件编译实例

来自本项目的思路，写一个跨平台读取函数：

```c
#ifndef SYSCALL_NUM_H
#define SYSCALL_NUM_H

#if defined(__aarch64__)
    #define SYS_PROCESS_VM_READV  270
    #define SYS_PROCESS_VM_WRITEV 271
#elif defined(__arm__)
    #define SYS_PROCESS_VM_READV  376
    #define SYS_PROCESS_VM_WRITEV 377
#elif defined(__i386__)
    #define SYS_PROCESS_VM_READV  347
    #define SYS_PROCESS_VM_WRITEV 348
#else
    #define SYS_PROCESS_VM_READV  310
    #define SYS_PROCESS_VM_WRITEV 311
#endif

#if !defined(SYS_PROCESS_VM_READV)
    #error "不支持的架构：无法确定 process_vm_readv 调用号"
#endif

#endif
```

`#error` 会在预处理阶段直接报错并停止编译——比运行到一半崩掉友好得多。

## 动手：用 -E 看宏展开

写个 `macro_test.c`：

```c
#include <stdio.h>

#define SQUARE_BAD(x) x * x
#define SQUARE_OK(x) ((x) * (x))
#define LOG(fmt, ...) printf("[%s] " fmt "\n", __func__, ##__VA_ARGS__)

```

1. 编译运行，看 `bad=5 ok=9`
2. 跑 `gcc -E macro_test.c -o macro_test.i`，打开 `.i` 找 `main` 函数，看展开结果

## 课后习题

### 习题 10.1 写一个带平台分支的系统调用号宏（★★）

**任务要求**：仿照本项目 `SysHal.h`，用 `#if defined(...)` 为不同架构定义 `SYS_PROCESS_VM_READV`：
aarch64=270、arm=376、i386=347、其它=310。并写一个 `#error` 兜底（不支持时直接报错）。

**参考实现**：

```c
#include <stdio.h>

#if defined(__aarch64__)
    #define SYS_PROCESS_VM_READV 270
#elif defined(__arm__)
    #define SYS_PROCESS_VM_READV 376
#elif defined(__i386__)
    #define SYS_PROCESS_VM_READV 347
#else
    #define SYS_PROCESS_VM_READV 310
#endif

#if !defined(SYS_PROCESS_VM_READV)
    #error "不支持的架构：无法确定调用号"
#endif

int main(void) {
    printf("readv 调用号 = %d\n", SYS_PROCESS_VM_READV);
    return 0;
}
```

**验证方式**：

```bash
# x86_64 本机编译运行，应输出 310
gcc q10_1.c -o q10_1 && ./q10_1
# 用 -D 强制当成 aarch64，应输出 270
gcc -D__aarch64__ q10_1.c -o q10_1a && ./q10_1a
```

> [!tip] 这正是本项目 `SysHal.h` 的真实结构
> 源码里 `#if defined(__arm__) ... 376 #elif defined(__aarch64__) ... 270 #else ... 310`，
> 和本题一一对应。做完这道题，你就读懂了那个文件的核心。

### 习题 10.2 找出坏宏并修正（★）

**任务要求**：下面的宏有 3 处缺陷，找出并用 `gcc -E` 验证修正前后的差异。

```c
#define MAX(a, b) a > b ? a : b
#define TWICE(x) x + x
#define AREA(w, h) (w * h)
```

**参考答案**：

```c
// ① MAX：参数无括号，且整体无括号。MAX(1+2, 3) 展开成 1+2 > 3 ? 1+2 : 3 → 错
#define MAX(a, b) (((a) > (b)) ? (a) : (b))

// ② TWICE：参数无括号，且参数求值两次（有副作用）。TWICE(i++) 会加两次
#define TWICE(x) ((x) + (x))          // 至少补括号；带 ++ 仍需避免

// ③ AREA：整体无括号。2 * AREA(3, 4) 展开成 2 * (3 * 4) 才对，但 2 * 3 * 4 恰好也对；
//        真正的问题是 AREA(1+1, 2+2) → (1+1 * 2+2) 错
#define AREA(w, h) ((w) * (h))
```

**验证**：

```bash
# 展开看替换结果
gcc -E -P q10_2.c | grep -A1 MAX
```

> [!warning] 宏的三条铁律
> ① 每个参数加括号；② 整个表达式再加一层括号；③ 参数不要带 `++`/`--`（会被求值多次）。
