## 先搞清：C++ 的标准版本是什么

你在第 11 章已经知道 C++ 是"在 C 基础上扩展"。但 **C++ 不是一成不变的**——它在不断演进，每隔几年发布一个新版本。

### C++ 的版本时间线

| 标准名 | 发布年 | 常用简称 | 主要新增 |
|---|---|---|---|
| C++98 | 1998 | C++98 | 第一个标准（之前的算"野生" C++） |
| C++03 | 2003 | C++03 | 小修订 |
| C++11 | 2011 | **C++11** | 大更新：`auto`、范围 for、`nullptr`、`unique_ptr`、lambda |
| C++14 | 2014 | C++14 | 小更新：`make_unique` |
| C++17 | 2017 | **C++17** | `optional`、`string_view`、`if constexpr`、结构化绑定 |
| C++20 | 2020 | **C++20** | ranges、`span`、概念、协程 |
| C++23 | 2023 | C++23 | 小更新 |

**本项目用 C++20。** 你会在 `Android.mk` 里看到 `-std=c++20`（第 34 章）。

### 编译时指定版本

```bash
g++ -std=c++17 main.cpp -o main.exe    # 用 C++17
g++ -std=c++20 main.cpp -o main.exe    # 用 C++20
g++ -std=c++11 main.cpp -o main.exe    # 用 C++11
```

**不写 `-std=` 会怎样**：编译器用它的默认版本（一般是 C++14 或 C++17，看编译器版本）。

**用旧版本编译新代码会报错**——比如在 `-std=c++11` 下用 `std::optional`（C++17 才有），编译器会说"找不到 std::optional"。

> [!tip] 遇到"找不到 std::xxx"或"xxx 不是 std 的成员"
> 90% 是**标准版本不对**——你用的特性比 `-std=` 指定的版本新。
> 解法：`-std=c++17` 或 `-std=c++20`。

## 先复习：`auto` 与范围 for

本章和后面几章会大量用到 `auto`。先复习一下它（第 12 章讲过）。

### `auto`：让编译器推导类型

```cpp
int x = 5;                     // 显式类型
auto x = 5;                    // 一样：编译器推导出 x 是 int

float y = 3.14f;
auto y = 3.14f;                // 推导出 float

std::vector<int> v;
auto v = std::vector<int>{};   // 推导出 std::vector<int>
```

**`auto` 只是"少写类型名"，不改变行为。**

**真正的好处**是类型名超长时：

```cpp
std::vector<std::pair<uintptr_t, uintptr_t>>::iterator it = regions.begin();
// 打这么多字，容易错

auto it = regions.begin();     // 编译器推导，不会错
```

### 范围 for

```cpp
std::vector<int> v = {1, 2, 3};

for (int x : v) { printf("%d\n", x); }        // 按值
for (const auto &x : v) { printf("%d\n", x); }  // 按引用（不拷贝）
```

**本项目大量使用 `for (const auto &x : v)`**——用 `const auto &` 既避免拷贝，又保证不修改。

> [!warning] `auto` 会丢掉引用和 `const`
> ```cpp
> const std::string &get();
> auto a = get();          // a 是 std::string（拷贝了一份！）
> const auto &b = get();   // b 才是 const std::string&
> auto &c = get();         // c 也是 const std::string&（auto 推导时保留 const）
> ```
> 想"不拷贝"必须显式写 `&`。**本章后面讲 `std::string_view` 时会再用到这个坑。**

## C++17：结构化绑定

```cpp
auto [ptr, ec] = std::from_chars(begin, end, pid);
// 等价于
auto result = std::from_chars(begin, end, pid);
auto ptr = result.ptr;
auto ec  = result.ec;
```

对 `pair`、`tuple`、结构体都能用：

```cpp
std::pair<uintptr_t, uintptr_t> region = {0x1000, 0x2000};
auto [start, end] = region;

// 遍历 map
for (const auto &[key, value] : cache) {
    printf("%llx -> %u\n", (unsigned long long)key, value);
}
```

```cpp

```

## C++17：if constexpr

编译期分支——不满足的分支**根本不会被编译**：

```cpp
template <typename T>
void process(T value) {
    if constexpr (std::is_integral_v<T>) {
        printf("整数：%lld\n", (long long)value);
    } else if constexpr (std::is_floating_point_v<T>) {
        printf("浮点：%f\n", (double)value);
    } else {
        printf("其它类型\n");
    }
}
```

和普通 `if` 的区别：普通 `if` 两个分支都要能编译（即使运行时不走）。
`if constexpr` 只编译成立的那个——所以可以在不同分支里调用对某些类型不存在的函数。

## C++17：std::from_chars / to_chars

比 `atoi`/`strtol` 更快、无异常、无内存分配：

```cpp
#include <charconv>

const char *str = "1234";
int value = 0;
auto [ptr, ec] = std::from_chars(str, str + strlen(str), value);

if (ec == std::errc{}) {
    // 成功，value = 1234
} else if (ec == std::errc::invalid_argument) {
    // 不是数字
} else if (ec == std::errc::result_out_of_range) {
    // 溢出
}
```

`ptr` 指向解析停止的位置——可以用来判断是否整个字符串都被解析了。

## 中文标识符

本项目用了大量中文变量名、函数名、甚至结构体字段：

```cpp
long int 玩家相机 = 0;
Vector3A 相机位置;
float 相机FOV = 0.0f;
bool 初始化 = false;

inline bool 写入角度(const Rotator &角);
void 提交候选(uint64_t actor, const Vec3 &世界位置, bool 被遮挡);

struct Config {
    bool 方框 = false;
    bool 骨骼索引 = false;
    float 垂直焦距系数 = 1.0f;
};
```

**这是合法的 C++。** C++ 标准允许 Unicode 标识符（编译器需支持 UTF-8 源码）。
GCC/Clang 都支持，MSVC 在较新版本也支持。

优点：领域概念一眼看懂，`相机FOV` 比 `cameraFov` 更直白（对中文母语者）。
缺点：
- 输入法切换麻烦
- 某些工具链/静态分析器可能不支持
- 与国际协作不便

> [!note] 你会遇到的实际问题
> 源文件必须是 **UTF-8 无 BOM**。带 BOM 的 UTF-8 在 GCC 下可能报
> `stray '\357' in program`。第 44 章会讲工程编码约定。

## 其它你会在本项目看到的现代写法

| 写法 | 含义 |
|---|---|
| `\[\[nodiscard\]\]` | 返回值不能忽略，否则编译器警告 |
| `noexcept` | 承诺不抛异常 |
| `override` | 明确覆盖虚函数（第 11 章） |
| `= default` / `= delete` | 显式要求/禁止编译器生成的函数 |
| `auto` 返回类型推导 | `auto f() { return 1; }` |
| `std::scoped_lock` | RAII 锁（C++17） |
| `std::atomic` / `__atomic_*` | 原子操作 |

```cpp
// driver.h 里的自旋锁
void lock() noexcept {
    while (__atomic_exchange_n(&locked, 1, __ATOMIC_ACQUIRE)) {
        while (__atomic_load_n(&locked, __ATOMIC_RELAXED)) {
            asm volatile("yield");
        }
    }
}
```

`__atomic_exchange_n` 是 GCC 内置的原子操作（第 82 章细讲并发）。

## 动手：用现代 C++ 重写一段

把下面这段 C 风格代码改写成 C++20：

```cpp
// 旧
int parse_pid(const char *s) {
    if (s == NULL) return -1;
    int len = strlen(s);
    for (int i = 0; i < len; i++) {
        if (s[i] < '0' || s[i] > '9') return -1;
    }
    return atoi(s);   // atoi：把字符串转成整数（C 老函数，出错时无法区分，所以本项目用 from_chars）
}
```

参考实现：

```cpp
#include <algorithm>      // std::ranges::all_of 在这里（不是 <ranges>！）
#include <charconv>
#include <string_view>
#include <ranges>
#include <optional>
#include <cstdio>

std::optional<int> parse_pid(std::string_view text) {
    if (text.empty()) return std::nullopt;
    if (!std::ranges::all_of(text, [](char ch) {
            return ch >= '0' && ch <= '9';
        })) return std::nullopt;

    int pid = 0;
    const auto [ptr, ec] = std::from_chars(text.data(), text.data() + text.size(), pid);
    if (ec != std::errc{} || ptr != text.data() + text.size() || pid <= 0)
        return std::nullopt;
    return pid;
}

int main(void) {
    for (auto s : {"1234", "12a4", "", "-1", "0"}) {
        if (auto p = parse_pid(s))
            printf("\"%s\" -> %d\n", s, *p);
        else
            printf("\"%s\" -> 无效\n", s);
    }
    return 0;
}
```

编译：`g++ -std=c++20 -Wall parse.cpp -o parse.exe`

注意 `-std=c++20`——`std::ranges` 需要 C++20。

## 课后习题

### 习题 15.1 `std::clamp` 限制数值范围（★）

**任务要求**：写 `int clamp_hp(int v)`，把血量限制在 `[0, 100]`。用 `std::clamp` 实现。

**参考实现**：

```cpp
#include <cstdio>
#include <algorithm>      // std::clamp
#include <cassert>

int clamp_hp(int v) {
    return std::clamp(v, 0, 100);   // 小于 0 得 0，大于 100 得 100
}

int main() {
    assert(clamp_hp(-5)   == 0);
    assert(clamp_hp(0)    == 0);
    assert(clamp_hp(50)   == 50);
    assert(clamp_hp(100)  == 100);
    assert(clamp_hp(9999) == 100);
    printf("clamp_hp(9999)=%d\n", clamp_hp(9999));
    printf("习题 15.1 全部通过\n");
    return 0;
}
```

> [!tip] 为什么用 clamp 不用 if
> 本项目 `limit_gui_frame_rate` 里就是 `std::clamp(Settings.gui_frame_rate, 60, 185)`——
> 一行替代 `if (v < lo) v = lo; if (v > hi) v = hi;`，意图更清楚。

### 习题 15.2 结构化绑定 + `from_chars`（★★）

**任务要求**：用 `std::from_chars` 解析字符串为整数，用结构化绑定 `auto [ptr, ec]` 接住结果；
若 `ec != std::errc{}` 或没消费完整个字符串，判为失败。

**参考实现**：

```cpp
#include <cstdio>
#include <charconv>
#include <string_view>
#include <cassert>
#include <optional>

std::optional<int> parse_int(std::string_view s) {
    if (s.empty()) return std::nullopt;
    int value = 0;
    const auto [ptr, ec] = std::from_chars(s.data(), s.data() + s.size(), value);   // ★ 结构化绑定
    if (ec != std::errc{} || ptr != s.data() + s.size()) return std::nullopt;
    return value;
}

int main() {
    assert(parse_int("123").value()  == 123);
    assert(parse_int("-45").value()  == -45);
    assert(!parse_int("12a").has_value());   // 有非数字
    assert(!parse_int("").has_value());        // 空串
    printf("parse_int(\"123\")=%d\n", parse_int("123").value());
    printf("习题 15.2 全部通过\n");
    return 0;
}
```

> [!note] `from_chars` vs `atoi`
> `atoi` 无法报告"解析失败"（`atoi("abc")` 返回 0，与真值 0 无法区分）；
> `from_chars` 用 `errc` 显式报告错误，还能告诉你"停在了哪个字符"（`ptr`）。
> 本项目 `driver.h` 的 `GetPid` 就是用 `from_chars` 解析 `/proc` 里的 PID 目录名。
