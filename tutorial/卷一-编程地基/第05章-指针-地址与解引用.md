# 第 05 章 · 指针：地址与解引用

> [!abstract] 本章目标
> 把指针从"难点"变成"顺手的工具"。
> 本章结束后你要做到：看到 `*(uint64_t*)(base + 0x30)` 不假思索就知道它在干什么。

> [!note] 承上
> 上一章你知道了"变量 = 一块有地址的内存"，还会用 `&a` 打印地址。
> 本章把那个"地址"本身变成能存、能算、能解引用的**指针**。

## 先看一个真实场景：为什么必须懂指针

> [!question] 你遇到过这个吗？
> 教程里到处出现 `*(uint64_t*)(base + 0x30)` 这种"天书"，
> 而本项目读游戏数据的每一行几乎都是这个形式。
> **看不懂指针，就读不懂任何一行内存操作代码。**
> 本章把指针从"难点"变成"顺手的工具"。

## 先搞清一件事：变量住在内存的哪一格

第 04 章讲过：**内存是一排带编号的格子，每格 1 字节。**
现在你要问一个更具体的问题：**"我声明一个变量 `int hp = 1000;`，它住在哪一格？"**

答案是：**编译器给它分配了某一格（或连续几格），并给它编了个号。这个编号就叫"地址"。**

### 用 `&` 拿到一个变量的地址

```c
#include <stdio.h>

int main(void) {
    int hp = 1000;
    printf("hp 的值是：%d\n", hp);
    printf("hp 的地址是：%p\n", (void *)&hp);
    return 0;
}
```

在你的电脑上输出类似（地址每次运行都不同，正常）：

```text
hp 的值是：1000
hp 的地址是：0x7ffd8e3c4a1c
```

看这一行：`&hp` —— **`&` 是一元运算符，意思是"取地址"**。

| 表达式 | 值 | 类型 |
|---|---|---|
| `hp` | `1000`（变量里装的东西） | `int` |
| `&hp` | `0x7ffd8e3c4a1c`（变量的地址） | `int *`（"指向 int 的指针"） |

**`&hp` 的结果是一个十六进制数**——和 `1000` 一样是"一个数"，只是它表示的是"格子的编号"，而不是"内容"。

> [!important] 地址在 64 位系统上是 8 字节的数
> 上面那个 `0x7ffd8e3c4a1c` 有 12 个十六进制位（每个 4 bit，共 48 bit）。
> 典型的 64 位地址用满时是 16 个十六进制位（64 bit = 8 字节）。
> **所以地址得用 8 字节的整数存**——这就是为什么本项目里地址都用 `uint64_t`（第 04 章讲过）。
> 用 `int`（4 字节）存地址会截断，是经典 bug。

### `%p` 是打印地址的专用占位符

```c
printf("%p\n", (void *)&hp);   // 打印地址
```

**为什么要写 `(void *)`**：`%p` 占位符要求参数类型是"通用指针" `void *`。
`&hp` 是 `int *`，不是 `void *`，编译器会警告。加 `(void *)` 就是**强制转换**（第 12 章讲）。

（**现在不用纠结这个转换**，记住"打印地址就写 `%p`，并且加 `(void *)`"就够了。）

## 指针变量：专门装地址的盒子

现在你知道了"每个变量都有地址"。接下来的问题是：**怎么把地址存起来以后用？**

答：用一个**指针变量**——一种专门装地址的盒子。

### 声明一个指针变量

```c
int *p;      // 声明一个指针，叫 p，它"指向 int"
```

拆开看：

```text
int  *  p  ;
│    │  │  └─ 分号：语句结束
│    │  └──── 变量名
│    └─────── 星号：表示"这是一个指针"
└──────────── 指向的类型：p 指向的那个地址上放的是 int
```

**`int *p;` 的含义**：声明一个变量 `p`，它的类型是"指向 int 的指针"（写作 `int *`）。

> [!note] 星号靠哪边都行
> `int *p;`、`int* p;`、`int * p;` **完全等价**。
> 写法之争纯属个人习惯，本项目混用。**编译器不在乎空格。**
> 只要记住：`int *` 是一个整体，读作"指向 int 的指针"。

### 让指针指向一个变量

```c
int hp = 1000;
int *p = &hp;      // p 装的是 hp 的地址
```

**内存里发生了什么**（示意）：

```text
          地址            内容
       ┌──────────┬──────────────┐
  hp   │ 0x…4a1c  │    1000      │  ← hp 的值（4 字节）
       ├──────────┼──────────────┤
  p    │ 0x…4a20  │  0x…4a1c     │  ← p 里装的是 hp 的地址
       └──────────┴──────────────┘
                        ↑
                     p 指向 hp
```

看这一行：`int *p = &hp;`

- 左边 `int *p`：声明 `p` 是一个指向 int 的指针
- 右边 `&hp`：取 hp 的地址
- 中间 `=`：把地址装进 p（就是赋值，第 04 章讲过）

**`p` 现在指向 `hp`。** 用图说就是"p 里存着 hp 的门牌号"。

### 通过指针读值：`*p`

```c
printf("%d\n", hp);     // 1000   —— 直接读变量
printf("%d\n", *p);     // 1000   —— 通过指针读
```

`*p` 的意思是"**去 p 里存的那个地址，把那个位置上的值取出来**"。

这个动作叫**解引用（dereference）**。`*` 在这里是"解引用运算符"。

### 通过指针写值：`*p = ...`

```c
*p = 200;                // 把 200 写到 p 指向的位置
printf("%d\n", hp);     // 200  —— hp 被改了！
```

**为什么改的是 `hp`**？因为 `*p` 和 `hp` 指的是**同一块内存**。
对 `*p` 赋值，就是往 `hp` 那一格写。

> [!tip] 一句话总结 `*` 的两种意思
> `*` 在**声明里**表示"这是一个指针"：`int *p;`
> `*` 在**表达式里**表示"解引用"：`*p = 200;`
> **位置不同，含义不同。** 看它在类型旁边还是值旁边就能分辨。

### 完整例子

```c
#include <stdio.h>

int main(void) {
    int hp = 100;
    int *p = &hp;      // p 指向 hp

    printf("hp = %d\n", hp);        // 100
    printf("*p = %d\n", *p);        // 100（和 hp 一样）
    printf("p = %p\n", (void *)p);  // 打印 p 里存的地址
    printf("&hp = %p\n", (void *)&hp);  // 打印 hp 的地址（和 p 一样）

    *p = 200;          // 通过指针改 hp
    printf("hp = %d\n", hp);        // 200（被改了）

    hp = 300;          // 直接改 hp
    printf("*p = %d\n", *p);        // 300（通过指针看到的也变了）

    return 0;
}
```

**观察点**：`p` 和 `&hp` 打印出来是**同一个值**（都是 hp 的地址）。
这就是"p 指向 hp"的含义。

## 指针的"类型"有什么用

既然指针就是"一个装地址的整数"，为什么还有 `int *`、`char *`、`float *` 这么多类型？

**因为类型决定了"读几个字节"和"怎么解释这些字节"。**

```c
int hp = 1000;
int *pi = &hp;        // 指向 int
char *pc = (char *)&hp;   // 也指向 hp，但类型是 char *

printf("%d\n", *pi);       // 1000（读 4 字节，按 int 解释）
printf("%d\n", *pc);       // 可能是 -24（读 1 字节，按 char 解释）
```

同样一个地址，`*pi` 读 4 字节，`*pc` 只读 1 字节。**结果完全不同。**

### `p + 1` 到底加了多少字节

**这是指针最容易迷惑人的地方。** `p + 1` **不是"地址加 1"**，而是"**跳到下一个同类型元素**"。

```c
int arr[3] = {10, 20, 30};
int *p = arr;             // p 指向 arr[0]

p + 1;                    // 地址加了 4（sizeof(int)），指向 arr[1]
p + 2;                    // 地址加了 8，指向 arr[2]
```

| 指针类型 | `p + 1` 实际加的字节数 | 原因 |
|---|---|---|
| `char *` | 1 | `sizeof(char)` = 1 |
| `short *` | 2 | `sizeof(short)` = 2 |
| `int *` | 4 | `sizeof(int)` = 4 |
| `int64_t *` | 8 | `sizeof(int64_t)` = 8 |

**规则**：`指针 + n` 的实际字节偏移 = `n × sizeof(指针指向的类型)`。

**这一条是本项目"按偏移读内存"能成立的根本。** 下一节你会看到它的实际用途。

> [!danger] 想按"字节"偏移，必须转成 `char *` 或 `uint8_t *`
> ```c
> int arr[3] = {10, 20, 30};
> int *p = arr;
> 
> (char *)p + 4       // 字节偏移 4 —— 指向 arr[1]
> p + 1              // 元素偏移 1 —— 也指向 arr[1]
> 
> (char *)p + 1       // 字节偏移 1 —— 指向 arr[0] 的中间某个字节
> ```
> **要按字节算偏移，先转成"每元素 1 字节"的指针类型**（`char *` 或 `uint8_t *`）。
> 本项目所有偏移计算都基于 `uint8_t *`，下一节详解。

## 动手：第一次玩指针

把这几个练习都跑一遍，看结果，**自己画一画内存图**（这一步最重要）：

```c
#include <stdio.h>

int main(void) {
    int x = 10;
    int y = 20;
    int *p = &x;      // p 指向 x

    printf("x=%d, *p=%d\n", x, *p);      // 10, 10

    *p = 99;                              // 通过 p 改 x
    printf("x=%d, *p=%d\n", x, *p);      // 99, 99

    p = &y;                               // 让 p 改指向 y（指针可以改指向）
    printf("y=%d, *p=%d\n", y, *p);      // 20, 20

    *p = 88;                              // 通过 p 改 y
    printf("x=%d, y=%d\n", x, y);        // 99, 88

    return 0;
}
```

**关键点**：

- `p = &y;` 之后 `p` **不再指向 x**，而是指向 y
- 这时 `*p` 是 20（y 的值），不是 99
- **指针可以改指向（它只是个装地址的变量）；引用不能改指向（第 12 章讲）**

**自己画图**：画三个盒子（x、y、p），p 盒子里的箭头从 x 移到 y，看看 `*p` 输出怎么变。
这个"画内存图"的动作，是把指针从"难点"变成"顺手的工具"的唯一办法。


## 先记住这一句话

**指针就是一个存着地址的整数变量，只不过编译器知道"这个地址上放的是什么类型"。**

```c
uint64_t addr = 0x7FF12340;       // 一个普通整数
uint64_t *p   = (uint64_t *)addr; // 一个指针，值是同一个整数
```

`addr` 和 `p` 在内存里长得一模一样，都是 8 字节。区别只在于：
- 对 `addr` 做 `+1`，结果是 `0x7FF12341`
- 对 `p` 做 `+1`，结果是 `0x7FF12348`（加了 8，因为 `uint64_t` 是 8 字节）

**这就是指针运算的全部秘密：+1 加的是"一个元素的大小"。**

## 两个运算符

| 符号 | 名字 | 作用 | 口诀 |
|---|---|---|---|
| `&` | 取地址 | 得到变量的地址 | "在哪" |
| `*` | 解引用 | 得到地址上的值 | "是什么" |

```c
int hp = 100;
int *p = &hp;      // p 存着 hp 的地址

printf("%d\n", hp);   // 100  直接读
printf("%d\n", *p);   // 100  通过地址读

*p = 200;             // 通过地址写
printf("%d\n", hp);   // 200  hp 被改了
```

## 为什么本项目到处都是指针运算

看这段真实代码（简化自 `draw_Gui.cpp`）：

```c
uint64_t Uworld = dr->Read<uint64_t>(libUE4 + 0xB3EC650);
uint64_t Uleve  = dr->Read<uint64_t>(Uworld + 0x30);
uint64_t Array  = dr->Read<uint64_t>(Uleve + 0x98);
int      Count  = dr->Read<int>(Uleve + 0xA0);
```

> [!note] 这段代码里的 `->` 和 `<>` 先忽略
> 上面 4 行里有几个还没学的语法，**现在不用管，只看"链"的形状**：
> - `dr->Read<...>` ：`->` 是"通过指针访问成员"（第 07 章讲），`<...>` 是模板（第 13 章讲）
> - `+ 0xB3EC650` ：地址加偏移（本章主角）
> 你只需要感受：**每一步都是"读 8 字节 → 当成新地址 → 加偏移 → 再读"**。

翻译成人话：

```
libUE4 是一个基址（模块加载地址）
  └─ +0xB3EC650 这个格子里，存着 UWorld 对象的地址  → 读出来
       └─ +0x30 这个格子里，存着 ULevel 的地址      → 读出来
            └─ +0x98  存着 Actor 数组首地址
            └─ +0xA0  存着数组元素个数
```

这就是**指针链**：沿着一串"存着地址的地址"一路跳下去。

用图表示：

```
地址        内容
0x7A0000000  ← libUE4 基址
   ...
0x7A3EC650   0x1B2C3D00   ← UWorld 指针
   ...
0x1B2C3D30   0x1B400000   ← ULevel 指针
   ...
0x1B400098   0x1C000000   ← Actor 数组首元素
0x1B4000A0   0x00000063   ← Count = 99
```

**每一步都是"读 8 字节 → 当作新地址 → 加偏移 → 再读"。** 这就是全部。

## 用 uint8_t* 做字节级偏移

当你需要按**字节**偏移而不是按元素偏移时，先转成 `uint8_t*`：

```c
uint64_t base = 0x1000;
uint8_t *b = (uint8_t *)base;

b + 0x30        // 0x1030，正确
(uint64_t*)base + 0x30  // 0x1180，错！加了 0x30*8
```

所以读内存的统一写法是：

```c
uint64_t read_ptr(uint64_t addr) {
    return *(uint64_t *)addr;   // 把 addr 当地址，读它上面的 8 字节
}
```

本项目的 `dr->Read<T>(addr)` 就是把这件事封装成了跨进程版本（第 75 章你会自己写）。

## NULL 与空指针

**"空指针" = 不指向任何有效内存的指针。** C 和 C++ 用不同的写法表示它：

| 写法 | 语言 | 说明 |
|---|---|---|
| `NULL` | C（老代码） | 一个宏，通常就是 `0` |
| `nullptr` | C++11 起 | 专门的"空指针"关键字，类型安全，**推荐** |
| `0` | C/C++ | `0` 也能当空指针用，但容易和整数 0 混淆 |

```cpp
int *p = NULL;      // C 风格（C 和 C++ 都能用）
int *q = nullptr;   // C++11 风格（本项目用这个；C 语言没有 nullptr）
```

**不管哪种写法，空指针就是"地址 0"，地址 0 永远不可访问：**

```cpp
int *p = nullptr;
*p = 10;         // 崩溃：段错误 Segmentation fault
```

所以读指针链时必须每一步都判空：

```c
uint64_t Uworld = read_ptr(libUE4 + 0xB3EC650);
if (Uworld == 0) return;              // 不判就崩
uint64_t Uleve = read_ptr(Uworld + 0x30);
if (Uleve == 0) return;
```

本项目里每一级都有这种检查（`if (Uleve == 0) return;`），因为目标进程可能正在切换关卡，链上任何一环都可能突然变 0。

## 多级指针

```c
int hp = 100;
int *p1 = &hp;
int **p2 = &p1;
int ***p3 = &p2;

printf("%d\n", ***p3);   // 100
```

| 表达式 | 类型 | 值 |
|---|---|---|
| `p3` | `int***` | p2 的地址 |
| `*p3` | `int**` | p1 的地址 |
| `**p3` | `int*` | hp 的地址 |
| `***p3` | `int` | 100 |

实际工程里很少写 `***`，但你要能读懂。
本项目 `Hack.h` 里 `uintptr_t PovPtr` 这类字段就是"指向某结构的地址"，使用时再加偏移解引用。

## 指针与数组是同一个东西

```c
int arr[5] = {10, 20, 30, 40, 50};
int *p = arr;      // 数组名就是首元素地址

arr[2]  == *(arr + 2)  == *(p + 2)  == p[2]   // 全是 30
```

为什么从 0 开始数？因为 `arr[i]` 就是 `*(arr + i)`，第一个元素偏移是 0。

本项目遍历 Actor 数组就是这么写的：

```c
for (int i = 0; i < Count; i++) {
    uint64_t obj = dr->Read<uint64_t>(Arrayaddr + 0x8 * i);
    //                                               ^^ 每个元素 8 字节（一个指针）
}
```

## 函数指针（先混个眼熟）

```c
void on_hit(void *regs) { /* ... */ }
void (*callback)(void*) = on_hit;
callback(NULL);
```

本项目 `PhysX.h` 的断点结构里有：

```c
void (*on_hit)(void *regs, void *fp_regs, void *hit_point);
```

意思是"这个字段存着一个函数的地址，命中时会调用它"。
先知道长这样就行，第 78 章会用上。

## 三个必踩的坑

> [!danger] 坑一：返回局部变量地址
> ```c
> int* bad(void) {
>     int x = 100;
>     return &x;      // 错！x 在函数返回时就没了
> }
> ```
> 返回的指针指向已经失效的栈空间，读出来的值是随机的。

> [!danger] 坑二：类型不匹配的强制转换
> ```c
> float f = 3.14f;
> int wrong = *(int*)&f;   // 把 float 的位模式当成 int 读 → 得到 1078523331
> float ok  = *(float*)&f; // 正确
> ```
> 反过来，想"把浮点数的位当成整数看"，这种转换是刻意的（第 26 章会用它解析 IEEE754）。

> [!danger] 坑三：指针算错了字节数
> ```c
> uint64_t v = read_ptr(base + 0x30);        // 读 8 字节
> uint32_t v2 = read_u32(base + 0x30);       // 读 4 字节
> ```
> 同样一个偏移，读 4 字节和读 8 字节，在高位非零时结果完全不同。

## 动手：模拟一条指针链

不用任何外部进程，在自己程序里搭一条链来练手：

```c
#include <stdio.h>
#include <stdint.h>
#include <string.h>

struct Level { uint64_t actors[3]; int count; };
struct World { struct Level *level; };

int main(void) {
    struct Level lv = {{0x1111, 0x2222, 0x3333}, 3};
    struct World w = {&lv};

    // 模拟"基址"
    uint64_t base = (uint64_t)&w;

    // 第一跳：base + 0 → level 指针
    uint64_t level_addr = *(uint64_t *)(base + 0);
    // 第二跳：level + 0 → actors 数组首地址（就在结构体开头）
    uint64_t first = *(uint64_t *)(level_addr + 0);
    int count = *(int *)(level_addr + 24);   // 3 个 uint64 = 24 字节后是 count

    printf("level=0x%llX first=0x%llX count=%d\n",
           (unsigned long long)level_addr,
           (unsigned long long)first, count);
    return 0;
}
```

改一改：把 `count` 的偏移从 24 改成 28，看输出变成什么。这就是"偏移错了"的真实体验。

## 课后习题

### 习题 05.1 模拟三级指针链（★★）

**任务要求**：搭一条"基址 → 偏移 → 偏移"的指针链，从基址读出最终的目标值，
并**故意改错一个偏移**观察结果变化。

**参考实现**：

```c
#include <stdio.h>
#include <stdint.h>
#include <assert.h>

// 模拟内存里的三层结构
uint64_t g_target = 0xDEADBEEF;
struct Level2 { uint64_t value; };
struct Level1 { struct Level2* l2; };
struct Level0 { struct Level1* l1; };

int main(void) {
    struct Level2 l2 = { (uint64_t)&g_target };   // l2.value 指向目标
    struct Level1 l1 = { &l2 };
    struct Level0 l0 = { &l1 };

    uint64_t base = (uint64_t)&l0;

    // 第一跳：base + 0 → l1 指针
    uint64_t p1 = *(uint64_t*)(base + 0);
    // 第二跳：l1 + 0 → l2 指针
    uint64_t p2 = *(uint64_t*)(p1 + 0);
    // 第三跳：l2 + 0 → 目标指针
    uint64_t targetPtr = *(uint64_t*)(p2 + 0);
    // 解引用：读出目标值
    uint64_t value = *(uint64_t*)targetPtr;

    printf("最终值 = 0x%llX\n", (unsigned long long)value);
    assert(value == 0xDEADBEEF);
    printf("习题 05.1 全部通过\n");
    return 0;
}
```

**验证断言**：沿三级链读出的值应为 `0xDEADBEEF`。

> [!tip] 这就是本项目读游戏数据的本质
> `dr->Read<uint64_t>(libUE4 + 0xB3EC650)` → `+0x30` → `+0x98` 就是这样的链。
> **每一跳都是"读 8 字节 → 当成新地址 → 加偏移 → 再读"**。
> 把某一跳的偏移改错（比如 `+0` 改成 `+8`），读出的就是垃圾或崩溃。

### 习题 05.2 指针运算的字节数（★★）

**任务要求**：验证 `p + 1` 到底加几字节——取决于指针类型。

**参考实现**：

```c
#include <stdio.h>
#include <stdint.h>
#include <assert.h>

int main(void) {
    int  arr[4] = {10, 20, 30, 40};
    char bytes[4] = {1, 2, 3, 4};

    int*  pi = arr;
    char* pc = bytes;

    // int* + 1 加 4 字节
    assert((char*)(pi + 1) - (char*)pi == 4);
    // char* + 1 加 1 字节
    assert((pc + 1) - pc == 1);

    printf("int* +1 加 %ld 字节, char* +1 加 %ld 字节\n",
           (long)((char*)(pi + 1) - (char*)pi), (long)((pc + 1) - pc));
    printf("习题 05.2 全部通过\n");
    return 0;
}
```

> [!note] 为什么这很重要
> 本项目里 `Arrayaddr + 0x8 * i` 用的是 `0x8 * i`（手算字节偏移），
> 而不是 `(uint64_t*)Arrayaddr + i`（类型指针运算）——两者等价，但显式写字节偏移更清楚。
> **要按字节偏移，用 `uint8_t*`/`char*`；要按元素偏移，用对应类型指针。**
