# 第 03 章 · 从源码到可执行文件

> [!abstract] 本章目标
> 拆开"编译"这个黑盒子，看清四个阶段各做了什么。
> 你会亲手产生 `.i` `.s` `.o` 四种中间文件，并知道去看哪一个。

## 先看四个中间产物

对同一个 `hello.c` 分别跑四条命令，会依次产生四个文件：

```bash
gcc -E hello.c -o hello.i     # 预处理 → 一坨展开后的 C 代码
gcc -S hello.i -o hello.s     # 编译   → 汇汇编指令
gcc -c hello.s -o hello.o     # 汇编   → 二进制机器码（还不能跑）
gcc    hello.o -o hello.exe   # 链接   → 可执行程序
```

| 文件 | 内容 | 大小 | 人能读懂吗 |
|---|---|---|---|
| `hello.c` | 你的源码 | ~100 字节 | 能 |
| `hello.i` | 展开所有 `#include` 后的源码 | ~20 KB | 勉强 |
| `hello.s` | 汇编指令 | ~2 KB | 学完第 25 章能 |
| `hello.o` | 机器码 + 符号表 | ~1 KB | 靠工具（第 30 章） |
| `hello.exe` | 完整可执行 | ~50 KB | 靠工具 |

打开 `hello.i` 你会震惊：你写了 5 行，它变成了 800 行——因为 `stdio.h` 被整个粘了进来。

## 四个阶段各干了什么

```
hello.c ──[预处理器]──> hello.i ──[编译器]──> hello.s ──[汇编器]──> hello.o ──[链接器]──> hello.exe
           处理 #           翻译成汇编        汇编→机器码       合并 .o 与库
```

### 1. 预处理（Preprocessing）

处理所有以 `#` 开头的行：

- `#include <xxx.h>` → 把文件内容贴进来
- `#define A B` → 文本替换
- `#ifdef / #endif` → 决定哪些代码留下

产物还是 C 代码，只是变肥了。（第 10 章详解）

### 2. 编译（Compilation）

把 C 代码翻译成汇编。这一步做语法检查、类型检查、优化。
你平时看到的 `error: expected ';' before ...` 就是这一步报的。

### 3. 汇编（Assembly）

把汇编指令逐条翻译成机器码，生成 `.o`（目标文件）。
`.o` 里已经有二进制指令了，但还跑不起来——因为 `printf` 的地址还不知道。

### 4. 链接（Linking）

做两件事：
1. **符号解析**：找到 `printf` 到底在哪（在 `libc` 里）
2. **重定位**：把调用 `printf` 的地址填进去

这就是"未定义引用"错误的来源：

```bash
# 故意写错：把 printf 写成 printff
gcc hello.c -o hello.exe
# undefined reference to `printff'
```

> [!note] `undefined reference` 是链接错误，不是编译错误
> 编译阶段只检查"你声明了没有"，链接阶段才检查"这东西真的存在吗"。
> 以后看到 `undefined reference to xxx`，第一反应是：忘了链接某个库。
> 本项目链接 6 个 Embree 静态库，漏一个就报这种错（第 43 章）。

## 源码里还能写什么

到这里你已经能编译程序了。但 `hello.c` 太简单——它只做了一件事："输出一行字"。
真正写程序，你还需要知道**源码里能写哪些东西**。先看一个比 `hello.c` 丰富一点的例子，存成 `demo.c`：

```c
#include <stdio.h>

int main(void) {
    // 声明两个变量：能装整数的"盒子"，名字分别叫 a 和 b
    int a = 5;
    int b = 3;

    // 计算 a + b，把结果打印出来
    printf("%d\n", a + b);

    return 0;
}
```

跑一遍：`gcc -Wall -Wextra demo.c -o demo.exe`，然后 `./demo.exe`，输出 `8`。

和 `hello.c` 比，这里多了四类新东西。**它们是你以后每一章都会用到的地基**，现在先认识个脸。

### 一、注释：写给人看，编译器完全忽略

```c
// 这是单行注释：从 // 开始，到这一行结束

/* 这是多行注释：
   从 /* 开始，到 */ 结束，
   中间可以跨很多行 */
```

注释的作用是**给读代码的人（包括未来的你）留说明**。编译器在预处理阶段会把注释**整段删掉**，对程序运行没有任何影响。

验证一下——写一行注释，用第 03 章开头的 `-E` 命令展开，你会发现注释消失了：

```bash
gcc -E demo.c -o demo.i
# 打开 demo.i 搜索"变量"，你会发现注释里的字都不见了
```

| 写法 | 范围 | 能用在哪 |
|---|---|---|
| `// 说明` | 到行尾 | 任何地方 |
| `/* 说明 */` | 从 `/*` 到 `*/` | 任何地方，可跨多行 |

> [!warning] `/* */` 不能嵌套
> `/* 外层 /* 内层 */ 还在外层？ */` —— 编译器在第一个 `*/` 就认为注释结束了，
> 后面的文字会被当成代码，报一堆莫名其妙的错。嵌套注释用不了，要一行行写 `//`。

本项目里到处是 `//` 注释，比如 `driver.h` 里解释每个偏移的含义。
**从现在开始，养成给关键代码写注释的习惯**，第 16 章排错时会救你的命。

### 二、表达式：能"算出一个值"的东西

**表达式（expression）= 一段能算出一个值的代码。**

```c
5              // 值就是 5
a              // 值是变量 a 里的数（这里是 5）
a + b          // 算出 5 + 3 = 8
a * 2 + 1      // 算出 5 * 2 + 1 = 11
```

每个表达式都有一个**值**，也都有一个**类型**（是整数？是小数？）。
上面这些都是整数表达式，因为参与的 `a`、`b`、`5` 都是整数。

`printf("%d\n", a + b);` 这一行里，`a + b` 就是一个表达式——`printf` 会先算出它的值 `8`，再打印。

### 三、运算符：表达式的"动词"

把值组合起来算的符号叫**运算符（operator）**。常用的分四类：

**① 算术运算符**（算数）：

| 符号 | 含义 | 例子 | 结果 |
|---|---|---|---|
| `+` | 加 | `5 + 3` | `8` |
| `-` | 减 | `5 - 3` | `2` |
| `*` | 乘（注意是星号，不是字母 x） | `5 * 3` | `15` |
| `/` | 除 | `6 / 3` | `2` |
| `%` | 取余数（除以几之后剩多少） | `7 % 3` | `1` |

> [!danger] 整数除法会丢小数
> `5 / 2` 的结果是 `2`，不是 `2.5`！因为两边都是整数，结果也是整数，小数部分被**直接扔掉**（不是四舍五入）。
> 想得到 `2.5`，至少一个数得是小数：`5.0 / 2` 或 `5 / 2.0`。
> 第 04 章讲类型时会说清楚这件事。

**② 比较运算符**（比较两个值，结果是"真"或"假"）：

| 符号 | 含义 | 例子 | 结果 |
|---|---|---|---|
| `==` | 等于（**两个等号**！） | `5 == 3` | 假 |
| `!=` | 不等于 | `5 != 3` | 真 |
| `>` | 大于 | `5 > 3` | 真 |
| `<` | 小于 | `5 < 3` | 假 |
| `>=` | 大于等于 | `5 >= 5` | 真 |
| `<=` | 小于等于 | `5 <= 3` | 假 |

> [!danger] 最容易犯的错：`=` 和 `==` 不是一回事
> - `=` 是**赋值**："把右边的值放进左边的盒子"。
> - `==` 是**比较**："左右两边相等吗？"
> 把 `==` 写成 `=`，程序不报错，但行为完全错——这是新手 bug 排行榜第一名。
> 第 04 章会亲手制造一次这个 bug。

**③ 逻辑运算符**（组合多个条件）：

| 符号 | 含义 | 例子 | 结果 |
|---|---|---|---|
| `&&` | 且（两个都真才真） | `5 > 3 && 2 > 1` | 真 |
| `||` | 或（有一个真就真） | `5 > 3 \|\| 2 > 100` | 真 |
| `!` | 非（真变假，假变真） | `!(5 > 3)` | 假 |

**④ 赋值运算符**（把值放进变量）：

| 符号 | 含义 | 例子 | 效果 |
|---|---|---|---|
| `=` | 赋值 | `a = 10;` | 把 10 放进 a |
| `+=` | 加后赋值 | `a += 3;` | 等价于 `a = a + 3;` |
| `-=` | 减后赋值 | `a -= 3;` | 等价于 `a = a - 3;` |
| `++` | 自增 1 | `a++;` | 等价于 `a = a + 1;` |
| `--` | 自减 1 | `a--;` | 等价于 `a = a - 1;` |

`+=`、`++` 这些是简写，本项目里到处都是（比如 `i++` 表示"循环变量加 1"）。

> [!tip] 优先级：和数学一样，先乘除后加减
> `2 + 3 * 4` = `2 + 12` = `14`（不是 `20`）。
> 记不清优先级就**加圆括号**：`(2 + 3) * 4` = `20`。圆括号永远最安全。
> 本项目里的复杂表达式都靠圆括号保证可读性。

**⑤ 位运算符**（按二进制位操作）：

这一组稍微难一点，先混个眼熟。**第 07 章**会用到它们解析"打包字段"。

先复习第 04 章（附录 R 也讲过）的进制：**一个字节 = 8 个二进制位**。位运算符就是**在这 8 个位上逐个操作**。

| 符号 | 名称 | 含义 | 例子（二进制） |
|---|---|---|---|
| `&` | 按位与 | 两位都是 1 才是 1 | `1100 & 1010` = `1000` |
| `\|` | 按位或 | 有一位是 1 就是 1 | `1100 \| 1010` = `1110` |
| `^` | 按位异或 | 两位不同才是 1 | `1100 ^ 1010` = `0110` |
| `~` | 按位取反 | 0 变 1，1 变 0 | `~1100` = `0011` |
| `<<` | 左移 | 整体向左挪 n 位，右边补 0 | `1 << 3` = `1000`（= 8） |
| `>>` | 右移 | 整体向右挪 n 位，左边补 0 | `1000 >> 3` = `1` |

**左移/右移的直觉**：`x << n` 相当于 `x × 2ⁿ`，`x >> n` 相当于 `x ÷ 2ⁿ`（整数除法）。

```c
1 << 0      // 1
1 << 1      // 2
1 << 2      // 4
1 << 3      // 8（= 2³）
1 << 8      // 256
```

> [!tip] 位运算最常用的三个场景
> **① 从一个大数里"抠"出一段位**（第 07 章会用到）：
> ```c
> uint16_t header = 0x1234;
> uint16_t low4   = header & 0xF;      // 取最低 4 位
> uint16_t high   = header >> 8;       // 取高 8 位
> ```
> **② 判断某个标志位**：
> ```c
> if (flags & 0x1) { /* 最低位是 1 */ }
> ```
> **③ 设置某个位**：
> ```c
> flags |= (1 << 3);   // 把第 3 位置 1
> ```
> 现在只要认识这几个符号**是什么**，具体怎么用第 07 章会讲。

**⑥ 三目运算符**（一个"简写的 if"）：

```c
条件 ? 值1 : 值2
```

**含义**：条件为真取 `值1`，为假取 `值2`。它是一个**表达式**（能算出一个值），不像 `if` 是语句。

```c
int a = 5, b = 3;
int max = (a > b) ? a : b;      // a > b 真，取 a，max = 5

int hp = 0;
const char *state = (hp > 0) ? "存活" : "阵亡";   // "阵亡"
```

> [!note] 第二行里的 `const char *` 先忽略
> 那是"字符串指针"（`const` 第 12 章讲、指针第 05 章讲）。**现在只要理解"三目按条件二选一"**：hp > 0 为假，所以取 `"阵亡"`。

**等价于**：

```c
int max;
if (a > b) { max = a; } else { max = b; }
```

**什么时候用三目**：简单的二选一，写成一行更清楚时。**复杂的逻辑还是用 `if`，可读性更好。**

> [!note] 为什么叫"三目"
> 因为它有**三个操作数**（条件、值1、值2）。
> `+` 是二目（两个操作数），`!` 是一目（一个操作数）。

**⑦ 其它你以后会遇到的运算符**（先混个眼熟）：

| 符号 | 名称 | 说明 | 出现章节 |
|---|---|---|---|
| `sizeof` | 求大小 | `sizeof(int)` → 4 | 第 04 章 |
| `&`（取地址） | 取地址 | `&x` 得到 x 的地址 | 第 05 章 |
| `*`（解引用） | 解引用 | `*p` 得到 p 指向的值 | 第 05 章 |
| `->` | 指针取成员 | `p->hp` | 第 07 章 |
| `.` | 取成员 | `obj.hp` | 第 07 章 |
| `::` | 作用域 | `std::vector` | 第 11 章 |

**这些用到的时候再回头看这张表**，不用现在记。

### 四、语句：程序的一条指令

**语句（statement）= 一条完整指令，以 `;` 结尾。**

程序就是一条条语句按顺序执行。常见的几种：

| 类型 | 样子 | 作用 | 出现章节 |
|---|---|---|---|
| 声明语句 | `int a = 5;` | 创建一个变量 | 第 04 章 |
| 表达式语句 | `a = a + 1;` / `printf(...);` | 算一个表达式并执行 | 本章 |
| 控制语句 | `if (...) { ... }` | 根据条件决定走哪条路 | 第 04 章 |
| 循环语句 | `for (...) { ... }` | 重复做某事 | 第 04 章 |
| 返回语句 | `return 0;` | 结束函数并返回值 | 第 02 章已见 |

前三类你还不熟，不用急——**第 04 章会从头讲变量和控制语句**，那是你写第一个"真正能干活"的程序的地方。

### 动手：给 demo.c 加内容

把 `demo.c` 改成这样，编译运行，看输出：

```c
#include <stdio.h>

int main(void) {
    int a = 5;
    int b = 3;

    printf("a + b = %d\n", a + b);      // 加法
    printf("a - b = %d\n", a - b);      // 减法
    printf("a * b = %d\n", a * b);      // 乘法
    printf("a / b = %d\n", a / b);      // 整数除法（注意结果！）
    printf("a %% b = %d\n", a % b);     // 取余
    return 0;
}
```

输出：

```text
a + b = 8
a - b = 2
a * b = 15
a / b = 1
a % b = 2
```

重点看 `a / b` —— 5 除以 3 得到的是 `1`，不是 `1.666...`。这就是"整数除法丢小数"。

> [!note] 为什么取余那行写了 `%%`
> 因为 `printf` 用 `%` 做占位符。想**输出一个真正的 `%`**，得写成 `%%`。
> 第 04 章和后面的章节会详细讲 `printf` 的占位符（`%d`、`%f`、`%s`、`%%`）。


## 多文件编译

真实工程不可能只有一个文件。假设有：

```c
// math_utils.c
int add(int a, int b) { return a + b; }
```

```c
// main.c
#include <stdio.h>
int add(int a, int b);          // 声明：告诉编译器有这个函数

int main(void) {
    printf("%d\n", add(3, 4));
    return 0;
}
```

编译：

```bash
gcc -c math_utils.c -o math_utils.o
gcc -c main.c -o main.o
gcc main.o math_utils.o -o app.exe
./app.exe    # 输出 7
```

为什么能跑？因为链接器在 `math_utils.o` 里找到了 `add` 的符号，把 `main.o` 里的调用点地址填上了。

> [!danger] 链接顺序有讲究
> ```bash
> gcc math_utils.o main.o -o app.exe   # 可能失败
> gcc main.o math_utils.o -o app.exe   # 正确
> ```
> 传统链接器从左到右扫描：先看到"我需要 add"，再在右边的文件里找。
> 依赖方放左边，被依赖方放右边。第 28 章会详细讲。

## 用 -save-temps 一次看全部

```bash
gcc -save-temps hello.c -o hello.exe
```

当前目录会同时出现 `hello.i`、`hello.s`、`hello.o`、`hello.exe`。
调试构建问题时这个参数很好用。

## make：不用每次手敲四条命令

文件多了以后，手写命令会疯。建一个 `Makefile`：

```makefile
app.exe: main.o math_utils.o
	gcc main.o math_utils.o -o app.exe

main.o: main.c
	gcc -c main.c -o main.o

math_utils.o: math_utils.c
	gcc -c math_utils.c -o math_utils.o
```

然后敲 `make` 就行。

> [!danger] Makefile 的缩进必须是 Tab
> 命令行前面**必须是 Tab 字符**，用空格会报 `missing separator`。
> 这是 Makefile 最经典的坑，没有之一。第 29 章会再讲一次。

`make` 的另一个好处：只重新编译改动过的文件。改了 `main.c`，它不会去重新编译 `math_utils.c`。
