## 先看一个真实场景：递归太深，程序"爆栈"

> [!question] 你遇到过这个吗？
> 写了个递归函数，小数据没事，数据一大就崩，报 `stack overflow` 或直接段错误。
> **根因**：每次函数调用都在栈上压一个"栈帧"，递归太深把栈用光了。
> 本章讲清"函数调用时内存里发生了什么"——理解它，你才知道为什么会爆栈、参数怎么传。

## 第一部分：函数基础

当代码越来越长，你会想要**把一段重复出现的代码打包成"一个动作"**。这就是**函数**。

**你已经用过函数了**：`printf`、`main` 都是函数。`main` 是"程序入口函数"，`printf` 是"打印函数"。

### 定义一个自己的函数

**语法**：

```c
返回类型 函数名(参数列表) {
    // 函数体
    return 返回值;
}
```

**最简单的例子**：

```c
int add(int a, int b) {
    return a + b;
}
```

逐部分：

| 部分 | 含义 |
|---|---|
| `int` | **返回类型**：这个函数执行完会交回一个整数 |
| `add` | **函数名**：你自己起的 |
| `(int a, int b)` | **参数列表**：调用时要传进来两个整数，函数内部叫 `a` 和 `b` |
| `{ ... }` | **函数体**：具体要做什么 |
| `return a + b;` | **返回语句**：算出 `a + b` 的值，交回给调用方 |

### 调用函数

```c
#include <stdio.h>

int add(int a, int b) {
    return a + b;
}

int main(void) {
    int result = add(3, 4);    // 调用：把 3 和 4 传进去，返回值存进 result
    printf("%d\n", result);    // 输出 7

    printf("%d\n", add(10, 20));  // 调用结果直接当参数，输出 30
    return 0;
}
```

**调用 `add(3, 4)` 时发生的事**：

1. `3` 传给参数 `a`，`4` 传给参数 `b`
2. 执行 `add` 的函数体：计算 `3 + 4 = 7`
3. `return 7;` 把 `7` 交回给调用点
4. 调用点用 `7` 替换 `add(3, 4)` 这个表达式的位置

（本章下一部分就讲"调用时内存里发生了什么"，包括栈帧。）

### 无返回值的函数：`void`

如果函数只是"做事"，不需要交回任何值，返回类型写 `void`：

```c
#include <stdio.h>       // printf

void print_hello(void) {
    printf("Hello\n");
}

int main(void) {
    print_hello();   // 调用；不需要用返回值
    return 0;
}
```

**`void` 就是"没有"的意思**：
- 作为返回类型：函数不返回值（没有 `return` 一个值，可以写 `return;` 或啥都不写）
- 作为参数列表：函数不需要参数（`print_hello(void)` 表示"不接受参数"）

### 参数和返回值的关系

| 需求 | 怎么定义 | 例子 |
|---|---|---|
| 有输入、有输出 | 正常函数 | `int add(int a, int b)` |
| 无输入、有输出 | 参数写 `void` | `int read_config(void)` |
| 有输入、无输出 | 返回类型 `void` | `void print(int x)` |
| 无输入、无输出 | 都 `void` | `void do_thing(void)` |

> [!important] 函数必须"先声明或定义，后使用"
> 函数定义在 `main` 之前，可以直接调用。
> 如果定义在 `main` **之后**，必须在 `main` 之前**声明**它（只写"返回类型 名字(参数);"，没有函数体）。
> 这是第 09 章讲"声明与定义分离"的起点，本项目 `include/` 里全是声明。
> ```c
> int add(int a, int b);   // 声明（前向声明）
> 
> int main(void) {
>     printf("%d\n", add(3, 4));   // 用到了 add，但定义在后面
>     return 0;
> }
> 
> int add(int a, int b) {       // 定义
>     return a + b;
> }
> ```

### 动手：把猜数字游戏拆成函数

把第 03 章的 `guess.c` 拆成两个函数，体会"把逻辑打包成函数"的思维：

- `int read_guess(void)`：负责打印提示、读一个整数、返回它
- `void check_guess(int guess, int target, int count)`：负责比较并打印"太大/太小/猜中"

`main` 里只留一个循环，每次调用这两个函数：

```c
#include <stdio.h>

int read_guess(void) {
    int g;
    printf("请输入：");
    scanf("%d", &g);
    return g;
}

void check_guess(int guess, int target, int count) {
    if (guess < target)       printf("太小了\n");
    else if (guess > target)  printf("太大了\n");
    else                      printf("恭喜！你用了 %d 次\n", count);
}

int main(void) {
    int target = 42;
    int count = 0;
    int guess = 0;
    while (guess != target) {
        guess = read_guess();
        count++;
        check_guess(guess, target, count);
    }
    return 0;
}
```

对比第 03 章那一版：逻辑没变，但 `main` 变短了，每个函数只做一件事。**后面章节所有代码都是这么组织的。**

### 函数的参数：可以有多个，可以没有

```c
int add(int a, int b) {          // 两个参数，用逗号隔开
    return a + b;
}

int no_arg(void) {               // 没有参数，写 void
    return 42;
}

void print_two(int x, float y) { // 混合类型参数
    printf("%d %.2f\n", x, y);
}
```

调用时**实参个数和类型必须对得上**（编译器会检查）：

```c
add(1, 2);           // 对
add(1);              // 错：参数个数不对
add(1, 2, 3);        // 错：参数太多
add("hi", 2);        // 错：类型不对（字符串 ≠ int）
```

### 参数和局部变量：只在函数里存在

**函数里定义的东西（参数、局部变量），出了函数就消失。**

```c
void f(int x) {
    int y = x * 2;      // x 和 y 都是 f 的"局部的东西"
    printf("%d\n", y);
}

int main(void) {
    f(10);
    // printf("%d\n", x);  // 错！x 在这里不存在
    // printf("%d\n", y);  // 错！y 在这里也不存在
    return 0;
}
```

这个"局部"的概念叫**作用域（scope）**——变量的"有效范围"。

**作用域由 `{}` 决定**：一个变量从"声明那一行"开始，到包含它的那一对 `{}` 结束，一直有效。出了这个 `{}`，就不认识了。

```c
int main(void) {
    int a = 1;        // a 的作用域：从这里到 main 的 }

    {
        int b = 2;    // b 的作用域：从这个 { 到配对的 }
        printf("%d %d\n", a, b);   // 都能用
    }
    // printf("%d\n", b);  // 错！b 已经出了自己的 {}

    printf("%d\n", a);    // a 还能用
    return 0;
}
```

**同名遮蔽**：内层作用域可以定义和外层同名的变量，内层的会"遮蔽"外层的：

```c
int x = 1;            // 全局 x

int main(void) {
    int x = 2;        // 局部 x，遮蔽了全局 x
    printf("%d\n", x);  // 输出 2（局部优先）
    return 0;
}
```

**不推荐同名遮蔽**，容易看混。本项目避免这种写法。

### 函数声明 vs 函数定义

**定义**是"完整写出函数体"：

```c
int add(int a, int b) {     // 定义（有函数体）
    return a + b;
}
```

**声明**是"只告诉编译器有这么个函数"，没有函数体：

```c
int add(int a, int b);      // 声明（末尾是分号，没有 {}）
```

**为什么需要声明**：如果函数定义在调用点**之后**，编译器处理到调用点时还没见过这个函数，就会报错。

```c
int main(void) {
    int r = add(3, 4);       // 编译到这里，编译器还不认识 add
    return 0;
}

int add(int a, int b) {      // 定义在这里（太晚了）
    return a + b;
}
```

加上声明就能解决：

```c
int add(int a, int b);       // ← 前向声明：先告诉编译器"有这么个函数"

int main(void) {
    int r = add(3, 4);       // OK 了
    return 0;
}

int add(int a, int b) {
    return a + b;
}
```

**这就是第 09 章"头文件"的由来**——把所有声明集中放在 `.h` 文件里，`.c` 文件只放定义。这样任何文件 `#include` 了头文件，就都认识这些函数了。

### `return` 的细节

```c
int  f(void) { return 42; }         // 返回 int
float g(void) { return 3.14f; }     // 返回 float
void h(void) { return; }            // void 函数可以不写 return，或写 return;
```

**规则**：

| 返回类型 | `return` 后面写什么 |
|---|---|
| `void` | 不写值，只写 `return;` 或什么都不写 |
| 其它类型 | 必须返回**对应类型**的值 |

**`return` 会立即结束函数**，后面的语句不执行：

```c
int check(int x) {
    if (x < 0) {
        return -1;         // 负数直接返回，后面的 return 0 不执行
    }
    return 0;              // x >= 0 时才执行到这里
}
```

**这个"提前 return"的写法本项目到处用**，用来做参数校验和错误处理：

```c
void process(void *ptr, int size) {
    if (ptr == NULL) return;        // 无效输入，直接返回
    if (size <= 0)  return;         // 无效输入，直接返回
    // 走到这里说明输入合法，继续处理...
}
```

## 动手：写几个自己的函数

**练习 1**：写一个 `int max_of_two(int a, int b)`，返回两个数里大的那个。

**练习 2**：写一个 `int max_of_three(int a, int b, int c)`，返回三个里最大的。**里面调用练习 1 的 `max_of_two`**（体会函数嵌套调用）。

**练习 3**：写一个 `void print_line(int n)`，输出 `n` 个 `-` 字符（体会"做事的函数"）。

**练习 4**：写一个 `int is_even(int x)`，如果 `x` 是偶数返回 `1`，否则返回 `0`。

参考答案：

```c
#include <stdio.h>

int max_of_two(int a, int b) {
    if (a > b) return a;
    return b;
}

int max_of_three(int a, int b, int c) {
    return max_of_two(max_of_two(a, b), c);
}

void print_line(int n) {
    for (int i = 0; i < n; i++) {
        printf("-");
    }
    printf("\n");
}

int is_even(int x) {
    return (x % 2 == 0) ? 1 : 0;   // ? : 是三元运算符，第 03 章讲过
}

int main(void) {
    printf("max(3, 7) = %d\n", max_of_two(3, 7));
    printf("max(3, 7, 5) = %d\n", max_of_three(3, 7, 5));
    print_line(20);
    printf("is_even(8) = %d, is_even(7) = %d\n", is_even(8), is_even(7));
    return 0;
}
```

**练习重点**：
- 练习 2 里调用练习 1 的 `max_of_two`——函数可以互相调用
- 练习 3 里"做事但不返回值"用 `void`
- 练习 4 里 `return 1/0` 表达"是/否"，C 里惯例用 `1`/`0` 而不是 `true`/`false`

> [!note] 关于 `is_even` 里的 `? :`
> `(条件) ? 值1 : 值2` 是**三元运算符**——条件真取 `值1`，假取 `值2`。
> 等价于：
> ```c
> if (x % 2 == 0) return 1;
> else return 0;
> ```
> 第 03 章「运算符」一节已经讲过它。**这里只是复习一下，不影响理解函数。**


## 先看一个爆栈

```c
#include <stdio.h>

void recurse(int n) {
    char buf[1024];              // 每层用掉 1KB 栈
    printf("depth=%d  buf@%p\n", n, (void*)buf);
    recurse(n + 1);
}

int main(void) { recurse(0); }
```

跑起来，几万层之后程序崩溃（Stack overflow）。
注意打印出来的地址：**每一层 `buf` 的地址都在变小**——栈是向下生长的。

## 栈是什么

每个线程有一块连续内存叫**栈**。它的规则极简：

- 只有一个口（栈顶指针 `SP`）
- 压数据：`SP` 往下移，把数据放进去
- 弹数据：`SP` 往上移
- 后进先出（LIFO）

```
高地址  0x7FFF_FFFF
   ┌──────────────┐
   │   main 的栈帧  │
   ├──────────────┤
   │  funcB 的栈帧  │  ← 当前函数
   ├──────────────┤
   │  funcC 的栈帧  │  ← SP 指向这里
   └──────────────┘
低地址                 栈向下生长
```

## 一次函数调用发生了什么

```c
int add(int a, int b) {
    int sum = a + b;
    return sum;
}

int main(void) {
    int r = add(3, 4);
    return 0;
}
```

调用 `add(3, 4)` 时，硬件和编译器配合做这些事：

1. **传参**：把 `3` 和 `4` 放到约定好的位置（x86-64 前 6 个参数放寄存器，ARM64 前 8 个放 `x0~x7`）
2. **保存返回地址**：把"调用完该回到哪"的地址压栈（ARM64 存 `x30`/LR 寄存器）
3. **跳转**：跳到 `add` 的第一条指令
4. **开栈帧**：`SP` 下移，给 `sum` 等局部变量腾地方
5. **执行函数体**
6. **收栈帧**：`SP` 上移，局部变量作废
7. **返回**：按返回地址跳回去，返回值放在约定寄存器（`x0` / `rax`）

关键点在步骤 6：**局部变量在函数返回那一刻就死了。**
这就是第 05 章"不要返回局部变量地址"的原因——那块栈空间马上会被下一个函数覆盖。

## 栈帧里都有什么

一个典型的栈帧（简化）：

```
        ┌────────────────┐
   +16  │  参数 7, 8, ... │   ← 超过寄存器数量的参数
        ├────────────────┤
   +8   │   返回地址      │   ← 函数返回后跳到哪
        ├────────────────┤
   +0   │  上一个栈帧指针 │   ← FP/LR 保存区
        ├────────────────┤
   -8   │   局部变量 1    │
        ├────────────────┤
   -16  │   局部变量 2    │
        ├────────────────┤
   -24  │   临时保存的寄存器│
        └────────────────┘  ← SP
```

调试器（gdb）就是靠这条链（每个栈帧记着上一个栈帧的地址）还原出"调用栈"的。
你崩溃时看到的 backtrace，就是它打印的。

## 参数传递：值传递是唯一的真相

```c
void inc(int x) { x++; }

int main(void) {
    int a = 10;
    inc(a);
    printf("%d\n", a);   // 还是 10
}
```

**C 语言只有值传递。** `inc` 拿到的是 `a` 的一份拷贝。

想改外面的变量，就传它的地址：

```c
void inc(int *x) { (*x)++; }

int a = 10;
inc(&a);
printf("%d\n", a);   // 11
```

这叫"模拟引用传递"——本质仍然是值传递，只不过传的值是地址。

## 用指针做输出参数

本项目里到处是这个模式：

```cpp
bool GetModuleAddress(std::string_view name, short segmentIndex,
                      uint64_t *outAddress, bool isStart);
```

> [!note] `std::string_view` 先当成"字符串参数"看
> 上面参数里的 `std::string_view` 是 **C++17 的"字符串视图"**——一种"只读、不拷贝"的字符串参数类型（第 13 章会讲）。
> 现在你只要知道：**"要传一个字符串进来"，本项目用 `std::string_view`**。

`outAddress` 是**输出参数**。调用时：

```c
uint64_t moduleBase = 0;
if (!dr->GetModuleAddress("libUE4.so", 0, &moduleBase, true)) {
    return;   // 失败
}
// 成功，moduleBase 被填上了
```

为什么返回值是 `bool`（成功与否），而真正的结果走指针？因为一个函数只能有一个返回值，
"成功了吗"和"值是多少"要分开表达。第 13 章会讲 C++17 的 `std::optional` 是更优雅的写法。

## 数组作为输出缓冲区

```c
int Read(uint64_t address, void *buffer, size_t size);
```

调用方负责准备空间：

```c
uint8_t buf[256];
int n = dr->Read(addr, buf, sizeof(buf));
if (n <= 0) { /* 处理失败 */ }
```

> [!danger] 缓冲区必须真的能装下 size 字节
> ```c
> uint8_t buf[16];
> dr->Read(addr, buf, 256);   // 灾难：写越界 240 字节
> ```
> 这是 C 语言里最常见的安全漏洞（缓冲区溢出）。
> 本项目的 `HandleVirtualMemoryRWEvent` 内部按 0x1000 分块，
> 就是保证任何一次拷贝都不会超过调用方给的缓冲区。

## 递归与栈深度

```c
uint64_t factorial(int n) {
    if (n <= 1) return 1;
    return n * factorial(n - 1);
}
```

每次调用都要一个新栈帧。深度 n 就压 n 层。
典型栈大小：Linux 主线程 8MB，pthread 默认 8MB（Android 上可能只有 1MB）。

> [!warning] 在 Android 子线程里注意栈大小
> 本项目创建了 3 个后台线程（更新物理场景）。如果线程函数里有大数组或深递归，
> 在 Android 默认的 1MB 栈上会崩。
> 解决：大数组改用 `malloc` 放堆上，或 `pthread_attr_setstacksize`。

## 内联函数

```c
static inline float dot(const Vec3 *a, const Vec3 *b) {
    return a->x*b->x + a->y*b->y + a->z*b->z;
}
```

`inline` 建议编译器"别生成函数调用，直接把代码贴过去"。省掉开栈帧的开销。

本项目数学代码几乎全是 `inline`（`WorldToScreen.h`、`SilentAim.h`），因为每帧要算几千次。
但注意：

> [!note] inline 只是建议
> 编译器可以无视它。开了 `-O2` 后编译器自己也会内联小函数。
> `inline` 在 C++ 头文件里的另一个作用是**避免重复定义**（第 09 章讲）。

#include <stdio.h>

## 课后习题

### 习题 8.1 带输出参数的整数解析（★）

**任务要求**：写一个函数 `bool parse_uint(const char *s, uint64_t *out)`，
把十进制字符串 `s` 解析成整数写入 `*out`。成功返回 `true`；
若字符串为空、含非数字字符、或为空指针，返回 `false` 且**不修改** `*out`。

**核心骨架**：

```c
#include <stdio.h>
#include <stdint.h>
#include <stdbool.h>

// 返回 false 时，*out 必须保持调用前的值
bool parse_uint(const char *s, uint64_t *out) {
    // TODO: 逐字符判断 + 累乘 10
}

int main(void) {
    uint64_t v = 999;
    bool ok = parse_uint("1234", &v);
    printf("ok=%d v=%llu\n", ok, (unsigned long long)v);   // ok=1 v=1234
    return 0;
}
```

**参考实现**：

```c
bool parse_uint(const char *s, uint64_t *out) {
    if (s == NULL || out == NULL || *s == '\0') return false;   // 空指针 / 空串
    uint64_t acc = 0;
    for (const char *p = s; *p; p++) {
        if (*p < '0' || *p > '9') return false;                 // 非数字
        acc = acc * 10 + (uint64_t)(*p - '0');
    }
    *out = acc;          // ★ 只有全部通过才写回，保证失败时不改 *out
    return true;
}
```

**验证断言**：

```c
#include <assert.h>
#include <stdint.h>
#include <stdbool.h>
#include <stdio.h>
#include <stddef.h>

// 接上面的 parse_uint 定义
bool parse_uint(const char *s, uint64_t *out);

int main(void) {
    uint64_t v = 999;
    assert(parse_uint("1234", &v) == true  && v == 1234);
    assert(parse_uint("0",    &v) == true  && v == 0);
    v = 999;
    assert(parse_uint("12a4", &v) == false && v == 999);   // 失败不改值
    assert(parse_uint("",     &v) == false && v == 999);   // 空串
    assert(parse_uint(NULL,   &v) == false && v == 999);   // 空指针
    printf("习题 8.1 全部通过\n");
    return 0;
}
```

> [!tip] 这道题练什么
> ① **输出参数**（`uint64_t *out`）——本章重点，函数用指针把结果传出去；
> ② **失败路径**——先判非法再改 `*out`，这是本项目 `dr->Read(...)` 失败返回 0 的同款习惯；
> ③ **空指针判空**——本章和第 05 章反复强调的防御。

### 习题 8.2 递归求幂与栈深度（★★）

**任务要求**：写递归函数 `uint64_t pow_rec(uint64_t base, int exp)` 计算 `base^exp`；
再写迭代版 `uint64_t pow_iter(uint64_t base, int exp)`。两者结果必须一致。

**参考实现**：

```c
uint64_t pow_rec(uint64_t base, int exp) {
    if (exp == 0) return 1;              // 递归基
    return base * pow_rec(base, exp - 1); // 每层压一个栈帧
}

uint64_t pow_iter(uint64_t base, int exp) {
    uint64_t r = 1;
    for (int i = 0; i < exp; i++) r *= base;
    return r;
}
```

**验证断言**：

```c
int main(void) {
    for (int e = 0; e <= 10; e++)
        assert(pow_rec(2, e) == pow_iter(2, e));
    assert(pow_rec(3, 4) == 81);
    printf("习题 8.2 全部通过\n");
    return 0;
}
```

> [!warning] 递归深度 = 栈帧数
> `pow_rec(2, 100000)` 会压 10 万个栈帧，**大概率爆栈**（本章"递归与栈深度"一节）。
> 这就是为什么本项目里处理大数据的循环都用 `for` 而不是递归。
