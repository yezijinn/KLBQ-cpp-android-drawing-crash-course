# 第 08 章 · 函数、栈帧与参数传递

> [!abstract] 本章目标
> 理解函数调用时内存里发生了什么，为什么递归太深会"爆栈"，以及参数是怎么传进去的。
> 第 25 章讲 ARM64 汇编时，本章是前置知识。

## 先看一个爆栈

```c
#include <stdio.h>

void recurse(int n) {
    char buf[1024];              // 每层用掉 1KB 栈
    printf("depth=%d  buf@%p\n", n, (void*)buf);
    recurse(n + 1);
}

int main(void) { recurse(0); }
```

跑起来，几万层之后程序崩溃（Stack overflow）。
注意打印出来的地址：**每一层 `buf` 的地址都在变小**——栈是向下生长的。

## 栈是什么

每个线程有一块连续内存叫**栈**。它的规则极简：

- 只有一个口（栈顶指针 `SP`）
- 压数据：`SP` 往下移，把数据放进去
- 弹数据：`SP` 往上移
- 后进先出（LIFO）

```
高地址  0x7FFF_FFFF
   ┌──────────────┐
   │   main 的栈帧  │
   ├──────────────┤
   │  funcB 的栈帧  │  ← 当前函数
   ├──────────────┤
   │  funcC 的栈帧  │  ← SP 指向这里
   └──────────────┘
低地址                 栈向下生长
```

## 一次函数调用发生了什么

```c
int add(int a, int b) {
    int sum = a + b;
    return sum;
}

int main(void) {
    int r = add(3, 4);
    return 0;
}
```

调用 `add(3, 4)` 时，硬件和编译器配合做这些事：

1. **传参**：把 `3` 和 `4` 放到约定好的位置（x86-64 前 6 个参数放寄存器，ARM64 前 8 个放 `x0~x7`）
2. **保存返回地址**：把"调用完该回到哪"的地址压栈（ARM64 存 `x30`/LR 寄存器）
3. **跳转**：跳到 `add` 的第一条指令
4. **开栈帧**：`SP` 下移，给 `sum` 等局部变量腾地方
5. **执行函数体**
6. **收栈帧**：`SP` 上移，局部变量作废
7. **返回**：按返回地址跳回去，返回值放在约定寄存器（`x0` / `rax`）

关键点在步骤 6：**局部变量在函数返回那一刻就死了。**
这就是第 05 章"不要返回局部变量地址"的原因——那块栈空间马上会被下一个函数覆盖。

## 栈帧里都有什么

一个典型的栈帧（简化）：

```
        ┌────────────────┐
   +16  │  参数 7, 8, ... │   ← 超过寄存器数量的参数
        ├────────────────┤
   +8   │   返回地址      │   ← 函数返回后跳到哪
        ├────────────────┤
   +0   │  上一个栈帧指针 │   ← FP/LR 保存区
        ├────────────────┤
   -8   │   局部变量 1    │
        ├────────────────┤
   -16  │   局部变量 2    │
        ├────────────────┤
   -24  │   临时保存的寄存器│
        └────────────────┘  ← SP
```

调试器（gdb）就是靠这条链（每个栈帧记着上一个栈帧的地址）还原出"调用栈"的。
你崩溃时看到的 backtrace，就是它打印的。

## 参数传递：值传递是唯一的真相

```c
void inc(int x) { x++; }

int main(void) {
    int a = 10;
    inc(a);
    printf("%d\n", a);   // 还是 10
}
```

**C 语言只有值传递。** `inc` 拿到的是 `a` 的一份拷贝。

想改外面的变量，就传它的地址：

```c
void inc(int *x) { (*x)++; }

int a = 10;
inc(&a);
printf("%d\n", a);   // 11
```

这叫"模拟引用传递"——本质仍然是值传递，只不过传的值是地址。

## 用指针做输出参数

本项目里到处是这个模式：

```c
bool GetModuleAddress(std::string_view name, short segmentIndex,
                      uint64_t *outAddress, bool isStart);
```

`outAddress` 是**输出参数**。调用时：

```c
uint64_t moduleBase = 0;
if (!dr->GetModuleAddress("libUE4.so", 0, &moduleBase, true)) {
    return;   // 失败
}
// 成功，moduleBase 被填上了
```

为什么返回值是 `bool`（成功与否），而真正的结果走指针？因为一个函数只能有一个返回值，
"成功了吗"和"值是多少"要分开表达。第 13 章会讲 C++17 的 `std::optional` 是更优雅的写法。

## 数组作为输出缓冲区

```c
int Read(uint64_t address, void *buffer, size_t size);
```

调用方负责准备空间：

```c
uint8_t buf[256];
int n = dr->Read(addr, buf, sizeof(buf));
if (n <= 0) { /* 处理失败 */ }
```

> [!danger] 缓冲区必须真的能装下 size 字节
> ```c
> uint8_t buf[16];
> dr->Read(addr, buf, 256);   // 灾难：写越界 240 字节
> ```
> 这是 C 语言里最常见的安全漏洞（缓冲区溢出）。
> 本项目的 `HandleVirtualMemoryRWEvent` 内部按 0x1000 分块，
> 就是保证任何一次拷贝都不会超过调用方给的缓冲区。

## 递归与栈深度

```c
uint64_t factorial(int n) {
    if (n <= 1) return 1;
    return n * factorial(n - 1);
}
```

每次调用都要一个新栈帧。深度 n 就压 n 层。
典型栈大小：Linux 主线程 8MB，pthread 默认 8MB（Android 上可能只有 1MB）。

> [!warning] 在 Android 子线程里注意栈大小
> 本项目创建了 3 个后台线程（更新物理场景）。如果线程函数里有大数组或深递归，
> 在 Android 默认的 1MB 栈上会崩。
> 解决：大数组改用 `malloc` 放堆上，或 `pthread_attr_setstacksize`。

## 内联函数

```c
static inline float dot(const Vec3 *a, const Vec3 *b) {
    return a->x*b->x + a->y*b->y + a->z*b->z;
}
```

`inline` 建议编译器"别生成函数调用，直接把代码贴过去"。省掉开栈帧的开销。

本项目数学代码几乎全是 `inline`（`WorldToScreen.h`、`SilentAim.h`），因为每帧要算几千次。
但注意：

> [!note] inline 只是建议
> 编译器可以无视它。开了 `-O2` 后编译器自己也会内联小函数。
> `inline` 在 C++ 头文件里的另一个作用是**避免重复定义**（第 09 章讲）。

## 动手：观察栈地址

```c
#include <stdio.h>

void level3(void) { int x; printf("level3  &x = %p\n", (void*)&x); }
void level2(void) { int x; printf("level2  &x = %p\n", (void*)&x); level3(); }
void level1(void) { int x; printf("level1  &x = %p\n", (void*)&x); level2(); }

int main(void) {
    int x;
    printf("main    &x = %p\n", (void*)&x);
    level1();
    return 0;
}
```

输出里，`main` 的地址最大，越深层的越小。差值就是每层栈帧的大小。
再改一下，在 `level2` 里加一个 `char buf[512]`，看 `level3` 的地址掉了多少。
