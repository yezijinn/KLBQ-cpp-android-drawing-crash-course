# 第 06 章 · 数组、字符串与连续内存

> [!abstract] 本章目标
> 理解"数组就是一段连续内存"，并知道越界为什么危险。
> 本章会带你解析一个真实存在的数组结构（UE4 的 TArray）。

> [!note] 承上
> 上一章的指针一次指向一块内存。本章要一次处理**一排连续的内存**——数组。
> 这也是后面读对象数组的基础。

## 数组：一排同类型的盒子

第 04 章你学会了"声明一个变量"。但很多时候你需要**一次放很多个同类型的数据**——比如 100 个学生的成绩、8 个坐标点、50 个 Actor 指针。

一个个声明又麻烦又没法用循环处理：

```c
int score1 = 90;
int score2 = 85;
int score3 = 88;
// ... 100 个怎么办？
```

**数组（array）就是解决这件事的：一排连续的、同类型的盒子。**

### 声明一个数组

**语法**：

```c
类型 数组名[元素个数];
```

**例子**：

```c
int scores[5];       // 5 个 int，名字叫 scores
float points[3];     // 3 个 float
char name[8];        // 8 个 char（可以用来存短字符串）
```

**含义**：`int scores[5]` 表示"创建一个数组，里面有 **5 个 `int` 类型**的格子，整个数组叫 `scores`"。

> [!note] 元素个数必须是编译期常量
> `int arr[5];` 合法（5 是写死的）。
> `int n = 5; int arr[n];` 在老式 C 里**不合法**（C99 起才允许"变长数组"，但很多编译器默认关闭）。
> **规矩**：数组大小要么写死，要么用 `#define` 或 `constexpr` 定义常量（第 10、12 章）。

### 初始化数组

**逐个给值**：

```c
int scores[3] = {90, 85, 88};       // 花括号里按顺序列出
```

**部分给值**（剩下的自动为 0）：

```c
int scores[5] = {90, 85};           // 前两个是 90、85，后面三个是 0
```

**全给 0**：

```c
int scores[5] = {0};                // 全部清零（只用写一个 0）
```

**让编译器数个数**：

```c
int scores[] = {90, 85, 88, 92};    // 自动变成 4 个元素
```

### 访问元素：用"下标"

**语法**：

```c
数组名[下标]
```

**下标从 0 开始数**：

```c
int scores[3] = {90, 85, 88};

scores[0]    // 第一个元素，值是 90
scores[1]    // 第二个元素，值是 85
scores[2]    // 第三个元素，值是 88
```

```text
下标:      0       1       2
        ┌───────┬───────┬───────┐
内容:   │  90   │  85   │  88   │
        └───────┴───────┴───────┘
```

**下标可以是变量或表达式**，这就让它和循环配合起来了：

```c
int i = 1;
scores[i]        // scores[1] = 85
scores[i + 1]    // scores[2] = 88
```

> [!danger] 下标从 0 开始，不是 1
> `scores[0]` 是**第一个**元素，`scores[1]` 是第二个。
> 如果你写 `scores[3]` 想去取"第三个元素"，实际上**越界了**——只有 `scores[0]`、`scores[1]`、`scores[2]` 是合法的。
> **这个"从 0 开始"是计算机里几乎所有"索引"的约定**，习惯它。

### 读和写元素

```c
int scores[3] = {90, 85, 88};

printf("%d\n", scores[0]);    // 读第一个：90

scores[1] = 100;               // 改第二个
printf("%d\n", scores[1]);    // 100
```

**元素就是普通变量**，只是用 `数组名[下标]` 的方式去访问它。读写规则完全一样。

### 用循环遍历数组

**这就是数组真正的价值**——配合循环处理"所有元素"：

```c
#include <stdio.h>

int main(void) {
    int scores[5] = {90, 85, 88, 92, 78};

    for (int i = 0; i < 5; i++) {
        printf("scores[%d] = %d\n", i, scores[i]);
    }
    return 0;
}
```

输出：

```text
scores[0] = 90
scores[1] = 85
scores[2] = 88
scores[3] = 92
scores[4] = 78
```

**`for (int i = 0; i < 5; i++)` 是遍历数组的标准写法**：

- `i = 0`：从第一个开始
- `i < 5`：到第 5 个之前（即下标 4）为止
- `i++`：每次下标加 1

> [!danger] 循环条件用 `<` 不用 `<=`
> 数组长度是 5 时，合法下标是 `0, 1, 2, 3, 4`。
> - `i < 5` ✓（i 到 4 就停，正好覆盖 0~4）
> - `i <= 5` ✗（i 到 5 时还进去，`scores[5]` **越界**！）
> 这个一字符之差是新手最常见的 bug。**背下来**：`i < 长度`。

### `sizeof` 求数组长度

```c
int scores[5];

printf("%zu\n", sizeof(scores));         // 20（5 个 int × 4 字节）
printf("%zu\n", sizeof(scores) / sizeof(scores[0]));  // 5（元素个数）
```

**`sizeof(数组)` = 数组总字节数**；除以 `sizeof(一个元素)` 得到**元素个数**。

这个技巧在循环里很实用：

```c
for (int i = 0; i < (int)(sizeof(scores) / sizeof(scores[0])); i++) {
    printf("%d\n", scores[i]);
}
```

**改了数组大小，循环条件自动跟上**，不用手改数字。

> [!warning] 但这是陷阱：传进函数后 `sizeof` 会变
> **数组作为参数传给函数时会退化为指针**，此时 `sizeof(参数)` 不再等于数组大小。
> 这就是为什么本项目的读取函数都要显式传"个数"参数。**本章后面「数组传参会退化成指针」会详解。**

## 动手：写一个成绩统计程序

```c
#include <stdio.h>

int main(void) {
    int scores[6] = {90, 85, 88, 92, 78, 95};
    int n = (int)(sizeof(scores) / sizeof(scores[0]));

    // 求总分
    int sum = 0;
    for (int i = 0; i < n; i++) {
        sum = sum + scores[i];
    }
    printf("总分 = %d\n", sum);

    // 求平均
    float avg = (float)sum / n;   // 转成 float 才能得到小数
    printf("平均 = %.1f\n", avg);

    // 找最高分
    int max = scores[0];
    for (int i = 1; i < n; i++) {
        if (scores[i] > max) {
            max = scores[i];
        }
    }
    printf("最高分 = %d\n", max);

    return 0;
}
```

输出：

```text
总分 = 528
平均 = 88.0
最高分 = 95
```

**关键点**：
- 总分用一个 `sum` 变量累加，初值必须是 0
- 平均用 `(float)sum / n`——不转 float，`sum / n` 会做整数除法（第 03 章讲过）
- 找最大值时 `max` 初值用 `scores[0]`，然后从 `i = 1` 开始比

这三段是"遍历数组做统计"的经典模板，后面章节里到处是它的变体。

## 数组在内存里的布局：元素是紧挨着的

这一节是数组最重要的性质，也是本章后半部分的基础。

```c
int scores[4] = {90, 85, 88, 92};
```

**四个 `int` 在内存里是紧挨着的**：

```text
地址:      0x1000  0x1004  0x1008  0x100C
         ┌──────┬──────┬──────┬──────┐
内容:    │  90  │  85  │  88  │  92  │
         └──────┴──────┴──────┴──────┘
下标:       0      1      2      3
偏移:      +0     +4     +8     +12
```

**三个事实**：

1. **元素紧挨着，没有空隙**（这就是"连续内存"）
2. **地址 = 首地址 + 下标 × 每个元素的大小**
   例如 `scores[2]` 的地址 = `0x1000 + 2 × 4 = 0x1008`
3. **数组名在大多数场合就是"首元素地址"**（也就是说 `scores` 等价于 `&scores[0]`）

**第 2 条是本项目遍历 Actor 数组的数学基础**——后面你会看到：

```c
uint64_t obj = dr->Read<uint64_t>(Arrayaddr + 0x8 * i);
//                                            ^^^^^^ 每个元素 8 字节（指针），所以是 8*i
```

**为什么从 0 开始数**？因为 `arr[i]` 的地址 = `首地址 + i × 大小`，第一个元素偏移必须是 0。所以第一个下标是 0。

### 数组名与指针的关系

**数组名在大多数场合会"退化"成首元素地址**：

```c
int arr[3] = {10, 20, 30};

arr           // 等价于 &arr[0]
*(arr + 0)    // 等价于 arr[0]，值是 10
*(arr + 1)    // 等价于 arr[1]，值是 20
```

**这就是为什么 `arr[2]` 等价于 `*(arr + 2)`**——下标运算本质上是"先指针偏移，再解引用"。

（这套等价关系在深挖 A 里有更细的讨论。现在记住"数组名可以当首元素地址用"就够了。）

## 动手：遍历数组打印所有元素

```c
#include <stdio.h>

int main(void) {
    int arr[4] = {10, 20, 30, 40};
    int *p = arr;              // p 指向首元素

    for (int i = 0; i < 4; i++) {
        printf("arr[%d]=%d  *(p+%d)=%d\n",
               i, arr[i], i, *(p + i));
    }
    return 0;
}
```

输出：

```text
arr[0]=10  *(p+0)=10
arr[1]=20  *(p+1)=20
arr[2]=30  *(p+2)=30
arr[3]=40  *(p+3)=40
```

**两列完全一样**——这证明 `arr[i]` 和 `*(p + i)` 做的是同一件事。

## 现在回头看：什么叫"越界"

前面你学会了数组的三种访问方式：

| 写法 | 含义 |
|---|---|
| `arr[i]` | 下标访问 |
| `*(arr + i)` | 指针偏移后解引用 |
| `*(p + i)` | 用另一个指针偏移 |

它们**都基于同一个公式**：`地址 = 首地址 + i × sizeof(元素)`。

那么问题来了：**如果 i 超过数组长度呢？**

答案是：**公式仍然成立，编译器不会拦你，运行时不报错，它就去算那个"越界的地址"，然后读写它**。

那个越界地址上住着谁？不知道——可能是别的变量、函数的返回地址、系统的数据。**写它可能改掉别人的东西，读它可能是垃圾值。**

**这就是"越界"，本章下面的章节会详解它的后果和防御。**


## 先看一个越界的现场

```c
#include <stdio.h>

int main(void) {
    int scores[3] = {90, 85, 88};
    int guard = 12345;

    printf("guard = %d\n", guard);
    scores[3] = 999;                    // 越界！只有 0,1,2 合法
    printf("guard = %d\n", guard);      // 可能变成 999
    return 0;
}
```

`scores[3]` 并不存在，但 C 语言**不检查**。它就往 `scores` 后面那一格写。
如果那一格恰好是 `guard`，`guard` 就被改了。如果那一格是函数返回地址，程序就跳到奇怪的地方去了。

> [!danger] 数组越界是 C 语言最常见的崩溃源
> 编译器不拦，运行时不报，症状是"偶发的离奇结果"。
> 本项目读取的 Actor 数组有 `Count` 字段控制上界，
> 每次遍历都必须用它，绝不能猜一个固定值。

## 数组传参会退化成指针

```c
#include <stdio.h>

void print(int arr[], int n) {   // 等价于 void print(int *arr, int n)
    printf("%zu\n", sizeof(arr));  // 输出 8（指针大小），不是数组大小！
}

int main(void) {
    int a[10];
    printf("%zu\n", sizeof(a));   // 输出 40
    print(a, 10);
}
```

**函数里无法用 `sizeof` 求数组长度，必须额外传个数。** 这就是为什么本项目的读取函数都长这样：

```cpp
int Read(uint64_t address, void *buffer, size_t size);  // size 必须显式传，返回读到的字节数
```

## 二维与"数组的数组"

```c
float m[4][4];      // 16 个 float，还是连续的 64 字节

m[1][2] 等价于 *(*(m + 1) + 2) 等价于 ((float*)m)[1*4 + 2]
```

本项目里的矩阵就是这么存的：

> 现在只要看懂：`Matrix` 里有一个 4×4 的 `float` 数组，一共 64 字节。

```c
struct Matrix {
    float M[4][4];
};
```

读它的时候，一次读 `sizeof(Matrix)` = 64 字节，然后按 `M[row][col]` 访问。

## 字符串：以 0 结尾的字符数组

```c
char name[] = "Player";
```

```
地址:   0:2000 2001 2002 2003 2004 2005 2006
内容:     P    l    a    y    e    r   \0
```

**`\0`（值为 0 的字节）是字符串的结束标志。** 所以：
- `"Player"` 占 7 字节，不是 6
- `strlen` 靠扫描到 `\0` 判断长度
- 如果 `\0` 丢了，`strlen` 会一直往后读直到碰巧遇到 0——这就是"读越界"

> [!warning] 从别的进程读字符串时必须限制长度
> ```c
> std::string ReadString(uint64_t address, size_t max_length = 128);
> ```
> 本项目这个接口有 `max_length` 参数，就是为了防止目标内存里没有 `\0` 时无限读。
> 第 75 章你自己实现时一定要带上。
>
> [!note] `std::string` 是什么
> 上面的 `std::string` 是 **C++ 的字符串类型**（第 13 章会讲）——它比 C 的 `char` 数组好用得多：能自动管理内存、能直接赋值、能拼接、自带长度。
> 本项目里"解析出来的字符串"大多用 `std::string` 装（`char` 数组主要用于"读原始字节"）。
> **现在只要知道：凡是看到 `std::string`，就是"C++ 的字符串对象"。**

> [!note] 字符串字面量的类型是 `const char *`
> 你写的 `"Player"`、`"hello"` 这种**字符串字面量**，它的类型是 **`const char *`**——"指向常量的字符指针"。
> ```c
> const char *s = "hello";   // s 指向字符串的第一个字符
> ```
> 这就是为什么函数参数里传字符串常用 `const char *`（第 08、15 章会见到）。
> 你现在只要知道：**`"..."` 这个字面量的类型是 `const char *`**，可以赋给 `const char *` 变量，也能直接传给 `printf`。

### 常用字符串函数

C 标准库提供了一组处理字符串的函数（都要 `#include <string.h>`）。**它们全都依赖"以 `\0` 结尾"这个约定。**

| 函数 | 作用 | 例子 | 注意 |
|---|---|---|---|
| `strlen(s)` | 求长度（不含 `\0`） | `strlen("hello")` → `5` | 返回 `size_t`（无符号） |
| `strcpy(dst, src)` | 复制字符串 | `strcpy(dst, "hi")` | **不检查目标够不够大** |
| `strncpy(dst, src, n)` | 最多复制 n 个字符 | `strncpy(dst, src, 15)` | 更安全，**推荐** |
| `strcmp(a, b)` | 比较（**相等返回 0**） | `if (strcmp(a,b) == 0)` | 别记反 |
| `strcat(dst, src)` | 拼接 | `strcat(dst, "!")` | 同样不检查越界 |
| `memcpy(dst, src, n)` | 复制 n 个**字节** | `memcpy(dst, src, 16)` | 用于二进制数据 |
| `memset(p, v, n)` | 把 n 字节全设为 v | `memset(buf, 0, 100)` | 常用于清零 |

**逐个看关键点**：

```c
#include <string.h>

char name[] = "Player";

size_t len = strlen(name);          // 6（不含 \0）
printf("%zu\n", len);

char copy[20];
strncpy(copy, name, sizeof(copy) - 1);   // 复制，留出 \0 的位置
copy[sizeof(copy) - 1] = '\0';          // 确保结尾有 \0（strncpy 的坑）

if (strcmp(name, "Player") == 0) {
    printf("相同\n");
}
```

> [!danger] `strlen` 返回无符号数，减法会下溢
> 第 04 章讲过这个坑，这里再强调一次：
> ```c
> if (strlen(s) - 10 < 0)     // 永远不成立！
> ```
> `strlen` 返回 `size_t`（无符号），减 10 后如果"结果是负的"，会回绕成巨大的正数。
> **正确写法**：`if (strlen(s) < 10)`。

> [!warning] `strcpy` / `strcat` 有缓冲区溢出风险
> 它们不知道目标数组有多大，源字符串一长就**写越界**。
> **优先用 `strncpy`**，并手动确保结尾有 `\0`。
> 本项目读外部字符串时**不仅限长，还自己管 `\0`**——因为目标进程的数据不可信。

**这些函数里，本项目最常用的是 `memcpy`**（复制字节）和 `memset`（清零）——处理二进制数据时离不开它们。

## 宽字符：UTF-16 与 UTF-32

游戏里的字符串常常不是 `char` 数组：

| 编码 | 每字符字节数 | C 类型 | 结尾 |
|---|---|---|---|
| UTF-8 | 1~4 | `char` | 1 字节 0 |
| UTF-16 | 2（常用） | `char16_t` | 2 字节 0 |
| UTF-32 | 4 | `char32_t` | 4 字节 0 |

本项目解析游戏对象名时就要处理两种：

```cpp
uint32_t len = header >> 6;
bool isWide = header & 1;      // 1 表示 UTF-16/32，0 表示 UTF-8

if (isWide) {
    std::u32string u32(len, 0);
    dr->Read(entryAddr + 2, u32.data(), len * 4);   // 每个字符 4 字节
    // 再手工转 UTF-8（代码见 variable.h 的 AppendUtf8）
} else {
    std::string s(len, 0);
    dr->Read(entryAddr + 2, s.data(), len);         // 每个字符 1 字节
}
```

关键观察：**长度字段的单位是"字符数"，读的字节数要乘上每个字符的字节数。**
第 85 章会完整实现这套解析。

## 实战：解析一个 TArray

UE4 里最常见的容器是 `TArray`，它在内存里就三个字段：

> [!note] `template <typename T>` 先忽略
> 下面结构体上面那句 `template <typename T>` 是 **C++ 的模板语法**——意思是"这个结构体里的 `T` 是个**待定类型**，用的时候再指定装什么"。
> 你现在只需要看**结构体本身的三个字段**（`Data` / `Count` / `Max`），不用管 `template`。
> **第 13 章会专门讲模板。** 这里出现只是因为本项目 `PhysX.h` 里就是这么定义的。

```cpp
template <typename T>
struct TArray {
    uintptr_t Data;   // 数组首地址（8 字节）
    int32_t   Count;  // 元素个数（4 字节）
    int32_t   Max;    // 容量（4 字节）
};
```
共 16 字节。本项目 `PhysX.h` 里就是这个定义。

判断一个 TArray 是否可用：

```c
bool IsValid() const {
    return Data && Count > 0 && Count <= Max && Max > 0;
}
```

为什么要这么判？因为读出来的可能是垃圾：

| 检查 | 防止什么 |
|---|---|
| `Data != 0` | 空指针解引用 |
| `Count > 0` | 负数（有符号被当无符号会变成天文数字） |
| `Count <= Max` | 数据不一致，说明读错了 |
| `Max > 0` | 未初始化的容器 |

遍历它：

```c
for (int32_t i = 0; i < arr.Count; i++) {
    uint64_t elem = dr->Read<uint64_t>(arr.Data + i * sizeof(uint64_t));
    // 用 Count 做上界，绝不用 Max
}
```

> [!note] 为什么用 Count 不用 Max
> `Max` 是容量（分配了多少格），`Count` 是实际元素数。
> 遍历到 `Max` 会读到未初始化的垃圾指针。

> [!note] 关于 `typedef struct { ... } TArray;` 这个写法
> 你会在下面看到这种结构体声明。**它是"定义结构体类型"的简写形式**：
> ```c
> typedef struct {
>     uint64_t data;
>     int32_t  count;
>     int32_t  max;
> } TArray;
> ```
> 含义：**定义一个匿名结构体，然后给它起个别名叫 `TArray`**。
> 用的时候直接写 `TArray a;`（不用写 `struct TArray`）。
> **第 07 章会详细讲 `typedef` 和结构体**，这里先混个眼熟。

## 动手：写一个"安全数组读取器"

```c
#include <stdio.h>
#include <stdint.h>
#include <stdlib.h>

typedef struct {
    uint64_t data;
    int32_t  count;
    int32_t  max;
} TArray;

int array_valid(const TArray *a) {
    return a->data && a->count > 0 && a->count <= a->max && a->max > 0;
}

// 从 src 的第 index 个位置读一个 8 字节元素
uint64_t array_get_u64(const TArray *a, int32_t index) {
    if (!array_valid(a)) return 0;
    if (index < 0 || index >= a->count) return 0;   // 边界检查
    return *(uint64_t *)(a->data + index * 8);
}

int main(void) {
    uint64_t elems[4] = {0xAAAA, 0xBBBB, 0xCCCC, 0xDDDD};
    TArray a = { (uint64_t)elems, 3, 4 };   // count=3，max=4

    printf("valid=%d\n", array_valid(&a));
    for (int i = 0; i < 5; i++) {
        printf("[%d] = 0x%llX\n", i, (unsigned long long)array_get_u64(&a, i));
    }

    TArray bad = { 0, 3, 4 };
    printf("bad valid=%d\n", array_valid(&bad));
    return 0;
}
```

预期输出：第 4 次（index=3）返回 0，因为 `count=3`，合法下标只有 0/1/2。
这就是"用 Count 拦住越界"的实际效果。

## 课后习题

### 习题 06.1 验证数组的连续内存（★）

**任务要求**：打印数组相邻元素的地址，验证它们相差 `sizeof(元素)`。

**参考实现**：

```c
#include <stdio.h>
#include <assert.h>

int main(void) {
    int a[4] = {10, 20, 30, 40};
    // 相邻 int 的地址差 4 字节
    assert((char*)&a[1] - (char*)&a[0] == 4);
    assert((char*)&a[2] - (char*)&a[1] == 4);
    // 数组首地址 + i*4 = 第 i 个元素地址（下标从 0 开始）
    assert((char*)&a[2] - (char*)&a[0] == 2 * 4);
    printf("&a[0]=%p &a[1]=%p\n", (void*)&a[0], (void*)&a[1]);
    printf("习题 06.1 全部通过\n");
    return 0;
}
```

**验证断言**：相邻元素地址差 `4`（`sizeof(int)`）；`&a[2]-&a[0] == 8`。

> [!note] 地址 = 首地址 + 下标 × 元素大小
> 这就是为什么下标从 0 开始（第一个元素偏移必须是 0），
> 也是本项目 `Arrayaddr + 0x8 * i`（每个指针 8 字节）的数学基础。

### 习题 06.2 写一个安全的数组读取器（★★）

**任务要求**：写 `int safe_get(const int* arr, int len, int index)`，
越界时返回 0 而不是崩溃（类比本项目 `TArray` 的 `Count` 上界检查）。

**参考实现**：

```c
#include <stdio.h>
#include <assert.h>

int safe_get(const int* arr, int len, int index) {
    if (arr == NULL || index < 0 || index >= len) return 0;   // ★ 边界检查
    return arr[index];
}

int main(void) {
    int a[3] = {10, 20, 30};
    assert(safe_get(a, 3, 0) == 10);
    assert(safe_get(a, 3, 2) == 30);
    assert(safe_get(a, 3, 3) == 0);    // 越界 → 0，不崩
    assert(safe_get(a, 3, -1) == 0);   // 负下标 → 0
    assert(safe_get(NULL, 3, 0) == 0);// 空指针 → 0
    printf("习题 06.2 全部通过\n");
    return 0;
}
```

> [!warning] 越界是 C 最常见的崩溃源
> C 语言**不检查**数组越界——`a[3]` 语法合法，但会读写别的内存。
> 本项目读游戏 Actor 数组时**必须用 `Count` 字段做上界**，绝不猜固定值。
