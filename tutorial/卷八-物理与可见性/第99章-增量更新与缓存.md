# 第 99 章 · 增量更新与缓存

> [!abstract] 本章目标
> 掌握"只更新变化的部分"的各种技巧。
> 这是让物理场景能在后台持续刷新而不卡顿的关键。

> [!note] 承上
> 上一章能从碰撞体重建网格了，但每次全量重建太慢。
> 本章学**增量更新**——只更新变化的部分，让后台线程能持续刷新而不卡顿。

## 先看问题

一个静态场景 50 万三角形，重建一次要 1~3 秒。

```
每帧重建 → 完全不可能
每 2 秒重建 → 每次卡 1 秒，游戏没法玩
```

**必须增量更新**：只处理变化的部分。

## 增量更新的四个层次

| 层次 | 手段 | 节省 |
|---|---|---|
| 1 | 跳过未变化的物体 | 90%+ |
| 2 | 复用已存在的 geometry | 避免重建 BVH |
| 3 | 复用场景（refit） | 避免全量重建 |
| 4 | 分帧处理 | 避免单帧卡顿 |

## 层次 1：变化检测

### 用变换判断

```cpp
struct CachedEntry {
    PxTransform lastTransform;
    uint64_t    lastMeshPtr;
    bool        dirty;
};

bool IsChanged(const PxRigidActor &actor, const CachedEntry &cached) {
    // 变换变了？
    PxTransform t = actor.getGlobalPose();
    if (Distance(t.p, cached.lastTransform.p) > 0.1f) return true;
    if (QuatAngle(t.q, cached.lastTransform.q) > 0.001f) return true;

    // 网格换了？（LOD 切换、模型替换）
    if (actor.getMeshPtr() != cached.lastMeshPtr) return true;

    return false;
}
```

本项目实际用的判据（与上面 Demo 版思路一致）：

```cpp
// 位移/旋转超阈值 或 mesh 指针变化 → 重建
位移 > 0.1  ||  旋转 > 0.1  ||  meshPtr 变化
```

**阈值选择**：
- 太小（0.001）：几乎每帧都重建，等于没优化
- 太大（10）：物体明显动了才更新，可见性判定不准
- **0.1 厘米** 是合理值（远小于物体尺寸）

### 用时间戳判断（更快）

物理引擎通常维护一个"场景版本号"：

```cpp
uint64_t GetSceneTimestamp(uint64_t sqManager) {
    return dr->Read<uint64_t>(sqManager + 0x2430);
}

if (currentTimestamp == lastTimestamp) {
    return;      // 场景没变，整个跳过
}
```

本项目：

```cpp
// SQManager(0x2430) 未变则跳过
// 时间戳读成 0 时不拦截（避免"永远不加载"）
```

> [!warning] 时间戳为 0 的陷阱
> 如果偏移失效或数据未初始化，时间戳永远是 0，
> 那么"和上次一样"就永远成立 → **场景永远不加载**。
> 所以要加"读成 0 就不拦截"的特判。这是个实战经验。

## 层次 2：复用 geometry

Embree 里每个 geometry 有 ID。物体没变就**不要动它**：

```cpp
class VisibleScene {
public:
    void Update(int pid) {
        // 1. 收集当前所有 shape
        auto shapes = CollectShapes(pid);

        // 2. 标记：本次见到的
        std::unordered_set<uint64_t> seen;

        for (auto &s : shapes) {
            seen.insert(s.shapePtr);

            auto it = cache_.find(s.shapePtr);
            if (it != cache_.end()) {
                // 已存在：检查是否变化
                if (!IsChanged(s, it->second)) continue;

                // 变了：更新 geometry
                UpdateGeometry(it->second.geomID, s);
            } else {
                // 新增：创建 geometry
                uint32_t id = CreateGeometry(s);
                cache_[s.shapePtr] = {id, s.transform, s.meshPtr};
            }
        }

        // 3. 移除本次没见到的（物体被删除了）
        for (auto it = cache_.begin(); it != cache_.end(); ) {
            if (!seen.count(it->first)) {
                rtcDisableGeometry(scene_, it->second.geomID);
                freeIDs_.push(it->second.geomID);      // 回收 ID
                it = cache_.erase(it);
            } else {
                ++it;
            }
        }

        rtcCommitScene(scene_);
    }

private:
    RTCScene scene_;
    std::unordered_map<uint64_t, CachedEntry> cache_;
    std::vector<uint32_t> freeIDs_;      // 可复用的 ID
};
```

**关键点**：

| 技巧 | 说明 |
|---|---|
| `unordered_map` 缓存 | O(1) 查找 |
| `rtcDisableGeometry` | 禁用而非删除（快） |
| ID 回收池 | 避免 ID 无限增长 |
| 一次 `rtcCommitScene` | 所有改动一起提交 |

## 层次 3：refit 而非 rebuild

只是物体移动（几何不变）：

```cpp
// 用 RTC_BUILD_QUALITY_REFIT
rtcSetSceneBuildQuality(scene, RTC_BUILD_QUALITY_REFIT);
```

或者用变换接口：

```cpp
// 只更新物体变换，不重建 BVH 结构
rtcSetGeometryTransform(geom, 0,
                        RTC_FORMAT_FLOAT4X4_COLUMN_MAJOR, &matrix);
rtcCommitGeometry(geom);
// 场景需要 commit，但比全量重建快得多
```

| 操作 | 耗时（1 万三角形） |
|---|---|
| 全量重建 | 20 ms |
| refit | 2 ms |
| setTransform | 0.5 ms |

## 层次 4：分帧处理

如果一次要处理 1000 个物体，分成 10 帧：

```cpp
class ChunkedUpdater {
public:
    void Tick(int pid) {
        if (pending_.empty()) {
            pending_ = CollectShapes(pid);      // 新一轮
            cursor_ = 0;
        }

        // 每帧处理 100 个
        int processed = 0;
        while (cursor_ < pending_.size() && processed < 100) {
            ProcessShape(pending_[cursor_++]);
            processed++;
        }

        if (cursor_ >= pending_.size()) {
            rtcCommitScene(scene_);             // 全部处理完才提交
            pending_.clear();
        }
    }

private:
    std::vector<ShapeInfo> pending_;
    size_t cursor_ = 0;
};
```

**好处**：单帧耗时可控（100 个物体 × 0.1ms = 10ms 以内）。

## 本项目的三个更新线程

```cpp
thread(&VisibleCheck::UpdateSceneByRange).detach();        // 静态
thread(&VisibleCheck::UpdateDynamicHeightField).detach();  // 高度场
thread(&VisibleCheck::UpdateDynamicRigid).detach();        // 动态
```

每个线程内部：

```cpp
void VisibleCheck::UpdateSceneByRange() {
    Throttler t(2000);        // 2 秒节流

    while (true) {
        if (!t.ShouldRun()) { sleep(50ms); continue; }

        // 检查时间戳
        uint64_t ts = GetSceneTimestamp();
        if (ts != 0 && ts == lastTimestamp_) continue;
        lastTimestamp_ = ts;

        // 增量更新
        scene->UpdateByRange(cameraPos, radius);
    }
}
```

**节流器（Throttler）**：

```cpp
class Throttler {
public:
    explicit Throttler(int64_t periodMs)
        : period_(periodMs), last_(SteadyNow()) {}

    bool ShouldRun() {
        auto now = SteadyNow();
        if (now - last_ < period_) return false;
        last_ = now;
        return true;
    }
private:
    int64_t period_;
    int64_t last_;
};
```

## 按距离更新（UpdateByRange）

只更新相机附近的物体：

```cpp
void UpdateByRange(const Vec3 &center, float radius) {
    for (auto &actor : actors) {
        float d = Distance(actor.position, center);
        if (d > radius) {
            // 太远，标记为"低优先级"或跳过
            continue;
        }
        UpdateActor(actor);
    }
}
```

**理由**：远处的物体对可见性判定没意义（本来就被近的挡住）。

## 缓存的失效条件

| 情况 | 处理 |
|---|---|
| 物体移动 | 更新 geometry |
| 物体删除 | disable + 回收 ID |
| 关卡切换 | **清空整个缓存** |
| 网格数据变化（LOD） | 重建 geometry |
| 进程重启 | 清空 |

**关卡切换的检测**：`UWorld` 或 `ULevel` 指针变了。

```cpp
if (currentLevelPtr != lastLevelPtr) {
    ClearCache();
    lastLevelPtr = currentLevelPtr;
}
```

## 常见错误

| 错误 | 症状 | 解法 |
|---|---|---|
| 从不移除 | 缓存无限增长，内存泄漏 | 每轮检查"没见到的" |
| 阈值太小 | 每帧重建，卡顿 | 调到 0.1 |
| 时间戳为 0 不特判 | 场景永不加载 | 加 `ts != 0` 条件 |
| 不回收 ID | geometry ID 耗尽 | 用 freeID 池 |
| 每帧 commit | 巨慢 | 批量后一次 commit |
| 忘了清缓存（切关卡） | 旧物体残留 | 检测 level 指针变化 |

## 课后习题

### 习题 99.1 用时间戳做变化检测（★★）

**要求**：实现"变化检测"——只更新发生变化的对象（时间戳变了才重建）。
统计全量更新 vs 增量更新的重建次数。

**核心骨架**：

```cpp
#include <cstdio>
#include <cstdint>
#include <vector>
#include <cassert>

struct Object { uint32_t lastTs; bool needsRebuild; };

int incrementalUpdate(std::vector<Object>& objs, const std::vector<uint32_t>& newTs) {
    int rebuilt = 0;
    for (size_t i = 0; i < objs.size(); i++) {
        if (objs[i].lastTs != newTs[i]) {   // ★ 只有时间戳变了才重建
            objs[i].lastTs = newTs[i];
            objs[i].needsRebuild = true;
            rebuilt++;
        } else {
            objs[i].needsRebuild = false;
        }
    }
    return rebuilt;
}

int main() {
    std::vector<Object> objs = {{100, false}, {100, false}, {100, false}, {100, false}};
    // 只有 2 个对象发生了变化
    std::vector<uint32_t> newTs = {100, 101, 100, 102};
    int n = incrementalUpdate(objs, newTs);
    printf("只重建了 %d / %zu 个对象\n", n, objs.size());
    assert(n == 2);                            // 增量：2 个
    assert(objs[1].needsRebuild && objs[3].needsRebuild);
    assert(!objs[0].needsRebuild && !objs[2].needsRebuild);
    printf("习题 99.1 全部通过\n");
    return 0;
}
```

**验证断言**：4 个对象中只有 2 个时间戳变化 → 只重建 2 个。

> [!tip] 这道题练什么
> ① **变化检测**——用时间戳/变换值判断"这个对象这帧变了吗"；
> ② **增量 vs 全量**——本项目三个更新线程都靠这招：没变的对象跳过重建，
> 大幅降低每帧开销（第 99 章核心）。

### 习题 99.2 refit vs rebuild（★，概念题）

**要求**：说出 BVH 的 `refit` 和 `rebuild` 的区别及适用场景。

> [!question]- 参考答案
> - **rebuild**：重新构建整棵 BVH（重新划分节点），慢但质量高；
> - **refit**：保持树结构不变，只更新每个节点的包围盒，快但树可能变差；
> 物体只是"小范围移动"时用 refit（快），大面积变化时才 rebuild。
> 本项目 Embree 内部会自动选，理解这个取舍有助于调优。
