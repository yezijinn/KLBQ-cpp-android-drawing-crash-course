## 一、旋转矩阵的完整推导

### 从基向量出发

一个物体有三个正交的单位基向量：

```
前（Forward）  F = (F.x, F.y, F.z)
右（Right）    R = (R.x, R.y, R.z)
上（Up）       U = (U.x, U.y, U.z)
```

旋转矩阵的作用是：**把标准基（X/Y/Z 轴）映射到这三个向量上**。

```
标准基            旋转后
(1,0,0)  →  F
(0,1,0)  →  R
(0,0,1)  →  U
```

用矩阵表达就是：

```
M × (1,0,0)ᵀ = F    →  M 的第一列 = F
M × (0,1,0)ᵀ = R    →  M 的第二列 = R
M × (0,0,1)ᵀ = U    →  M 的第三列 = U
```

**所以矩阵的三列就是三个基向量。**

现在关键问题：按上面的推导，**列向量约定下基向量是矩阵的列**。
但本项目的 `rotatorToMatrix` 返回的矩阵里，**基向量（F/R/U）是它的三行**——
这不是矛盾，而是因为本项目用的是**行向量约定**（点写成一排、矩阵在右：`v' = v × M`）。
行向量约定下，矩阵相当于列向量约定的转置，所以"列变行"。
两种约定互为转置（第 46 章详述），**本项目源码统一按行向量约定，基向量看"行"**。

验证（Pitch=Yaw=Roll=0）：

```
CP=1, SP=0, CY=1, SY=0, CR=1, SR=0

M[0][0] = CP*CY = 1     M[0][1] = CP*SY = 0     M[0][2] = SP = 0
M[1][0] = SR*SP*CY - CR*SY = 0     M[1][1] = SR*SP*SY + CR*CY = 1
M[2][0] = -(CR*SP*CY + SR*SY) = 0  M[2][1] = CY*SR - CR*SP*SY = 0
```

得到单位矩阵。✓

### 三个轴各自的作用

**绕 Z 轴转 Yaw（偏航）**：

```
     Y
     │
     │___ X
    /
   Z（向上）

绕 Z 转 θ：X 轴 → (cosθ, sinθ, 0)
```

**绕 Y 轴转 Pitch（俯仰）**：

```
X 轴 → (cosθ, 0, sinθ)
```

注意本项目 Pitch 的正方向：抬头 → z 分量变正。

**绕 X 轴转 Roll（翻滚）**：

```
Y 轴 → (0, cosθ, sinθ)  （大致）
```

### 组合顺序：Roll → Pitch → Yaw

本项目的公式是这段组合的结果：

```
M = Rotate_Z(Yaw) × Rotate_Y(Pitch) × Rotate_X(Roll)
```

为什么是这个顺序？因为 UE4 的定义如此：**先翻滚，再俯仰，最后偏航**。

验证 `M[0][2] = SP`：
- 只有 Pitch 影响前方向的高度分量
- Roll 绕 X 轴转，不影响 X 轴本身
- Yaw 绕 Z 轴转，不改变 Z 分量
- **所以前向量的 z 分量只由 Pitch 决定 → z = sin(Pitch)** ✓

这是一个非常有用的直觉：**`GetForward` 里的 `SP` 直接来自这里**。

### 正交性验证

旋转矩阵必须满足 `MᵀM = I`（正交）。验证第 0 行与第 1 行的点积：

```
M[0] · M[1] = (CP*CY)(SR*SP*CY - CR*SY)
            + (CP*SY)(SR*SP*SY + CR*CY)
            + (SP)(-SR*CP)

= CP*SR*SP*CY² - CP*CR*SY*CY
+ CP*SR*SP*SY² + CP*CR*SY*CY
- SP*SR*CP

= CP*SR*SP*(CY² + SY²) - SP*SR*CP
= CP*SR*SP - SP*SR*CP
= 0  ✓
```

**正交性保证了旋转不产生缩放或剪切。**

## 二、四元数的完整代数

### 定义

```
q = w + xi + yj + zk
```

其中：

```
i² = j² = k² = ijk = -1
ij = k,  jk = i,  ki = j
ji = -k, kj = -i, ik = -j
```

**注意最后一行**：四元数乘法**不可交换**（和矩阵一样）。

### 乘法公式

由上面的规则可以推出两个四元数的乘积：

```
q1 × q2 = (w1w2 - x1x2 - y1y2 - z1z2)
        + (w1x2 + x1w2 + y1z2 - z1y2) i
        + (w1y2 - x1z2 + y1w2 + z1x2) j
        + (w1z2 + x1y2 - y1x2 + z1w2) k
```

**这就是四元数乘法的完整展开**。记忆方法：前半部分是"标量部分"（点积形式），
后半部分是"向量部分"（叉积形式 + 交叉项）。

写成向量记号：

```
q1 × q2 = (w1w2 - v1·v2,  w1v2 + w2v1 + v1×v2)
```

### 共轭与求逆

```
共轭：q* = (w, -x, -y, -z)      即标量不变，向量取反
模长：|q| = √(w² + x² + y² + z²)
逆：  q⁻¹ = q* / |q|²

对单位四元数（|q|=1）：q⁻¹ = q*
```

**四元数的逆代表"反向旋转"。**

### 旋转向量

四元数 `q` 旋转向量 `v` 的公式：

```
v' = q × v × q⁻¹
```

其中 `v` 被当作纯四元数 `(0, v.x, v.y, v.z)`。

直接算需要两次四元数乘法（16 次乘法），有更快的形式：

```
t = 2 * (q_vec × v)
v' = v + q.w * t + q_vec × t
```

**这就是第 86 章用到的公式**：

```cpp
// 前提：Quat 有 {float x,y,z,w}，Cross 是第 45 章的向量叉积。
// 注意 q.xyz 是"伪代码简写"，指把 (x,y,z) 当成一个 Vec3。
// 若你的 Quat 没有 xyz 成员，就显式构造：
Vec3 RotateByQuat(const Vec3 &v, const Quat &q) {
    Vec3 qv(q.x, q.y, q.z);              // 四元数的"向量部分"
    Vec3 t = Cross(qv, v) * 2.0f;
    return v + t * q.w + Cross(qv, t);
}
```

从 16 次乘法降到 2 次叉积 + 几次加法。

### 四元数 → 矩阵的推导

用 `v' = v + 2q.w(q_v × v) + 2q_v × (q_v × v)` 展开，可以得到矩阵形式。

设 `q = (w, x, y, z)`，令 `q_v = (x,y,z)`：

```
M = I + 2w[q_v]× + 2[q_v]×²
```

> [!warning] 这个 M 是"列向量约定"版，下面表格是"行向量约定"版
> 上面这个 `M` 满足 `v' = M · v`（**列向量约定**，点写成一列、矩阵在左）。
> 而**下面展开出来的那张表格，是本项目源码用的"行向量约定"版**（`v' = v · M`，
> 与第 46 章讲的"平移在第 4 行"是同一套约定），它正好是上面这个 M 的**转置**。
>
> 两者描述的是**同一个旋转**，只是"点写在左还是右"不同：
> - 用 `RotateByQuat`（`q v q⁻¹`，列向量）验证 → 对应上面的 `M`
> - 用项目源码 `TransformToMatrix`（行向量）验证 → 对应下面的表格
>
> **别拿下面表格去乘列向量**（那样会得到"反向旋转"），这是最容易踩的坑。

其中 `[v]×` 是叉积矩阵：

```
        ┌              ┐
[v]× =  │  0   -vz   vy │
        │  vz   0   -vx │
        │ -vy   vx    0 │
        └              ┘
```

展开后得到（对应本项目 `TransformToMatrix` 的公式）：

```
M[0][0] = 1 - 2(y² + z²)        M[0][1] = 2(xy + wz)      M[0][2] = 2(xz - wy)
M[1][0] = 2(xy - wz)            M[1][1] = 1 - 2(x² + z²)  M[1][2] = 2(yz + wx)
M[2][0] = 2(xz + wy)            M[2][1] = 2(yz - wx)      M[2][2] = 1 - 2(x² + y²)
```

本项目的写法用 `x2 = 2x` 来减少乘法：

```cpp
const float x2 = q.x + q.x;     // = 2x
const float xx2 = q.x * x2;     // = 2x²
matrix.M[0][0] = (1 - (yy2 + zz2)) * scale.x;
```

对照上表：`1 - (2y² + 2z²) = 1 - 2(y²+z²)` ✓

**为什么用 `x + x` 而不是 `2 * x`**：加法和乘法在浮点上有细微差异
（`x+x` 是精确的加倍，`2*x` 也是），这里主要是编译器的习惯优化。

### 轴角 ↔ 四元数

```cpp
// 轴角 → 四元数
Quat FromAxisAngle(Vec3 axis, float degrees) {
    Vec3 n = axis.Normalized();
    float half = degrees * DEG2RAD * 0.5f;      // ★ 注意是半角
    float s = sinf(half);
    return {n.x*s, n.y*s, n.z*s, cosf(half)};
}
```

**为什么是半角**：因为 `q × v × q⁻¹` 里 `q` 出现了两次，
等效旋转角是 `q` 的角度的两倍。所以想转 θ，`q` 要用 θ/2。

验证：绕 Z 转 90°

```
half = 45°
s = sin45° = 0.7071
w = cos45° = 0.7071
q = (0, 0, 0.7071, 0.7071)     ✓（与第 47 章的验证一致）
```

### SLERP（球面线性插值）

两个四元数之间最平滑的插值：

```
slerp(q0, q1, t) = (sin((1-t)Ω)/sinΩ) q0 + (sin(tΩ)/sinΩ) q1

其中 Ω = acos(q0 · q1)
```

**为什么不用线性插值**：线性插值 `(1-t)q0 + tq1` 会让角速度不均匀，
而且结果的模长不是 1（需要重新归一化）。SLERP 保持恒定角速度。

本项目自瞄用的是**欧拉角线性插值**（更简单），
因为相机角度范围有限，误差可接受。

## 三、视图矩阵的严格推导

### 定义

视图矩阵把世界坐标变换到相机坐标。相机坐标的定义：

```
相机在原点
朝 +X 看（前）
+Y 是右
+Z 是上
```

### 第一步：平移

把相机移到原点：

```
v₁ = v_world - C
```

### 第二步：旋转

把相机的朝向"摆正"到标准朝向。
设相机的基向量是 F（前）、R（右）、U（上）。

那么相机空间坐标就是 `v₁` 在三个基上的投影：

```
v_cam.x = F · v₁
v_cam.y = R · v₁
v_cam.z = U · v₁
```

### 写成矩阵

```
        ┌                    ┐   ┌              ┐
        │ F.x  F.y  F.z      │   │ v.x - C.x    │
v_cam = │ R.x  R.y  R.z      │ × │ v.y - C.y    │
        │ U.x  U.y  U.z      │   │ v.z - C.z    │
        └                    ┘   └              ┘
```

**这就是"旋转矩阵的转置"**（因为原矩阵的列是 F/R/U，转置后行是 F/R/U）。

展开第一行：

```
v_cam.x = F.x(v.x - C.x) + F.y(v.y - C.y) + F.z(v.z - C.z)
        = (F.x·v.x + F.y·v.y + F.z·v.z) - (F.x·C.x + F.y·C.y + F.z·C.z)
        = F·v - F·C
```

**这就解释了第 49 章那个 `matrix[15] = -dot(F, C)`。**

### 对应到代码

本项目的 `matrix[16]` 用列主序存储，第 3 行（下标 3、7、11、15）是深度行：

```
matrix[3]  = F.x = cy*cp
matrix[7]  = F.y = sy*cp
matrix[11] = F.z = sp
matrix[15] = -(C.x*matrix[3] + C.y*matrix[7] + C.z*matrix[11]) = -F·C
```

**完全一致。**

### 合并投影

本项目把投影矩阵也合并进来了（除以 `t`）：

```
matrix[0]  = R.x / t = -sy / t
matrix[4]  = R.y / t =  cy / t
```

其中 `t = tan(FOV/2)`。这样一次矩阵乘就同时完成视图变换和投影，
少一次矩阵乘法。

## 四、投影矩阵的严格推导

### 从几何出发

```
        上边界 y=+H/2
          /|
         / |
        /  |  深度 d
       /   |
      / θ/2|
     └─────┤
     相机   成像平面
```

由相似三角形：

```
屏幕半高 H/2 对应实际半高 = d · tan(θ/2) = d · t
```

所以相机空间一点 `(depth, right, up)`：

```
屏幕横向偏移比例 = right / (depth · t)
屏幕纵向偏移比例 = up    / (depth · t)
```

映射到像素（`px`、`py` 是屏幕半宽半高）：

```
screenX = px + (right / (depth·t)) · px
screenY = py - (up    / (depth·t)) · py
```

**注意 `up` 前面是减号**——屏幕 y 向下。

### 归一化形式

定义 NDC：

```
ndc_x = right / (depth · t)
ndc_y = up    / (depth · t)
```

范围：当 `right = depth·t` 时 `ndc_x = 1`（屏幕右边缘）。

所以：

```
screenX = (ndc_x + 1) · px
screenY = (1 - ndc_y) · py
```

**这就是第 51 章的公式。**

### 标准投影矩阵 vs 本项目

标准投影矩阵（列主序）：

```
        ┌                        ┐
        │ 1/(t·aspect)  0   0  0 │
        │      0      1/t   0  0 │
        │      0        0  A  B  │
        │      0        0 -1  0  │
        └                        ┘
```

其中 `A`、`B` 与近远平面有关。

**本项目没有 aspect 项**——因为横向和纵向分别用 `px` 和 `py` 缩放：

```
横向：除以 t，再乘 px
纵向：除以 t，再乘 py
```

**等价于** `aspect = px / py`（屏幕宽高比）。但这样写的好处是：
`px`/`py` 是已知的，不用额外计算，而且能独立微调（第 50 章的焦距系数）。

### 为什么需要近平面 `tnear`

`ndc = right / (depth·t)`，当 `depth → 0` 时 `ndc → ∞`。

所以必须设一个下限：

```cpp
if (w < 0.001f) return false;
```

**这个 0.001 就是近裁剪面**（单位：UE4 厘米 = 0.01 毫米）。

## 五、W2S 的边界情况全表

| 情况 | `w` 的值 | 处理 | 后果（若不处理） |
|---|---|---|---|
| 点在相机正前方 | `w > 0` | 正常投影 | — |
| 点在相机后方 | `w < 0` | 返回 false | 得到镜像坐标，画面出现"背后的人" |
| 点在相机位置 | `w ≈ 0` | 返回 false | 除以 0 → inf |
| 点在近平面内 | `0 < w < 0.001` | 返回 false | 坐标极大，线飞出屏幕 |
| 点正好在侧面 | x/y 分量极大 | 由包围盒剔除处理 | 坐标极大 |
| 坐标为 NaN | - | isfinite 拦住 | NaN 传播到绘制调用 |
| 坐标 inf | - | isfinite 拦住 | 同上 |

### 四道防线

```cpp
// ① 深度检查
if (w < 0.001f) return false;

// ② 除法（此时 w 安全）
float ndc_x = clip_x / w;
float ndc_y = clip_y / w;

// ③ 结果有限性
if (!std::isfinite(ndc_x) || !std::isfinite(ndc_y)) return false;

// ④ 调用方还要做屏幕包围盒检查（第 52 章）
```

## 六、万向节死锁的数学证明

### 现象

当 `Pitch = ±90°` 时，Yaw 和 Roll 失去独立性。

### 证明

取 `Pitch = 90°`，则 `SP = 1`、`CP = 0`。代入第 47 章的公式：

```
M[0][0] = CP*CY = 0
M[0][1] = CP*SY = 0
M[0][2] = SP = 1

M[1][0] = SR*SP*CY - CR*SY = SR*CY - CR*SY = sin(Roll - Yaw)
```

用三角恒等式化简 `SR*CY - CR*SY = sin(Roll - Yaw)`：

```
M[1][0] = sin(Roll - Yaw)
M[1][1] = SR*SP*SY + CR*CY = SR*SY + CR*CY = cos(Roll - Yaw)

M[2][0] = -(CR*SP*CY + SR*SY) = -(CR*CY + SR*SY) = -cos(Roll - Yaw)
M[2][1] = CY*SR - CR*SP*SY = CY*SR - CR*SY = sin(Roll - Yaw)
```

**关键观察**：所有元素只依赖 `(Roll - Yaw)` 这个差值，
而 `Roll` 和 `Yaw` 单独的值**消失了**。

**所以：Pitch=90° 时，改变 Roll 和改变 Yaw 产生完全相同的效果——
两个自由度塌缩成一个。这就是万向节死锁的数学本质。**

### 为什么本项目不受影响

游戏的相机 Pitch 被限制在 ±89°，永远到不了 ±90°。
肌肉记忆点：**只要有一个轴不接近 ±90°，欧拉角就安全。**

VR、飞行模拟这类需要任意朝向的场景必须用四元数——因为那里 Pitch 会到 90°。

## 七、矩阵的其它性质

### 行列式

```cpp
// 前提：Matrix 支持 m[i][j] 取第 i 行第 j 列（如第 53 章 mathlib 的 Mat4::operator[]）。
float Det3x3(const Matrix &m) {
    return m[0][0]*(m[1][1]*m[2][2] - m[1][2]*m[2][1])
         - m[0][1]*(m[1][0]*m[2][2] - m[1][2]*m[2][0])
         + m[0][2]*(m[1][0]*m[2][1] - m[1][1]*m[2][0]);
}
```

含义：**变换对体积的缩放倍数**。

| 行列式 | 含义 |
|---|---|
| 1 | 保持体积（纯旋转） |
| > 1 | 放大 |
| < 1 | 缩小 |
| 0 | 压扁了（不可逆） |
| < 0 | 翻转了手性（镜像） |

**验证旋转矩阵是否正确**：行列式必须为 +1。

### 逆矩阵

3×3 的逆 = 伴随矩阵 / 行列式：

```
M⁻¹ = adj(M) / det(M)
```

但对**正交矩阵**（旋转），有捷径：

```
M⁻¹ = Mᵀ
```

**这就是视图矩阵能用转置构造的原因。**

### 验证正交性的代码

```cpp
bool IsOrthonormal(const Matrix &m, float eps = 1e-4f) {
    // 1. 三个基向量长度都是 1
    for (int i = 0; i < 3; i++) {
        Vec3 row{m[i][0], m[i][1], m[i][2]};
        if (fabsf(row.Length() - 1.0f) > eps) return false;
    }
    // 2. 两两垂直
    Vec3 r0{m[0][0], m[0][1], m[0][2]};
    Vec3 r1{m[1][0], m[1][1], m[1][2]};
    Vec3 r2{m[2][0], m[2][1], m[2][2]};
    if (fabsf(r0.Dot(r1)) > eps) return false;
    if (fabsf(r0.Dot(r2)) > eps) return false;
    if (fabsf(r1.Dot(r2)) > eps) return false;
    return true;
}
```

**把它加到你的测试里**——任何旋转矩阵都应该通过。

## 八、把推导用在项目里

| 推导 | 项目位置 |
|---|---|
| 旋转矩阵三行是 F/R/U | `rotatorToMatrix`、`GetForward` |
| 四元数乘法公式 | `TransformToMatrix` |
| `v' = v + w·t + q×t` | `RotateByQuat`（第 86 章） |
| 视图矩阵 = 转置 + 平移 | `camMakeMatrix` 的前 4 个元素 |
| `matrix[15] = -F·C` | `camMakeMatrix` 第 4 个深度元素 |
| `ndc = right/(depth·t)` | `WorldToScreen` |
| `screen = (ndc+1)·px` | `WorldToScreen` |
| 万向节死锁 | 自瞄用欧拉角的前提（Pitch 不接近 ±90°） |
| 正交性 | 矩阵验证测试 |
