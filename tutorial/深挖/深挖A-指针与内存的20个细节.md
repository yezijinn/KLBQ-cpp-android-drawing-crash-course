# 深挖 A · 指针与内存的 20 个细节

> [!abstract] 这篇解决什么

> 指针减法是什么、`const` 和指针的四种组合、严格别名规则、野指针的六种来源……
> 这篇把 20 个细节一次讲完。**建议学完卷一第 07 章后读。**

## 一、指针算术的完整规则

### 1. `p + n` 到底加几字节

```c
int    *pi = (int*)0x1000;
char   *pc = (char*)0x1000;
double *pd = (double*)0x1000;

printf("%p %p %p\n", pi+1, pc+1, pd+1);
// 0x1004  0x1001  0x1008
```

**规则**：`p + n` 的字节偏移 = `n * sizeof(*p)`。

**为什么会这样设计**：因为 `arr[i]` 等价于 `*(arr + i)`。
如果 `+1` 加 1 字节，数组索引就要写成 `*(arr + i*sizeof(T))`——很丑。

### 2. 指针减法得到的是"元素个数"

```c
int arr[10];
int *a = &arr[2];
int *b = &arr[7];
printf("%td\n", b - a);       // 5，不是 20
```

两个指针相减得到 `ptrdiff_t`，单位是**元素个数**。
想得到字节数：`(char*)b - (char*)a`。

### 3. 指针比较只在"同一数组内"有意义

```c
int a[5], b[5];
if (&a[3] > &b[0])   // 未定义行为！
```

标准规定：不同数组的指针比较是未定义的。
实践中大多数编译器按地址比大小，但**不能依赖**。

例外：`p == NULL` 和 `p == q`（同一对象）永远是良定义的。

### 4. `void*` 的算术是非法的

```c
void *p = malloc(100);
p + 1;              // GCC 扩展：按 1 字节算（不是标准）
```

标准 C/C++ 里 `void*` 不能做算术（因为没有 `sizeof(void)`）。
编译器可能允许（当 char* 处理），但**不要依赖**。要偏移就转成 `uint8_t*`。

### 5. 空指针不一定是全 0 位

```c
int *p = nullptr;
memset(&p, 0, sizeof(p));     // 通常是全 0
```

标准只保证 `nullptr` 与 0 相等，**不保证其位模式是全 0**。
实际所有主流平台都是全 0，但严谨的代码不该 `memset` 指针。

## 二、`const` 与指针的四种组合

```c
int x = 1;
const int cx = 2;

int       *p1 = &x;         // 都可改
const int *p2 = &x;         // 不能通过 p2 改 x（但可以直接改 x）
int * const p3 = &x;        // p3 不能改指向（但能改 x）
const int * const p4 = &x;  // 都不能
```

读法：**从右往左读**，`const` 修饰它左边的东西；
如果 `const` 在最左边，修饰它右边的类型。

| 写法 | 含义 | 记忆 |
|---|---|---|
| `const int *p` | 指向常量的指针 | "不能改内容" |
| `int * const p` | 常量指针 | "不能改指向" |
| `const int * const p` | 都不能 | |

**一个实用的判断法**：看 `const` 在 `*` 的哪一边。

```
const int *p;      const 在 * 左边 → 内容不可改
int * const p;     const 在 * 右边 → 指针不可改
```

## 三、数组与指针的七个陷阱

### 6. `sizeof(数组)` 在函数里变成指针大小

```c
void f(int arr[10]) {
    printf("%zu\n", sizeof(arr));    // 8（指针），不是 40
}
```

因为数组作为参数会**退化成指针**。三种写法完全等价：

```c
void f(int arr[10]);
void f(int arr[]);
void f(int *arr);
```

**结论**：函数里无法求数组长度，必须额外传。

### 7. 数组名不是"指针变量"

```c
int arr[5];
arr = NULL;         // 编译错误！数组名不是左值
```

数组名在大多数场合"退化"成首元素地址，但它**不是一个可赋值的指针变量**。

例外（不退化）：
- `sizeof(arr)`
- `&arr`（得到数组指针 `int(*)[5]`）
- 声明为引用时（C++）

### 8. `&arr` 和 `arr` 的值相同，但类型不同

```c
int arr[5];
printf("%p %p\n", (void*)arr, (void*)&arr);      // 值一样
printf("%zu %zu\n", sizeof(*arr), sizeof(*&arr)); // 4 vs 20
```

- `arr` 类型 `int*`，`*arr` 是 `int`（4 字节）
- `&arr` 类型 `int(*)[5]`，`*&arr` 是 `int[5]`（20 字节）

所以 `arr + 1` 跳 4 字节，`&arr + 1` 跳 20 字节。

### 9. 二维数组的退化规则

```c
int m[3][4];
```

| 表达式 | 类型 | 意义 |
|---|---|---|
| `m` | `int(*)[4]` | 指向第一个"4元素数组" |
| `m[0]` | `int*` | 指向第一个 int |
| `m[0][0]` | `int` | 值 |

所以 `m[1][2]` 等价于 `*(*(m+1)+2)`。

**内存上它仍是连续的 48 字节**——这点很重要（第 46 章的矩阵就靠这个）。

### 10. 变长数组（VLA）不是标准 C++

```c
void f(int n) {
    int arr[n];        // C99 允许，C++ 不允许（GCC 扩展允许）
}
```

C++ 里用 `std::vector` 或 `alloca`。本项目全部用 `std::vector`。

### 11. 字符串字面量的类型是 `const char[N]`

```c
char *s = "hello";       // C 允许（危险），C++ 禁止
s[0] = 'H';              // 段错误！字面量在 .rodata（只读）
```

正确写法：`const char *s = "hello";` 或 `char s[] = "hello";`（拷贝一份可改）。

### 12. `strlen` 返回 `size_t`，减法的下溢

```c
if (strlen(s) - 10 < 0)     // 永远不成立！
```

`strlen` 返回无符号，减 10 后下溢成巨大正数。

正确：`if (strlen(s) < 10)`。

## 四、函数指针的读法

### 13. 从里往外读

```c
void (*f)(int, int);
```

读法：`f` 是 → 指针 → 指向函数 → 接受两个 int → 返回 void。

```c
void (*arr[5])(int);       // 5 个元素的数组，每个是函数指针
void (*(*f)(int))[5];      // f 是指针，指向接受 int 返回指向"5元素数组的指针"的函数
```

第二种几乎没人写。**实用技巧**：用 `typedef` 拆开。

```c
typedef void (*Callback)(int, int);
typedef Callback CallbackArray[5];
```

本项目的例子：

```cpp
void (*on_hit)(void *regs, void *fp_regs, void *hit_point);
```

`on_hit` 是指针，指向"接受三个 void\* 返回 void"的函数。

### 14. 成员函数指针不是普通指针

```cpp
struct A { void f(); };
void (A::*p)() = &A::f;      // 注意 A::*
A a;
(a.*p)();                    // 调用需要对象
```

而且在多继承下，成员函数指针可能是 16 字节（存调整量）。
本项目用 `dlsym` 时把成员函数当普通函数调（手动传 `this`），绕过了这个复杂性（第 65 章）。

## 五、内存与别名的深水区

### 15. 严格别名规则（Strict Aliasing）

```c
float f = 3.14f;
int i = *(int*)&f;          // 违反严格别名！
```

标准规定：**通过不兼容类型的指针访问同一内存是未定义行为**。
编译器有权假设"不同类型的指针不会指向同一块内存"，从而做优化。

实践中：
- `-O0` 通常没问题
- `-O2` 可能被优化成错误结果

**正确写法**：

```c
int i;
memcpy(&i, &f, 4);         // 安全
```

C++20 更优雅：

```cpp
int i = std::bit_cast<int>(f);
```

**例外**：`char*` / `unsigned char*` 可以做任何类型的别名访问。
所以 `hexdump` 那种逐字节读的函数是完全合法的。

### 16. 对齐与指针转换

```c
uint8_t buf[16];
uint32_t *p = (uint32_t*)(buf + 2);      // 未对齐
*p = 1;                                   // ARM 上可能崩溃
```

ARM 对未对齐访问的处理：
- 普通加载/存储指令（`ldr`/`str`）：可能崩溃
- 字节访问（`ldrb`/`strb`）：允许

**本项目全部用 `memcpy`/逐字节读，回避了对齐问题**（`dr->Read(addr, &v, sizeof(v))`）。
本地解引用 `*(T*)p` 才有对齐要求。

用 `memcpy` 的另一个好处：编译器会把小尺寸的 `memcpy` 优化成单条指令，
性能没有损失。

### 17. 未对齐的结构体访问

```c
#pragma pack(push, 1)
struct Packed { uint8_t a; uint32_t b; };   // b 在偏移 1，未对齐
#pragma pack(pop)

Packed p;
p.b = 1;              // 编译器生成字节拼接指令（慢但安全）
```

`#pragma pack` 让编译器生成"安全但慢"的代码。
x86 上无所谓，ARM 上要注意性能。

## 六、野指针的六种来源

### 18. 六种情形

| # | 来源 | 症状 | 防御 |
|---|---|---|---|
| 1 | 未初始化 | 随机地址 | **定义时就初始化**（`= nullptr`） |
| 2 | `free`/`delete` 后继续用 | use-after-free | 释放后置空；用 `unique_ptr` |
| 3 | 返回局部变量地址 | 栈上垃圾 | 编译器警告 `-Wreturn-local-addr` |
| 4 | 越界写破坏相邻指针 | 偶发崩溃 | 数组边界检查；ASan |
| 5 | 指向已释放对象的成员 | 读到垃圾 | 明确所有权（第 14 章） |
| 6 | **从外部读来的无效地址** | 崩溃/垃圾数据 | **八层防御**（第 89 章） |

第 6 种是本项目最关心的——读别的进程时，**每一个指针都可能是野的**。

```cpp
// 必须每次都校验
if (!IsValidObject(addr)) continue;
```

第 89 章讲了完整的八层防御流水线。

### 19. 悬垂指针的检测

```c
// ASan 能精确抓到
gcc -fsanitize=address -g test.c -o test
./test
# ==1234==ERROR: AddressSanitizer: heap-use-after-free on address 0x...
# READ of size 4 at 0x... thread T0
#     #0 0x... in main /path/test.c:12
```

**学习期一定要开 ASan**。它比任何调试技巧都高效。

### 20. 指针与整数互转的规则

```c
uintptr_t u = (uintptr_t)p;      // 指针 → 整数
int *q = (int*)u;                // 整数 → 指针
```

| 类型 | 保证 |
|---|---|
| `uintptr_t` / `intptr_t` | 能装下指针，标准保证 |
| `size_t` | **不保证**能装下指针（虽然实践中都是 8 字节） |
| `long` | Windows 4 字节、Linux 8 字节 → **不要用** |
| `int` | 绝对不够 |

**本项目统一用 `uint64_t` 或 `uintptr_t` 存地址**（第 04 章强调过）。

## 七、一个综合的调试练习

下面这段代码有 6 个 bug，每个对应上面的一个知识点。找出来：

```c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

char *make_name(const char *prefix) {
    char buf[64];                              // bug?
    strcpy(buf, prefix);
    return buf;
}

void process(int arr[], int n) {
    for (int i = 0; i <= n; i++)               // bug?
        arr[i] = i;
    printf("size = %zu\n", sizeof(arr));        // bug?
}

int main(void) {
    char *s = "hello";
    s[0] = 'H';                                 // bug?

    int *a = malloc(10 * sizeof(int));
    process(a, 10);
    free(a);
    printf("%d\n", a[0]);                       // bug?

    float f = 1.0f;
    int i = *(int*)&f;                          // bug?
    printf("%d\n", i);

    char *name = make_name("user");
    printf("%s\n", name);
    return 0;
}
```

> [!question]- 答案与解释
> 1. **`return buf`**（返回局部变量地址）：`buf` 在栈上，函数返回后失效。
>    改用 `malloc` 或让调用方传缓冲区。
>
> 2. **`i <= n`**（越界）：应为 `i < n`。写了 `arr[n]`，越界 1 个元素。
>
> 3. **`sizeof(arr)` 是 8**（数组退化成指针）：不是 40。
>
> 4. **`s[0] = 'H'`**（写只读内存）：字符串字面量在 `.rodata`，段错误。
>    应为 `char s[] = "hello";`。
>
> 5. **`a[0]` after free**（use-after-free）：释放后继续访问。
>
> 6. **`*(int*)&f`**（违反严格别名）：`-O2` 下可能出错。
>    应改为 `memcpy(&i, &f, 4)` 或 `std::bit_cast`。
>
> 用 `-fsanitize=address -Wall -Wextra -O2` 编译，ASan 会直接指出 1、2、5；
> 编译器警告指出 3、4。这就是"工具比眼睛快"的实证。
