# 第 75 章 · 封装跨进程读写类

> [!abstract] 本章目标
> 把裸系统调用封装成一个好用的类：模板读、字符串读、错误处理、PID 管理。
> 这是 `SysHal` 和 `IDriver` 的设计蓝图。

> [!note] 承上
> 上一章写的是裸系统调用，用起来啰嗦。
> 本章把它**封装成类**（模板读、字符串读、错误处理）——`SysHal` 的设计蓝图。

> [!important] 前置条件
> - **读真实进程**需 root 设备（`process_vm_readv` 权限，见第 73 章）。
> - **本机（Windows/WSL）**：本章的类可用本地内存模拟验证，不依赖设备。

## 先看想要什么样的 API

调用方希望这么写：

```cpp
MemReader mem(pid);

auto hp     = mem.Read<int32_t>(addr);
auto pos    = mem.Read<Vec3>(addr + 4);
auto name   = mem.ReadString(addr + 16, 64);
auto matrix = mem.Read<Matrix>(matrixAddr);

mem.Write<int32_t>(addr, 9999);
```

而不是每次都构造 `iovec`。**封装的价值就在这里。**

## 架构总览：MemReader 在系统中的位置

> [!tip] 先看全局，再看细节
> 中后期章节信息量大。**先建立这张「谁调用谁」的架构图**，
> 后面每一段代码都能对号入座，不至于迷失在细节里。

```
┌──────────────────────────────────────────────────────┐
│  上层：业务代码（DrawPlayer / SilentAim / pXthread）    │
│        只写 mem.Read<Vec3>(addr) 这样的调用            │
└───────────────────────┬──────────────────────────────┘
                        │ 依赖「好用 API」
                        ▼
┌──────────────────────────────────────────────────────┐
│  MemReader（本章）：模板读 / 字符串读 / 错误处理        │
│    · Read<T>()  ── 模板 + 大小校验                     │
│    · ReadString() ── 分块读到 \0 或上限               │
│    · 记录 pid_ / 上次错误                              │
└───────────────────────┬──────────────────────────────┘
                        │ 抽象为「驱动接口」
                        ▼
┌──────────────────────────────────────────────────────┐
│  IDriver（第80章）：纯虚接口，屏蔽底层实现差异          │
│    用户态 SysHal ── process_vm_readv                  │
│    内核态 MemDriver ── 共享内存请求-响应               │
└──────────────────────────────────────────────────────┘
```

> [!note] 为什么要这层抽象
> **上层只认 MemReader，不认系统调用**。
> 于是从「用户态读」切到「内核态读」（第 78 章），
> 只换底层实现，上层代码一行不改——这就是第 80 章 `IDriver` 的价值。

### 坏味道重构推演：从"裸系统调用"到"封装类"

> [!tip] 为什么要把 `process_vm_readv` 封成类？
> 先看"直接调系统调用"的写法有多啰嗦。

❌ **稚嫩写法：每个调用点手写 iovec**

```cpp
// ❌ 坏味道：每次读都要手写 iovec 数组、判返回值、拆类型
uint64_t ReadU64(pid_t pid, uint64_t addr) {
    uint64_t val = 0;
    struct iovec local[1] = {{&val, sizeof(val)}};
    struct iovec remote[1] = {{(void*)addr, sizeof(val)}};
    ssize_t n = process_vm_readv(pid, local, 1, remote, 1, 0);
    return (n == sizeof(val)) ? val : 0;
}
float ReadFloat(pid_t pid, uint64_t addr) {
    float val = 0;
    struct iovec local[1] = {{&val, sizeof(val)}};      // ← 又抄一遍
    struct iovec remote[1] = {{(void*)addr, sizeof(val)}};
    ssize_t n = process_vm_readv(pid, local, 1, remote, 1, 0);
    return (n == sizeof(val)) ? val : 0;
}
// ... 每个类型一个函数，iovec 样板反复复制
```

| 坏味道 | 后果 |
|---|---|
| iovec 样板重复 | 每个类型抄一遍 |
| 类型不通用 | 加新类型要加新函数 |
| 无状态 | pid 每次都要传 |
| 错误处理散落 | 每处都要判 n |

✅ **优雅写法：封装成 MemReader 类（本项目 MemDriver/SysHal 的思路）**

```cpp
// ✅ 用模板封装：一个 Read<T> 覆盖所有类型
class MemReader {
    pid_t pid_;
public:
    explicit MemReader(pid_t pid) : pid_(pid) {}
    pid_t Pid() const { return pid_; }

    int Read(uint64_t address, void* buffer, size_t size) {
        struct iovec local[1]  = {{buffer, size}};
        struct iovec remote[1] = {{(void*)address, size}};
        ssize_t n = process_vm_readv(pid_, local, 1, remote, 1, 0);
        return (n == (ssize_t)size) ? (int)size : -1;
    }

    template <typename T> T Read(uint64_t address) {
        T value = {};
        if (Read(address, &value, sizeof(T)) <= 0) value = T{};
        return value;
    }
};

// 业务代码清爽：pid 只传一次，类型自动推导
MemReader mem(pid);
auto hp    = mem.Read<int32_t>(addr);
auto pos   = mem.Read<Vec3>(addr + 4);
```

### 核心指标对比

| 维度 | ❌ 裸系统调用 | ✅ 封装类 |
|---|---|---|
| **可维护性** | iovec 样板 N 处 | 只在类内 1 处 |
| **可扩展性** | 加类型加函数 | 模板自动支持 |
| **可测试性** | 需真实 pid | 可换 mock |
| **调用便捷** | 每次传 pid | pid 存成员 |

### 演进动因剖析

> [!note] 为什么本项目先封装 SysHal，再抽象 IDriver？
> 1. **消除样板**：iovec + 判返回值是重复劳动，封装一次即可。
> 2. **模板通用**：一个 `Read<T>` 支持所有类型，无需为每种类型写函数。
> 3. **为抽象层铺路**：封装成类后，才能进一步抽象出 `IDriver`（第 80 章），
>    让"用户态 SysHal"和"内核态 Driver"共用同一接口。
>
> **一句话**：先用**类**消除样板，再用**接口**消除实现差异——
> 这是本项目从 `SysHal` 到 `IDriver` 的两步走。

## 实现

```cpp
#include <sys/uio.h>
#include <cerrno>
#include <cstring>
#include <string>
#include <vector>

class MemReader {
public:
    MemReader() = default;
    explicit MemReader(pid_t pid) : pid_(pid) {}

    bool Attach(pid_t pid) {
        if (pid <= 0) return false;
        pid_ = pid;
        return true;
    }
    pid_t Pid() const { return pid_; }
    bool IsValid() const { return pid_ > 0; }

    int Read(uint64_t addr, void *buf, size_t size) const {
        if (!buf || size == 0 || pid_ <= 0) return -1;

        struct iovec local  = {buf, size};
        struct iovec remote = {(void*)addr, size};

        size_t total = 0;
        while (total < size) {
            ssize_t n = process_vm_readv(pid_, &local, 1, &remote, 1, 0);
            if (n <= 0) break;
            total += (size_t)n;
            local.iov_base  = (char*)buf + total;
            local.iov_len   = size - total;
            remote.iov_base = (char*)addr + total;
            remote.iov_len  = size - total;
        }
        return total > 0 ? (int)total : -1;
    }

    int Write(uint64_t addr, const void *buf, size_t size) const {
        if (!buf || size == 0 || pid_ <= 0) return -1;

        struct iovec local  = {(void*)buf, size};
        struct iovec remote = {(void*)addr, size};

        size_t total = 0;
        while (total < size) {
            ssize_t n = process_vm_writev(pid_, &local, 1, &remote, 1, 0);
            if (n <= 0) break;
            total += (size_t)n;
            local.iov_base  = (char*)buf + total;
            local.iov_len   = size - total;
            remote.iov_base = (char*)addr + total;
            remote.iov_len  = size - total;
        }
        return total > 0 ? (int)total : -1;
    }

    template <typename T>
    T Read(uint64_t addr) const {
        T value = {};
        if (Read(addr, &value, sizeof(T)) <= 0) value = T{};
        return value;
    }

    template <typename T>
    bool Write(uint64_t addr, const T &value) const {
        return Write(addr, &value, sizeof(T)) == (int)sizeof(T);
    }

    std::string ReadString(uint64_t addr, size_t maxLen = 128) const {
        if (addr == 0 || maxLen == 0) return {};
        std::vector<char> buf(maxLen + 1, 0);
        if (Read(addr, buf.data(), maxLen) <= 0) return {};
        buf[maxLen] = '\0';                     // 保证终止
        return std::string(buf.data());          // 遇 \0 自动截断
    }

private:
    pid_t pid_ = 0;
};
```

## 设计要点逐个说

### 1. 失败时返回默认值

```cpp
template <typename T>
T Read(uint64_t addr) const {
    T value = {};
    if (Read(addr, &value, sizeof(T)) <= 0) value = T{};    // ★
    return value;
}
```

读失败返回零值，而不是让调用方拿到半初始化的垃圾。

**但这也带来问题**：调用方分不清"读到 0"和"读失败"。
本项目靠**调用方自己判合理性**解决（第 89 章）：

```cpp
uint64_t obj = mem.Read<uint64_t>(addr);
if (obj == 0) continue;         // 0 一定无效（没有对象在地址 0）
```

### 2. 循环处理部分成功

`process_vm_readv` 可能只读一部分（跨页、权限不均）。
循环推进 `iov_base` 直到读完或失败。

### 3. 字符串必须限长

```cpp
std::string ReadString(uint64_t addr, size_t maxLen = 128) const;
```

**为什么不能无限读**：目标内存里可能没有 `\0`（比如刚好是二进制数据），
一直读下去会碰到一个不可访问的页才停 —— 甚至可能读到几百 KB。

而且 `buf[maxLen] = '\0'` 保证本地缓冲区一定终止。

### 4. 地址用 uint64_t

不用 `int`（32 位会截断）、不用 `long`（Windows/Linux 长度不同）。

### 5. 窄字符 vs 宽字符

UTF-16 字符串要单独处理：

```cpp
std::string ReadWString(uint64_t addr, size_t maxLen = 128) const {
    if (addr == 0) return {};
    std::vector<char16_t> buf(maxLen + 1, 0);
    if (Read(addr, buf.data(), maxLen * 2) <= 0) return {};
    buf[maxLen] = 0;

    std::string out;
    for (size_t i = 0; i < maxLen && buf[i]; i++) {
        char16_t c = buf[i];
        if (c < 0x80) {
            out += (char)c;
        } else if (c < 0x800) {
            out += (char)(0xC0 | (c >> 6));
            out += (char)(0x80 | (c & 0x3F));
        } else {
            out += (char)(0xE0 | (c >> 12));
            out += (char)(0x80 | ((c >> 6) & 0x3F));
            out += (char)(0x80 | (c & 0x3F));
        }
    }
    return out;
}
```

这就是本项目 `GetNameById` 里 `AppendUtf8` 做的事（第 06 章讲过原理）。

## 课后习题

### 习题 75.1 封装一个模板读取类（★★）

**任务要求**：写 `MemReader` 类，提供 `template<T> T read(uint64_t addr)`（失败返回默认值）
和 `std::string readString(uint64_t addr, size_t maxLen)`（限长、手动补 `\0`）。

**核心骨架**（用本地内存模拟，跨平台可跑）：

```cpp
#include <cstdio>
#include <cstdint>
#include <cstring>
#include <string>
#include <cassert>

class MemReader {
    const uint8_t* mem_;
    size_t size_;
public:
    MemReader(const uint8_t* m, size_t s) : mem_(m), size_(s) {}

    // 底层读：越界返回 -1
    int readRaw(uint64_t addr, void* buf, size_t n) {
        if (addr + n > size_) return -1;
        memcpy(buf, mem_ + addr, n);
        return (int)n;
    }

    // 模板读：失败返回默认值
    template <typename T> T read(uint64_t addr) {
        T v{};
        if (readRaw(addr, &v, sizeof(T)) <= 0) v = T{};
        return v;
    }

    // 字符串读：限长 + 手动补 \0
    std::string readString(uint64_t addr, size_t maxLen) {
        std::string s;
        for (size_t i = 0; i < maxLen; i++) {
            char c = read<char>(addr + i);
            if (c == '\0') break;
            s += c;
        }
        return s;
    }
};
```

**验证断言**：

```cpp
int main() {
    uint8_t mem[32] = {0};
    int hp = 1234;
    memcpy(mem + 0, &hp, 4);
    memcpy(mem + 8, "hello", 6);

    MemReader r(mem, sizeof(mem));
    assert(r.read<int>(0) == 1234);
    assert(r.read<int>(100) == 0);          // 越界 → 默认值 0
    assert(r.readString(8, 16) == "hello");
    printf("习题 75.1 全部通过\n");
    return 0;
}
```

> [!tip] 三个设计要点
> ① **失败返回默认值**（不抛异常、不崩）；② **字符串必须限长**（防止目标内存无 `\0`）；
> ③ **模板读**——一个 `read<T>` 读所有类型。这正是本项目 `dr->Read<T>(addr)` 的设计。

## 常见坑排查表

| 症状 | 最可能的原因 | 解法 |
|---|---|---|
| 读字符串**越界/读到乱码** | 没限长，目标内存无 `\0` | `readString(addr, maxLen)` 必须限长 |
| 模板读返回**垃圾值** | 类型和字段不匹配 | 确认字段真实类型（float vs int）|
| 读失败**程序崩了** | 没判失败直接解引用 | 失败返回默认值，不抛异常 |
| 读 4 字节却得到 8 字节数据 | `sizeof(T)` 用错 | 用 `read<int>` 而非 `read<uint64_t>` |
