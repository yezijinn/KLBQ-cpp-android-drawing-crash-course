## 先制造一个数据竞争

```cpp
#include <thread>
#include <cstdio>

int counter = 0;

void increment() {
    for (int i = 0; i < 100000; i++)
        counter++;          // 三个线程同时做
}

int main(void) {
    std::thread t1(increment), t2(increment), t3(increment);
    t1.join(); t2.join(); t3.join();
    printf("counter = %d (期望 300000)\n", counter);
    return 0;
}
```

跑几次，输出可能是 `187432`、`291003`……**每次都不一样**。

原因：`counter++` 不是原子操作，实际是三步：

```
1. 从内存读到寄存器
2. 寄存器 +1
3. 写回内存
```

两个线程交叉执行就会丢更新：

```
线程A: 读 0
线程B: 读 0     ← A 还没写回
线程A: +1 → 写 1
线程B: +1 → 写 1    ← 覆盖了 A 的结果
结果: 1（应该是 2）
```

## 解法一：互斥锁 std::mutex

```cpp
#include <mutex>

std::mutex mtx;
int counter = 0;

void increment() {
    for (int i = 0; i < 100000; i++) {
        std::lock_guard<std::mutex> lock(mtx);    // RAII（第 11 章）
        counter++;
    }
}
```

- 拿不到锁的线程**进入睡眠**，让出 CPU
- 锁释放时被唤醒

**适合**：临界区较长（几十微秒以上）。

## 解法二：自旋锁（SpinLock）

```cpp
class SpinLock {
    unsigned char locked = 0;
public:
    void lock() noexcept {
        while (__atomic_exchange_n(&locked, 1, __ATOMIC_ACQUIRE)) {
            while (__atomic_load_n(&locked, __ATOMIC_RELAXED)) {
                asm volatile("yield");      // ARM64 提示指令
            }
        }
    }
    void unlock() noexcept {
        __atomic_store_n(&locked, 0, __ATOMIC_RELEASE);
    }
};
```

- 拿不到锁的线程**死循环等待**，不睡
- 没有上下文切换开销

**适合**：临界区极短（几微秒以内）。

### 逐行解读本项目的自旋锁

```cpp
while (__atomic_exchange_n(&locked, 1, __ATOMIC_ACQUIRE))
```

`__atomic_exchange_n`：**原子地**把 `locked` 设为 1，返回旧值。

| 返回值 | 含义 |
|---|---|
| 0 | 原来没上锁 → 我抢到了，进入临界区 |
| 1 | 原来已上锁 → 进入内层循环等 |

```cpp
while (__atomic_load_n(&locked, __ATOMIC_RELAXED)) {
    asm volatile("yield");
}
```

内层循环：不断读 `locked`，直到变 0。

`yield` 指令（ARM64）告诉 CPU：
"我在自旋等待，可以降频/让出执行资源"。
比空转 `while(1);` 文明得多——**省电且不会饿死其它核心**。

```cpp
void unlock() noexcept {
    __atomic_store_n(&locked, 0, __ATOMIC_RELEASE);
}
```

释放：把 `locked` 写回 0。

### 内存序（Memory Order）

| 常量 | 含义 |
|---|---|
| `__ATOMIC_ACQUIRE` | 获取：**之后**的读写不会被重排到前面 |
| `__ATOMIC_RELEASE` | 释放：**之前**的读写不会被重排到后面 |
| `__ATOMIC_RELAXED` | 只保证原子性，不保证顺序 |

**Acquire-Release 配对**能保证：
解锁前的所有写操作，对下一个加锁的线程可见。

```cpp
// 线程 A
data = 42;                    // 临界区内写
lock.unlock();                // RELEASE：保证 data=42 已生效

// 线程 B
lock.lock();                  // ACQUIRE：能看到 data=42
use(data);
```

## 用 RAII 包装锁

本项目用法：

```cpp
void HandleVirtualMemoryRWEvent(...) {
    std::scoped_lock<SpinLock> lock(m_mutex);      // 构造时加锁
    /* ... 整个函数体 ... */
}                                                  // 析构时自动解锁
```

**`std::scoped_lock` 保证**：
- 无论正常返回还是抛异常，锁都会释放
- 不可能忘记解锁

> [!danger] 手动 unlock 是 bug 之源
> ```cpp
> lock.lock();
> if (error) return;        // ← 忘了 unlock！死锁
> process();
> lock.unlock();
> ```
> 用 RAII 永远不会有这个问题。

## detach 的问题

```cpp
thread(&func).detach();
```

- 线程独立运行，主线程不等它
- 主线程退出时，detach 的线程**被强制终止**
- 无法 join，无法得知它是否结束

**本项目的问题**：没有停止机制。程序退出时这三个线程可能正在操作 Embree 场景，
而主线程正在销毁——**潜在崩溃点**。

改进方案：

```cpp
std::atomic<bool> g_running{true};

void UpdateSceneByRange() {
    while (g_running) {
        /* 更新 */
        sleep(2s);
    }
}

// 主线程退出前
g_running = false;
std::this_thread::sleep_for(100ms);      // 给线程一点时间退出
```

>

> ```cpp

> { std::lock_guard lk(sceneMutex); mesh_datas.push_back(...); }
> // 主线程
> { std::lock_guard lk(sceneMutex); for (auto &m : mesh_datas) ...; }
> ```

## 死锁的四个条件

死锁发生需要**同时满足**：

| 条件 | 说明 |
|---|---|
| 互斥 | 资源一次只能一个线程用 |
| 持有并等待 | 拿着 A 还要等 B |
| 不可抢占 | 不能强行抢别人的锁 |
| 循环等待 | A 等 B，B 等 A |

**打破任意一个就不会死锁。** 最实用的做法：

> [!tip] 固定加锁顺序
> ```cpp
> // 所有地方都按 lockA → lockB 的顺序
> std::scoped_lock lock(mutexA, mutexB);    // C++17 一次性锁多个，避免死锁
> ```
> `std::scoped_lock` 用死锁避免算法（类似 `std::lock`），安全。

## 条件变量：等待某个事件

自旋等待适合"极短时间"，长时间等待要用条件变量：

```cpp
#include <condition_variable>

std::mutex mtx;
std::condition_variable cv;
bool dataReady = false;

// 消费者
void consumer() {
    std::unique_lock<std::mutex> lock(mtx);
    cv.wait(lock, []{ return dataReady; });    // 睡到 dataReady
    /* 处理数据 */
}

// 生产者
void producer() {
    {
        std::lock_guard<std::mutex> lock(mtx);
        dataReady = true;
    }
    cv.notify_one();        // 唤醒
}
```

**适合**：等待时间不确定或较长（毫秒级以上）。

| | 自旋锁 | 互斥锁 | 条件变量 |
|---|---|---|---|
| 等待方式 | 死循环 | 睡眠 | 睡眠 + 通知 |
| 适用等待时长 | < 几 µs | 任意 | 较长/不确定 |
| 开销 | 占 CPU | 切换开销 | 切换开销 |

## 动手：三种锁的性能对比

> [!important] 前置条件
> 本节用 `std::thread` 对比锁性能，可在**任意平台本机编译运行**（需编译器支持多线程）。

```cpp
#include <chrono>
#include <thread>
#include <mutex>
#include <atomic>
#include <vector>
#include <functional>      // std::function
#include <cstdio>

constexpr int N = 1000000;

// 1. 无锁（会有竞争，结果错误，只测速度）
volatile int counter1 = 0;
// 2. 互斥锁
int counter2 = 0; std::mutex mtx;
// 3. 自旋锁
int counter3 = 0; std::atomic<unsigned char> spinFlag{0};
// 4. 原子
std::atomic<int> counter4{0};

void bench(const char *name, const std::function<void()> &fn) {
    auto t0 = std::chrono::steady_clock::now();
    fn();
    auto t1 = std::chrono::steady_clock::now();
    printf("%-10s : %6.1f ms\n", name,
           std::chrono::duration<double, std::milli>(t1-t0).count());
}

int main(void) {
    bench("无锁", []{
        for (int i = 0; i < N; i++) counter1++;
    });
    bench("互斥锁", []{
        for (int i = 0; i < N; i++) { std::lock_guard<std::mutex> l(mtx); counter2++; }
    });
    bench("自旋锁", []{
        for (int i = 0; i < N; i++) {
            while (spinFlag.exchange(1)) { }
            counter3++;
            spinFlag.store(0);
        }
    });
    bench("原子", []{
        for (int i = 0; i < N; i++) counter4++;
    });
    return 0;
}
```

典型结果（单线程，无竞争）：

```
无锁     :    2.5 ms
互斥锁   :   25.0 ms
自旋锁   :   12.0 ms
原子     :    6.0 ms
```

**结论**：
- 能用原子就用原子（最快）
- 临界极短用自旋锁
- 一般情况用互斥锁（安全、通用）

### 习题 82.1 复现数据竞争并修复（★★）

**任务要求**：写两个线程各把共享计数器加 100 万次。先不加锁跑，观察结果错误；
再加 `std::mutex` 修复，断言结果正确为 200 万。

**核心骨架**：

```cpp
#include <thread>
#include <mutex>
#include <cstdio>
#include <cassert>

constexpr int N = 1000000;
int counter = 0;
std::mutex mtx;

void worker_locked() {
    for (int i = 0; i < N; i++) {
        std::lock_guard<std::mutex> lock(mtx);   // ★ RAII 加锁
        counter++;
    }
}
```

**参考实现**：

```cpp
#include <thread>
#include <mutex>
#include <cstdio>
#include <cassert>

constexpr int N = 1000000;

// 正确版：互斥锁保护
int counter = 0;
std::mutex mtx;
void worker_locked() {
    for (int i = 0; i < N; i++) {
        std::lock_guard<std::mutex> lock(mtx);
        counter++;
    }
}

int main() {
    std::thread t1(worker_locked);
    std::thread t2(worker_locked);
    t1.join();
    t2.join();
    printf("加锁后 counter = %d（期望 %d）\n", counter, 2 * N);
    assert(counter == 2 * N);      // ★ 加锁后必然正确
    printf("习题 82.1 全部通过\n");
    return 0;
}
```

**验证断言**：加锁版本 `counter` 必须恰为 2000000。

> [!tip] 亲手看到"不加锁会错"
> 把上面的 `worker_locked` 里的 `lock_guard` 注释掉，跑几次会发现 `counter` **小于** 200 万
> （两个线程读到同一旧值、各自 +1、写回，丢了一次加）。这就是数据竞争（本章开头"先制造一个数据竞争"）。

### 习题 82.2 用原子变量重写（★★）

**任务要求**：不用锁，改用 `std::atomic<int>` + `fetch_add` 实现同样的累加，结果必须也是 200 万。

**参考实现**：

```cpp
#include <thread>
#include <atomic>
#include <cstdio>
#include <cassert>

constexpr int N = 1000000;
std::atomic<int> counter{0};

void worker_atomic() {
    for (int i = 0; i < N; i++) counter.fetch_add(1, std::memory_order_relaxed);
}

int main() {
    std::thread t1(worker_atomic);
    std::thread t2(worker_atomic);
    t1.join(); t2.join();
    printf("原子后 counter = %d\n", counter.load());
    assert(counter.load() == 2 * N);
    printf("习题 82.2 全部通过\n");
    return 0;
}
```

> [!note] 三种方案对比
> - **不加锁**：最快但**结果错**（有竞争）；
> - **互斥锁**：正确但每次加锁/解锁有开销；
> - **原子 fetch_add**：正确且比锁快（无阻塞），是"简单计数"的最优解。
> 本项目自旋锁用的是裸 `__atomic_*`（本章"本项目的自旋锁"），原理同源。

### 习题 82.3 复现并修复死锁（★★★）

> [!note] 验证方式
> **复现**：两个线程各持一把锁、再等对方的锁——程序会**永久卡住**（不退出）。
> **验证死锁**：给程序设 `timeout`，若超时被杀说明死锁（正常应 1 秒内结束）。
> **修复**：统一加锁顺序（两个线程都先锁 A 再锁 B），程序应正常结束。

**任务要求**：两把锁 `A`、`B`，线程 1 先锁 A 再锁 B，线程 2 先锁 B 再锁 A——
这会死锁。改成**两个线程都按 A→B 的固定顺序**加锁，死锁消失。

**参考实现**：

```cpp
#include <thread>
#include <mutex>
#include <cstdio>

std::mutex A, B;

void good() {
    // ★ 两个线程都按 A→B 的固定顺序加锁 → 不会死锁
    std::lock_guard<std::mutex> la(A);
    std::lock_guard<std::mutex> lb(B);
    printf("线程 %lu 拿到两把锁\n", (unsigned long)std::hash<std::thread::id>{}(std::this_thread::get_id()));
}

int main() {
    std::thread t1(good);
    std::thread t2(good);
    t1.join(); t2.join();
    printf("习题 82.3 全部通过（无死锁）\n");
    return 0;
}
```

> [!warning] 死锁四条件
> ① 互斥；② 持有并等待；③ 不可抢占；④ 循环等待。
> **打破任一条即可避免死锁**——本题用的是"打破循环等待"（固定加锁顺序）。
> 本项目里多个线程访问 Embree 场景时，也是靠"统一加锁顺序 + RAII"避免死锁。

```cpp
threads.emplace_back(UpdateDynamicRigid);
// 运行一会儿
std::this_thread::sleep_for(std::chrono::seconds(1));
StopAllThreads(threads);   // 应能正常返回，不卡死
assert(true);              // 线程全部回收
```
