> 这是卷六全部内容的前提。

> [!note] 承上

## 先做一个实验

打开两个终端，各跑一个程序：

```c
// a.c：打印一个变量的地址，然后睡眠
#include <stdio.h>
#include <unistd.h>

int secret = 0x12345678;

int main(void) {
    printf("pid=%d  &secret=%p  value=0x%X\n",
           getpid(), (void*)&secret, secret);
    fflush(stdout);
    sleep(300);
    return 0;
}
```

```c
// b.c：试着读 a 的地址
#include <stdio.h>
#include <stdlib.h>          // strtoul 在这里

int main(int argc, char **argv) {
    unsigned long addr = strtoul(argv[1], NULL, 16);   // 注意：.c 里用 NULL，不是 nullptr
    int *p = (int*)addr;
    printf("读到: 0x%X\n", *p);      // 会怎样？
    return 0;
}
```

运行：

```bash
./a &          # 输出 pid=1111 &secret=0x60104c
./b 0x60104c   # → Segmentation fault
```

**崩溃了。** 因为 `0x60104c` 在 B 进程里要么没映射，要么映射到别的东西。

这就是进程隔离：**同样的地址，不同进程看到的是不同的物理内存**（第 17 章）。

## 隔离是怎么实现的

```
进程 A 的页表            进程 B 的页表
虚拟 0x60104c ──→ 物理 0x1A300000
                        虚拟 0x60104c ──→ 物理 0x2B700000
```

MMU 查哪个页表，取决于当前 CPU 在跑哪个进程。
切换进程时，内核换掉页表基址寄存器（ARM64 是 `TTBR0_EL1`）。

**A 的页表里根本没有 B 的物理页，所以 A 无论如何也访问不到。**

## 那内核为什么能

内核运行在 EL1，有独立的页表，而且：
- 内核空间映射了**所有**物理内存（线性映射区）
- 内核知道每个进程的 `task_struct` 和它的页表

所以内核可以：
1. 拿到 B 进程的页表
2. 把 B 的虚拟地址翻译成物理地址
3. 从内核的线性映射区访问那块物理内存

**这就是所有"跨进程读内存"技术的本质：借内核的手。**

## 内核开放的三个口子

| 接口 | 谁提供 | 能力 | 需要什么权限 |
|---|---|---|---|
| `ptrace` | 内核（调试接口） | 读写单字、附加进程 | 同 UID 或 `CAP_SYS_PTRACE` |
| `process_vm_readv/writev` | 内核（Linux 3.2+） | 批量读写 | 同上 |
| `/proc/pid/mem` | 内核（伪文件） | 按偏移读写 | 需要 `PTRACE_MODE_ATTACH` |
| **自定义内核模块** | 自己写的驱动 | 任意（包括硬件断点） | root + 能加载 .ko |

本项目用了后两种：`process_vm_readv`（无内核时）和自建内核驱动（有内核时）。

## 权限检查：ptrace_may_access

内核在允许你读别人内存前，会做一串检查：

```c
// 内核源码（简化）
static int ptrace_may_access(struct task_struct *task, unsigned int mode) {
    // 1. 是不是自己？（自己读自己永远可以）
    if (current == task) return 0;

    // 2. UID 检查
    if (current_uid() == task_uid(task)) goto ok;

    // 3. capability 检查
    if (ns_capable(task_user_ns(task), CAP_SYS_PTRACE)) goto ok;

    // 4. LSM（SELinux）检查
    if (security_ptrace_access_check(task, mode)) return -EPERM;

    // 5. YAMA（如果启用）
    ...
    return -EPERM;
ok:
    return 0;
}
```

**结论**：

| 场景 | 能不能读 |
|---|---|
| 读自己 | ✓ |
| 同 UID 的进程 | ✓ |
| 不同 UID，普通权限 | ✗ |
| 不同 UID，有 root（`CAP_SYS_PTRACE`） | ✓ |
| SELinux 策略拒绝 | ✗（即使 root） |

这解释了第 37 章那个"明明是 root 还是被拒"的现象。

## Android 上的额外限制

Android 每个 App 有独立 UID，所以：
- App A 读不了 App B
- App 读不了系统进程

但**root 进程（UID 0）可以**——前提是 SELinux 放行。

```bash
adb shell su -c "cat /proc/1/mem"     # 可能被 SELinux 拒
adb shell su -c setenforce 0           # 临时关（仅排错）
adb shell su -c "cat /proc/1/mem"     # 现在可以了
```

## 三条技术路线的取舍

| | `ptrace` | `process_vm_readv` | 内核模块 |
|---|---|---|---|
| 速度 | 慢（每次一个字） | **快**（批量） | 快 |
| 是否暂停目标 | **是** | 否 | 否 |
| 可被检测 | 容易（`TracerPid`） | 较难 | 最难 |
| 需要内核模块 | 否 | 否 | **是** |
| 额外能力 | 断点 | 无 | 硬件断点、触摸注入等 |
| 权限 | ptrace 权限 | ptrace 权限 | root + 加载模块 |

> [!note] 本项目为什么选 process_vm_readv 作为无内核方案
> 1. **不暂停目标进程**——ptrace 会停掉游戏，卡顿明显
> 2. **批量读**——一次能读多段，ptrace 一次只能一个字
> 3. 不需要内核模块，root 就能用

## 检测面：TracerPid

```bash
adb shell cat /proc/self/status | grep TracerPid
# TracerPid: 0        ← 0 表示没被 ptrace
```

被 ptrace 后这个字段会变成追踪者的 PID。
**这是 App 检测自己被调试的标准方法。**

`process_vm_readv` **不会**改变 `TracerPid`——这是它相对 ptrace 的一大优势。

> [!warning] 本卷的练习对象
> 本卷所有练习，读取的目标进程都是**你自己写的 demo 程序**（第 83 章会带你写一个）。

>
> 这样做有三个理由：
> 1. **合法**：读自己的进程没有任何问题
> 2. **可验证**：你知道真值，能对答案
> 3. **学得会**：先理解数据在内存里怎么放，再谈读别人
>

## 动手：验证隔离

```bash
# 1. 启动 a
./a &
# 记下 pid 和地址

# 2. 在 b 里尝试读 → 崩溃
./b <地址>

# 3. 看 a 的 maps（自己能看自己）
cat /proc/<a的pid>/maps

# 4. 看 b 的 maps，对比同样的地址
cat /proc/<b的pid>/maps | grep 60104c

# 5. 用 root 看 a 的内存（这次能成功）
sudo cat /proc/<a的pid>/maps
```

观察：两个进程的 maps 里，`0x60104c` 附近的内容一样吗？
（通常一样，因为是可执行文件的同一段——但**物理内存不同**，
除非是共享库的代码页。）

## 课后习题

### 习题 73.1 验证进程隔离（★★，Linux/Android）

**要求**：写程序打印自己一个全局变量的地址，再写另一个程序尝试读那个地址——观察崩溃。

**a.c**（被读方）：

```c
#include <stdio.h>
#include <unistd.h>

int secret = 0x12345678;

int main(void) {
    printf("pid=%d &secret=%p\n", getpid(), (void*)&secret);
    fflush(stdout);
    sleep(300);
    return 0;
}
```

**b.c**（尝试读方）：

```c
#include <stdio.h>
#include <stdlib.h>

int main(int argc, char** argv) {
    unsigned long addr = strtoul(argv[1], NULL, 16);
    int* p = (int*)addr;
    printf("读到: 0x%X\n", *p);   // 大概率 Segmentation fault
    return 0;
}
```

**运行**：

```bash
./a &            # 输出 pid 和 &secret
./b 0x7ffd...    # 用 a 打印的地址 → 段错误
```

> [!danger] 为什么会崩
> 同一个虚拟地址，在不同进程里映射到**不同的物理内存**。b 直接解引用 a 的地址，
> 在 b 自己的地址空间里那可能是未映射的空洞 → SIGSEGV。
> **要跨进程读，必须走内核**（`process_vm_readv`，第 74 章）。

### 习题 73.2 内核开放的口子（概念题）

**要求**：说出内核提供的三种跨进程读写途径。

> [!question]- 参考答案
> ① `process_vm_readv/writev` 系统调用（本项目主用）；
> ② `ptrace`（调试用，会暂停目标，慢）；
> ③ 内核驱动 / 共享内存（本项目另一条路，卷六内核方案）。
> 三条都需要相应权限（同 UID 或 root），且受 SELinux 约束（第 37、73 章）。
