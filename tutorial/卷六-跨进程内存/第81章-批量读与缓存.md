# 第 81 章 · 批量读与缓存

> [!abstract] 本章目标
> 把每帧几千次 I/O 压到几十次。
> 这是本项目性能优化中**收益最大**的一环。

> [!note] 承上
> 前面把"能读"解决了。
> 本章解决"**读得快**"——批量读 + 缓存，把每帧几千次 I/O 压到几十次。

## 先量化问题

看 `DrawPlayer` 对每个 Actor 做了什么：

```
读 Actor 指针       1 次
读名字 ID           1 次
读名字字符串         2 次（头 + 内容）
读 RootComponent     1 次
读世界坐标           1 次
（如果画骨骼）读 Mesh  1 次
              读骨骼数组 1 次
              每根骨骼   1 次 × 15 = 15 次
--------------------------------
每个对象约 7~22 次
```

50 个对象 × 15 次 = **750 次 I/O**。
每次 3µs → **2.25ms**，占 60fps 预算（16.6ms）的 13.5%。
再加上自瞄、PhysX 更新……很容易超过预算。

## 三个优化层次

| 层次 | 手段 | 收益 |
|---|---|---|
| 1. 减少次数 | **批量读**（一次调用读多块） | 10× |
| 2. 减少次数 | **整块读**（一次读整个结构体/数组） | 5× |
| 3. 避免重复 | **缓存**（不变的数据只读一次） | 视情况 |

## 层次 1：批量读（iovec 数组）

第 74 章讲过，`process_vm_readv` 支持 iovec 数组。
把 N 次调用合成 1 次：

```cpp
struct ReadRequest {
    uint64_t remote;
    void    *local;
    size_t   size;
};

bool ReadBatch(MemReader &mem, const std::vector<ReadRequest> &reqs) {
    const size_t n = reqs.size();
    if (n == 0 || n > IOV_MAX) return false;

    std::vector<struct iovec> local(n), remote(n);
    for (size_t i = 0; i < n; i++) {
        local[i].iov_base  = reqs[i].local;
        local[i].iov_len   = reqs[i].size;
        remote[i].iov_base = (void*)reqs[i].remote;
        remote[i].iov_len  = reqs[i].size;
    }

    ssize_t got = process_vm_readv(mem.Pid(), local.data(), n,
                                   remote.data(), n, 0);
    return got > 0;
}
```

**注意内核驱动模式也支持**——只是要把多个请求合并进
`request_obj` 的 4096 字节缓冲（地址连续时）。

## 层次 2：整块读

比批量更进一步：**如果数据在目标进程里是连续的，一次全读回来**。

### 例：一次读整个 Actor 数组

```cpp
// 低效：逐个读
for (int i = 0; i < count; i++) {
    actors[i] = dr->Read<uint64_t>(arrayAddr + i * 8);
}

// 高效：一次读整个数组
std::vector<uint64_t> actors(count);
dr->Read(arrayAddr, actors.data(), count * 8);
```

**1 次 vs N 次。**

### 例：一次读整个骨骼数组

```cpp
// 15 根骨骼 × 48 字节 = 720 字节，一次读完
struct BoneTransform bones[15];
dr->Read(boneArray, bones, sizeof(bones));
// 之后全部在本地计算，零 I/O
```

### 例：一次读整个结构体

```cpp
// 低效：每个字段一次
int   hp = dr->Read<int>(obj + 0x10);
float x  = dr->Read<float>(obj + 0x14);
float y  = dr->Read<float>(obj + 0x18);

// 高效：一次读整个
struct ObjData { int hp; float x, y; };
ObjData d = dr->Read<ObjData>(obj + 0x10);
```

> [!warning] 前提是字段在目标进程里真的连续
> 用自己的结构体"套"别人的内存，必须确认布局一致（第 07 章的对齐！）。
> 不确定就老老实实按偏移逐个读。

## 层次 3：缓存

有些数据**一帧内不变**甚至**长期不变**：

| 数据 | 变化频率 | 缓存策略 |
|---|---|---|
| 模块基址 | 进程启动后不变 | 读一次，永久缓存 |
| GName 池地址 | 同上 | 同上 |
| 相机位置/朝向 | 每帧变 | 每帧读一次（不要每个对象读一次！）★ |
| Actor 数组内容 | 每帧可能变 | 每帧读一次 |
| 骨骼数据 | 每帧变 | 按需读 |

**最常见的错误**：在循环里反复读同一个值。

```cpp
// 错误：每个对象都读一次相机位置！
for (int i = 0; i < count; i++) {
    Vec3 cam = dr->Read<Vec3>(camAddr);       // ← 应该提到循环外
    ...
}

// 正确：循环外读一次
Vec3 cam = dr->Read<Vec3>(camAddr);
for (int i = 0; i < count; i++) {
    // 用 cam
}
```

本项目在 `UpdateGameData()` 里一次性读好相机数据，
存到 `AppBase.Location/Rotation/Fov`，循环里直接用——**就是这个原则**。

## 缓存的实现：地址缓存

模块基址缓存：

```cpp
class ModuleCache {
public:
    uint64_t GetBase(MemReader &mem, const std::string &name) {
        auto it = cache_.find(name);
        if (it != cache_.end()) return it->second;

        uint64_t base = FindModuleBase(ParseMaps(mem.Pid()), name);
        if (base) cache_[name] = base;
        return base;
    }

    void Invalidate() { cache_.clear(); }     // 进程重启后调用

private:
    std::unordered_map<std::string, uint64_t> cache_;
};
```

**失效条件**：目标进程重启、模块卸载重载。
本项目在"初始化"时重新获取，所以没做长期缓存。

## 缓存的实现：数据缓存（带时间戳）

```cpp
template <typename T>
struct TimedCache {
    T        value{};
    uint64_t lastUpdate = 0;
    bool     valid = false;

    bool Get(const std::function<T()> &fetch, uint64_t nowMs,
             uint64_t ttlMs, T &out) {
        if (valid && (nowMs - lastUpdate) < ttlMs) {
            out = value;
            return true;
        }
        value = fetch();
        lastUpdate = nowMs;
        valid = true;
        out = value;
        return true;
    }
};
```

本项目的 PhysX 更新就是这种思路（三个线程按 2s/3s/300ms 周期刷新）。

## 实测：优化前后对比

假设 50 个对象，每对象需要：名字、位置、15 根骨骼。

| 方案 | I/O 次数 | 估算耗时 |
|---|---|---|
| 朴素（逐个读） | 50 × 18 = 900 | 2.7 ms |
| 批量（iovec 数组，每对象一次） | 50 | 0.15 ms |
| 整块（数组 + 骨骼块） | 50 + 1(数组) = 51 | 0.15 ms |
| 整块 + 剔除（只处理可见的） | ~15 | 0.05 ms |

**从 2.7ms 降到 0.05ms，快 54 倍。**

> [!tip] 优先级建议
> 1. **先消除循环内的重复读**（成本最低，收益立竿见影）
> 2. 再做剔除（第 52 章），减少要处理的对象数
> 3. 最后做批量/整块读（改动最大）

## 一个完整的优化示例

优化前：

```cpp
for (int i = 0; i < Count; i++) {
    uint64_t obj = dr->Read<uint64_t>(Arrayaddr + 8*i);
    if (!IsValid(obj)) continue;

    uint32_t nameId = dr->Read<uint32_t>(obj + 0x18);
    std::string name = GetNameById(nameId);          // 内部 2 次 I/O

    uint64_t root = dr->Read<uint64_t>(obj + 0x168);
    if (!IsValid(root)) continue;
    Vector3A pos;
    dr->Read(root + 0x1F0, &pos, sizeof(pos));

    // 画...
}
```
每个对象 5 次 I/O。

优化后：

```cpp
// 1. 一次读整个指针数组
std::vector<uint64_t> objects(Count);
dr->Read(Arrayaddr, objects.data(), Count * 8);

// 2. 批量读所有对象的名字 ID 和 root 指针（两次批量调用）
std::vector<uint32_t> nameIds(Count);
std::vector<uint64_t> roots(Count);
std::vector<ReadRequest> reqs;
for (int i = 0; i < Count; i++) {
    if (!IsValid(objects[i])) continue;
    reqs.push_back({objects[i] + 0x18, &nameIds[i], 4});
    reqs.push_back({objects[i] + 0x168, &roots[i], 8});
}
ReadBatch(dr, reqs);

// 3. 批量读所有有效的世界坐标
reqs.clear();
std::vector<Vector3A> positions(Count);
for (int i = 0; i < Count; i++) {
    if (!IsValid(roots[i])) continue;
    reqs.push_back({roots[i] + 0x1F0, &positions[i], sizeof(Vector3A)});
}
ReadBatch(dr, reqs);

// 4. 之后全部本地处理，零 I/O
for (int i = 0; i < Count; i++) {
    /* 投影、绘制 */
}
```

**I/O 次数：5×Count → 3 次（外加数组 1 次）。**

## 注意事项

| 注意 | 说明 |
|---|---|
| IOV_MAX 限制 | 通常 1024，批量请求不能超 |
| 目标内存可能变 | 批量读期间对象可能被释放，仍要判有效性 |
| 地址必须有效 | 一个无效地址会导致该批次部分失败 |
| 缓存要能失效 | 进程重启后必须清缓存 |

## 课后习题

### 习题 81.1 统计「单次读」vs「批量读」的调用次数（★★）

**任务要求**：写一个假的「读取器」，每次读 8 字节计一次调用。
遍历一个 56 元素的 `uint64_t` 数组，分别用两种方式读取，统计调用次数并断言批量版更少。

**核心骨架**：

```cpp
#include <cstdio>
#include <cstdint>
#include <vector>
#include <cstring>
#include <cassert>

struct FakeReader {
    const uint8_t* base;      // 模拟目标内存
    int readCount = 0;        // 每次读计一次

    // 单次读一个 8 字节
    uint64_t ReadU64(uint64_t offset) {
        readCount++;
        uint64_t v;
        memcpy(&v, base + offset, 8);
        return v;
    }
    // 一次读整块（只计一次）
    void ReadBlock(uint64_t offset, void* dst, size_t n) {
        readCount++;
        memcpy(dst, base + offset, n);
    }
};
```

**参考实现**：

```cpp
int main() {
    const int N = 56;
    std::vector<uint64_t> mem(N);
    for (int i = 0; i < N; i++) mem[i] = 0x1000 + i;

    // 方式 1：逐个读 N 次
    {
        FakeReader r{ reinterpret_cast<const uint8_t*>(mem.data()) };
        uint64_t sum = 0;
        for (int i = 0; i < N; i++) sum += r.ReadU64(i * 8);
        printf("逐个读: 调用 %d 次\n", r.readCount);
        assert(r.readCount == N);
    }

    // 方式 2：整块读 1 次
    {
        FakeReader r{ reinterpret_cast<const uint8_t*>(mem.data()) };
        std::vector<uint64_t> buf(N);
        r.ReadBlock(0, buf.data(), N * 8);
        printf("整块读: 调用 %d 次\n", r.readCount);
        assert(r.readCount == 1);
        // 验证数据一致
        for (int i = 0; i < N; i++) assert(buf[i] == mem[i]);
    }

    printf("习题 81.1 全部通过（56 次 → 1 次）\n");
    return 0;
}
```

**验证断言**：逐个读调用 **56** 次；整块读调用 **1** 次，且两块数据一致。

> [!tip] 这道题练什么
> 本章核心结论：「**批量读把 N 次系统调用压成 1 次**」。
> 真实项目里 56 根骨骼逐一读要 56 次 `process_vm_readv`，整块读只要 1 次——
> 本题用普通 `memcpy` 模拟，把"调用次数"这个关键指标量化出来。
> 缓存那部分（层次 3）记住一句话：**静态偏移可缓存，每帧变化的动态数据不能**。
